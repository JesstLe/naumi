# Naumi 发布手册：用户连续可用

## 1. 最新约定与实现状态（2026-10-13）

用户已确认：频繁更新不应让前端用户遇到502、丢失编辑或中断正在执行的创作。**常规版本发布采用蓝绿切换，先启动和验收新版，再切入口，最后排空旧版。** 本约定优先于历史文档中的单容器直接重建流程，但不改变指定发布对象、数据保护、固定镜像、Git整合、部署锁及备份要求。

本次只写入发布标准，没有修改发布脚本或服务器。以下必须区分：

| 项目 | 当前记录 | 下一步要求 |
|---|---|---|
| App切换 | 现有脚本仍直接重建同一个Compose app，然后等待健康 | 实现双槽位旁路启动、就绪验证、切流及排空 |
| Agent会话 | 运行中的会话保存在进程内SESSIONS Map；有数据库历史，但不等于活动会话可跨实例恢复 | 实现活动会话归属路由和排空；进一步实现持久事件/可恢复任务 |
| Worker | 现有固定镜像发布仍涉及重建/停启Worker | 实现停止领取、租约交接、在途任务完成及幂等结算 |
| 旧前端 | 尚未在本轮验证跨版本资源保留及RSC/Server Action兼容 | 实现版本资源保留、协议兼容和必要的版本路由 |
| 103数据更新 | 2026-10-13增量合并曾短暂停App/Worker，已有备份与演练 | 在线增量同步单独设计，不宣称此前已无感 |

**状态：标准已确认，工程改造待实施，连续发布验收待完成。** 不能因改了文档、容器running、健康200、模拟SSE或单次页面200就记录“无感发布已上线”。

先在103.30.76.93完成改造与验收，再按明确任务推广到120.27.162.85。两站各自执行，不把两台独立站点组成共享业务负载均衡；各站的数据库、媒体、渠道及秘密保持独立。香港/101不是本约定自动发布目标。103当前R2/private-media配置不能被旧local示例覆盖。

## 2. 发布前必做

1. 从独立codex分支/worktree开工；刷新origin/main和同事分支，比较最新已完成业务提交并整合。保护他人未提交内容，排除专用历史回滚分支。构建前和切流前再次复核远端，发现新业务变更则更新候选。
2. 使用已提交的clean固定40位SHA镜像；在旁路完成构建/导入，不边停服务边构建。
3. 从读取当前基线、备份开始，全程持目标站Naumi/Hub部署锁，到实际功能验收及最终状态保存后释放；所有agent、回滚和空间清理使用同一套锁。
4. 记录BASE_COMMIT、CANDIDATE_COMMIT、当前App/Worker Image ID、构建版本、入口槽位、配置/包SHA、任务和连接基线、可读备份、回滚方式。切流前基线变化则重新核对，不覆盖别人的发布。
5. 检查双实例同时运行所需内存、CPU、磁盘和DB连接池余量；限制旁路构建资源。未达到双槽容量时先补容量，不把两套程序OOM称作无感更新。
6. 新版旁路预热不自动领取历史/新任务，不启动重复定时器或执行不可逆迁移。原鉴权、私有端口、媒体权限、历史任务保护保持。

## 3. 蓝绿发布流程

```text
固定候选与备份 → 旧槽持续服务、新槽旁路启动
→ 新槽就绪/预热/受影响功能验收
→ nginx -t → 平滑reload切新请求
→ 旧槽继续完成已有请求/会话/任务
→ 排空确认 → 停旧槽，保留资源和回滚材料
```

- 一台目标服务器内使用两个独立App容器/槽位和两个回环端口。13012/13013仅为设计示例，实施前检查占用；不硬改现有公网或DB端口。
- 两个槽位使用目标站同一数据库和本机媒体/R2配置；没有第二份可变业务库，不发生跨站同步。共享数据必须满足新旧版本同时读写兼容。
- 新槽只有通过就绪验收后才接新业务；readiness应覆盖DB/必要配置/迁移状态/版本及业务可读性，而不是只检查端口或OpenAI key存在。`/api/ready`仅是待设计入口，不是已存在或已验收接口。
- 新槽失败，旧槽继续服务，入口保持旧槽；不能提前停止旧容器或先挂维护503再验证新槽。
- 更新代理配置前做语法校验和固定基线核对；使用Nginx平滑reload，不restart网关。记录reload成功及公网实际目标版本，不把配置文件写完当作切换完成。
- 切流后旧槽不接受新的创作会话，但仍处理归属于它的活动会话操作和在途请求。只有活动连接、会话、任务计数均完成排空才停止旧槽。
- 排空超过预期，不强制杀进程来兑现“无感”。保留旧槽并继续观察/取消切换；排空预算和处理策略在每次发布前明确记录。
- 入口切换不是数据回滚。新业务数据始终留在同一DB/媒体，不回灌旧dump。

## 4. 生图、Agent与Worker连续性

### Agent/SSE

- Nginx平滑reload只保护已有连接，不能代替应用会话归属管理。当前进程内活动会话不能直接在新槽继续执行。
- 维护服务端认证绑定的 `(账号, sessionId, runId) → 所属实例` 路由；同一运行的stream、steer、stop、恢复/状态请求均发到原实例，直到完成交接。不能信任客户端任意指定后端实例。
- 新槽承接新会话；旧槽保留已有会话直到自然完成。已有SSE关闭前，不能仅凭“新槽健康”退出旧进程。
- 后续持久化事件编号、已提交工具结果及运行状态，支持重连续读。消息历史落库不等于工具调用/执行状态可恢复；网络超时不能盲目再次调用供应商。
- 代理与前端保持SSE正常无缓冲、心跳和合适超时；出现断线自动重连时按运行ID恢复，不另建收费任务。

### 生图/视频/工具任务与Worker

- 接单与耗时执行解耦；任务ID、幂等键、提交结果、供应商任务ID和结算状态持久化。用户等待中的节点/进度持续读取同一任务，不因发布变成新任务。
- 旧Worker进入drain后停止领取新任务，已领取任务继续执行和结算；新Worker在验证租约/领取互斥后接新任务。
- 重叠期间通过DB租约/唯一约束保证同一任务只有有效执行者，确认供应商调用与扣费/退款幂等；不能仅使用每个进程自己的Map或内存锁。
- 检查所有后台执行入口，而不只名称为video-worker的容器，包括App内定时/任务恢复、图片后处理、供应商费用补查和Agent工具。
- 接口断线不能抹去已接受任务；旧供应商请求状态未知时保留待核对，不重复生成、退款或扣费。

## 5. 旧页面、画布与静态资源

- 保留旧版构建对应的JS/CSS/chunk和版本清单，覆盖活跃浏览器/排空及回滚保留窗口；同一公共路径的旧chunk仍应可取到原字节。
- 设计旧build资源路由，避免新版容器未包含旧chunk导致404/ChunkLoadError。Next.js的RSC/Server Action请求还需协议兼容或build归属路由，单纯保留JS文件不够。
- 旧页面应能继续加载面板、上传、查看历史、保存画布、执行已承诺的操作；新旧API增加字段时保持旧客户端兼容。
- 不通过强制刷新解决版本错配，不覆盖未保存画布或本地草稿。非强制的新版本提示不能中断创作；刷新选择由用户决定。
- 持续保留当前运行版本、最近两个成功版本及依赖的回滚资源；旧资源何时可清理由活跃版本/排空和空间维护约定共同决定，不刚切流就删。

## 6. 数据库升级：扩展、迁移、收缩

1. **扩展**：先添加兼容字段/表/索引，旧代码继续运行；评估锁级别、设置有限lock_timeout并验证DDL在真实版本的行为。
2. **迁移**：后台限速、可续跑的分批回填，短事务、进度记录；必要时新旧字段双读/双写，核验一致性。
3. **切换**：确认旧客户端/旧实例和回滚镜像仍能正常读写，新代码切换读取路径。
4. **收缩**：旧槽和旧客户端兼容窗口结束后，在独立后续发布删除旧字段/约束；保留相应可回滚版本。

不得把删列/改类型、全表长事务、不可逆启动迁移混入普通无感发布。需要阻塞写入的破坏性操作，作为独立迁移任务明确窗口、影响、备份及验收；不记录为零中断发布。程序回滚仍必须验证数据和权限兼容，尤其私有媒体/团队授权，不能切回会泄露数据的旧镜像。

## 7. 跨站数据更新单独处理

蓝绿发布解决程序入口切换，不自动让全量数据替换变成在线同步。103的120备份增量合并证据见[数据更新记录](changes/2026-10-13-data-update-103.md)；此前短暂停服务不当作连续更新已通过。

- 保持不可变来源快照及祖先，先在隔离副本计算/演练差异、验证媒体，在线阶段只应用兼容增量。
- 不替换正在使用的数据库、不删目标测试数据；使用行版本/前像校验、有限锁等待和短事务，出现并发修改保留并记录冲突。
- 钱包余额、批次、预占和账本按一个一致性单元处理，不能先导余额再逐步补流水；已有目标分叉钱包不能被源历史重放。
- 保留历史任务来源保护，导入后不重跑原任务/费用补查/退款。原图按校验清单不覆盖发布，媒体和DB引用先后关系要有一致性方案。
- 持续同步、增量追踪/CDC及合并策略是另外的工程任务，需要明确同步目标和冲突规则，不因本发布约定自动开启跨站写入互通。

## 8. 连续性验收与回滚门槛

每次改造验收要保存**切换前、切换中、切换后**证据，而非只在发布完成后截图。普通业务发布须采用已验收流程，并保留本轮受影响功能证据。

| 场景 | 必须记录的通过条件 |
|---|---|
| 公网连续探测 | 真实入口页面、登录态API、静态资源及版本持续探测，发布引起的502/503、超时和连接重置为0；记录采样频率、时段与请求数 |
| 已打开页面 | 在旧build上打开的画布跨切流继续加载面板/保存；无ChunkLoadError/RSC错配，无强制刷新或未保存内容丢失 |
| 新登录/权限 | 新旧槽会话签名/权限一致；匿名、跨账号和私有媒体保护不退化 |
| 在途生图 | 一个发布前已接受的任务跨切换最终到达同一作品/任务ID，无重复供应商提交、扣费或退款 |
| Agent | 发布前开始SSE回复，切换后继续接收；同一会话的steer/stop仍作用于正确运行，断线重连不重放收费工具 |
| Worker交接 | 停领取/租约/排空可观察，任务归属唯一，切流后新任务正常执行，旧任务不丢 |
| 并发保存/DB | 用户并发编辑和保存不被更新覆盖，锁等待/延迟可观测，迁移前后数据/配置兼容 |
| 故障与切回 | 候选启动失败时旧槽正常；切后异常能切回兼容旧槽，原业务数据与已接受任务保留；按既有安全约定阻止不兼容旧镜像 |

- readiness、业务用例与模拟故障验证分开记录。模拟生成/fixture/受控SSE不能冒充真实供应商在途任务验收；真实调用按任务授权执行并核对最终持久化结果和结算。
- 持续监控错误率、请求耗时、活动连接、队列、租约、DB锁和资源；发布前确定观察时长及性能阈值，达不到门槛就保留/恢复旧槽，而不是靠增加重试隐藏502。
- 普通切回只切兼容入口/程序，不自动恢复旧数据库或媒体。全过程保留部署锁、版本核对和回滚材料；记录实际切回结果，不把脚本存在当作回滚已验证。
