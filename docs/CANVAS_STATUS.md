# 画布功能状态

更新日期：2026-09-14

## 目标链路

进入画布 → 创建项目 → 上传或引用素材 → 节点移动与重命名 → 节点连线与多输入 → AI 生成衍生图 → 保存作品与坐标 → 刷新恢复 → 下载、删除、撤销与回收站恢复。

## 本轮已处理

- 画布项目及作品接口绑定真实登录态，写操作不再信任前端提交的邮箱。
- Supabase 模式下，画布的上传、重命名、坐标、连线、删除和回收站请求统一携带访问令牌。
- 服务端校验连线两端必须属于同一用户、同一项目，并再次执行防环判断。
- 占位节点上传补齐授权头、HTTP 状态判断与可见失败反馈。
- 项目 ZIP 下载兼容自托管默认的 `/media/...` 本地存储图片。
- 项目聚合兼容 `/media/...` 节点，修复本地上传成功后节点从画布消失。
- 生成前先清理进程重启遗留的过期积分预约，修复孤儿预扣占满余额后账号无法再次触发自愈的问题。
- 增加接口、真实浏览器交互、真实模型生成三层画布冒烟脚本。
- 移除前端全局生图锁，改为节点级生成任务：同一节点防重复提交，不同节点可同时生图；任务各自显示、拖动和结束，不阻塞添加节点、上传或操作其他节点。
- 生成数量从固定 `1/2/4` 改为可输入、加减的 `1–8`；API 继续做 `1–8` 边界校验，多图结果按纵向节点完整落入画布。
- 下一节点默认引用当前节点结果，支持真实的“上传 → 提取主体 → 继续生成”链路，不再隐式跳回上一级素材。
- 增加三视图两种模式：一张横向正/侧/背合成图；或正面锚点完成后，侧面与背面并发引用“主体图 + 正面锚点”生成三个子节点。
- 增加“重做”操作：复用原节点提示词、比例、风格、清晰度和血缘，可在提示词框加入本次修改要求；旧结果保留，新结果作为新版本落图。
- 多图生成不再依赖上游一次请求的 `n` 参数，统一拆为多次单图请求；兼容服务即使忽略 `n>1`，选择 4 张也会真实执行 4 次并返回 4 个结果。
- 多图允许部分成功：保留成功图片，按实际成功张数扣积分，失败张数自动退回预扣差额；全部失败仍走全额退款。
- 并发闸按真实单图请求计数，多个节点和单个多图任务合计默认最多 4 路上游请求。
- 增加显式框选模式：开启后左键拖框即可部分命中多选，中键仍可平移，Esc 或批量工具条关闭选择。
- 多选后显示浅色批量工具条，支持把最多 6 张所选图片合并为一个多输入生成节点、批量标记/取消标记、ZIP 打包下载与批量删除。
- 多个已选节点可作为一组拖动，停止拖动后会逐个持久化坐标，并作为一次批量移动进入撤销/重做记录。
- 合并节点新增“详情图组”模式：把框选的正面、侧面、背面等最多 6 张参考图直接交给既有 A+ 规划管线，按首屏主视觉、核心卖点、使用场景、多角度等模块顺序串行生成 1–8 张，避免“数量 4”被误解成同提示词随机四版。
- 普通生成模式继续支持“以框选 N 张参考图生成新节点图”；两种语义在生成 Dock 中显式切换。
- 批量工具条新增“拼接长图”：按画布从上到下、同一行从左到右的空间顺序，把 2–12 张成品无裁切纵向拼接，保存为带完整多输入血缘的新画布节点；长图缩略图使用 `object-contain` 完整展示。

## 2026-09-16：批量拖入本地图片

### 已实现

- 在已打开的画布（包括新建空白画布）拖入多张 PNG / JPG / WebP；右键上传也支持多选，每张图片单独生成节点，名称保留文件名。
- 通过 React Flow 的屏幕到画布坐标转换处理缩放和平移；以拖入位置为起点，最多四列排列，避开现有节点和排队中的上传位置。
- 复用 `/api/artworks/add`，不新增上传存储协议。每张上限 12MB；非法类型、空文件、超限、接口失败逐张报告，成功项继续保存。
- 同一画布内的导入批次排队；空画布先建立第一张成功图片为根，随后每批最多四张并发上传。后续图片与紧接着拖入的批次都归入同一项目；不制造虚假连线。
- 上传期间画布编辑保持可用；切换项目后，未完成上传仍归入原项目，不会跳回原画布。每批成功节点作为一次撤销/重做记录。
- 新增浅色导入进度/结果面板和拖入高亮；成功提示可关闭，开始下一批时清理旧成功提示，失败项保留。中英文文案齐全。

### 本轮验证

- `node scripts/canvas-batch-upload-smoke.mjs` 使用临时 PostgreSQL、独立媒体目录、随机测试账号和真实 Chrome/Next 路由，不接触已有账号数据，不调用生图模型。
- 13 项验证：三图节点与资源加载、连续批次分组和避让、批量撤销/重做、多选及同文件再次选择、非法/超限文件、部分接口失败、刷新恢复、缩放和平移落点、非文件拖动、空画布首图失败后的连续批次、上传中切换项目、只读拦截、无浏览器运行时异常。
- 原版本通过 `--baseline` 验证：拖入三图新增 0 节点，上传选择器不支持 `multiple`。
- 将被 Git 忽略的 `output/` 证据/回滚副本目录排除出 TypeScript 扫描，避免历史产物中的 `.ts` 快照被误当作应用源码参与构建；旧画布验收脚本同步按上传文件名定位根节点。
- 构建、差异和独立副本回滚证据保存于忽略目录 `output/canvas-batch-import/`；本轮只更新本地仓库和 GitHub，未部署服务器。

### 边界

- 只接收系统文件拖放，不把网页图片链接或画布内部节点拖动当成上传；项目列表页不接收文件，需要先打开/新建画布。
- 上传队列保存在当前页面内，刷新/关闭页面不会续传尚未完成的文件；失败项可按提示重新拖入，成功项不受影响。
- 占位节点内的“替换/上传这一个节点”继续保持单图语义；批量入口是画布拖放和右键上传。

## 已知边界

- 生图任务状态仍保存在单进程内存 `Map`；进程重启时任务结果不可继续轮询，但过期积分预约可自动释放。
- 单任务数量上限为 8，服务端默认最多同时执行 4 个真实上游图片请求；更多单图请求会排队，但不会锁住画布。
- 三视图一致性通过锚点图、共享参考图和强约束提示词提升；生成模型仍具有随机性，单张不满意时应使用“重做”并补充具体要求。
- 详情图组按模块顺序逐张生成，四张图会比普通并发四版耗时更长；前一张失败不会改变既定模块顺序，最终按实际成功张数结算。
- 浏览器用例使用本机 Chrome，需要安装 Chrome；真实生成用例依赖已配置且支持 Images API 的模型中转。
- 仓库现有 3 条非画布 React Hook Lint 警告仍保留，本轮未修改对应模块。
- 画布主组件体积较大，后续应按项目浏览器、节点编辑器、生成 Dock 和弹窗拆分，但本轮不做高风险结构重写。

## 2026-09-17：原像素画布与自定义生成尺寸

### 已实现

- 上传图片时由服务端使用 Sharp 读取真实宽高并写入作品记录；画布采用 `1 图片像素 = 1 画布坐标像素`，例如 `900×900` 图片节点的图片区域就是 `900×900`，不再压成固定 `170×110` 缩略图。
- 节点端口、选中工具条、生成 Dock、任务占位、复制节点、多图生成落点、详情图组落点、拼接长图落点和自动树布局统一使用节点真实宽高。
- 批量拖入会在浏览器解码后按每张图片的真实尺寸排布；连续排队批次共享已占用矩形，避免后一批大图覆盖前一批。
- 历史作品缺少宽高时，浏览器从已加载原图读取 `naturalWidth/naturalHeight`，即时更新节点并通过 `/api/artworks/dimensions` 按登录账号回填数据库。
- 比例面板保留现有预设，并新增 `64–4096 px` 自定义宽、高。应用后将精确宽高提交为 `targetWidth/targetHeight`，服务端在生成完成后用 Sharp 输出指定尺寸并将真实宽高落库。
- 普通预设比例也会在服务端执行最终精确裁切，避免只依赖上游方图、横图、竖图三档导致画幅偏差；自定义尺寸则跳过后续分辨率档位放大，保证最终像素不被二次改变。

### 本轮验证

- `node scripts/canvas-native-size-smoke.mjs`：真实 Chrome、临时 PostgreSQL 和独立媒体目录验证 `900×900`、`600×1200` 上传按原像素显示且互不覆盖；历史尺寸首次加载自动回填；自定义 `900×1200` 生成精确落库与显示；尺寸回填无法跨账号修改。4 项通过且无浏览器异常。
- `node scripts/canvas-batch-upload-smoke.mjs`：13 项批量拖入回归全部通过，包括空画布首图失败后的连续排队批次仍按真实尺寸互不重叠。
- `node scripts/upload-performance-smoke.mjs`：4 路画布上传、3 路竞品上传、传输前压缩和 390px 响应式状态面板继续通过。
- `npm run lint` 与 `npm run build` 退出 0；只保留仓库既有 React Hook 警告，生产构建已包含 `/api/artworks/dimensions`。
