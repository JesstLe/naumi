# 重整策略：一个管理产品，保留清楚的业务 owner

状态：研究后的实施建议；本轮未开发/发布这些页面，未应用新售价。

## 1. 核心取舍

**统一入口、操作语言和详情页，不把模型配置、计费、采购、恢复合并成一个万能 manager。** 新功能按既有公共接口推进，先减少管理员理解成本，再收敛重复编辑器；不重写已成熟的出图/扣款链。

管理员的主要问题应直接对应页面：

1. 用户能选哪些模型，在哪些功能里能用？
2. 每个模型到底接哪个供应商、什么实际型号、什么规格？
3. 每个档位收多少积分，当前生效价来自哪里？
4. 供应商还剩多少、真实采购成本多少、原操作执行到哪一步？
5. 谁在何时改了什么，是否生效，如何恢复？

## 2. 目标信息架构

模块顶部只保留「模型 / 供应商 / 定价 / 运行」，右侧共用「变更记录」和新增操作。使用全站 shell，一套页标题、一层主导航；删除内层重复品牌/导航，不堆标语和长期说明文字。

### 2.1 模型

列表列：模型名称、类型、应用范围、启用通道、售价、状态、操作。第一屏直接有新增、改价、通道和规格；参考价必须明确规格，多个用途/价差不能只显示某一格当整模型价格。

模型详情分区：

- **概览**：公开 ID、展示名、启停/可见性、用途和默认项。
- **规格**：用户可选质量/尺寸/比例、参考图/蒙版、高级参数；有效 wire 映射放展开区。
- **供应通道**：实际 provider + upstream、优先级/权重、已验证范围、切换条件、当前容量状态。
- **售价**：用途切换、质量×尺寸矩阵、按次/按张/用量等原模式、有效来源和版本；0、未开放、未知/估算分别展示。
- **记录**：相关变更与真实调用关联；不把配置日志当任务执行结果。

图片、文本/视觉、视频、音频使用同一详情框架，但规格编辑器按模态分派，不把视频时长、语音、图片 quality 强行装成同一种参数。

生命周期单独定义：显示/隐藏、允许新请求/停用、收费/免费彼此独立。删除优先体现为从活动配置撤下/归档；物理清除须证明没有历史任务/凭据/账本引用，不能为了CRUD齐全删不可变证据。现有快捷协议不提供统一delete动作，相关用例需明确设计与验证。

### 2.2 供应商

列表以连接为主，单个供应商详情聚合：连接/协议与凭据、上游模型、目录/公开资料、余额、采购/对账、运行观察与变更。

- 新增流程：协议模板 → URL/密钥 → 读取目录 → 核对实际模型/参数 → 设置公开用途/价格 → 预览 → 发布。
- 已适配且契约一致时减少填写；新协议仍需 adapter，不以“任意供应商只填地址密钥”承诺未实现能力。
- 同一 key 多连接或轮换凭据产生的采购账户保留可解释关联，不错误合并不同供应商钱包。
- 余额是原币/额度/单位待确认，不给未知接口伪造“0元”。目录成功、资料完整、参数已验证、真实生成已通过分别表达。
- 手动资料与来源 revision 都保留；刷新结果可供选择，不覆盖管理员价格/映射/明确禁用。

### 2.3 定价

同一价格编辑器可以从模型或全局定价进入，**不要再维护另一套矩阵规则**。

- 普通操作：按公开模型、用途、质量和分辨率设置积分。
- 高级操作：保留 CNY 固定、实际用量、成本加成、tariff 条件规则、默认价和结算政策。
- 同时展示生效价和来源；“撤销本层覆盖”与“设为0积分”是不同操作。
- 拷贝/批量涨价以选定范围、完整 diff 和未选项不变为验收条件；不自动统一所有模型价格。
- 初始 onboarding 的 option 价和后续 Billing override 通过同一 read model 呈现；不为了让保存按钮只有一个就发明未实现的跨 owner 原子事务。
- “标准1元10积分”作为待配置运营政策，和充值促销、赠送、采购FX分开；调整新规则不重写余额批次、已付订单和已接受任务。
- 成本未知就保留未知。只有成本、收入归属和折算口径齐全时显示可解释毛利，不用售价减某个上游估价冒充净利润。

充值商品、订单、用户流水、人工调账仍在财务模块；模型定价可链接，不把整个财务后台搬进供应商详情。

### 2.4 运行

运行视图聚合真实业务调用、原任务链、通道状态、供应商费用与健康证据：

- 以 operation/task/call 关联，不通过模型名称猜同一次请求。
- 明确“未提交 / 已接受 / 结果未知 / 供应商完成 / 已入库 / 已交付”等实际证据；不以 HTTP200 当完成。
- 真实业务观察与主动探针分区。探针显示支持范围与预算，发供应商付费 POST 前使用相应授权流程；读取资料不触发生成。
- 查询原供应商任务、核对原发布操作是安全可追溯入口；不是无条件重放、清 unknown 或人工随意补完成。
- 老板的用户用量总览继续使用已约定指标，不把此前明确不要的失败/等待耗时加回老板报表；技术排障记录独立保留。

### 2.5 共用变更记录

展示 actor、时间、变更对象、diff、操作ID、模型版本/计费版本、实际状态与恢复入口。UI可统一列表；写入继续委托各 owner。结果不确定时沿原 UUID/revision 核对，不创建新请求“试一次”。

## 3. 旧功能迁移对照表

| 原能力/入口 | 新位置 | 必须保留的行为 |
|---|---|---|
| 模型管理列表、类型筛选、排序/改名 | 模型列表与概览 | audio类型、previous IDs、scope、排序与默认选择 |
| 新增前端模型 onboarding | 新增模型流程 | additive、copy有效价、原默认不变、精确供应商ID |
| 上游来源、Connect/Register、目录发现 | 供应商详情/新增向导 | encrypted refs、目录stale/error、能力确认不是目录成功 |

| 通用Billing商品/赠送/人工核对 | 财务原模块 | 订单冻结、退款/预占、审计与权限，不并入模型规则 |
| 供应商余额/容量/活动 | 供应商详情与运行 | 单位/时间/缓存真实、未知不作零、查询不收费生成 |

| BI models质量审计/实际请求模型 | 运行-调用详情 | 图片覆盖范围、实际响应证据、缺失不是执行成功 |

## 4. 实施分组与顺序

### M1：编辑契约与统一读模型

先处理 F01/F02/F06/F07：有效价格来源、各种合法定价模式的无损呈现、当前模态/功能兼容的测试、audio类型文案。为模型/供应商详情建立聚合 read projection，输出精确状态/版本/可编辑动作；不持长DB事务等上游I/O，不新增第二套计费逻辑。

验收：不操作时 roundtrip JSON 等值；打开/关闭不会隐式换定价；改选中格不丢未选功能/原单位；只读请求不publish/discover/DDL/生成；旧任务冻结不变。

### M2：模型与供应商对象化界面

一批完成列表、详情、所有模态和子页，再集中浏览器验收。复用现有编辑器的领域操作/session协议，重组壳层与导航。仅展示对象能力允许的操作；常用动作直接可达，高级字段按需展开。

验收：浅色、桌面/小屏、键盘可用、空/加载/错误状态；所有旧能力有去处；新增/编辑/启停/发布/核对真实连到原API，不是按钮静态占位。

### M3：统一定价工作台

在 M1 的 effective view 上复用一套编辑器。提供矩阵、复制、批量预览、来源解释、默认/例外层级；旧CNY/usage等保留为高级编辑。新运营兑换与价格表另作配置发布，不与UI合并成自动迁移。

验收：模型/全局入口同规格同价；客户端quote与服务端预占/最终结算同来源；免费/未开放/估算不混淆；并发改价冲突、原操作reconcile、历史任务/订单按原规则完成。

### M4：运行、采购和发布记录收敛

关联已有调用/费用/版本/健康证据，不擅自清unknown；补足明确需要的协议探针支持，并保留费用授权与预算。不以完整观察台为理由创建后台自动重提。

验收：分清not submitted与accepted unknown；supplier completed但保存失败不报已交付；原task补查不再生成；同ID核对配置；恢复历史产生新版本；脱敏字段无密钥/原请求敏感正文。

### M5：旧入口退出和回退验收

用迁移表逐项核对后再简化旧页面；先保留旧URL跳转、协议兼容和持久化操作key。退出条件是业务能力与自动化验收完成，不是新截图更好看。

UI回退应能恢复原页面组件而不还原DB/媒体；配置恢复由原owner发布新版本。为旧前端、旧任务、旧凭据验证兼容，不清业务状态冒充回退通过。

## 5. 集中验收矩阵

| 链路 | 核心验收 | 所需证据 |
|---|---|---|
| 页面/子页 | 全部旧能力可达、表单无损、模态正确 | 实际浏览器与交互断言 |
| 新增模型 | public→upstream→protocol→用途→售价完整 | 原生handler + 独立PG + 用户catalog |
| 修改配置 | draft/revision/diff/publish/reconcile/restore | 真实HTTP/PG与Router协议fixture |
| 权限 | 普通用户拒绝、admin允许、跨站拒绝、企业隔离 | HTTP正反例，不只隐藏菜单 |
| 定价 | 完整优先级、0/null、价格矩阵、批量保例外 | pure quote + PG真实预占/结算 |
| 映射 | 显示档位→一次wire编译，编辑/omit/像素/比例 | 本地协议contract + frozen golden对比 |
| 生成 | 生成/参考图/慢返回/刷新/旧配置/空图坏图 | 真实App/PG/媒体边界fixture端到端 |
| 未知结果 | 受理未知不跨收费通道重放，原task GET恢复 | supplier POST计数/原身份/账本断言 |
| 余额/资料 | 只查原账户、单位未知、人工值不被覆盖 | mock GET + 真handler + revision冲突 |
| 成本/对账 | 真实/估算/缺失、FX快照、同费用不重复累计 | 独立PG与原任务查询fixture |
| 历史/回退 | 原quote/ref/参数保留，恢复新版不改历史 | 副本字节回退+行为验证 |

真实供应商收费验收只在另有明确模型/站点/预算时执行。本次策略研究不会用历史的1美元授权另开一轮付费测试。正式部署沿最新站点HOLD、固定main、锁、蓝绿/排空和回切协议，和本轮文档交付分开。

## 6. 完成定义

完成不是“新后台壳能打开”。必须同时满足：迁移表无遗失；所有合法配置可读可编辑可核对；同一个选择得到同一份有效报价；历史任务继续按原供应商/参数/凭据收尾；权限和审计保留；有实际HTTP/PG/浏览器证据，再决定上线。每个完整模块同步文档、集中测试，避免每次样式微调都重跑整站构建。
