## 结论

**不是缺一套模型后端，而是已有后端能力没有被组织成一套一致的管理产品。** 应保留版本、报价、凭据、任务冻结、路由与对账 owner，统一围绕「模型、供应商、定价、运行」安排操作；先修编辑契约和信息呈现，再迁移高级入口，最后退出重复页面。

本次业务源码只读，未调价格、写业务数据库、调用真实供应商、连接服务器或部署。新文档不改变线上行为。研究不把历史测试和已合 main 当作当前线上验收。

## “全部代码不要遗漏”的落实方法

- 对本模块目录及管理入口作 Git 跟踪文件枚举，不依赖导航是否展示；含 CSS、JSON，不只统计 `.tsx`。
- 对源码解析静态 import/export、字面量动态 import、函数/类型位置、SQL 调用与页面引用；补入 BI 质量审计、旧设置、鉴权、用户模型目录、Worker、供应商回调、Router 容量回调。
- 从核心与补充入口递归追踪仓内静态依赖，并单列直接调用本模块的消费者；补齐两个 `docs/` JSON 依赖与 `.mjs` 边界文件。
- 关键业务链按真实实现串联阅读；**“进入全量索引”与“已执行运行验证”分别记录**。逐文件清单不等同于对所有外部消费者和第三方依赖逐行完成漏洞审计。
- 仓外 Router 只有仓内固定历史源码 fixture，本次核对其 SHA 和管理协议边界，不将其宣称为当前线上 Router 全量源码。

初始核心为 **375 文件 / 30,223 行**（含数据、样式）；补充关联55文件，静态递归闭包928文件，连同直接消费者等共1161个索引条目。完整统计以 `AUDIT_INDEX.json.stats` 为准。本轮实跑三组本地检查通过，另有一组旧批量配置测试失败，详见验证记录；没有“全测试通过”的结论。
