# 面向用户的更新记录维护

## 每次更新的必做项
1. 对照本轮实际交付范围，人工整理用户可感知的优化和修复；没有用户可见变化的内部维护不写公开记录，内部交接仍单独保留。
2. 不复制Git日志、工单、运维报告或聊天内容。禁止公开用户/企业/花名/账号/订单/作品标识、内部地址/路径/密钥/提交号、模型及供应商、价格成本、后台管理改造、部署与架构细节。改写为用户实际获得的改善；无法公开的条目直接不进入公开目录。
3. 只描述候选真实具备且将向用户发布的功能；尚未整合、仅本地完成或别的站点的工作不写成当前站点已发布。首次上线之前不补造历史。当前目录为空是刻意的，既有内部文档不自动转为公开历史。
4. 在固定候选构建前，绑定本次真实BUILD_VERSION，准备公开JSON并经人工复核。使用下列维护命令追加，不复用/改写旧版号，变更随候选一同提交。独立站点、回滚及旧页面只读取当前服务制品和已加载版号上限内的记录。
5. 构建/候选验收检查入口、双语、移动端、公开内容检查；用户可见更新需 `check --version`通过。内部维护无公开条目时记录不适用原因，不塞入内部内容凑条数。
6. 在原授权/部署锁/蓝绿流程内切流，公网核对实际版号及对应说明。回退程序也恢复对应候选目录，不回灌业务DB。维护脚本仅改本地公开JSON，不构建、不发布、不访问远端。

## 公开数据格式
文件 `src/content/public-release-notes.json`，不添加私有备注字段；严格白名单字段为version/title/improvements/fixes，文本均有zh/en。version是实际构建时间戳字符串。版本在界面格式化为现有日期版号；按新到旧排序。

```json
{
  "version": "BUILD_VERSION",
  "title": { "zh": "使用体验更新", "en": "Experience update" },
  "improvements": [{ "zh": "新增更新说明入口，方便查看每次体验改进。", "en": "Added update notes so you can review experience improvements." }],
  "fixes": []
}
```

示例版号占位不通过校验，需替换成实际候选版号；示例文案也必须与真实候选一致。

```powershell
node scripts/maintain-public-release-notes.cjs append --input C:/path/reviewed-note.json --reviewed
node scripts/maintain-public-release-notes.cjs check --version BUILD_VERSION
```

维护脚本严格校验字段、重复版号、文本长度以及常见隐私/内部词、地址、凭据、邮箱等；不回显被拒文案。关键词检查只是补充，不保证识别所有人名或新模型名，人工复核仍是发布门槛。前端只从公开API读取这份专用目录，不读取内部docs，也不打包未发布草稿。

## 版本与异常
- `/api/release-notes?version=已加载页面版本`只返回不晚于运行制品版号及已加载页面版号的公开条目，最多最近100条；原始文件保留完整记录（最多500条）。dev/未知版号不宣称正式已发布记录。
- desktop沿用现有路径前缀请求 `/desktop/api/release-notes`。不自动跨站点拉取记录。
- 读取失败显示重试，空目录显示暂无公开记录，不显示内部报错。不改现有版本检查、旧页面更新提示和刷新行为。
- 网站版本弹层不再展示源码提交标识；原运维version接口保持兼容，本任务没有改造后台或供应商配置。
