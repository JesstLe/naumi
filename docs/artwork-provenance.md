# 作品创建来源与后台溯源（2026-10-07）

## 已实现

- `app_artworks.creation_provenance` 保存版本、创建操作、入口、事件/任务编号、复制源作品编号和证据类型。它与可变的 `origin`（画布归属）分离。
- 生图任务、套图、A+、异步改字、视频、ComfyUI、上传、复制、导入、模板根节点和恢复接口保存明确创建记录。同步工具复用现有计费操作编号与服务端路由上下文，关联模型调用和账务，不增加扣费或上游请求。
- 生图页、画布、生图对话、Agent、作品库和竞品素材入口可区分；客户端入口标签只描述 UI 入口，不作为权限凭据。复制源必须属于当前账号且文件一致，项目挂靠父节点不冒充复制源。
- 后台按实际操作展示，不再把上传图片显示成商品主图。尺寸优先实际宽高，保留生成档位；上传无提示词显示“不适用：上传文件”。列表与 CSV 使用一致的来源、状态和编号。
- 详情提供复制源作品查看和已关联生图任务的执行链路；单作品查看支持跨日期与回收站，并保持账号限制和管理员授权。
- 创建来源不会因移动画布、重复写入或恢复冲突被改写。

## 历史口径

- 优先使用创建时保存的数据；旧数据通过同账号任务精确关联、原上传文件名与作品编号一致、模板根标记、明确 `derived` 标记及已知服务端批次前缀识别。
- `canvas-add` 同时用于上传、复制和导入，单凭此标记只显示“加入画布（操作待核验）”。指向别人的上传路径也不能当成当前作品的上传证据。
- 历史生图任务的空 origin 不证明来自生图页，显示“生成图片（入口待核验）”。画布归属也不证明创建来源。`derived` 可能是副本或拼图，`prt-` 同时用于印花提取和印花文件，均保留待核验标记，不强分具体工具。无充分证据时显示“历史记录待核验”，并保留作品编号。
- 历史识别发生在读取时，不覆写历史数据库记录或伪造来源、任务、提示词。

## 验收

`NAUMI_VERIFY_ISOLATED_DB=1`，`DATABASE_URL` 必须指向隔离的本地 PostgreSQL：

```powershell
npx tsx --conditions react-server scripts/verify-artwork-provenance.ts
npx tsx --conditions react-server scripts/verify-private-bi.ts
npx tsx --conditions react-server scripts/verify-product-fixes.ts
npx tsx --conditions react-server scripts/verify-billing-tools.ts
```

覆盖上传、复制、导入、模板、异步生成、同步工具、来源不变、跨账号拒绝、历史不猜测、尺寸、提示词、单作品跨日期查询、迁移幂等及地址脱敏。没有调用付费生图接口。

## 发布与回滚

- 迁移 `scripts/migrations/20261007-artwork-provenance.sql` 仅新增可空 JSON 字段与任务反向索引；启动也幂等确保这些结构。旧程序忽略新增字段，回滚只切换应用版本，不删除列，不回滚数据库、钱包或媒体。
- 生产发布仍使用固定镜像与 `scripts/deploy-release.sh`。最新生产只读预检发现 3 条未结算模型任务；既有发布回滚保护要求先核验这些任务，不能把它们改成完成或删除后强行发布。
- 浏览器协作预览已打开，但快照和页面执行超时；本轮不将该项宣称为浏览器通过。隔离 Windows Next 生产构建编译与类型检查通过（standalone 复制阶段存在原有 junction 权限警告），可部署 Linux 镜像构建单独验证。首次冷启动 HTTP 任务回归因多个路由同时初始化 schema 出现 deadlock、任务恢复超时，保留失败证据，不掩盖为通过。
- HTTP 任务回归在逐个初始化路由后通过：三个持久化检查点恢复成功、部分结果各扣费一次，`IMAGE_JOB_ROUTES_RESULT=PASS`。仅修正隔离测试启动顺序，没有更改任务或计费语义；首次冷启动 schema 并发问题仍单列为待核验。
- 非本任务的供应商目录、批量模型配置、package.json 修改不纳入此任务提交或发布包。
