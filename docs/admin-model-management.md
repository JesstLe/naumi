# 管理后台：模型管理

入口 `/admin/model-management`，元数据库 `/admin/model-management/library`，位于管理导航最上方。正式模块覆盖前端模型名称、上游来源、应用范围、排序、质量参数映射及积分售价。页面与组件位于 `src/app/admin/model-management`、`src/components/admin/model-management`，业务模块为 `src/lib/model-config/management*.ts`；API为 `/api/admin/model-management` 及其 `/library` 子路径。

原 `/admin/mvp` 页面与元数据库子页面保留永久跳转，并保留查询参数；原 API 保留同一鉴权、处理器、操作锁与幂等逻辑，不重定向 POST。已有供应商 ID、积分规则前缀、发布 actor 与浏览器待处理记录的旧命名属于持久兼容协议，保持可读与可重试，不迁移业务数据。

## 模型映射

列表使用与 `/api/models` 相同的生效目录和功能可见性，再按现有用户侧图片家族规则折叠。展示当前前端名称、实际 wire model ID、上游来源及使用工具；未应用到任何工具的已启用模型仍保留，以便重新选择范围。用户自带图片 API 入口和新请求已取消；ComfyUI自定义工作流保留。

原“配置别名”是旧配置中一个比例分支的 label，并非另一个模型家族。该提示已移除，多个比例分支现在明确说明“模型家族、统一管理”，后台操作始终保留真实模型 ID。

每行“编辑范围”打开分组多选面板：生图与内容、编辑工具及画布系统。普通工具支持逐项、整组、全选可用工具、清空、恢复当前范围、搜索和保存发布。画布勾选一次，覆盖符合能力的模块；可展开查看模块用途与状态。不可用选项说明当前能力/工具配置未开放，不替用户生成供应商能力或新价格。范围作用于整个图片家族，包含暂时隐藏的分支。

用户选模型的工具限定其公开目录及新请求解析。画布图片与文字／图片理解使用各自模型池，Agent对话要求图片理解能力、出图使用图片池；默认项用于有效选择的回退，保存范围和用户选择不改变模型顺序。移除默认项时使用现有允许且兼容的替代项，无替代项则拒绝发布并保留编辑。范围独立保存于公开模型的可选 toolScope 字段，画布系统标记为 systems:["canvas"]；旧部分范围保留，管理员勾选并保存后才统一授权。独立操作草稿、并发版本、同操作核对及已接受任务冻结流程继续适用。

“参数设置”维护展示质量档位和实际 quality；默认按精确供应商 ID + 实际模型 ID 的元数据库匹配，显示来源与修订，允许恢复默认、原生候选或手动覆盖。已有显式映射保留，缺资料不猜测参数；元数据修订冲突会保留输入。发布后的映射固定在版本化执行配置，积分售价独立维护。图片／文字共享选中模型时，能力不符的模块使用可用回退。

简单切换保持公开 ID、别名、售价及功能绑定，更新实际目标；同一公开 ID 或图片家族在多个功能使用时一起生效。家族切换同时更新其比例分支；启用的条件路由和失败回退会明确提示并关闭，避免发布后仍调用旧目标。已接受任务继续使用冻结版本。备选开放启用、凭据已配置且满足既有输入与规格记录的已接入模型；旧接入能力未核验时明确标注，仍由完整配置校验决定能否发布到对应功能。

每行“修改显示名称”可发布1–100字符的前端名称。改名仅更新公开模型label及对应预设别名label，不改ID、真实目标、路由、用途绑定或价格；图片家族包含暂时隐藏/停用的比例分支一并更新。前端图片选项读取受管名称；旧比例分支名称不一致时仍折叠成原家族ID。与现有发布一样，改名保留完整配置中心草稿，冲突需刷新，未知结果沿用原操作编号核对。

APIMart 专用默认预设涉及模型专属能力证据、原生参数矩阵及成本，快捷页面不能复制旧模型证据给新模型；此类变更转至完整配置中心。目录发现与管理员能力声明均不代表付费出图验收通过。

## 上游来源

填写名称、URL、协议和凭据，发布来源后自动读取标准模型目录；重新进入页面时按现有缓存有效期刷新。保留目录错误、未支持协议、空目录、旧缓存和截断状态。支持当前 OpenAI 图片/文字/视频、New API 图片、APIMart 图片的快捷接入；其他协议使用完整配置中心。

目录模型需管理员根据文档或测试结果确认类型和能力后才能添加，再进入兼容目标列表；不会猜测成本、能力或修改当前前端模型。HTTPS/localhost 使用现有 RSA-OAEP；HTTP 兼容现有系统设置的服务端加密保存流程，HTTP 本身不提供传输加密。明文凭据不进入草稿、浏览器存储、日志或返回值。发布重试只保留凭据引用。

## 发布与验收

复用既有模型配置校验、Router 准备/激活、版本冲突和任务冻结流程。模型管理每次发布使用独立操作草稿，不覆盖完整配置中心未发布草稿；同操作串行处理，结果未知时保留原编号供重试核对。所有页面和接口保留管理员权限及同站修改校验。

本地隔离 PostgreSQL 下：

- `npm run verify:model-management`：真实目标切换、新旧任务版本、草稿保留、结果未知恢复、凭据加密、目录发现、版本冲突、权限检查。
- `npm run verify:model-management-ui`：浏览器映射、切换与刷新恢复、RSA 接入/自动目录、模型登记、搜索、类型过滤、手机布局及普通用户拒绝。
- `npm run verify:provider-catalog`、`npm run verify:model-publication`、`npm run verify:image-model-family-routing` 和 `npx tsc --noEmit`。

隔离测试不调用真实模型，不改变真实上游配置。新机发布遵循固定镜像、先备份、准备回滚、保留现有数据库/媒体/配置和线上验收的约定。

## APIMart 接入修正

真实新机直连 APIMart 时 DNS 解析异常且连接超时；同机现有代理可取得用户已保存来源的 376 个模型 ID。模型传输新增服务端显式 `MODEL_CONFIG_PROXY_URL` / `MODEL_CONFIG_PROXY_ORIGINS`，只对精确批准的 HTTPS origin 走 CONNECT 代理，其余目标继续原 DNS 绑定与内网拒绝。代理端看不到 TLS 内的供应商 Authorization。手动刷新目录可绕过旧失败缓存。

APIMart URL 接受根地址或 `/v1`；新来源规范化为根地址，Router 适配器亦去掉末尾 `/v1`，避免生成路径重复。多个同地址账户可以作为独立来源保存。固定 Router 源码 `b3fc8dd61e62c564ac2ba2a08cf943f7c391970c` 保存在验收源码包中；Go 全量测试通过。API 与已明确批准的媒体来源使用独立 `NAUMI_MODEL_PROXY_URL` / `NAUMI_MODEL_PROXY_ORIGINS`，其他媒体仍校验公网地址。`scripts/verify-model-proxy.ts` 验证来源隔离、CONNECT 和密钥边界。

受管图片任务向 Router 传递冻结的文字能力要求，避免完整提示词中的“不要文字”等系统约束被再次推断成文字绘制需求；显式操作要求仍优先，旧路由继续使用自动推断。`scripts/verify-managed-gateway-facts.ts` 验证普通生图、冻结文字需求、显式要求和旧路由，`verify-image-gateway.ts` 验证任务恢复、原报价和积分结算。

## 模型客户积分售价

模型行的“设置积分”按模型家族和应用工具维护客户售价。主界面是质量 × 分辨率价格表，可查看各工具现行报价、逐格独立修改、批量填价、多选工具应用，以及恢复所选工具的原计价。统一积分仍可选；图片默认使用价格表，不再要求管理员心算加价公式。数量按现有工具单位（张/项/次）计算；0积分为免费，未开放组合存为null且不能报价。采购成本、模型能力、路由和完整模型草稿保持原值。

积分写入现有计费配置的模型条件规则，新增matrix计价类型，独立递增计费版本。发布事务同时检查计费版本和模型版本，避免覆盖其他管理员更新。模型规则优先于该模型原业务售价与 APIMart 成本倍率售价；自带密钥继续原免计费策略。模型选项显示标准1K参考积分，提交按钮和结算使用同一冻结报价；已提交任务继续原价，按成功数量扣费，全失败释放预占。APIMart映射到标准档的高档请求按实际档位报价，后台相应行标明映射且不允许另填高价。无需新数据库迁移；回滚到不理解matrix/MVP规则的旧代码前须先恢复原计费配置。

验收：`scripts/verify-model-management-credit-pricing.ts`（隔离 PostgreSQL，`tsx --conditions react-server`）检查业务售价覆盖、模型家族、工具范围、规格数量、真实钱包部分成功/失败、冻结旧价、版本冲突与幂等恢复；`verify:model-management-ui` 检查后台弹窗、前端参考价/实际报价与刷新缓存；`verify:apimart-preset` 增加客户固定积分覆盖预设成本计价回归。均使用本地隔离供应商，真实收费调用0。
