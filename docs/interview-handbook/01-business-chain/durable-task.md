# 01-01 请求、任务与账务事务

[返回总目录](../README.md)

## 1. 主链路与三个状态轴

用户提交意图 → 校验归属、输入和冻结执行上下文 → 保存任务与预占 → 执行者领取 → 供应商受理与生成 → 结果保存 → 账务结算 → 用户获得回执。

- **执行事实**：供应商受理了吗？结果保存了吗？
- **观察状态**：浏览器是否拿到回执？当前页面展示什么？
- **账务状态**：预占、扣除或释放了多少？

它们有关联，但不能用一个状态字段互相替代。

## HB-001 用户关掉页面，任务为什么还要存在？

### 现场问题

用户提交一次生图，页面关闭；或者 Web 在返回响应前重启。再次打开页面时，系统应该知道什么？

### 旧模型与反例

旧模型：“一次请求就是一次任务。”反例：请求消失时，供应商可能仍在执行，积分可能已经预占。

### 基本事实与不变量

连接、页面和进程都可能消失；已接受的业务意图需要可追踪。不能因为丢失连接就把旧任务悄悄变成一次新任务。

### 推导与参考回答

把任务作为独立、持久的业务对象，记录稳定身份、归属、冻结输入、执行进度和付费检查点。请求负责提交或查询任务，不独占任务生命周期。恢复器根据持久事实接续原任务，而不是要求用户再点一次。

参考表达：“我先区分请求生命周期和业务生命周期。业务跨重启存在，所以任务及必要上下文必须持久化；用户重开页面读取原身份。只有明确满足协议条件的恢复才能继续外部操作，不能把恢复等同于重新提交。”

### L1—L4 追问

- **L1**：内存 Map 为什么不够？要点：进程退出丢失，其他进程也看不到。
- **L2**：最少保存哪些字段？要点：身份、归属、输入/执行版本、进度与副作用证据，按业务恢复需要取舍。
- **L3**：插入成功但响应丢失怎么办？要点：使用原业务身份查询或按协议去重，不能仅凭响应失败判定未创建。
- **L4**：怎样证明可恢复？要点：在关键边界注入重启/丢回包，检查原任务、结果和账务，不只检查进程重新启动。

### 项目证据与验证

源码：[`DurableImageJobs.create`](../../../src/lib/durable-image-jobs.ts) 与 [`createImageJob`](../../../src/lib/image-job-repository.ts)。数据库路径和无数据库的本地路径要分开理解；不是所有运行配置都具备同样持久能力。

验证设想：对任务保存前后、供应商受理前后、结果保存前后分别注入中断，核对任务身份连续性。这是验收设计，本轮文档工作未执行业务故障注入。

### 边界与待追问

持久化不自动保证幂等或不重复外部调用。前置题：无。后续：HB-002、HB-008。学习状态：未评估。

## HB-002 任务创建和积分预占为什么要一起提交？

### 现场问题

先预占再保存任务，中途崩溃；反过来先保存任务再预占，中途也可能崩溃。怎样避免两边各成功一半？

### 旧模型与反例

旧模型：“两条 SQL 最后都会执行到。”反例：进程在两条语句之间退出，重试时还可能重复执行。

### 基本事实与不变量

同一次受理中的任务与应有预占需要一致，且重复提交不能多预占。任务事实和账务规则有不同职责，但可以共享同一个事务连接。

### 推导与参考回答

同库场景先采用同一事务原子提交任务与预占，模块接口显式接收事务连接。不能每个模块各开一个事务后就声称“有事务，所以一致”。在事务外调用供应商，依靠持久检查点与恢复协调外部副作用。

参考表达：“我先找必须一起成功的本地写入，使用共享事务。事务不跨长时间生成过程；本地提交以后，再执行外部工作。数据库原子性不等于供应商也跟着回滚。”

### L1—L4 追问

- **L1**：什么叫原子性？要点：限定事务中的本地写入一起提交或回滚。
- **L2**：模块拆开是否必须拆事务？要点：职责边界和事务边界不等同。
- **L3**：COMMIT 实际成功但回包丢失呢？要点：结果未知，按原身份读回，不凭异常无脑重复写。
- **L4**：若以后真的跨数据库怎么办？要点：先证明拆分必要性，再讨论 outbox、幂等与补偿；外部效果往往不能物理撤销。

### 项目证据与验证

源码：[`createImageJob`](../../../src/lib/image-job-repository.ts) 的 BEGIN、任务 INSERT、`reserveTx(client, ...)` 与 COMMIT；账务接口见 [`createBillingService`](../../../src/lib/billing/service.ts)。

验证设想：预占失败时没有半成品任务；任务写失败时没有残留预占；重复身份不会新增第二笔；提交回执丢失时按原身份确认。

### 边界与待追问

本地事务解决不了跨供应商原子性。也不能在事务里长时间下载媒体或等待生图。前置：HB-001。后续：HB-004、HB-008。学习状态：未评估。
