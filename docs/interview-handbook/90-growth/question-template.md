# 90-04 新题模板

[返回总目录](../README.md)

新题从 HB-021 继续，保留旧题号。模板槽位只用于新题，未填写不进入“已成稿”索引。先判断它属于开场、项目、基础、实际问题还是收尾，不让目录退回只有事故深挖。

## 题号与标题

HB-NNN / 标题 / 前置题号 / 核对日期与基线 / 成熟度 / 学习状态。

### 现场问题

写具体角色、时间顺序、输入、现象与决策难点。

### 旧模型与反例

写旧认识，以及哪个变化条件使它解释不通。未实际听到用户回答时，只称“教学用朴素模型”，不归因给用户。

### 基本事实与不变量

去掉中间件名词，明确资源、失败边界、已有证据和必须保护的结果。

### 推导与参考回答

#### 直接回答

**答案：** 用完整段落先回答问题，再解释条件与结果，不只列技术名词。

#### 从事实推导

分三至五步解释事实、反例、不变量与机制的因果关系，写清为什么不用另一个方案。

#### 示例与落地

给具体时序、数据、伪代码、SQL 或验证矩阵。明确是教学示例、源码事实还是已经实测，不能混写。

#### 面试表达

写一段可在约九十秒内复述的回答，不冒充学习者亲历。

### L1—L4 追问

#### L1 解释：具体问题

**答案：** 完整解释基本概念、因果与一个例子。

#### L2 推导：具体问题

**答案：** 解释从约束到机制的步骤与方案取舍。

#### L3 变式：具体问题

**答案：** 列变化后的时序，指出原方案失效或仍成立的原因。

#### L4 负责：具体问题

**答案：** 说明观测、验证、成本、上线及恢复边界。

### 常见误区

至少两项，每项解释为什么错以及正确判断。

### 跨业务迁移

附电商或社交的具体类比与对应答案，说明共同原理及不能机械迁移的差异。

### 项目证据与验证

分别标注源码、历史记录、规则要求或教学假设；给存在的相对路径、函数/字段与必要基线。验证建议和已执行结果分开。

### 边界与待追问

写方案未覆盖什么、下一题、仍待验证的判断。同步索引、对话记录与更新记录。
