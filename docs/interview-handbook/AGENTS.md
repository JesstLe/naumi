# 面试手册维护约定

- 本目录的唯一入口是 README.md。后续对话围绕本手册时，先读总目录、题目索引和最新对话记录，再按题号定位正文。
- 用户要求持续补充：优先修改原题，不创建平行手册；新主题才分配 HB 新题号，旧题号不重排。
- 保持“现场问题→旧模型与反例→事实与不变量→详细答案与推导→L1—L4完整问答→证据与验证→边界”结构。
- 用户要求详细且每题附答案：主问题要有直接回答、逐步推导、示例落地和面试表达；四级追问各有独立完整答案，并补常见误区与跨业务迁移。正文不使用一行判断要点代替答案。只有用户明确选择模拟面试时才在聊天中先问后答，文档保持完整答案。
- 默认面试顺序从 `00-interview-flow/README.md` 开始：自我介绍、背景交流、项目概述与职责、基础与选型、实际问题深挖、变式、总结反问。原HB-001—HB-012是深挖题，不作为整场开头。新HB题号沿时间追加，阅读顺序可以不同；个人背景未知用槽位，不虚构。
- 源码、历史事故、规则、教学假设和未知分别标明；新增事实核对实际基线，不把旧分支或历史部署写成现状。
- 用户实际回答才是学习状态更新依据；不将参考答案、赞同或阅读完成当成掌握，不虚构个人事故经历。
- 每轮有实质新增后更新对应正文、90-growth/dialogue-log.md 与 CHANGELOG.md；新增题号同步 README.md 与索引。
- 文档集中验证使用 `python docs/interview-handbook/verify.py . --require-detailed`；检查主答案、全部追问答案和链接题号，只做文档验证，不触发业务构建或发布。
