# 完整面试流程：从认识候选人到检验工程判断

[返回总目录](../README.md)

## 1. 这条路线怎样使用

之前的 12 题回答的是“进入项目以后，可以深挖什么”，并没有覆盖一场完整面试。现在把**真实交流顺序**和**知识分类目录**分开：本页负责前者，业务链路各章负责后者。

下面是一轮技术面的教学样例，不是所有公司的统一规定。实际岗位可能单独安排算法、语言基础、系统设计或交叉面；面试官也可能提前跳转。我们保留自然的因果线索，而不把流程背成固定剧本。

## 2. 第一阶段：自我介绍

入口：[HB-013](opening.md#hb-013)。

**面试官：**“先简单介绍一下自己。”

**示范回答骨架：**“我目前的真实背景是【实际经历】，主要关注【岗位相关方向】。最近投入较多的是 Naumi，它是把商品素材、AI 生成、画布和批量处理组织起来的视觉工作站。我实际参与到【学习/实现/设计/负责的真实层次】，其中最能展开的是【一项有证据的工作】。我希望结合这个项目说明我对【对应能力】的理解。”

这些槽位必须替换成事实。对项目只做过阅读分析，也可以介绍学习与分析成果，但不能把它说成主导上线或处理真实事故。

**自然过渡：** 面试官从介绍中挑选一条线索：“你说主要做这个项目，最近具体在做什么？”进入下一阶段，而不是直接问一个不相干的分布式难题。

## 3. 第二阶段：简单交流背景、近期工作和技术栈

入口：[HB-014](opening.md#hb-014)。

**面试官：**“你最熟悉哪一块？为什么开始做这个项目？”

**示范回答：**“我把熟悉程度分为使用过、独立实现过、深入理解过和实际负责过。当前我最能展开的是【真实模块】，能说明其输入输出、调用链和验证方式。选择 Naumi 的实际原因是【真实动机】；它让我把界面、任务、数据库和外部调用串成完整链路。对【未实操技术】我有原理认识，但不会把它列成生产经验。”

**自然过渡：**“那先整体讲讲 Naumi，用户在里面做什么？”候选人先解释业务价值，再逐步进入技术。

## 4. 第三阶段：项目概述与本人职责

入口：[HB-015](project-overview.md#hb-015)、[HB-016](project-overview.md#hb-016)。

**面试官：**“不要先说用了什么框架，先说你解决了什么问题。”

**示范回答：**“Naumi 面向商品视觉创作，把参考素材、提示词、生成、处理、作品和画布放到一个流程里。一次付费生成不是简单地调用模型返回图片，还要处理任务保存、积分预占、供应商受理、结果存储和用户回执。我的实际贡献是【具体职责】，证据是【代码/测试/记录】。全项目目标与本人已经验证的结果，我会分开表述。”

随后明确本人负责的边界，否则面试官可能把整个项目的每个模块都当成候选人的个人工作。

**自然过渡：**“刚才你说用了数据库保存任务。事务为什么这样划分？”从已经提到的项目技术，过渡到基础知识。

## 5. 第四阶段：基础知识与方案选择

入口：[HB-017](fundamentals.md#hb-017)、[HB-018](fundamentals.md#hb-018)。

**面试官：**“Node 是单线程，为什么还能同时处理多个慢请求？”

**示范回答：**“要区分 JavaScript 回调执行与异步 I/O。一个主线程不等于一次只能有一个请求在途。网络等待期间，执行权可以交给其他回调；但 CPU 密集计算仍可能阻塞事件循环，不能因为用了 async 就获得多核并行。项目要结合任务、连接和媒体处理分别测瓶颈。”

**面试官：**“多实例计数不一致，为什么不直接用 Redis？”

**示范回答：**“需要的是共享原子状态，不是某个产品名称。本手册基线里项目复用了 PostgreSQL 共享限流；Redis 也是候选，但要结合延迟、吞吐、热点、故障和运维成本决定。选择已有组件不代表永远不变，后续应由测量触发迁移。”

**自然过渡：**“你的方案在正常情况下成立。如果进程中途退出呢？”由基础和选型进入实际故障条件。

## 6. 第五阶段：按项目线索深入，不机械问完所有题

以下各分支均有主答案和追问答案，面试官按回答选择深入：

1. **任务可靠性线**：[HB-001](../01-business-chain/durable-task.md#hb-001) 请求与任务 → [HB-002](../01-business-chain/durable-task.md#hb-002) 事务 → [HB-008](../04-external-side-effects/timeout-and-recovery.md#hb-008) 外部超时。
2. **容量与排障线**：[HB-003](../02-capacity-and-database/resources.md#hb-003) 指标 → [HB-004](../02-capacity-and-database/pool-and-waits.md#hb-004) 等待环 → [HB-010](../05-engineering/evidence-driven.md#hb-010) 三类证据。
3. **多实例执行线**：[HB-005](../03-distributed-execution/shared-state.md#hb-005) 共享状态 → [HB-006](../03-distributed-execution/lease-and-fencing.md#hb-006) 原子领取 → [HB-007](../03-distributed-execution/lease-and-fencing.md#hb-007) 陈旧执行者。
4. **交付与判断线**：[HB-009](../04-external-side-effects/timeout-and-recovery.md#hb-009) 回执 → [HB-011](../05-engineering/verification-and-narrative.md#hb-011) 验证边界 → [HB-012](../05-engineering/verification-and-narrative.md#hb-012) 项目叙事。

每条线的后一道题都改变前一道题的条件。这才是连续追问，不是随机抽取术语。

## 7. 第六阶段：改变条件，检验迁移能力

入口：[HB-019](closing.md#hb-019)。

**面试官：**“如果流量翻十倍，你先改哪里？”

**示范回答：**“先确认翻十倍的是在线人数、读取 RPS 还是生成任务到达率，再根据资源时间线测瓶颈。持续到达率超过处理能力时，队列只会延后故障，不会创造吞吐。我会明确哪些是实测，哪些是假设，再讨论扩容、减少工作量或合适的背压，不直接承诺加十个实例就解决。”

追问也可换为电商支付、社交发布：共同原则保留，但重复、延迟、可见性和账务的代价必须重新解释。

## 8. 第七阶段：总结、反思与反问

入口：[HB-020](closing.md#hb-020)。

**面试官：**“你还有什么想问的？”

**示范回答：**“我想了解这个岗位近期最需要解决的工程问题，以及新人进入后怎样判断工作取得了成效。刚才我们讨论了任务可靠性，我也想知道团队现在最关注的是交付速度、稳定性还是某类成本约束，以便理解这个岗位的重点。”

这是了解岗位和协作环境，不是假设对方一定有某个事故，也不是为了展示术语追问不相干的内部细节。

## 9. 两种阅读模式

- **学习模式，默认**：每个问题连同答案完整展示，先理解再练习。
- **模拟面试，用户明确选择后**：按阶段逐题问，等待真实回答再追问。文档仍保留答案，结束后将实际误区和新增结论写回原题。

不知道个人信息时保留槽位，不阻塞手册；后续用户提供真实信息后，编辑原有模板，形成个人版本。流程完整不等于学习已经完成，所有学习状态仍按实际回答记录。
