## HB-006 两个 Worker 同时抢到一单怎么办？

### 现场问题

A、B 同时扫描到同一条 pending 任务；两边都准备调用付费供应商。

### 旧模型与反例

旧模型：“先 SELECT 未处理，再 UPDATE 处理中。”反例：A、B 同时通过 SELECT，之后都认为自己有权执行。

### 基本事实与不变量

检查与领取必须原子完成；同一时刻有效执行权要有可核查的归属。类别级总并发也是共享约束，不能每实例各自计数后假装整站受控。

### 推导与参考回答

用条件更新、事务锁或合适的队列协议竞争执行权，只有成功取得凭据的一方继续。Naumi 的 claim 在事务里按任务类别协调，结合条件 UPDATE、租约和共享活跃数量判断；不是仅靠本地 `running` 布尔值。

参考表达：“我把检查条件和授予执行权放在一个原子协议里。抢到任务后使用它返回的 token；没抢到是正常竞争结果，不是重新创建任务的理由。”

### L1—L4 追问

- **L1**：先读后写有什么窗口？要点：读取结束到更新之间被其他执行者穿插。
- **L2**：原子领取成功后保存什么？要点：归属凭据、期限和必要的执行上下文。
- **L3**：每实例并发上限为 5，三实例是否仍是 5？要点：局部计数可能变 15，需要定义并发约束作用域。
- **L4**：领取成功但执行者立刻退出呢？要点：交给租约和恢复，不永远锁死，也不盲目重放外部操作。

### 项目证据与验证

源码：[`claimImageJob`](../../../src/lib/image-job-repository.ts)、[`imageJobConcurrency`](../../../src/lib/image-job-queue.ts)。验证设想：并发 claim 仅有一个有效所有者，类别总额度不因实例数被重复计算。

### 边界与待追问

领取正确不等于外部副作用恰好一次。前置：HB-005。后续：HB-007、HB-008。学习状态：未评估。

## HB-007 旧 Worker 恢复后，为什么租约过期还不够？

### 现场问题

A 领取任务后卡住，租约过期，B 接管；A 随后恢复并准备写结果。允许谁写？

### 旧模型与反例

旧模型：“锁过期了，旧任务肯定停止了。”反例：锁存储只撤销执行权，不会自动终止旧进程或撤回已发出的网络请求。

### 基本事实与不变量

执行权是一份限时授权，不是进程存活证明。过期持有人不能覆盖新持有人的事实；心跳失败和任务最大耗时需要联动分析。

### 推导与参考回答

续租和写入核对 token 与有效期限；本地失权后停止继续推进。数据库在取得必要行锁后用实时数据库时钟重新确认租约，不能用过早计算的时间判断跨越锁等待后的有效性。

租约可以短于任务耗时，只要可靠续租并严格处理失权；不能机械要求租约永远大于最长任务。还要预算调度暂停、网络延迟、数据库竞争、心跳重试及恢复时间。

参考表达：“我区分超时接管和陈旧执行者隔离。租约让崩溃任务可接管，token 校验让旧执行者失去写入权；所有受保护副作用都必须经过对应权威校验，外部供应商要另外依靠幂等或身份恢复。”

### L1—L4 追问

- **L1**：租约到期能证明 A 死了吗？要点：不能。
- **L2**：心跳失败一次就永远停止合理吗？要点：区分短暂故障和已确认失权，有界重试不等于重试付费工作。
- **L3**：SQL 等行锁期间租约到期呢？要点：取得锁后重新判断；事务起始时间不等于当前时间。
- **L4**：随机 token 是否等于通用 fencing 序号？要点：这里是当前所有者匹配校验；不冒充所有外部资源都支持的单调 fencing 协议。

### 项目证据与验证

源码：[`assertLeaseTx`、`saveImageJob`、`heartbeatImageJob`](../../../src/lib/image-job-repository.ts) 与 [`startImageJobHeartbeat`](../../../src/lib/image-job-lease.ts)。历史验证见[租约隔离记录](../../changes/2026-10-29-capacity-x2-lease-fencing.md)。

验证设想：旧 token、过期 token、锁等待后到期、短暂心跳错误、接管后旧进程恢复。外部调用是否重复要另查付费检查点与供应商身份，不能只看 DB 更新行数。

### 边界与待追问

数据库拒绝旧写入，不能撤销旧 Worker 已发出的供应商请求。前置：HB-006。后续：HB-008。学习状态：未评估。
