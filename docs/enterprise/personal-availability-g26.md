# G26 团队内个人可用容量

## 目标和数据口径

延续18482原团队排期，在团队工作日历之外表达某位成员某一天实际可安排的小时上限。用于已经确认的半天占用、培训、休假或跨团队时间分配；本模块是排期容量配置，不是请假审批、考勤或工资依据。不读取或推测钉钉请假记录，不代填真实姓名或花名关系。

配置范围为企业+执行团队+稳定subject。只对该团队的个人容量生效，不冒充全企业人员空闲时间。同人在多个团队的容量仍独立显示，跨团队总产能分配需主管明确维护。原因仅在本人和当前团队主管可见，周排期只给出小时和“个人容量调整”，不泄露具体请假/健康原因。

## 算法与任务联动

- 日期为上海公历，例外总量最多366天，日期唯一、排序保存。单日上限0–1440分钟、15分钟粒度。0明确表示当天不可安排，不能当成缺省。
- 无个人配置时继承团队日历；个人例外是容量上限，当日有效容量=min(团队分钟,个人上限)。团队休息日仍为0，不借个人配置绕过工作日历增加加班。
- 已计划工时仍按团队日历在完整计划区间分摊，不因个人请假自动分摊到别的日期。原任务计划/截止/工时/状态/版本/验收不变。
- 周排期展示“已排 / 个人有效容量”，超量明确标色，提供团队标准、个人上限和个人版本。原有无工作日提示保留；没有任何计划的人员也可在个人容量面板维护，但不向周视图伪造任务。
- 可读跨团队任务使用实际执行团队的容量，不套用请求团队；只附带可读任务已有执行人的容量数字，不返回私人原因或整个团队目录。

## 权限与版本

有效成员只能读取本人设置与历史；manage/dispatch可分页搜索当前团队有效execute成员、读取/预览/发布该团队成员配置。前端角色与姓名不授权。目标账号、团队和execute成员资格在每次预览、写入以及幂等重放前核验，停用/过期后拒绝新调整。

017新增person_availability_versions：企业、团队、目标subject、revision、完整例外配置、commandId、fingerprint、操作者、原因、created_at。不可变版本追加；清空例外作为新版本，不删历史。全企业commandId唯一，重放同正文同主体返回原回执，变更正文冲突。

发布需expectedRevision、previewHash、commandId、reason。预览零写入，列出已变日期、已计划工时、调整前后容量、超载日期/任务数量。当前/目标各最多366个日期（差异并集最多732天）、5000项相关任务，超限明确失败，不截断冒充完整影响。hash绑定当前/目标配置、团队日历版本、相关需求ID及版本。实际保存重新计算，陈旧计划或日历要求重新预览；锁序为命令→目标容量→团队日历→需求，任务并发修改用现有需求行锁处理。

只允许本人或主管读取原因历史。重新分配或历史参与者仍能按任务权限查看有效容量数字，但不因此获得编辑目标人员或读取原因权限。

## API / 原UI

GET /v1/availability/members?query&page（主管）；GET /v1/availability?subject（本人/主管）；GET /v1/availability/history?subject&page（本人/主管）；POST /v1/availability/preview、/save。

原Naumi BFF actions=availability-members/availability/availability-history/availability-preview/availability-save；Naumi会话、企业/团队、viewer与同源写入规则沿用。原排期增加“个人容量”，主管选择成员，本人只读；日期/小时编辑→影响预览→明确发布；重读保留输入；清空恢复团队规则需预览确认。详情关闭、换号、换团队丢弃迟到响应，不缓存正式人员信息到本地存储。浅色布局，390px可用。
