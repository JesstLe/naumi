# G16 正式工作区原表与人员接线

## 目标与使用路径

保留 18482 原浅色产品界面。员工工作区选择企业、团队后，目录管理员从团队排期进入“原表与人员”：选导入批次 → 查看原行/原附件 → 明确确认父关系或真名/花名 → 按 G03 独立转需求草稿 → 提报/分配/执行。普通员工仍使用新建需求与自己的任务，不开放企业全量原表。

## 授权与事务

- 每次读取、下载和确认都重新解析当前主体、企业、团队、有效成员资格及 manage 权限，同时读取 enabled 的 person_directory_admins 企业授权。UI 按钮不替代服务端检查。
- 原生 Naumi 会话在 BFF 复核，使用短时签名向工作流传递身份；不采用浏览器指定姓名、权限或本机 local-owner。
- 父关系确认锁住活动批次与源行，校验 expectedVersion、候选父行、非空原因，在同一事务写版本和审计。重复旧版本返回冲突，不静默覆盖。
- 原 document、姓名、状态、日期、附件字节保持。父关系不生成任务依赖；人员资料不授予登录权限；来源转草稿沿用唯一性与幂等规则。

## 文件契约

可选 importRoots 显式按工作流企业 UUID 指向只读 blob 目录；缺少配置时元数据可读，文件返回 SOURCE_STORAGE_NOT_CONFIGURED。不创建、接管或复用交付目录。只用数据库校验过的 SHA256 定位文件，拒绝符号链接、越界、字节数/哈希不符。下载不代理原表外部链接。PNG/JPEG 验证签名后可预览，其余按附件；正式模式本轮读取原图，不依赖本机缩略图目录。

## UI 与多表

保留原表格/分组/看板/列样式组件，新增批次选择。切换批次清空源行、人员选择与抽屉；切换账号/企业/团队及授权撤销清空旧数据并隔离布局存储键。正式请求只走 /api/enterprise/workflow，附件走 /api/enterprise/workflow/imports；旧本机准备 API 仅用于未进入员工工作区时。

## 验收

隔离 PostgreSQL 覆盖：普通员工/无目录授权主管拒绝、跨企业/团队拒绝、权限撤销生效、多批次读取、父关系 CAS 与审计回滚、原文件 hash、未配文件根拒绝、停用批次拒绝、独立转草稿唯一性。BFF 检查会话、参数、同源写入与错误传播；原 UI 浏览器检查本机回归和正式来源界面。真实库只读复核 364 行、292 附件、129 链接与原 ZIP hash，不建立猜测映射。

## 实施状态

正式来源事务层、BFF、运行时和原 UI 接线已实现；集中验证与修正记录见下方，最终 Git 与副本回滚以本轮 VERIFICATION.txt 为准。真实员工登录配置、公司目录管理员授权、真实姓名对应关系及企业部署仍需实际配置，不以合成验收代替。

## 接口及配置

| 产品操作 | BFF | 工作流 |
|---|---|---|
| 批次列表 | GET workflow?action=imports-context | GET /v1/imports/context |
| 原行与附件目录 | GET workflow?action=imports-rows&source=HASH | GET /v1/imports/rows |
| 父关系确认 | POST workflow?action=imports-resolve&source=HASH | POST /v1/imports/resolve |
| 原文件 | GET workflow/imports?source=HASH&id=HASH&viewer=EMAIL | GET /v1/imports/asset |

以上均带 enterpriseId、teamId，实际源企业通过签名身份映射至工作流企业。viewer 仅用于校验当前会话是否换号，不是身份凭证；文件以当前会话及企业授权鉴权。文件返回 private/no-store、nosniff 与 sandbox，URL 不含长期 token。配置 importRoots 默认空字典，不自动采用本机真实文件。

```json
{"importRoots":{"WORKFLOW_ENTERPRISE_UUID":"/var/lib/naumi-enterprise/source-blobs"}}
```

示例 UUID 为待填写槽位。正式目录应单独只读挂载；运行时核对存在、可读、非符号链接且与交付目录互不包含，未初始化原表来源目录。正式模式预览 PNG/JPEG 原图；本机模式继续使用既有缩略图。整批行数沿用导入器上限 10000，界面按原分页组件展示；超大批次服务端分页与独立缩略缓存后续扩展。
