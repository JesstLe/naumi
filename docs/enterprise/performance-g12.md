# G12 贡献分摊复核与周期绩效

## 数据来源与权限

18482原贡献页继续使用同一任务事实。只读取workflow.task.accepted.v1不可变事件，不把Excel历史“已完成”或Naumi积分消费当验收事实。员工只看本人事实、分摊状态及已确认周期的本人结果；manage/dispatch/review可读当前团队复核资料。所有请求复核真实来源登录、企业、团队和实时成员资格。

## 分摊流程

单执行者且contributionBps=10000的事实保持100%；交接或未知分摊事实进入待复核。dispatch或manage提交分摊方案，参与者只能来自该验收事实的真实执行账号，百分比以整数基点存储，必须逐个填写全部参与者，允许明确0基点，总和必须10000，不按姓名猜人。review人员通过/拒绝；审核者既不是提案人，也不是贡献参与者。拒绝保留记录，可以新版本重提。更改已经批准的方案重新走复核，旧审计不覆盖。

已经进入确认周期的事实锁定分摊。离职/停用不删除历史贡献账号，也不将贡献转给同名新人；当前读取和修改资格仍实时检查。后续跨周期更正另建调整流程，不改历史验收与确认快照。

## 规则与计算口径

规则先草稿后发布，manage保存，另一名同时具备manage+review的人员发布。未发布配置不生效。规则版本永久保留，周期创建时显式选择版本，后续新规则不回算旧周期。

规则包含质量1–5档倍率、迟交倍率、每次返工扣减基点及返工扣减上限。所有倍率为整数基点，规则需人工显式保存和发布；无内置自动生效评分制度。

```
返工倍率 = 10000 - min(返工次数 × 每次扣减基点, 扣减上限)
任务计分毫点 = 四舍五入(计划工作量点 × 1000 × 质量倍率 × 及时倍率 × 返工倍率 / 10000³)
个人毫点 = 任务毫点按已确认贡献基点分配
```

使用整数运算；分配采用最大余数法，余数相同按稳定subject排序，确保个人合计精确等于任务总毫点。基础工作量同样按比例分配。及时性用最后提交时间≤承诺截止，而非验收人处理时间。返工次数和质量保留原事实，不允许在绩效页篡改。

展示本人参与任务数、及时任务数/比例、返工次数、分摊基础工作量和规则计分。多人任务在个人任务数中各记参与1次，这些计数不跨人直接求和；工作量/计分可以精确加总。没有薪酬系数、奖金发放、自动排名、自动奖惩或人员去留决定。

## 周期流程

manage创建周期，按上海自然日、验收事件发生日期归集，起止含首尾，最长366天。预览列出事实、已批准分摊、规则版本、逐项计算和阻塞项。待复核/事实不完整不会被默默跳过，确认必须全部可计算。

确认要求周期已结束、至少1项事实，操作者同时具备manage+review，且不是周期创建人或其中任何贡献参与者。确认带expectedVersion和previewHash；期间分摊变化、规则引用/事实集合变化、其他周期已领取事实均拒绝旧预览。每个事实在当前团队最多进入一个已确认周期，避免重叠周期重复计绩效。

确认将规则内容、事实输入、分摊版本、计算明细与汇总写为不可变周期快照；不再实时重算。草稿可作废，确认后不可删除或原地改写。员工仅能读取其本人快照，CSV与页面遵循相同范围并防公式注入。
