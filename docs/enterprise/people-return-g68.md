# G68 填写表回导与本机单人字段关联

## 目标与本轮结果

接收用户填写的姓名/花名表后，沿既有 G18 资料预览/保存和 G02 源字段预览/保存接口回导，不新增客户专属代码，不改原始 Excel、源行单元格、工作表或任务执行事实。

2026-10-20 本机已完成：

- 58 份人员资料，保留上一轮已经固定的随机 personId；source 账号元组全部为空，状态为未录账号。
- 675 个单人源字段关联，按 500 + 175 分成两批。字段精确匹配源行号、字段类型、源姓名原文与原版本；关联目标人员版本为 1。
- 14 个缺花名字段和 1 个多人字段保持未绑定。多人字段保留两个参与人候选，不将复合文本当成一个人或任意选择一人。
- 3 条实际命令、3 条审计；逐条以相同 commandId 与同一原请求重放，均返回 replayed=true，没有重复人员或绑定。

姓名资料与正式 Naumi 账号分开。两个暂未找到来源账号的人仍保存用户填写的姓名资料；不会猜测账号，不创建身份、团队权限或管理员权限。此前目录核对是某时点证据，不能代替员工实时会话与正式来源键配置。

## 执行路径

1. 核对工作树与本机进程、目标连接；仅允许回环数据库和明确的本机工作库。
2. 固定输入快照摘要；用户原表不修改。私有输出目录撤销继承，仅当前用户和 SYSTEM 可读写。
3. 完整 pg_dump 备份，实际恢复到新建的独立测试数据库；恢复后全库业务表与人员表状态一致。
4. 在副本通过现有导入 HTTP 服务完成资料/绑定预览及提交，测试命令重放。
5. 副本测试精准撤销，核验 0 资料/0 关联；保留原审计与幂等命令，另加一条补偿审计。再次撤销返回已完成。
6. 经原 18482 入口会话、同源与 CSRF 校验执行本机回导。每批使用即时 previewHash，不复用旧预览。
7. 回读全部 58 份资料、690 个源字段；逐项比较姓名、花名、personId、资料版本及绑定版本。96 张非人员表的行数与内容摘要前后完全一致。

## 回滚设计

保留完整备份，但默认回滚不回灌整库。精准回滚只撤销本次明确创建且状态未变化的 58 份资料和 675 项关联。执行时持人员目录事务锁，逐项核对当前完整记录、版本与计划后状态；出现额外关联、后续修改或其他业务引用则事务拒绝，不覆盖后续使用。

回滚保留原 3 条操作审计和 3 个幂等命令，追加补偿审计，记录被撤销的原命令 ID。原命令的 replay 表示历史命令已执行，不代表被补偿撤销的数据仍存在；需要重新导入时必须重新预览并制定新命令，不能把旧成功响应当作当前状态。

副本回滚已执行；本机工作库未回滚，保留已导入状态。测试数据库在回滚与重放验收后仅按本轮精确数据库名删除，没有停止或删除持久数据库容器、卷或其他测试环境。
