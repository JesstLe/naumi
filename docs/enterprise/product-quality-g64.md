# G64 企业工作表保存可靠性与产品差距

日期：2026-10-20。任务分支：`codex/enterprise-workflow-foundation-20261016`。

## 本轮目标

用户填写人员花名表期间，继续完善现有产品。以18482原产品Shell为唯一交付方向，不把Naumi `/admin`变为产品入口，不创建第二套企业代码，不应用未确认身份映射，不部署或连接47。

本机恢复检查发现18482 Web已随后台命令取消退出；18546既有数据服务仍存活。本轮仅恢复原Web并指向既有工作库，没有重跑会停止18494/18482的历史组合脚本，没有重复初始化数据库。

## 发现的问题

1. 原`sgSubmit`把第一次提交的指纹固定下来：确定未执行的校验失败后修改输入，也会提示关闭重开。
2. 原工作表CAS失败保留输入，但没有在表单内读取新版本、比较和合并的入口；用户依赖刷新会丢输入。
3. 原`sgCommand`把命令和刷新串在同一个异常路径中，写成功而读失败时界面未区分保存结果。
4. 普通单元格、整行和字段表单直接关闭没有未保存提醒；G62 Excel已有独立保护，应保留而非替换。
5. 本机来源请求没有前端时限，网络悬挂时表单可能持续等待。

## 产品行为与实现

### 保存状态机

`ready → saving → saved → loading → closed`。确定拒绝进入`rejected`，版本冲突进入`conflict`，断网/超时/5xx进入`unknown`。请求不自动重发，成功之后只有读刷新。

- 400/401/403/404/413/422/429等确定拒绝允许修正输入，下一次使用新命令ID。
- 网络错误、408、5xx及幂等指纹冲突不猜测未提交，固定原命令ID、版本和完整输入，锁定表单；用户点击“按原命令重试”后由后端幂等记录返回结果。
- 已收到写成功，只是刷新失败时明确显示“内容已保存”，操作仅重试GET。
- 本机来源fetch增加30秒AbortSignal；超时归入结果未知，而非创建新命令。正式工作流通用请求时限未在本轮改动。
- 来源错误保留原始机器码`error.code`，避免中文错误消息破坏冲突分类。

### 三方比较与合并

保留打开时的工作表快照、当前输入、独立GET读到的最新快照。仅对普通文本/日期/数字的`set-cells`提供合并：

- 未修改本次字段的并发变化：提示用户基于最新版本重试，保留其他人的字段。
- 同一字段发生不同修改：展示“打开时／最新内容／我的输入”，每个冲突字段必须显式选“最新内容”或“我的输入”。没有默认覆盖。
- 父记录修改单独比较；可显示关联名称，后端仍重新检查有效父项和循环。
- 行删除、字段删除/结构变化、附件修改和结构性命令不提供自动重基，保留输入并要求重新核对。
- 重新提交仍经过服务器CAS；核对后又有别人修改，重新进入比较，不绕过版本校验。
- 比较GET不更新后台列表的本地快照；取消比较不偷偷改变工作表版本。

### 离开与数据处理

普通表单关闭/替换/页面刷新在有修改时提醒；正在保存或核对时阻止误关。结果未知的离开提示明确说明会失去当前窗口的重试信息。工作空间/身份切换清除当前编辑上下文，不把甲企业草稿带到乙企业。

草稿只在当前窗口内存保存，不写localStorage/sessionStorage，不自动绑定任何真实员工。明确放弃或浏览器进程崩溃后的跨重启草稿恢复尚未实现。

新增`sheet-save-model.js`、`sheet-save-ui.js`和局部浅色样式；原Excel预览/Office保存协议、附件存储、后端权限和数据结构保持。本模块没有数据库迁移。

## 验收及证据

新模型覆盖33项边界。新增双独立浏览器会话测试覆盖三方对照、不同字段合并、逐项混合选择、二次CAS竞争、已提交后丢响应的原命令重放、确定拒绝后修正、只重试读取、未保存离开、已删除记录保护、390px、原来源不变及pageerror。

现有G58工作表测试同步更新新冲突面板定位和明确确认放弃，不放宽数据、权限或版本断言。G60原测试曾直接关闭已填表单，新增离开保护正常阻止该动作，导致后续点击被弹窗遮挡；更新测试为明确确认放弃，未删除离开保护。

集中最终结果：新模型33项、双会话保存23项、G58 CRUD 29项、G60懒加载27项（包含5000行合成压力与观察器清理）、G62服务58项与Excel轻编辑28项、完整release-check通过。具体运行与退出状态见VERIFICATION。实际18482只读验证单独执行，不在真实工作库写测试记录。

验收使用一次性PostgreSQL和独立无头浏览器，不附着普通Chrome。T3协作浏览器snapshot连续两次返回`Preview automation snapshot timed out after 15000ms.`后，沿用仓库已记录的隔离浏览器工作流。

首次新UI验收的审计断言错误地假定HTTP历史返回command_id。实际端点只返回version/subject/operation/detail/created_at；修正为“目标行、唯一保存内容和版本只增加1”组合断言，保留原失败日志。
