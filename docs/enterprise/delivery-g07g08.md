# G07/G08 交付文件、返工与验收

## 契约

沿用原18482任务详情和同源员工工作区。执行人仅在active/in_progress任务上传文件；每次选择文件产生新asset UUID与不可变版本，重试复用该UUID。文件名仅显示，不用作磁盘路径；后端计算SHA256、字节数。上传成功仅候选文件，不改变进度和任务状态。员工选1–30个本任务文件并填写说明提交交付，任务进入review；具有review权限且非执行人的验收人填写原因退回rework，或填写1–5质量等级和意见验收。返工后须重新开始制作；旧文件/原提交事件保留，新提交显式选择版本。全任务验收后需求completed。

## 存储与权限

- 独立工作流文件根目录，不复用Naumi生产媒体目录。原始文件按企业+内容SHA存储；数据库保存UUID、order/task/uploader、version、name、sha256、bytes、createdAt。禁止覆盖/删除既有版本接口。
- 32MiB单文件上限、单进程最多2个流式上传、2GiB默认企业文件字节配额（构造配置可调）。不把完整文件放入JSON/base64或数据库。超限、无效名称、无权限、版本冲突、断流均明确失败；前后复核权限，上传完成时同订单锁检查当前状态。
- 暂存文件随机名，只在本次上传finally清理；落盘后元数据/审计同事务。最终内容文件不在事务错误时盲删，避免未知提交状态误删；未引用内容需后续离线盘点清理，本轮不清生产介质。
- 下载每次经Naumi会话→源企业→工作流团队/需求权限校验，记录下载审计；固定application/octet-stream、attachment、nosniff、private/no-store、sandbox，无公共文件URL/静态直读。读取校验字节及SHA，损坏不交付。
- 提交交付在业务事务内核对所有asset归属企业/当前需求/当前任务，禁止借用其他任务文件；validateAssets扩展order/task上下文。文件磁盘缺失或校验失败拒绝提交。验收前同样验证当前提交文件，贡献事件仅成功验收产生一次。
- BFF二进制上传限额、同源、账号变化前置条件及流式转发；文件下载转发当前已鉴权响应，不暴露内部令牌或路径。

## 运行接线

正式独立工作流服务使用同一工厂，传入已验证身份解析器和文件目录：

```ts
const delivery = new DeliveryStore(pool, resolveDatabaseActor, FILE_ROOT);
const workflow = new WorkflowStore(pool, resolveDatabaseActor, delivery.validate);
const server = createWorkflowServer(workflow, authenticate, scheduling, identity, people, delivery);
```
