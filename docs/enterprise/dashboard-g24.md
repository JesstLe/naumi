# G24 正式员工工作台

## 现状与目标

G23后正式任务、排期、交付、绩效各自可用，但原工作台仍被员工工作区占位页拦截。本模块沿用18482原HTML布局补齐真实首页，不改成/admin后台，不增加另一套任务状态或浏览器业务库。

## 页面结构与口径

1. 现有员工身份、企业、团队选择器保持；未选择团队展示选择提示，不展示演示数字。新建需求仅有request权限时显示，复用既有草稿表单。
2. 四个统计卡：待分配/确认=open或assigned且需求active；执行中=claimed/in_progress/blocked/rework且需求active；待验收=review且需求active；已验收=持久任务accepted（保留历史已验收事实，取消或归档不抹去既有验收）。没有真实任务时为0，不生成假趋势、完成率或绩效金额。
3. 当前可见/我的任务切换只改变任务统计与概览；我的任务指当前执行人或待交接接收人。权限范围始终沿用任务中心的canRead/readScope，不按花名、浏览器角色或跨团队角色并集扩大范围。
4. 任务概览支持全部/待安排/执行中/待验收/已验收/逾期/今日到期筛选，最多展示8项并显示匹配总数，按截止时间/需求ID/任务ID稳定排序。所有统计独立于分页，禁止从前30条累加。概览统计仅执行中需求及已经accepted的持久任务；未发布方案和取消后的未验收任务不计入四卡，未发布需求从待办进入。
5. 待我处理独立按当前操作者职责计算，30条分页：本人草稿、执行团队待受理/拆分发布、可认领/本人待确认/待开始/制作/阻塞、独立评审、待我接收交接、运营签收。前置未验收时不列为可认领/待开始；任务参与者不列为独立评审/签收；交接中冻结其他任务操作。点击只打开原详情，不自动执行业务命令。是否可最终提交仍由既有服务端状态/附件/路由校验裁决。
6. 临期与逾期按服务器时间判断。今日范围固定Asia/Shanghai自然日，逾期仅统计active且未accepted任务；不修改承诺交付日期。
7. 最近动态只读当前可见需求的真实事件，展示最多10条类型/操作者/时间/所属需求，省略原始提示词、正文和附件URL。我的任务模式只取本人操作或当前本人任务的事件；任务已从方案移除时打开所属需求，不跳不存在的任务。

## 数据与一致性

新增GET /v1/dashboard及同源BFF action=dashboard，参数scope=all|mine、queue=all|pending|running|review|accepted|overdue|today、todoPage。无额外数据库迁移。

一个REPEATABLE READ事务内解析实时身份、执行授权范围过滤、完整SQL聚合、有限列表及事件查询，响应返回asOf和timezone。统计和列表来自同一快照；不持有整个公司订单行锁，不拉取全量需求正文到浏览器。既有身份FOR SHARE锁不兼容只读事务声明，因此事务只执行SELECT但不声明READ ONLY。并发快照冲突返回可重试状态，不伪装成空列表。

页面切换企业/团队/账号或离开工作台后丢弃旧请求；刷新中展示加载态，不将旧企业数字留作当前企业数据。服务错误展示明确错误和重试，不回退演示数据。停留工作台时关闭详情或完成操作后重新读取；新建需求沿用既有表单保存后进入需求中心，返回工作台时重新读取。

## 验收清单

- 超过30项真实测试任务仍有完整计数；统计/队列分页和空页总数一致。
- 员工、主管、评审、需求方、跨执行/来源团队、跨企业、停用/撤权、同名资料不影响权限。
- 前置、交接、返工、取消/归档、独立评审与运营签收规则；不产生任务事件、绩效或来源写入。
- 服务器上海日期边界、逾期边界、0数据、我的任务筛选；同一快照一致性。
- 原UI四卡/待办/详情跳转/切号清空/错误重试/390px；同一固定HTML与原演示入口并存。
- 独立PG、原生会话BFF、固定运行包、真实Next组合与代码副本回滚；真实364行/292附件及0人员映射/0正式需求保持。
