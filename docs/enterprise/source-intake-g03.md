# G03 来源转需求与需求中心

## 业务契约

原团队排期保留为来源资料；需求中心增加“真实需求”模式，不替换演示数据。人工选择某一源行，确认标题、需求说明、验收标准后创建 draft。创建者是实际请求主体，本机适配器显示 local-owner / 本机项目管理员，不冒用 Excel 需求方。源表已完成、日期、设计师、数量不会自动成为执行记录、工时或绩效。

来源唯一键为 enterprise + sourceHash + row；同一行至多建立一个需求。源行版本参与乐观锁；表批次停用后不接受新转换。首次转换必须明确勾选“只转换本行为独立需求，不继承父子关系、人员、状态”。父关系无论是候选还是已确认均作为溯源快照，不建立业务依赖。未来整组转换使用独立契约。

## 权限与事务

转换要求 request 与 manage 两个权限以及显式企业级 person_directory_admins 授权（团队管理员不自动获得整批来源权限）；正式服务通过 G01 当前账户/团队绑定校验，浏览器角色无权授予能力。本机预览单独固定主体，仅用于管理员准备及需求受理，不授予 execute/review。普通员工使用新建需求命令而非读取整批导入资料。任何读取必须满足企业、团队与领域 canRead。

命令、需求、事件、来源引用同一事务提交。commandId 防重放，sourceHash+row 唯一约束防止换命令重复转入，expectedVersion 防止覆盖修改。请求超时保持同一命令重试；正文变化时更换命令号。失败保留表单。源批次与源行加共享锁，所有转换按 command→order→source 顺序加锁。
