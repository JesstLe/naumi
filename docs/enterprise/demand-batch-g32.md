# G32 需求复制与批量建单

## 场景与范围

运营复用历史需求制作下一批商品图，或一次录入同活动的多条需求。入口仍为原需求中心，单条复制与批量创建使用同一服务端合同；只生成草稿，不跳过提交、路由、审批或认领。

请求体上限512KiB，服务端派生预览快照上限2MiB。一次1—20条，采用**整批原子提交**：预览显示每行问题；任一行有误、来源版本变化或写入失败，整批不产生需求、事件或回执。没有“部分成功再盲目重跑”的中间状态。大规模导入继续沿来源确认流程，不把此编辑器当Excel迁移器。

## 输入、可复制项及不继承项

每行包含稳定orderId、新标题/需求说明/验收标准、可选routingFields；复制时另带copy={orderId,version,includeForm,includeCatalog,includeRouting}。原单业务文字先填入编辑器，可逐条改写。三个复制开关默认关闭，确认后由服务器读取原单，不接受客户端表单或商品快照。

- 来源须同企业且当前账号可读，来源提报团队必须等于当前团队；有request权限才可创建。承接团队看见一张单不自动取得原提报团队的复用权。
- 选择复制表单时，沿原固定发布修订和字段值，重新核验模板有效、当前团队、值类型；必填可待草稿完善。旧模板停用则该行报错，可取消勾选后重新预览。
- 选择复制商品时，重新核验店铺范围、四实体有效性及原引用版本。目录变化报错，不暗中换最新商品。
- 复制路由字段只复制业务输入，不复制路由决策或原承接团队；新单提交时重新匹配当前规则。手工routingFields与includeRouting不得并存。
- 新单提报人是当前账号，提报/当前团队是当前团队，状态draft，version=1，tasks=[]，时间为实际创建时间。
- 不继承任务、执行人、进度、审批/路由结果、验收/贡献/绩效、交付、Naumi作品/扣费关联、原Excel行确认或来源附件授权；附件需后续独立选取并检查。复制来源仅是可审计关联，不赋予原单读取权。

## 预览与提交

POST /v1/demand-batches/preview接收{batchId,entries,reason}，只读返回可创建数、逐行错误、选定复制项与未继承项、previewHash。预览哈希绑定当前身份/团队、规范化输入和服务端实际派生的草稿内容；不依赖客户端声明。

POST /v1/demand-batches/apply增加{previewHash,confirmed:true}。事务内重新检查身份、来源和目标ID并锁定；同批ID和身份/正文/hash重放返回原回执，不新增需求。变更正文/哈希要求新的批ID；陈旧预览拒绝并保留输入，重新核对后确认。已成功批次即使来源后续变化也可读取原回执，但只能返回当前仍可读的新单摘要，不绕过撤权。

GET /v1/demand-batches?action=list|detail为本人、当前团队、当前来源身份的回执列表/详情；以稳定批ID恢复结果。列表30条分页，空页仍返回总数。回执不是订单当前状态；返回createdVersion与当前状态分开。没有服务端未提交草稿列表：浏览器编辑内容不写本地存储，关闭前明确提示，重开已提交批次通过回执恢复。

## 锁、数据及兼容

021新增demand_creation_batches，仅记录成功批次；订单与事件沿既有表。batch锁→按UUID排序的所有来源/目标order锁→表单团队锁→商品企业锁。新单通过既有evolve(create)生成并在同事务插入；每单固定命令ID派生自批ID+orderId并写commands，避免绕过标准命令回执。事件增加批ID、原因、选定复制范围和来源ID/version；不改原单。

这次是附加表/附加信息，不引入旧程序不能解释的状态或约束。读取/写入兼容下限不因schema21增加，旧20普通草稿读写语义保持；新API要求实际21迁移，旧8拒绝新API。运行配置demandBatchEnabled默认false，独立打开此API，不隐式启用表单/商品。若选择复制表单/商品，其原feature门禁仍生效。需检查实际20固定程序在隔离21库读取和修改新草稿，不以版本号推断兼容。

## 原页面交互

需求中心“批量新建”、需求详情“复制需求”。编辑卡片提供添加空行、复制当前编辑行、移除、标题/说明/验收/路由字段以及可用复制开关；最多20条。预览确认前不得生成订单；确认页显示逐行问题，返回编辑保留输入。提交期间冻结正文，响应未知时仅重试原请求或按批ID查回执。403/409/503分别反馈，关闭/换团队/换号丢弃迟到响应。成功页逐条打开新需求，回执支持重开；手机单列布局。

## 验收与剩余项

验证1/20/21行边界、重复ID大小写、非法正文/额外快照、无权限/跨团队/跨企业、源版本变更、模板停用/商品过期、0/false隐藏值、原单完全不变、不继承事实、未知响应幂等、批ID冲突、目标ID冲突、事务注入失败、并发单赢家、回执撤权和分页；真实BFF/原UI/固定运行/Next组合/旧20兼容。真实库不迁移，真实姓名与花名不自动推断。

本轮聚焦复制/批量建单，不缩减整体目标。需求新上传附件与模板附件规则、批次跨团队分发、超过20条的异步编排及真实公司模板确认仍是后续工作；不把复制历史来源字段变成原Excel重复转单通道。

## 集中验证修正记录

G32开发集中回归发现G31旧测试将并发第一个请求误当必然赢家；服务端正确拒绝了输家重试。测试改为选取Promise.allSettled实际成功命令再核验重放，保留单赢家断言，未放宽CAS。首次BFF测试把没有request权限的员工预期写成404，实际先检查提报权限返回403；按接口权限顺序改正断言，未修改业务门禁。失败日志保留在本轮输出目录。
