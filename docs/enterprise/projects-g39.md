# G39 活动项目、阶段里程碑与需求组合

状态：本地实现与集中验收完成，固定交付收尾中。对应M04；18482原页面、同一主干、多企业隔离。项目不是画布项目。真实schema8/原Excel不迁移，真实身份不推断。

## 1. 场景与结果

运营为大促、新品或品牌升级建立项目；多个团队分别关联原需求，项目负责人按阶段查看已承诺/已验收工作量及缺口。一个原需求在同项目只出现一次；跨项目复用是引用，不写第二份任务、贡献或积分事实。项目移除引用不删除原需求。授权撤销后所属团队管理员可按团队显式移除失效引用，无需返回隐藏的原单ID。项目改期只改变项目基准与影响提示，不直接改任务截止/排期。

## 2. 对象与字段

028 projects/project_commands/project_revisions：企业唯一code（ASCII大写，2—40字符）、项目UUID、title/brief、ownerTeam/ownerSubject/createdBy、version、状态planning/approved/active/retrospective/archived、milestones、grants、links、archiveSnapshot。

- milestone：UUID、title、targetAt（显式ISO时间）、critical、dependsOn（同项目无环图），最多30个，移除被引用或被依赖阶段须先明确调整关联。
- link：orderId、milestoneId可空、teamId（关联时提报团队）、linkedBy/At。最多300个；每个原需求只能对应一个阶段，移动阶段是明确变更，不复制。
- grant：目标团队UUID、state invited/approved/revoked、邀请与同意/撤销人员时间。最多50组。邀请不授予原单据权限；双方批准仅允许共享项目元数据与其关联需求的**数值进度**。
- archiveSnapshot：显式归档时的数值汇总和依赖/期限基准；之后原业务变化显示liveChanged，不改归档快照。重开仅owner团队manage+review、原因、版本确认。

## 3. 权限与双向授权

owner团队当前有效成员可读项目。owner团队manage创建/改元数据/阶段/邀请/生命周期；planning→approved须另一个manage+review且非创建人核准。任意有管理权限不等于跨企业管理。

其他团队只在同意邀请后看项目；未同意的团队主管仅看到邀请卡片（项目名/业务号/邀请方ID），不得看brief/阶段/单据。目标团队manage批准，明确共享项目元数据及原需求的数值进度；owner或目标manage可撤销。过期成员/禁用团队不绕过授权。

关联必须当前团队已获准，当前request/manage/dispatch，原需求提报团队等于当前团队且canRead成立；其执行路由可能在其他团队，仍引用原需求。原订单不可见时不返回ID/标题/任务明细/店铺信息。项目成员资格不授予原单据查看、执行或附件权限。批准的团队授权只提供汇总进度；撤销/失效后相关引用保留为unavailable数量，不泄露原状态或隐含总工时。

## 4. 流程与计算

planning→approved→active→retrospective→archived。active→retrospective需当前快照全部关联需求已交付、关键阶段有需求且依赖就绪，无失效授权/未分阶段需求；不能用99%任务数替代全部就绪。零分母ratio=null；draft/submitted/approved不计承诺量；active/completed计任务points；archived/cancelled保留已accepted事实点但取消未完成工作不算承诺，取消需求仍阻碍就绪。

阶段汇总：已承诺点、已验收点、比例、需求数、未完成/阻塞任务数、未规划任务数、逾期风险、依赖阻碍。百分比按points，不按文件或任务数量。阶段targetAt不覆盖原dueAt/planEnd。无明确工时不猜时长，不把里程碑DAG叫作工时关键路径。

所有写操作先preview，返回完整变更摘要、当前项目版本、相关单据版本/数值影响及previewHash，再confirmed执行。确认时锁定项目并重读授权与关联单据；任一原单变化则409重预览。旧请求同commandId重放，不重复生效；撤权后不重放敏感回执。

从项目创建需求：项目内明确填title/brief/acceptance、选阶段，原生evolve(create)同事务生成draft和正式事件/命令，随后关联；不自动审批/拆任务/复制历史事实。该事务失败全部回滚。模板批量生成继续使用既有G32，先人工建单再显式关联；完整批量项目模板后续实现。

## 5. 接口与UI

GET /v1/projects list/detail/history/invitations；POST /v1/projects preview（只读）或apply。BFF /api/enterprise/workflow/projects沿原生登录、来源身份、同源/viewer、请求限流、256KiB体积门限。

原需求中心/任务中心/排期增加“活动项目”，轻量卡片显示状态/业务号/负责人/已验收点。详情阶段和需求分开展示，可见单据打开原详情，其他仅汇总。创建/编辑、阶段调整、关联/移除、项目新草稿、邀请/同意/撤销、状态变化均先预览再确认；未知响应冻结命令原样重试。390px单列、表格内部滚动，关闭/换团队/换号失效迟到响应。

## 6. 事务与兼容

锁顺序command→project→相关order UUID排序，项目草稿创建使用与原工单相同的order锁和正式evolve事件；原工单命令不获取project锁。项目code企业级唯一；事务内回执、project更新、revision原子。projection按当前权限过滤所有旧修订的关联细节；用户历史仅展示项目元数据/变更原因，不外泄隐藏原单。

projectsEnabled默认false；schema28附加表，不抬升原26WIP门禁；实际旧27程序读取/修改原工单不会改项目快照，需集中实测。真实库缺迁移503，不自动迁移。回滚只做源码副本，不回灌项目、原单、附件。
