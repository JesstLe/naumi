# G40 品牌规范版本与冻结检查清单

状态：本地实现与集中验收完成，固定交付收尾中。沿M14原蓝图，连接M03目录、M05需求与M16交付评审。原18482 UI为唯一产品；真实schema8、原表和身份映射保持。不是自动法律判断，不把供应商标题或未审文字当作授权事实。

## 1. 规范对象与版本

规范册绑定同企业品牌目录ID与维护团队；书名/渠道、品牌说明、色值、字体、经人工核准的表达/限制表达、来源说明、有效起止、检查清单组成发布定义。每版最多10条检查项，每条UUID+文字+mandatory；至少一条mandatory。渠道为明确场景文字，非推断平台真实规格。来源说明是维护人提供的查证线索，不代表附件字节或权利已经机器验证。

029新增guideline_books、guideline_versions、guideline_commands。草稿可修改，已发布JSON永不覆盖；撤回只写版本独立revoked/withdrawnBy/At/reason。旧发布可复现；新版本不替换已选需求。brandId创建后不可改。validFrom含边界，validUntil排除边界，null表示明确未设置结束；到期/撤回版本保留可读但禁止新选用、需求提交、评审批准和正式验收。

## 2. 权限与独立发布

维护须当前团队manage+企业catalog_admins显式enabled；发布额外review且非该草稿作者。两人角色当前有效，作者/发布者/来源/理由写入发布快照。仅已发布定义向普通成员显示，不泄露草稿标题/内容；另一团队不列出本团队规范库。跨团队执行只能从其有权读取的需求/评审中查看冻结规范，不因路由获得整个源团队规范库。

## 3. 原需求联动

新增原工单命令set-demand-guideline，只有草稿提报方request及本人或manage，选择{id,revision}或显式清空。服务端从已发布定义生成快照，校验当前品牌目录enabled及order.catalog.brand.id完全一致；记录before/after事件，同原单版本/CAS/命令事务。

提交需求重验版本未撤回/有效期/品牌一致。商品目录变更造成不匹配时拒绝提交，须明确换规范或清空。复制/批量建单、项目新草稿、运营后续单不自动继承旧规范；执行中不静默换版。影响查询仅列出当前调用者可读的引用单据，按版本分页；过期/撤回不改历史accepted事实。

## 4. 评审强制检查

采用规范的需求任务必须结构化评审，不能走无评审的直接验收旁路。创建轮次时服务端把冻结规范清单与用户补充检查合并（合计最多20条，ID相同但label不同拒绝），保存冻结规范及requiredCheckIds。mandatory条目必须pass，不能通过na规避；可选项仍按原评审备注规则。

评审approve及原accept-delivery事务重验规范快照hash、品牌、撤回与有效期，并核对本轮requiredCheckIds及冻结版本；只看客户端结果不算通过。历史轮次/决定不自动改写；当前规范失效显示阻断。退回changes、问题讨论允许继续以便整改，不把规范失效变成全流程无处可退。

## 5. 页面

原需求中心/素材页提供“品牌规范”；列表、草稿编辑、独立发布/撤回、固定版本内容、影响单据/历史。字段以文本、色值、有效期和逐行检查项编辑，不要求用户写JSON。需求详情显示冻结版本，草稿可选取/清空，执行阶段只读；任务详情可看采用规范；评审清单自动包含规范项并标记必过。

未知写入响应保留原commandId及冻结内容重试；关闭/切号/换团队丢弃迟到响应。390px单列、表格内滚。正式登录未配置仍显示原配置状态，不代入测试账号。
