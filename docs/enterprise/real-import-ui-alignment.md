## 用户问题与实现

上一版真实数据入口采用原始数据平铺，缺少演示排期的层级、样式和布局交互。本轮仅改展示层，继续使用原18482入口和已导入的PostgreSQL记录；不重新迁移、不修改状态/人员/日期/父关系。

- 直接复用sc-sheet/sc-table/sc-parent/sc-child-line/sc-sticky/sc-designer等原排期CSS结构。固定首列和表头、56px标准行高、46×39缩略图、头像和状态徽标、浅蓝需求方列/浅黄附件列保持同一套视觉。
- 总表按父记录+制作子项展示。已人工确认使用明确关系；唯一名称候选使用“候选关联”标识，只形成临时展示树。23个歧义不自动归并。364源行在全量投影中各出现一次。
- 每页12个树分组，不把一组子项拆到不同页；设计师/需求方分组保持40行分页。搜索只命中子项时展示其父上下文，不将上下文计为新增源行。
- 折叠/展开仅隐藏显示；全局筛选数量不受折叠影响。空名称、缺字段和待核对记录保留。
- 看板增加源状态、人员头像、父名称、源完成日期和核对入口。没有根据展示名称伪造完成/验收事实。
- 编辑布局：列顺序、显隐、宽度、别名、底色、行密度；名称列固定；支持恢复默认显示。浏览器独立键`naumi-enterprise-source-layout-v1:<sourceHash>`仅存布局，不含源记录，不写演示任务/排期配置。
- “保存本机布局”明确非团队发布；刷新恢复本机设置。布局解析失败保留原配置并提示，采用默认临时显示。
