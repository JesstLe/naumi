## 本轮执行边界

优先G01：源账号不是Excel姓名。用户补充：真实Excel使用真名，Naumi使用花名，真名↔花名对应关系后续人工提供。采用`sourceInstanceId + sourceEnterpriseId + sourceSubject`稳定元组；显式绑定到工作流enterprise/team/subject，数据库每请求核验账号/团队/角色，角色不从源名称或前端下拉框推导。源端实时授权仍独立核验，工作流绑定不扩大源数据可见范围。

### 真名与花名映射

Excel原始姓名→内部person/subject ID→Naumi稳定账号键(email+instance+enterprise)，realName/nickname只是展示属性，花名更改不改变身份。映射按原批次+源行+人员字段保存，防止同名人员一键串号。确认界面并列真名、花名、账号标识、企业、团队；同名/一人多账号/停用/未匹配单列。批量操作先显示影响行与候选，人工确认后才写入；不因姓名相似自动开账号、指派或计绩效。改绑需要版本校验、原因和审计；解绑保留历史。

用户尚未提供的对应关系保持待绑定，不将其作为整套本地开发停工条件。G02实现映射操作界面和导入契约；本轮G01提供稳定账号与业务身份桥梁，原364行姓名原文保持。

复用Naumi现有登录，不建立一套客户分叉账号密码系统。来源与工作流数据库独立，真实企业ID、签名密钥和连接配置未绑定前返回明确配置/绑定状态，不能以合成企业验收替代真实接入。测试使用独立PG和合成已验证来源身份。
