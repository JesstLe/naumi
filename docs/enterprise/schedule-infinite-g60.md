# G60 团队排期连续滚动与懒渲染

## 用户需求和交付边界

用户要求团队排期支持“无限下滑，懒加载”。本轮在原18482入口的可编辑真实工作表实现；不连接或发布47，不启动企业服务，不改源Excel、账户映射、数据库模式、任务状态或验收事实。演示任务仍保留原视图。

本轮是**前端记录分批渲染 + 图片原生懒加载**，不是后台游标分页。工作表接口仍一次读取完整文档，以保持现有版本CAS、全量筛选排序与父子上下文正确。当前364行适用；5000行测试仅证明首屏与追加DOM行为，不是4核8GiB线上容量证明，也不代表任意规模数据已经虚拟化。

## 实现

- `SG_BATCH_SIZE=40`，去掉上一页/下一页，首批显示40行；距底部240px时由IntersectionObserver触发，下一帧仅追加40行。到底显示已全部显示，不无限重复请求或造空行。
- 总表、设计人员分组、需求方分组共用同一投影。批次之间保留父子顺序和分组标题连续性，不重复分组标题。
- 看板每列独立首批40卡，独立滚动/追加，不一次渲染整列记录。
- 图片保留 `loading=lazy` 并加 `decoding=async`；尚未追加的行没有图片DOM，不提前创建全部图片节点。
- 行片段通过DocumentFragment追加并绑定单元格/图片/行菜单/折叠事件，不调用整页shell，不替换已有节点，不打断编辑弹窗和未提交输入。
- 顶部显示已显示/总记录数，底部显示加载/完成/失败重试状态；手动继续加载兜底，无IntersectionObserver时用被动scroll事件兜底。正在加载的同列拒绝重复触发。
- 筛选、搜索、排序、模式、折叠或来源变化重建加载窗口；筛选排序始终作用全部记录。相同条件下的保存重绘保留已加载数量与纵横滚动位置。
- 视口高度根据可见区域计算，固定表头与横向滚动保持，390px手机横向溢出限定在表格内部。
- 页面切换/重绘/工作空间清除均断开观察器、移除scroll/resize监听并取消待执行帧，通过generation校验拒绝失效回调。
