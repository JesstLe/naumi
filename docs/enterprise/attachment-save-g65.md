# G65 附件关联可靠保存与版本保护

日期：2026-10-20。分支：`codex/enterprise-workflow-foundation-20261016`。

## 目标与发现

承接G64，完善团队排期中的普通附件与产品图管理。产品入口仍为18482原界面。本轮不应用人员映射、不连接服务器或发布、不迁移数据库；既有真实工作库和来源文件保持。

原附件弹窗有四个具体缺口：保存提交的是打开时的整份引用列表；上传/移除后重建整个弹窗，焦点与表单状态容易丢失；保存失败后不能像普通单元格那样分类恢复；来源选择跳到另一个弹窗，未保存附件和Excel编辑之间缺少明确的进入条件。

## 交互与合并规则

1. 上传、移除、来源附件搜索/勾选留在同一个弹窗内，草稿只在当前窗口内存保存。桌面弹窗扩大至780px上限，移动端内部滚动，长文件名换行。
2. 引用以`kind+id`识别，文件名与`excelRevision`作为版本内容。不同文件新增取并集；只应用本窗口明确的移除，保留同事新增或更新的未触碰文件。
3. 提交遇到CAS冲突后，读取最新快照并给出核对入口。没有冲突的集合变更也需要用户点击确认后才重试，不自动发送合并写入。
4. 同一个引用发生“移除与新版本”“两个不同编辑副本”等竞争时，显示打开时、最新版本、我的变更。每项显式选择后才能保存。显示短版本标识，完整引用保持在命令中。
5. 合并后超过50个附件、引用重复、字段结构变化或行已删除时保留当前输入并提示核对，不以整份旧数组覆盖。
6. 关联请求结果未知时，固定`commandId/expectedVersion/action`并锁定列表，按原命令重试；明确拒绝后允许修改列表并使用新命令；已保存但读取失败只重试GET。
7. 上传进行中阻止误关与刷新。上传响应丢失不虚构引用，提示重新选择同一文件，复用服务器按内容去重；上传与正式关联仍是两个步骤。
8. 有未保存的附件列表变更时，先保存关联再进入Excel预览/编辑，避免在尚未关联的文件上编辑后失去入口。已保存的Excel仍可直接内嵌查看、轻编辑和返回附件管理。

单文件4MiB、每格50个、附件下载权限和服务端配额保持原规则。移除仅解除关联，不删除原文件、既有副本或审计记录。

## 实现

- `sheet-attachment-model.js`：纯集合三方比较与逐项解析，输入和原命令不变；最终写入仍由服务器CAS/授权/校验负责。
- `sheet-save-model.js`：文本字段继续原规则；附件字段独立生成`filePlans`和冲突选择，不把数组转成文本再比较。
- `sheet-save-ui.js`：支持自定义草稿快照、合并结果回填、动态控件锁定和上传忙状态；不创建第二套保存命令协议。
- `sheet-attachment-ui.js`：一个附件管理组件。原`sgAttachments`只做委托，删除旧实现，避免并行维护两个上传表单。
- `sheet-save.css`：附件弹窗、搜索、长文件名和移动端局部样式，不改其他页面。
- `verify-sheet-save-live.mjs`：原入口只读验收同时验证新附件组件和来源选择，无POST。

## 明确区分Excel能力

本轮完成的是**附件集合和Excel版本引用的保护**，不是工作簿单元格级自动合并。G62原生轻编辑功能、G63完整Office适配器保持：Excel编辑中的结果未知恢复、不同工作簿单元格合并、完整Office真实工作库激活和长期并发仍是后续工作。本轮没有启动Office适配器或更改原Excel文件。
