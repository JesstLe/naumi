# G69 多人源字段归属

## 需求与产品边界

一个原表人员字段可包含多个人。保存一个字段的完整参与人列表，而不是选择其中一个人代表所有人；原字段内容不修改。参与人关联不等于任务执行分工、工时、绩效、登录身份或权限。本轮不自动平分积分或工作量，不推断主负责人。

### 页面流程

- 人员映射页同时显示所有关联人的真名、花名和各自账号状态；搜索可命中任一参与人。
- 单条/批量选择启用人员，可添加或取消多位；显示当前关联及待提交完整名单，支持明确清空。
- 同名人员继续按personId区分，不按显示名自动合并。最多20人/字段，最多500字段/请求。
- 预览显示原人员列表和新列表；确认后原子保存，版本冲突或资料变化提示重新预览。
- 旧单人交互和接口继续兼容；旧接口不允许覆盖多人字段或把原复合姓名静默压成一个人。
- 切换工作区、来源、关闭面板后丢弃旧响应；保存结果未知时保留同一命令重试，不生成第二次写入。

## 数据与合同

保留`import_person_links`作为每个源字段的版本头；新增成员表，按企业+来源哈希+行号+字段+personId存储，含明确顺序，关联人员资料。一个成员时保留旧person_id投影，多个成员时旧投影为空，权威成员列表包含全部人员。

新增迁移039，不修改已发布迁移005；回填既有非空单人关联，原版本不变。运行包schema使用实际完整迁移数量，正式读写最低版本提升到39，避免旧程序把多人成员误读为空绑定。

既有people-preview/people-apply接受原单人字段，另接受显式`members:[{personId,personVersion}]`。空数组明确清空；重复人员、越界、跨企业、不存在/停用人员拒绝。people列表额外返回personIds，personId仅在单人时非空。

资料账号更换检查所有成员关系；来源替换检查任何成员存在，避免只检查旧单人投影。所有成员、版本头、命令和审计同事务；同命令重试返回原结果。批量中任一冲突整批不写。
