# G02 真名、花名与源记录人员映射

## 目标

Excel需求方/设计师是真名，Naumi显示花名；名字不用于鉴权。本模块将人员资料、源行人员字段绑定和账户验证状态独立建模，接入原“成员与团队”和真实排期详情。未提供的对应关系保持待绑定。

## 数据与权限

- person_profiles：内部personId、真名、花名、可选来源账号元组、启用状态、版本。真名不唯一；账号元组不得被两个内部人员重复认领。资料录入本身不创建Naumi/工作流账号或权限。
- import_person_links：enterprise+sourceHash+row+field→personId，保存原姓名与版本。逐行选择防止同名人员串绑。解绑以personId=null保留行版本与历史。
- people_commands与people_audit：幂等指纹/结果，变更前后和操作人、原因；批量同一事务提交。姓名原文不写回import_rows。
- 账号验证由G01已审核source_identities+账号/来源企业状态实时计算。资料中填email只能得到“账号待验证”，不是登录授权。
- 批量先preview；返回受影响条数/旧绑定/新绑定/版本与摘要哈希，apply必须同一预览摘要。任何一条变更过期整批409，不部分覆盖。
- 本机入口仍是明确标注的local-owner；正式部署复用已验证企业principal和数据库manage权限，普通员工不能列出/改写全公司映射。

## UI

“成员与团队”增加“人员映射”：来源姓名清单（需求方/设计师出现次数），待绑定/已绑定/账号待验证统计，原始行列表和多选、人员资料列表、新增/编辑/停用、单条/批量预览确认、解绑、操作记录。所有目标显示personId短码、真名、花名和账号；无候选不自动创建。真实排期详情可跳转该行映射。

## 验收

同名源记录可绑定不同personId；人名/花名变更不改稳定ID；批量预览无写入、提交原子、同key重复不新增审计；冲突不部分提交；跨企业/非主管拒绝；禁用目标拒绝；账号绑定撤销后验证状态实时改变；业务订单/验收事实和源行哈希不变。真实数据只做读取验收，写操作在合成来源库完成。
