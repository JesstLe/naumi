# 集中验收矩阵、业务样本与证据要求

## 1. 验收原则
按大模块/业务切片集中验收，避免每改字段都跑全仓重型测试。每次验收区分：契约/单测、真实隔离数据库、真实多人浏览器、外部授权适配、生产候选/切流；不能相互替代。

方案文档校验与产品验收分开。本轮只做文档完整性/交叉引用/代码事实一致性和交付阅读页检查，不宣称下面业务测试已通过。

## 3. 技术恢复与可靠性专项

| 编号 | 注入场景 | 验收标准 |
| --- | --- | --- |
| T01 | 订单更新后事件插入失败 | 工单/去重/事件三者事务一致回滚 |
| T02 | 相同commandId不同载荷/主体 | 幂等冲突，不能返回他人快照 |
| T03 | outbox投递后消费响应丢失 | inbox去重，事实/待办/成本不重复 |
| T04 | consumer掉线、事件缺号/乱序 | 缺口挂起/补读，水位不跳过失败 |
| T05 | 工作流/DB连接重建 | 持久状态恢复，不靠进程内存保真 |
| T06 | 服务间认证失效、资产隔离 | 敏感写入拒绝；不放行旧缓存权限 |
| T07 | CPU/内存/磁盘压力 | 保交互，降后台；超预算升级而非停在线服务 |
| T08 | 候选新槽失败/切流后回退 | 旧槽保留，新业务数据不被旧备份覆盖 |
| T09 | 隔离实例恢复备份+私有文件引用 | 关键单据/事件/权限/媒体可用，RPO/RTO有实测 |

## 4. 必存证据

测试输入/身份/企业/角色、固定源码SHA、环境/配置修订、真实命令与退出码、API响应、数据库前后结果、浏览器状态/截图及错误、事件/队列/计费关联、故障注入和回退结果。
截图只证明当时画面，不证明数据库/权限和整个闭环；静态mock或模拟上游必须明确标记，不写成真实外部平台验收。
真实收费/发布测试需单独明确范围并记录次数；历史导入和读模型重放默认这些副作用为0。

## 5. 试点放行清单

五身份全链路、任务级权限、素材私有、重复提交/抢单、变更/交接、验收证据、数据来源/水位、站内待办、故障人工兜底、备份可恢复和蓝绿余量缺一项均不声称完整公司试点通过。
