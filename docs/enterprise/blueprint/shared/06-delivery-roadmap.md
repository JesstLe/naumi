# 分阶段实施计划、工作包、依赖与验收门槛

## 1. 推进方式

先明确整体契约，再按完整业务切片交付；不是32模块各做一半，也不是先铺满空页面。每个工作包包含后端、权限、页面、数据、文档和集中验收。
以下按完成门槛排序，不承诺无依据的工期。排期须结合实际开发人数、公司确认速度、外部权限和样本；优先把第一条真实闭环用起来。

## 2. 当前完成状态

- 上轮基础服务：独立workflow工厂/状态机/PG事务/幂等/事件已实现，隔离验证8项通过；非生产身份/资产适配，非公司真实闭环验收。
- 本轮：32模块与共享规范的详细方案，文档校验通过才计方案交付；不新增业务上线或服务器发布计数。
- 所有P1公司端页面、生产连接器、团队范围、绩效核算仍待按下列工作包实施。

## 4. P1 最小公司真实业务闭环

### P1-A：一次填表，归属明确
- M01/M02最小任职与业务授权；M03人工主数据；M05/M06系统表单；M07路由、待分配与单级审批；M30运营/受理页面。
- 实施：扩展v1表单快照、稳定userId映射、任务级授权port；建立BFF会话/原生命令适配与分页列表。
- 门槛：真实运营登录后提单→唯一团队或待分配→主管受理→退回补资料/批准；重复点击只建一单；越权店铺/人员拒绝。

### P1-B：拆单，派单或认领，执行留证
- M08计划/规格、M09简版日历与WIP、M10任务池/指派确认、M11进度/阻塞、M12最小受控交接、M13附件/版本。
- 实施：任务级读模型与范围裁剪；团队/技能/依赖/WIP并发校验；责任区间和阻塞事实。
- 门槛：主管拆设计+美工依赖任务；多人抢单仅一成功；错组不可见；员工开始/阻塞/恢复；开工后换人必须交接。

### P1-C：制作，评审，验收，签收
- M14必要品牌清单、M15创作关联/外部软件上传、M16文字/清单评审、M17验收包/签收；M21最小贡献事实、M19站内待办与获批钉钉通知、M24流程看板。
- 实施：资产ready/权利核查，保存与提交分开，交付manifest，不可变验收；outbox/inbox基础消费者先服务通知/事实。
- 门槛：五角色真实多人全链路；至少一轮返工、一条资料阻塞、一次重复提交/事件重投；最后交付可下载并签收，证据可回溯。

### P1-D：试点发布与稳定观察
- M29审计、M30培训/旧表切换、M32容量/备份/蓝绿；文档覆盖故障和人工兜底。
- 门槛：固定候选/真实依赖/双槽余量、备份恢复和切回演练、无历史付费任务重放；只有批准后启用试点企业/部门。
- 试点观察建议覆盖至少一轮真实业务高峰，具体时长由公司决定；先修错派/重复填报/不可见，再扩部门。

## 6. P3 公司推广与业务深化

M18受控渠道发布/召回、M27业务效果/实验、M28外包按需进入；不是首期必须全部上线的范围。
正式采用绩效制度需公司独立批准；全公司推广按部门/品牌逐批，不一次导入全部历史并启动所有通知/执行器。
资源触发时可先升服务器，再独立数据库/媒体worker/报表节点；拆服务不改变已定义的业务ID和领域命令。

## 7. 每包Definition of Done

1. 对应模块文档/契约/实现状态更新，未完清单明确。
2. 模块权限、持久化、幂等、异常恢复与真实UI集中验收；不以构建成功或HTTP200代替。
3. 新增数据的来源、版本、可见范围和删除/保留规则明确。
4. 只提交本任务改动，刷新main/同事已完成分支并记录整合状态，保护他人工作树。
5. 若发布：固定镜像、目标锁、基线、备份、真实就绪、平滑切流、排空、回退和最终服务/功能核验。

## 8. 停止/回退门槛

未实现团队/任务级授权、资产私有权限、unknown付费恢复、数据单写者约束或双槽资源余量时，不批准正式试点。保留旧应用/数据，但不能让两套需求表长期并行可写。
发布失败保留旧槽；试点业务回退需保留新系统新增单据/附件/验收事实并明确人工接管，不把旧快照覆盖新数据。
