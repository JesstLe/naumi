## 3. 同步模式与能力探测

每个connector登记system、tenant、environment、owner、grantedScopes、capabilityEvidence、credentialRef、rateLimitPolicy、mappingVersion、lastSuccess、watermark。

接入顺序：授权只读样本 → 确认字段/分页/增量/删除语义 → 建本地外部ID映射 → dry-run → 业务逐项确认 → 小批apply → 对账 → 扩范围。API返回200不等于字段完整或映射正确。

钉钉回调如可用需验签/时效/去重并入inbox；聚水潭接口版本与签名方式只按实际获批文档实施，不在方案猜签名算法或固定URL。平台未提供的信息一律unknown，不用名称推断权限。

## 4. 通用记录结构

```json
{
  "source": "jushuitan",
  "sourceTenant": "CONFIGURED_TENANT_ID",
  "sourceEntity": "sku",
  "sourceRecordId": "EXTERNAL_SKU_ID",
  "sourceRevision": "SOURCE_REVISION_OR_UPDATED_AT",
  "observedAt": "2026-10-16T08:00:00Z",
  "mappingVersion": 1,
  "payloadDigest": "SHA256_OF_REDACTED_CANONICAL_RECORD",
  "status": "validated"
}
```

外部记录键为(source,sourceTenant,sourceEntity,sourceRecordId)，不能仅用SKU文本或人员姓名。sourceRevision缺失时使用规范化内容hash，并记录“来源无版本”。

## 5. 字段级优先级与冻结

- 外部组织状态以HR指定来源为准；业务权限在本系统明确授予，不能被外部岗位名自动扩大。
- ERP规格/外部ID来自来源层；人工批准创作卖点、品牌资料、任务点数/期限来自本地业务层。
- 人工维护优先；明确false、0、空集合/禁用是值，不是“未填写”。同步不覆盖这些决定。
- 每个任务冻结表单、商品、品牌规范、点数和期限版本；来源刷新只影响新选择，不静默改在途工作。
- 手动覆盖必须有原因、作者、有效期和冲突提示；到期后恢复来源值也需可追溯。

## 6. 数据质量和失败恢复

分层：landing原始受限记录/导入文件 → normalized映射 → quarantined异常 → approved域资料。保留期按M29，不无限留原始个人数据。

导入回执必须满足：输入行数=通过+拒绝+待确认+明确去重行；apply数量、更新数量、保持人工值数量分别报告。分页失败保留已确认水位，不跨失败页推进；重叠补拉窗口去重；每日按来源ID/状态对账。

拒绝全表清空：权限被收回、平台分页漏数或超时不能判为全员离职/全商品删除。批量失效阈值触发人工确认。

## 7. 历史需求切换策略

1. 先确认钉钉表具体产品、表头、状态和附件可导出性。
2. 原表字段→M05模板映射，必要字段不得无提示丢弃。
3. 未结记录按来源ID预演；业务确认当前负责人、承接组、实际进度。
4. 试点切换时确定水位T；T前旧表只读，T后本系统新增；例外补录带旧来源ID。
5. 不导入历史收费执行器，不发历史通知，不把已完成单重新发布到任务池。
6. 对账/回退保留旧表只读证据与本地新单；不得恢复旧表为第二写入源而不处理切换后的新记录。

## 8. 隐私与当前边界

设计流程不需要买家姓名/手机/地址/完整订单明细。HR请假原因、工资、供应商密钥不进入通用商品/需求库。只同步最小必要数据，下载/导出逐范围授权。

本轮没有调用钉钉、聚水潭或生产数据库；上表是可实施接入设计，不是已采集到的数据目录。样本、权限和接口限流列入待确认项。
