# M21 标准工作量、多人贡献、返工与责任事实

服务域：绩效事实｜阶段：P1留证、P2校准｜上游：D08、D09｜依赖：M08、M12、M17

## 1. 使用场景与责任
同样“完成一张图”可能是原创新视觉或简单改尺寸，直接按数量比较不公平。本模块建立可解释的工作量与贡献事实，主管校准、员工可查证，最终评分由M22/M23处理。

## 2. 功能与页面
- 按岗位/任务类型的难度锚点、标准点数库、任务估点复核、贡献明细和证据纠错。
- 贡献按任务责任区间与已确认交接分配；复用资产和渠道适配分别列出新增工作。
- 多人任务后续允许比例分摊，合计10000基点；不能每人各记100%。
- 返工分“原标准未达/需求新增/资料错误/规范变化/无充分归因”，不默认全扣执行人。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| benchmarkId / version / jobFamily | 岗位和任务类型的锚点修订 | 主管校准 |
| frozenPoints / rationale / approvedBy | 发布时点数及依据 | M08/M12 |
| factId / acceptanceEventId | 可去重的已验收事实 | M17 |
| contributorId / contributionBps | 员工及贡献比例，合计10000 | 交接/分摊复核 |
| employmentSnapshot / responsibilityIntervals | 当时组织和责任时段 | M01/M12 |
| reworkClass / attributionEvidence | 已复核返工责任及证据 | M16 |

## 4. 流程与状态
`估计 → 校准 → 发布冻结 → 验收事实入账 → 待纠错/已确认`。点数不是人工实时可改的积分账户；事实调整产生新修订和差额链。
首期一个任务一个贡献人，v1验收事件固定10000基点；多人分摊必须发新schema事件并保留v1兼容，不能悄悄改变同名事件语义。

## 5. 跨模块联动
M08定义基准，M12交接/变更新增事实，M17验收触发记录，M22读取可评价事实，M23锁周期快照，M24展示事实口径，M25成本使用独立分摊规则不冒充贡献。

## 6. 权限与规则
执行人可看自己的证据并申请纠错，主管不能单方改已锁周期；跨团队比较先做岗位和任务类型校准。重复创作、拆碎任务、刷退回或换资产版本不得重复计同一验收产出。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/contributions/me`；`POST .../contribution-adjustments`；`POST .../benchmarks/{id}:approve`。
消费 `workflow.task.accepted.v1` / `workflow.handover.completed.v1`；产生 `performance.fact.recorded.v1`，以来源eventId建立inbox唯一约束。

## 8. 异常与验收
- 重复/乱序验收事件不重复计分，迟到事件保留业务时间和接收时间。
- 缺点数基准、分摊比例不满/超100%、责任归因未定进入不可评价列表。
- 转岗、离职、跨组支援保留历史事实；员工可查到来源工单及版本。
- 锚点升级不重算旧事实；冲销不删除已审证据。

## 9. 实现边界
当前仅有验收事件中的点数和单人事实，没有事实消费者/多人分摊/标定库。先积累事实再校准，不立即推出全公司排行榜。

## 10. 开发工作包（本模块实施清单）
- **M21-W01** 数据：建立inbox/来源验收唯一键、点数锚点、贡献区间/比例和调整事实链。
- **M21-W02** 后端：实现单人v1事实去重投影、比例守恒与迟到/争议队列，多人模型用新schema。
- **M21-W03** 前端：实现本人贡献明细、来源工单/交接/归因证据和纠错申请。
- **M21-W04** 验收：重放/乱序不多计、跨岗保留历史、缺证据不可评价、锚点更新不改旧分。
