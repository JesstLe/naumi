# M07 按表归属、审批、优先级与受理SLA

服务域：工作流｜阶段：P1｜上游：D01、D03、D06、D07｜依赖：M01、M02、M05、M06

## 1. 使用场景与责任
用户已确认按需求表确定任务归属。本模块决定“哪组受理、谁审核”，不把运营填写的期望执行人直接当最终派单。业务负责人维护规则，主管处理例外。

## 2. 功能与页面
- 归属规则表、条件编辑、模拟匹配、待分配队列、审核台、紧急申请和超时升级。
- 条件包括事业部、品牌、店铺、需求类型、渠道；结果包括承接teamId、受理人/岗位、验收角色、SLA模板。
- 标准优先级正常/较急/紧急；紧急需理由、影响范围及批准人，不允许人人默认“最高”。
- 审核动作：批准、退回补充、拒绝、移交待确认；移交不自动改变已开工任务。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| routingRuleId / revision | 已发布不可变规则 | 业务管理员 |
| matchConditions / specificity | 有类型条件和确定优先级 | M31配置 |
| teamId / intakeOwnerId / reviewerRole | 真实有效成员/岗位引用 | M01/M02 |
| decisionId / matchedRuleIds | 本次匹配结果与解释 | 服务端计算 |
| businessPriority / urgencyReason | 业务等级、证明及审批结果 | 表单+审批 |
| responseDueAt / slaCalendarId | 受理时限及工作日历 | 批准的SLA配置 |

## 4. 流程与状态
建议匹配顺序：经批准的单次例外 → 店铺+需求类型 → 品牌+需求类型 → 事业部+需求类型 → 明确配置的公共承接池。
只在已授权可服务范围内匹配；同优先级多命中、无匹配、承接团队停用均进入 `待分配`，由值班主管处理，不随机选第一条。归属结果冻结规则版本和输入快照。
`待受理 → 待补充/待审批 → 已批准/已拒绝`；审批通过后才可M08拆单。SLA按工作日历计时，退回是否暂停须有明确规则。

## 5. 跨模块联动
M06给出表单快照；M08继承承接团队与验收角色；M09核实产能后承诺期限；M10完成具体执行人指派/认领；M19处理SLA升级；M24监控规则冲突率和待分配积压。

## 6. 权限与规则
规则维护和发布分权；部门主管不能通过编辑规则接管其他品牌。运营负责人、承接团队、执行人、验收人分开字段。审核通过不等于同意运营期望截止，实际承诺期限需M09确认。

## 7. 接口与事件（拟定）
`POST /api/enterprise/v2/routing:simulate`；`POST .../requirements/{id}:approve`；`POST .../requirements/{id}:resolve-route`。
产生 `workflow.route.resolved.v1` 及现有 `workflow.approve-requirement.v1`。M08/M19消费；历史路由不随规则升级重算。

## 8. 异常与验收
- 无规则、多规则、组停用、审核人离职均有待分配记录和升级负责人。
- 同样输入/规则版本得到相同结果，模拟与提交结果一致；提交时复核最新授权。
- 紧急插单须显示被影响任务和批准依据；审批重复点击不重复发起任务。
- 路由变更产生解释与审计；不能让归属不明确的单据静默进入某员工任务池。

## 9. 实现边界
现有基础支持审批/退回，不含表单路由、SLA、多级审批。第一期可只设一个受理岗位和单级审批，但归属决策版本、异常队列和责任字段必须具备。

## 10. 开发工作包（本模块实施清单）
- **M07-W01** 数据：建立归属规则修订/匹配输入/决策解释和待分配原因模型，责任字段独立。
- **M07-W02** 后端：实现确定性路由与规则冲突校验、受理审批、当前团队/岗位有效性复核。
- **M07-W03** 前端：实现规则模拟器、待分配队列、审批/退回台和紧急申请影响提示。
- **M07-W04** 验收：执行R01—R07样例，验证多命中/无规则/团队失效不随机派单。
