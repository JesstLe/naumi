# M10 指派、任务池、认领与责任确认

服务域：工作流｜阶段：P1｜上游：D01、D07、D08｜依赖：M02、M07、M08、M09

## 1. 使用场景与责任
需求按表归属到承接团队后，由主管指派具体人员或开放团队任务池。设计和美工只看自己有权、有能力接的工作；认领成功就是明确责任，不是“点关注”。

## 2. 功能与页面
- 团队任务池、我的待确认指派、可认领任务、已认领任务、退回和主管调整。
- 每张任务卡展示类型、必要商品/店铺摘要、交付规格、点数、承诺截止和前置状态。
- 支持主管指派后员工确认；不把指派通知送达当接受责任。
- 控制单人WIP、允许的任务类型和跨组支援协议；推荐算法只给候选，不自动承诺。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| taskId / teamId / routingDecisionId | 任务及归属依据 | M07/M08 |
| assignmentMode | directed或pool；由主管决定 | 派单策略 |
| assigneeId / assignedBy / confirmedAt | 接收人、指派人、确认时点 | 登录/命令 |
| skillSnapshot / scopeRevision | 当时能力和授权版本 | M01/M02 |
| expectedVersion / commandId | 并发防抢单与幂等 | 客户端业务命令 |
| releaseReason / supportAgreementId | 退回理由及跨组依据 | 员工/主管 |

## 4. 流程与状态
指派：`open → assigned → claimed`；任务池：`open → claimed`。前置任务未验收时按当前v1禁止认领；不能仅靠按钮隐藏保护依赖。
未开工可说明理由释放；开工后换人走M12交接。认领提交时重查团队、能力、授权、WIP、前置和版本；并发只有一个执行人成功。

## 5. 跨模块联动
M07只决定承接团队，M10决定执行人；M09占用产能；M11开始进度；M15生成工作上下文；M19发待确认/认领成功通知；M21保存责任区间。

## 6. 权限与规则
任务池查询做任务级数据裁剪。无权限者即使猜到ID也不能读取brief全文或附件；指派目标须同企业且具备能力。禁止把老板管理权限等同于能代表员工点击认领。

## 7. 接口与事件（拟定）
v1已有 `assign` / `claim` / `release`；拟增 `GET /api/enterprise/v2/tasks/pool?cursor=` 与任务级详情投影。
产生现有 `workflow.assign.v1`、`workflow.claim.v1`、`workflow.release.v1`；M09/M11/M19/M21按版本更新，不重复增加WIP。

## 8. 异常与验收
- 两人同时认领一项任务只成功一人；未获可见性的失利者不泄露新执行人信息。
- 刷新/重试同commandId不抢第二次；新命令使用旧version冲突。
- 主管指派给已离职、错误技能、别家公司或未批准支援成员均拒绝。
- 开工后不能简单清空执行人；指派未确认有超时升级，而非永远占用队列。

## 9. 实现边界
基础已验证原子认领和同租户执行能力适配，尚无任务池查询、团队级范围、WIP和生产成员resolver。正式使用前先补这些约束。

## 10. 开发工作包（本模块实施清单）
- **M10-W01** 数据：建立任务级授权查询投影、当前执行人唯一约束和指派确认责任区间。
- **M10-W02** 后端：在claim事务加入team/skill/WIP/dependency复核，派单目标按实时任职核验。
- **M10-W03** 前端：实现任务池/我的任务/待确认指派及原子认领回执，失利刷新不自动改派。
- **M10-W04** 验收：两人抢单、离职抢单、错技能/越权任务、旧version与重放全部覆盖。
