# M30 员工工作台、角色体验、培训与内部推广

服务域：企业BFF/前端｜阶段：P1并贯穿后续｜上游：D01、D07、D08｜依赖：M02、M06、M10、M19

## 1. 使用场景与责任
运营从“填钉钉需求表”变为“系统提单”；设计/美工从聊天接活变为任务认领/交付；主管从追问进度变为查看队列。业务推广负责人负责培训、反馈和切换纪律，不只让IT发一个网址。

## 2. 功能与页面
- 运营首页：新建需求、待补充、我的进度、待签收；主管：首页待受理/待分配/容量风险/待验收。
- 员工首页：待确认指派、可认领、执行中、阻塞、返工、待交付；绩效单独授权入口。
- 桌面优先用于制作/审核，钉钉内移动页用于提单、查进度和轻量确认；复杂画布不强行塞手机。
- 浅色布局、紧凑表格/看板、统一状态/筛选/空态；无宣传口号，错误与待处理责任要有用。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| userId / roleCapabilities / activeScope | 登录及当前业务范围 | M02 |
| inboxItems / taskSummaries / watermarks | 最小摘要及同步水位 | 各读模型 |
| savedFilters / viewPreference | 用户偏好，不赋权 | 本地业务设置 |
| trainingCohort / onboardingState | 试点批次与培训记录 | 推广负责人 |
| feedbackId / category / businessRef | 问题反馈及关联单据 | 员工输入 |
| adoptionMetrics / errorMetrics | 提交成功、耗时、重复填报等汇总 | 经批准遥测 |

## 4. 流程与状态
试点 `准备 → 影子试填 → 单部门正式切换 → 稳定观察 → 分批扩展`。
确定切换日后，新需求只在系统创建；钉钉旧表只读并指向新入口。紧急例外由值班主管补录且留来源，不能长期两套表都当权威。

## 5. 跨模块联动
所有页面经BFF聚合，不从浏览器直连内部服务库；M05表单、M07待分配、M09排期、M15工作区、M17签收、M23个人证据和M24授权看板保持同一业务ID。

## 6. 权限与规则
无权入口不显示，已显示页面仍每次服务端校验；换号/换组织清缓存，异步旧请求不能覆盖新身份。移动链接带业务ID不带权限，点击后重新鉴权。
关键动作有明确成功回执与重试状态，不因页面刷新重复提单；无障碍键盘、焦点和表格溢出纳入验收。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/workbench`；`GET .../me/capabilities`；`POST .../feedback`。
前端消费只读更新提示，状态最终来自权威查询；不依赖浏览器本地时间决定SLA或绩效截止。

## 8. 异常与验收
- 使用运营/主管/设计/美工/验收五个真实身份走完整链路，不能只用管理员演示。
- 钉钉内打开、普通浏览器、390px与常用桌面宽度可操作，未授权字段不出网。
- 网络断开/慢查询/重复点击有确定回执，不丢草稿、不覆盖他人更新。
- 试点衡量一次录入率、错派率、待分配滞留和重复沟通，不仅看登录人数。

## 9. 实现边界
现有EnterpriseConsole仅组织/统计入口；员工工作台与任务页面待实现。本次文档和架构图不是已完成UI或公司推广验收。

## 10. 开发工作包（本模块实施清单）
- **M30-W01** 数据：定义角色首页最小投影、培训/试点批次、反馈分类和只采必要的采用度指标。
- **M30-W02** 后端：实现BFF聚合/权限/草稿恢复与慢查询隔离，不把多服务故障变空白页。
- **M30-W03** 前端：实现浅色角色工作台、筛选/看板/表格/移动轻操作，错误定位到责任动作。
- **M30-W04** 验收：五身份/钉钉内/390px/桌面/换号弱网走闭环；试点旧表停止双填。
