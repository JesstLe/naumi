# M11 执行进度、阻塞、工时与交付准备

服务域：工作流｜阶段：P1｜上游：D08、D09｜依赖：M10、M13

## 1. 使用场景与责任
设计/美工更新实际工作节点；运营看到可理解的进度与等待原因；主管区分正在制作、缺素材、待确认和返工。工时仅用于容量/改进，不采集屏幕或键鼠监控。

## 2. 功能与页面
- 我的任务、开始/暂停、进度节点、阻塞申请、工作记录、交付预检查。
- 可配置“资料确认/构图/初稿/修改/待交付”里程碑，人工确认而非根据AI任务数自动填百分比。
- 阻塞填写类别、责任对象、所需资料、预计恢复；解除后保留完整区间。
- 工时允许按日填报或开始/停止计时；一天多任务不重复累计同一时段，补记留理由。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| taskId / assigneeId / executionSegmentId | 任务与责任区间 | M10/M12 |
| status / percent / milestoneCode | 0—99，验收前不能100 | 员工命令 |
| workStartedAt / submittedAt | 服务器实际时间，补记另存 | 执行/交付命令 |
| blockId / reasonCode / ownerId / intervals | 阻塞事实和责任，不能只存一条说明 | 员工+确认 |
| worklogId / duration / confidence | 人工工时与估计标记 | 填报/计时 |
| deliveryCandidateRevisionIds | 候选交付物版本，不是任意URL | M13/M15 |

## 4. 流程与状态
`claimed → in_progress ↔ blocked → review`；返工后回到制作，历史进度保留。只有实际提交版本才进入review。
阻塞不自动暂停考核时钟：需分类及责任方确认后，由M22规则判断可扣除区间。未确认的阻塞在报表中单列。

## 5. 跨模块联动
M09更新容量风险；M12处理范围/期限变更；M16读取候选稿；M19向责任方通知阻塞；M21记录贡献区间；M24显示瓶颈，M22不把进度百分比当绩效。

## 6. 权限与规则
只有当前执行人更新执行状态；主管补记不能冒充员工操作。业务运营不能把任务改成“已完成”。工时明细、请假原因和绩效访问分级，避免全员互相查看。

## 7. 接口与事件（拟定）
v1已有 `start/progress/block/resume/submit-delivery`；拟增 `POST /api/enterprise/v2/tasks/{id}/worklogs`。
产生相应 `workflow.*.v1`；工作区自动保存事件不等同于业务提交，只有明确的submit-delivery进入评审。

## 8. 异常与验收
- 重复开始/停止计时不多计工时；跨午夜按工作日历拆分，时区统一。
- 断网草稿可恢复，但旧版本状态提交必须提示冲突，不覆盖新交接结果。
- 阻塞解除后仍能计算等待区间；错误填写用更正事件而非删除历史。
- 无交付物、处理失败/隔离资产不能提交；已验收任务拒绝再写进度。

## 9. 实现边界
v1只有简单进度、阻塞/恢复和提交时间，尚无阻塞区间/责任/工时。不能用现有单个reason字段承诺已经可精准核算有效工时。

## 10. 开发工作包（本模块实施清单）
- **M11-W01** 数据：建立阻塞区间/归因状态/工作日志更正记录；actual时间和补记时间分开。
- **M11-W02** 后端：实现执行节点命令、工时区间校验、资产候选ready检查和状态版本保护。
- **M11-W03** 前端：实现开始/阻塞/恢复、里程碑、候选稿与待交付清单，不把保存当提交。
- **M11-W04** 验收：未验收不100%、阻塞不自动免责、跨日工时/重复计时、断网旧状态拒绝。
