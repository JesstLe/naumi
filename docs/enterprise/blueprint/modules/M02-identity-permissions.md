# M02 钉钉登录、业务权限与数据隔离

服务域：组织身份｜阶段：P1｜上游：D01、D02｜依赖：M01

## 1. 使用场景与责任
员工用企业账号进入工作台；系统根据当前任职及业务授权显示需求、任务、评审、绩效。IT负责钉钉应用与身份映射；业务负责人审批角色。

## 2. 功能与页面
- 钉钉免登/扫码登录适配、既有Naumi账号绑定、首次绑定复核、解绑与会话失效。
- 角色模板：运营提单、派单主管、设计、美工、验收、绩效复核、系统管理员；允许组合但检测职责冲突。
- 权限调试页说明“通过/拒绝的规则来源”，不暴露他人的资料。
- 普通员工有自己的业务入口，不要求拥有现有管理岗位。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| subjectId / accountMappingVersion | UUID和绑定版本；禁止按姓名自动绑定 | D01、D02复核 |
| issuer / audience / expiresAt | 内部短时凭据声明，验证签名和时钟偏差 | BFF签发 |
| permissionCodes | 明确业务权限集合，不由前端传入 | 角色策略 |
| enterpriseId / scopeRevision | 租户与范围版本，缺失拒绝 | 当前任职 |
| departmentScope / brandScope / shopScope | 受控集合或关系表达式 | 授权审批 |
| authEpoch / disabledAt | 撤权版本和停用时间 | 账号权威源 |
- 钉钉软件已确认；应用类型、corpId、权限及免登方式仍需IT确认。请求失败不降级成信任客户端身份头。

## 4. 流程与状态
`未绑定 → 待确认 → 有效 → 冻结/撤销`。有效登录不等于有所有企业权限。
每次业务命令检查账号、任职、企业状态、授权范围与职责；读模型和搜索同样校验，不能只藏菜单。

## 5. 跨模块联动
- M06按用户可提单的品牌/店铺限制选项；M10按团队/能力过滤任务池。
- M13签发短时下载；M23个人绩效仅本人及获批复核范围可见；M24汇总防止小群体反推个人。
- M29记录授权变更和敏感读取；M31审批策略变更；M01离职使现有会话失效。

## 6. 权限与规则
任务池只返回可认领任务的必要摘要，不返回同需求下其他保密任务、成本或人员信息。管理人员不默认继承全部素材/绩效读取；执行人不能验收本人任务。登录管理员不能自行给自己发绩效复核权。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/me/capabilities`；钉钉回调由专用适配器校验state、一次性code和企业来源。
产生 `auth.policy.changed.v1`，由M19提示必要重登、各服务清理短TTL授权缓存；最终写命令仍检查实时授权版本。

## 8. 异常与验收
- 伪造企业ID、x-user、前端permissions和越权资产ID均拒绝。
- 离职/过期后登录、命令和幂等重放读取均拒绝；组织源失联时敏感写入关闭。
- 并发撤权/提交有可解释结果；跨租户搜索、导出、统计、签名URL均覆盖测试。
- 登录失败不创建新重复账号；钉钉停用时保留可审计的IT恢复路径。

## 9. 实现边界
现有账号/企业grant和管理权限可复用。工作流基础只有必填认证/resolver接口；尚无生产SSO和部门范围。现有基础 `canRead` 可返回整个工单，正式任务池必须先增加字段裁剪和任务级范围校验，才适合公司使用。

## 10. 开发工作包（本模块实施清单）
- **M02-W01** 数据：定义业务permission与brand/shop/team/task范围，建立账号绑定版本和authEpoch。
- **M02-W02** 后端：实现钉钉授权回调与一次性state、内部短时认证和当前范围resolver，覆盖签名/audience/expiry。
- **M02-W03** 前端：实现登录绑定/冲突处理、无权入口隐藏、换号清缓存和权限原因提示，不把JWT内容当最终授权。
- **M02-W04** 验收：跨租户猜ID、伪头、撤权后重放、敏感搜索/导出/媒体逐路径验证。
