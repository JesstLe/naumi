# M25 创作积分、费用、预算与效率核算

服务域：计费适配+报表｜阶段：P1关联、P2预算｜上游：D08、D11、D14｜依赖：M15、M17、M24

## 1. 使用场景与责任
管理者希望知道某品牌/活动的创作资源消耗和交付效率；财务/授权人员看采购成本，普通员工看自己的任务额度。积分、人民币成本、绩效点数是不同单位，不能混加。

## 2. 功能与页面
- 任务/活动成本归集、团队额度、预算申请、超额批准、退款对账、异常消耗与单交付效率。
- 已生成但未交付、失败退款、未知结算、共享素材复用分别列示。
- 创作额度只控制新增消费，恢复已接受作业不因额度耗尽而停止查询。
- 外包/人工成本先获批导入且限定财务角色，不默认采集个人工资。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| billingOperationId / ledgerEntryId | 账本权威引用，去重键 | D11 |
| businessTaskId / projectId / costCenterId | 按发生时关联和成本中心 | M15/M01 |
| unit / currency / amount | credit、point、CNY分别字段 | 账本/财务 |
| reserved / settled / refunded / unknown | 预留、结算、退款分开 | 原计费状态 |
| allocationRuleVersion / allocationBps | 共享费用分摊合计10000 | 财务审批 |
| budgetVersion / approvedLimit / approver | 额度与批准链 | 预算管理 |

## 4. 流程与状态
预算 `申请 → 批准 → 使用 → 对账 → 关闭`；成本事实 `预留 → 结算/退款/未知 → 对账`。
费用归集只读取原账本或事件，不通过业务任务重试再次扣款。人民币估计与真实账单分开，无法获得采购价时标记未知。

## 5. 跨模块联动
M15写业务关联，M17提供已交付分母，M24显示经授权成本/效率，M28归集外包验收费用，M29记录敏感读取；M22不把高模型消费自动记为员工绩效差。

## 6. 权限与规则
沿用企业管理可看积分汇总、不能看供应商采购秘密的边界。任务成员只看本任务可公开额度；财务成本详情单独授权。汇率/税/退款窗口有版本和来源，金额用整数最小单位或decimal。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/costs/summary`；`POST .../budgets`；`POST .../budget-exceptions:approve`。
消费现有计费事件适配后的 `billing.operation.settled.v1` / `billing.operation.refunded.v1`；M25不作为原账本写入者。

## 8. 异常与验收
- 重复退款/结算事件不多记金额；未知结算单列，不猜失败再扣款。
- 任务跨组交接后原费用归属可追溯，不因当前部门改写历史。
- 共享作业多任务引用分摊总额等于来源账本，不每单全记。
- 预算用尽只拦新消费；已接受作业查询/最终结算继续恢复。

## 9. 实现边界
现有Naumi有积分与持久计费；业务工单归集、公司预算和外包成本待开发。不能把目前的积分统计称为完整财务核算或工资系统。

## 10. 开发工作包（本模块实施清单）
- **M25-W01** 数据：建立计费/退款引用、成本中心快照、独立单位/货币及分摊规则版本。
- **M25-W02** 后端：实现只读账本适配与对账/预算预留，恢复已接受作业不受新预算阻断。
- **M25-W03** 前端：实现授权额度/费用/退款/unknown明细，采购成本和员工积分分区授权。
- **M25-W04** 验收：分摊守恒、退款不多记、转岗不改旧成本、unknown不重复扣费。
