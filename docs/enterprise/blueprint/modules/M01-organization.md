# M01 多公司、事业部、部门与任职

服务域：组织身份｜阶段：P1基础、P2扩展｜上游：D01、D02｜依赖：无

## 1. 使用场景与责任
- HR/组织管理员维护公司、事业部、设计中心、运营组、汇报关系；业务主管确认承接范围。
- 支持固定品牌团队、共享设计中心和跨组支援；公司实际组织模式未确认，不硬编码一种模式。
- 本模块管理“谁属于哪里”，M02决定“能做什么”，M10决定“本次任务由谁做”。

## 2. 功能与页面
- 组织树、人员列表、任职详情、批量导入预览、变更差异、离职交接清单。
- 主任职与兼任分开；成本归属、汇报上级、任务服务范围不是同一个字段。
- 钉钉组织先只读映射，人工新增本地业务团队不反写钉钉；合并/撤销部门保留历史映射。
- 离职事件阻止新派单和新认领，并生成未结任务清单；既有贡献保留。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| enterpriseId / legalEntityId | UUID；公司边界，不以部门名区分 | 本地确认、D01 |
| departmentId / parentId | UUID；父子不得成环 | D01映射或审核导入 |
| userId / externalUserKey | 本地稳定ID；钉钉corpId+userId唯一 | D01、D02 |
| membershipId / validFrom / validTo | 任职有效区间，允许兼任但不得无主归属 | HR确认 |
| primaryDepartmentId / supervisorId | 主部门、直属上级，分开校验 | 钉钉或人工主数据 |
| teamId / serviceScope | 本地承接团队与品牌/店铺服务范围 | 业务主管 |
- 先取得钉钉字段样本和部门权限；按D01增量同步，定时全量对账。钉钉同名人员不自动合并。

## 4. 流程与状态
`待映射 → 待复核 → 有效 → 调岗待交接 → 失效`。导入差异经HR确认后生效；批量失效有预览、人数阈值和二次确认。
调岗分为当前权限收回、未结任务交接、历史归属冻结三件事；不能通过改部门重写上月绩效。

## 5. 跨模块联动
- M02读取当前任职；M09获取可排班人员；M10核验承接团队与能力。
- M12接收调岗/离职交接；M21按执行时任职快照归属；M23按周期权限展示绩效。
- 外部组织同步中断时暂停新的组织变化，不将“未拉到”当作“已离职”。

## 6. 权限与规则
组织管理员可改组织，不默认可看个人绩效、素材或模型费用。跨公司兼任须逐公司授权；下属范围读取需服务端计算。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/organization`；`POST .../organization/imports:preview`；`POST .../memberships:change`。
产生 `org.membership.changed.v1`；M02/M09/M12/M21消费；事件只传ID与版本，人员敏感详情另行鉴权获取。

## 8. 异常与验收
- 重复导入无重复人员；同名不同钉钉ID不合并；缺失父部门进入异常队列。
- 员工离职后旧登录不能认领；未结任务有主管接收人，历史绩效不消失。
- 同时调岗/派单以任职版本复核；失效同步失败可重试，不恢复旧权限。
- 跨公司、越级、循环层级及无主兼任均有拒绝测试。

## 9. 实现边界
已有 `app_enterprise_members`、岗位及上级关系；当前以email为成员键且有唯一约束。多任职/多法人是新增设计，须先做ID映射和兼容迁移，不能直接把当前表当完整HR系统。

## 10. 开发工作包（本模块实施清单）
- **M01-W01** 数据：建立钉钉corpId/外部人员ID到稳定userId的唯一映射及导入差异表；保留现有email兼容关系。
- **M01-W02** 后端：实现任职有效区间、主部门/兼任校验、部门无环约束与失效交接事件；同步缺页不批量离职。
- **M01-W03** 前端：组织树联动人员详情，变更预览列受影响任务和权限，批量失效显示人数和确认人。
- **M01-W04** 验收：同名不同ID、兼任、上级循环、离职与在途派单竞争逐项校验，历史绩效保持。
