# M24 经营协作看板、指标口径与数据质量

服务域：报表读模型｜阶段：P1流程看板、P2经营分析｜上游：D07—D14｜依赖：M06、M10、M17

## 1. 使用场景与责任
运营经理看需求积压和活动交付，设计负责人看容量/质量/返工，企业负责人看跨部门瓶颈与成本。数据负责人维护口径，不能让各页面各算一套“完成数”。

## 2. 功能与页面
- 需求漏斗、受理等待、任务WIP、逾期风险、交付准时率、返工分类、素材复用、发布完成率和数据质量。
- 指标有定义、数据范围、时间粒度、时区、生成时间和水位；缺失/未知单列。
- 按公司/事业部/品牌/店铺/活动/任务类型钻取；人员层受M02和M23限制。
- 查询大范围报表走异步导出，不让主管一次点全量把主站拖慢。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| metricDefinitionId / version | 分子分母、排除项和维度定义 | 数据负责人 |
| tenantScope / dimensionKeys | 使用稳定ID，名称仅展示 | M01/M03 |
| eventTime / ingestedAt / watermark | 业务时间、入库时间、水位 | 事实事件 |
| numerator / denominator / unknownCount | 不把缺失当零 | 各投影 |
| grain / sourceRevision | 日/任务/需求等不可混加粒度 | 指标口径 |
| queryJobId / snapshotId / generatedAt | 可复现导出和结果 | 报表任务 |

## 4. 流程与状态
`事实采集 → 去重投影 → 质量检查 → 发布读模型 → 对账/修正`。业务命令成功不等于看板立即同步；页面展示滞后，目标时延先按资源实测设定。
结项数量按唯一需求ID，任务数量按唯一taskId；同一需求多个交付物不能叠成多笔完成需求。

## 5. 跨模块联动
消费需求、任务、验收、发布、成本、绩效等事件；M27业务效果另有归因口径；M29审计导出；M32监控投影积压。生产交易库不承接所有报表全表扫描。

## 6. 权限与规则
统计先范围过滤再聚合；小群体敏感数据设置抑制/合并阈值（公司确认），不能靠减法反推个人绩效。企业管理者可看积分汇总不等于可看供应商成本/对话/真实模型调用。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/reports/flow?from=&to=&group=`；`POST .../report-exports`；`GET .../data-quality`。
投影消费按eventId去重并核对聚合版本；产生 `report.snapshot.ready.v1`，由M19通知下载。查询投影无权回写工单。

## 8. 异常与验收
- 同事件重投、重建读模型前后总量一致；乱序事件不造成状态回退。
- 带退款/取消/迟到数据可说明口径和修订；零分母显示无数据。
- 钉钉/ERP源中断有明显水位和未知数量，不把未同步显示成业绩归零。
- 导出字段、页面权限和底层查询范围一致，跨企业聚合失败关闭。

## 9. 实现边界
现有企业analytics覆盖积分/作品/创作任务汇总，不是本方案业务工单BI。新流程读模型先PostgreSQL索引与日级汇总，不在4核8GB首期部署ClickHouse/ES。

## 10. 开发工作包（本模块实施清单）
- **M24-W01** 数据：定义业务粒度/指标口径、水位、缺失数量和日级投影，不混需求/任务/文件。
- **M24-W02** 后端：实现inbox幂等投影、聚合scope过滤、限时查询和异步分块导出。
- **M24-W03** 前端：实现流程漏斗/积压/准时/返工/数据质量，显示生成时间和来源滞后。
- **M24-W04** 验收：重建前后总量一致、乱序不回退、无数据不显示0、小群体防反推。
