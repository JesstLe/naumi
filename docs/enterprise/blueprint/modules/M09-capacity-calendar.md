# M09 工作日历、产能排期与跨组支援

服务域：工作流｜阶段：P1简版、P2增强｜上游：D01、D07、D08｜依赖：M01、M08

## 1. 使用场景与责任
主管在承诺需求截止前看团队可用产能；设计/美工能看到已承诺任务和排期变动。HR提供批准的休假/出勤区间，不以键盘活跃度或在线时长衡量劳动。

## 2. 功能与页面
- 周/月排期、个人任务量、团队可用量、临期风险、跨组支援申请。
- 区分运营期望截止、团队承诺截止、实际上交和最终验收时间。
- 初期人工选择可用时段和任务WIP上限；后续接钉钉已批准休假，具体接口权限待核对。
- 紧急插单显示将推迟的原任务，主管先协调再确认，而不是后台改日期。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| calendarId / timezone / workIntervals | 时区+工作时段，节假日可修订 | HR/业务日历 |
| userId / availabilityRevision | 人员与产能版本 | M01+人工确认 |
| leaveIntervals | 批准的不可用时间，不复制请假隐私原因 | D01或审核导入 |
| capacityUnits / maxWip | 按岗位设置建议值，非考核分数 | 主管校准 |
| taskReservations / dueAt | 任务容量占用及承诺期限 | M08/M10 |
| supportAgreementId / costOwner | 跨组支援批准与成本归属 | 双方主管 |

## 4. 流程与状态
`候选计划 → 资源确认 → 承诺 → 执行跟踪 → 释放`。容量预占有有效期；重复请求不重复占用。超配时主管可以带理由批准并记录风险，不伪装成系统可保证按期。
跨组支援要求派出和接收双方确认，不自动转移员工的主组织和历史绩效。

## 5. 跨模块联动
M07用排期结果确认受理承诺，M10在认领前检查WIP与可用时间，M11回传完成/阻塞，M12处理延期与支援变更；M19通知受影响需求人，M24显示需求供给缺口。

## 6. 权限与规则
员工可查看自己的负载，主管看授权团队；其他团队只暴露可支援容量摘要，不展示个人休假原因。排期不等于强制加班计划；特殊工时规则由公司确认。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/capacity?teamId=&week=`；`POST .../capacity:reserve`；`POST .../support-agreements`。
产生 `capacity.plan.committed.v1`；M10/M19消费；M09消费任务验收/取消/交接事件释放容量，重复事件不得多释放。

## 8. 异常与验收
- 同一人被两个主管同时排期时能检测超配；容量版本冲突需重新确认。
- 请假同步中断不将缺失数据视为全员可用；人工覆盖有有效期与来源。
- 紧急任务能列出被影响任务、原/新期限、批准人和通知结果。
- 跨组任务完成后释放占用，历史贡献/成本归属仍按当时协议保存。

## 9. 实现边界
当前无工作日历/容量服务。P1先做团队日历、WIP和承诺日期，不引入复杂自动优化求解器；真实使用数据充分后再评估智能排期。

## 10. 开发工作包（本模块实施清单）
- **M09-W01** 数据：建立日历版本、批准休假区间、WIP/容量和支援协议，去掉请假隐私原因。
- **M09-W02** 后端：实现容量预占/到期释放/任务完成释放，承诺日期变更留原基线。
- **M09-W03** 前端：实现周排期、超配提示、紧急插单影响和跨组支援双边确认。
- **M09-W04** 验收：并发占同人、休假源中断、重复释放和跨组归属不改主组织。
