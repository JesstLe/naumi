# M03 品牌、店铺、商品与SKU主数据

服务域：业务主数据｜阶段：P1人工基础、P2聚水潭同步｜上游：D03、D04、D05｜依赖：M01、M02

## 1. 使用场景与责任
运营提需求时直接选择品牌、店铺、商品和SKU，避免手填错名称。商品主数据管理员负责映射；店铺负责人确认归属，不要求设计人员登录ERP查商品。

## 2. 功能与页面
- 品牌/店铺目录、商品搜索、SKU规格图、历史名称、外部ID映射和异常待核对列表。
- 同款跨平台/跨店铺关联保留来源，不把不同规格合成同一SKU。
- 商品资料可附规格、卖点、包装版本和禁用说明；人工确认的创作卖点不能被ERP同步覆盖。
- 运营可提交缺失商品补录申请，未审核资料清楚标记。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| brandId / shopId | 本地UUID，店铺归属独立于平台账号 | D03、D05确认 |
| channel / externalShopId | 平台枚举+聚水潭店铺映射 | D03 |
| productId / skuId / externalSkuKey | 内部ID+系统/租户/外部ID组合键 | D04 |
| specification / barcode / status | 规格及状态，允许未知，不用空串冒充 | D04 |
| productRevision / effectiveAt | 可冻结的商品资料版本 | 导入批次 |
| creativeSellingPoints / approvedBy | 人工创作资料，独立修订 | 商品/合规负责人 |
- 聚水潭已确认，但商品、店铺及图片接口范围尚未实查。先审核CSV导入；API能力确认后按D03/D04增量+全量对账接入。

## 4. 流程与状态
`待导入 → 待映射 → 待确认 → 有效 → 停用`。外部删除做墓碑，不级联删除历史需求引用；需求冻结的是productRevision，不跟随商品名随时变化。

## 5. 跨模块联动
M06使用下拉选项并冻结商品快照；M07/M10依品牌、店铺、需求类型寻找归属规则；M13关联素材；M18映射上架对象；M24用一致ID分析复用和交付，M25按业务对象分摊成本。

## 6. 权限与规则
仅能选择授权店铺；不从ERP导入订单收件人、电话、地址来支持设计任务。临时商品不直接推送上架。外部采集仅更新来源层，人工已维护false、0和明确禁用不得被当作缺失。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/catalog/products?shopId=&cursor=`；`POST .../catalog/imports:preview`。
产生 `catalog.product.changed.v1`，M06刷新可选目录，M14提示品牌资料复核；已发布工单仍保留旧快照。

## 8. 异常与验收
- 重复导入不重复建SKU；外部ID冲突进入人工对照，不按标题相似度自动覆盖。
- 店铺停用不能新提需求，旧任务仍可读取其冻结资料并完成交付。
- 部分接口无权限不视为数据已删除；同步页面展示水位、滞后和失败数。
- 商品更名后历史验收资料不变；缺失必需规格时提单明确阻止。

## 9. 实现边界
当前Naumi创作项目/作品不等于公司商品库。本模块待开发，聚水潭字段表和店铺映射须拿样本确认；一期不承担库存、订单、采购或财务ERP替代。

## 10. 开发工作包（本模块实施清单）
- **M03-W01** 数据：建立品牌/店铺/商品/SKU与聚水潭外部ID映射、字段来源层和人工覆盖修订。
- **M03-W02** 后端：实现审核CSV预演、唯一键去重、增量更新与墓碑，提供范围内分页商品查询。
- **M03-W03** 前端：商品选择器显示规格/状态/资料水位，缺SKU可发补录申请，旧需求展示冻结名称。
- **M03-W04** 验收：重复SKU、同名商品、店铺停用、权限缺失和人工false/0不被覆盖。
