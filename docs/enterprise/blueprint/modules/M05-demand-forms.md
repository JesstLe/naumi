# M05 需求表单、字段模板与版本

服务域：工作流｜阶段：P1｜上游：D05、D06、D07｜依赖：M02、M03

## 1. 使用场景与责任
把目前钉钉上的需求表迁入本系统。运营在这里一次填写；业务表单管理员与设计主管共同确认字段和交付标准，普通运营不需要理解技术服务划分。

## 2. 功能与页面
- 表单类型：主图/详情页、活动视觉、商品精修、短视频/素材适配；第一批以现有钉钉表单样本为准，不擅自删字段。
- 可配置字段顺序、说明、必填、枚举、联动显隐、附件限制、复用模板；不允许任意脚本执行。
- 新建、另存草稿、复制需求、批量创建预览、历史版本对照和字段缺失提示。
- 表单提交前显示“需求负责人/预计承接团队/验收角色”；匹配结果只是预览，提交时服务端重新计算。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| formTemplateId / formVersion | 已发布不可变模板版本 | 表单管理员 |
| demandType / brandId / shopId | 归属规则必需字段；可选范围受权控 | M03、D06 |
| productRefs / campaignId | 商品版本引用和活动引用 | M03/M04 |
| businessOwnerId / deliveryAt | 运营负责人、期望交付时间 | 提单人确认 |
| deliverableSpecs | 尺寸、格式、数量、用途、源文件要求 | 模板+运营 |
| acceptanceChecklist / attachments | 验收清单与私有附件ID | 表单输入、M13 |
- 先导出/人工收集现有钉钉表头、枚举、校验规则和样本，映射到本地字段；没有历史API也可提供脱敏样本迁移结构。

## 4. 流程与状态
模板 `草稿 → 评审 → 发布 → 停用`；发布产生新版本，不能就地覆盖。旧需求沿原版本展示；提交前发现模板停用时提示迁移草稿，不静默丢字段。

## 5. 跨模块联动
M06负责提交单据；M07读取字段做归属/优先级与审批；M08读取交付规格拆任务；M16/M17使用冻结验收清单；M31管理模板发布权限。

## 6. 权限与规则
业务字段与内部字段分开：运营可以提“期望团队”，不能任意填写实际执行人绕过主管；任务归属以批准的规则为准。禁止用隐藏字段承载浏览器可篡改的角色/成本信息。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/forms/{id}/versions/{version}`；`POST .../forms/{id}:publish`；`POST .../requirements:validate`。
产生 `config.revision.published.v1`，归类formTemplate；M06刷新草稿兼容提示，历史单据不回写。

## 8. 异常与验收
- 同款需求复制后新业务号、旧附件按授权复用，不复制已完成状态。
- 钉钉表字段逐项映射，枚举缺失有报告；未识别字段保留原值待确认。
- 同时升级模板/提交表单能给出确定版本；必需交付规格缺失不进入任务池。
- 服务端重新验证所有字段，前端绕过必填仍拒绝。

## 9. 实现边界
基础工作流当前仅title/brief/acceptance，尚无动态表单。新字段需版本化扩展，保留原v1单据读取；本轮只设计，不新增空表单入口。

## 10. 开发工作包（本模块实施清单）
- **M05-W01** 数据：取得旧钉钉表样本，逐字段登记枚举/必填/附件与新schema的映射和丢失风险。
- **M05-W02** 后端：实现受限字段schema、表单版本发布与服务器校验；废弃字段保留历史展示。
- **M05-W03** 前端：实现动态表单/显隐/草稿恢复和归属预览，必填错误定位到具体字段。
- **M05-W04** 验收：旧表全字段覆盖、模板升级中提交、明确false值、绕过前端校验及超长字段处理。
