# M27 上架效果、实验、经营复盘与归因边界

服务域：报表读模型｜阶段：P3｜上游：D03、D05、D12、D14｜依赖：M03、M18、M24、M26

## 1. 使用场景与责任
运营想知道哪版主图点击更好、活动素材是否被使用、商品转化变化。数据分析负责人控制统计口径；设计团队看改进证据，不把店铺GMV自动归因给某个人。

## 2. 功能与页面
- 发布实例使用情况、曝光/点击/转化漏斗、对照实验登记、活动复盘、素材与商品版本时间线。
- 指标按平台/店铺/对象/位置/日期/归因窗口定义；无共同粒度的数据不强行拼接。
- 展示价格、促销、投放、人群、库存、季节等混杂因素与样本不足标记。
- 先做描述性复盘，具备真实随机/可比实验条件后再谈因果收益。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| publicationId / creativeRevisionId | 具体发布素材版本 | M18 |
| channelAccount / shopId / externalObjectId / slot | 外部业务粒度，不只按商品名 | D05/D12 |
| date / attributionWindow / timezone | 平台时区及归因口径 | 来源定义 |
| impressions / clicks / conversions / sales | 来源实际可取值，未知不填0 | D14 |
| metricRevision / refundCutoff / completeness | 修订、退款窗口和完整度 | 数据源对账 |
| experimentId / allocation / confounders | 实验分组及干扰记录 | 运营/分析确认 |

## 4. 流程与状态
`发布映射 → 指标采集 → 质量校验 → 描述复盘/实验分析 → 结论复核`。聚水潭可能提供商品交易事实，不等于具备平台曝光/点击/素材粒度数据；这些指标须另核权限或报表。
同商品一天多版素材且无位置/时间分辨率时显示“不可准确归因”，不均分GMV伪造精度。

## 5. 跨模块联动
M18提供发布版本，M03统一ID，M26获取平台/ERP数据，M24展示业务复盘，M20沉淀获批案例；M22若未来使用业务指标须另行评估公平性，不默认接入个人评分。

## 6. 权限与规则
只取汇总业务数据；不需要订单买家姓名/手机/地址。对外平台数据按公司授权使用。实验规则、统计检验和样本量计划须预先约定，不选择性只报告上涨结果。

## 7. 接口与事件（拟定）
`POST /api/enterprise/v2/experiments`；`GET .../publications/{id}/outcomes`；`POST .../reviews/business-outcomes`。
产生 `outcome.snapshot.ready.v1`；所有数值带source、grain、window、revision和observedAt。

## 8. 异常与验收
- 指标修订/退款晚到后生成新快照，保留原复盘版本。
- 曝光/点击无权限或错粒度时明确不可得，不能用订单数替代点击率。
- 多渠道汇总去重与货币转换有来源，样本不足不给“提升X%”确定结论。
- 验证素材ID→发布实例→外部对象→指标的完整关联，缺一环进入未知组。

## 9. 实现边界
本模块待数据条件成熟后实施；不是第一期上线前提。不承诺已能从聚水潭取到所有营销分析指标，也不把相关性当设计因果贡献。

## 10. 开发工作包（本模块实施清单）
- **M27-W01** 数据：定义publication到外部对象/位置/时间窗映射、指标粒度/修订/缺失与实验分组。
- **M27-W02** 后端：实现授权聚合指标导入和来源对账，错粒度/无映射标不可归因。
- **M27-W03** 前端：实现素材使用/业务复盘/混杂因素与样本量说明，不自动给人员贴收益标签。
- **M27-W04** 验收：无点击权限不造CTR、一天多素材不均分GMV、退款晚到保留新旧快照。
