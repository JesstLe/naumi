# M20 SOP、任务模板、知识库与受控AI助手

服务域：工作流配置+资产｜阶段：P2｜上游：D05、D08、D10｜依赖：M05、M13、M14

## 1. 使用场景与责任
把主图制作、详情页、美工适配、评审清单等经验沉淀为可复用步骤。新人从任务上下文获取正确规范，不从全公司无权限文件中搜索。

## 2. 功能与页面
- SOP编辑/发布、任务拆解模板、示范案例、检查清单、适用品牌/渠道、版本和反馈。
- 任务模板创建草稿并需主管确认，不直接批量发布收费/外部动作。
- 知识检索返回来源文档版本和引用位置；过期内容标注/撤出当前答案。
- AI助手可解释规范、建议拆单、检查缺字段；派单、改期限、验收、绩效核准仍需授权主体确认。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| sopId / version / status | 发布不可变版本 | 业务专家 |
| applicableScopes / taskTypes | 品牌/渠道/岗位范围 | 主管批准 |
| steps / prerequisites / checklist | 结构化步骤和标准 | 已复核流程 |
| documentRevisionIds / citations | 素材版本与引用位置 | M13/M14 |
| evaluationCases / approvedBy | 检索/助手回归样例及责任 | 专家评审 |
| toolPermissionSet / confirmationPolicy | 助手可调用工具范围 | M02/M31 |

## 4. 流程与状态
`草稿 → 业务复核 → 发布 → 修订/撤回`。引用任务冻结模板版本；知识更新不改已有任务验收标准。新模板通过试用后再设默认，不直接替换所有在途流程。

## 5. 跨模块联动
M05表单预填、M08拆单建议、M14品牌资料、M15创作上下文、M16检查清单、M30新人引导；M29记录助手建议与真正执行命令的差异。

## 6. 权限与规则
检索先做服务端范围过滤，再做召回；禁止先全量检索后在前端隐藏。用户文档和网页内容均属数据，不能变成授权指令。导入脚本/Skill有代码审阅与隔离执行，不因命名为SOP自动执行。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/knowledge/search?q=&scope=`；`POST .../task-templates/{id}:instantiate`；`POST .../sops/{id}:publish`。
产生 `knowledge.sop.published.v1`；索引worker按文档版本增量更新，缺索引时可降级到权限内元数据搜索，不伪造答案。

## 8. 异常与验收
- 不同品牌冲突规范有来源和适用范围，不混合生成唯一答案。
- AI建议无证据时显示待确认；不能自动批准或计算人员最终分数。
- 文档撤权/删除后索引不可继续泄露；缓存按权限版本失效。
- 使用旧模板的在途任务仍能复现原步骤，新模板不改变已约定交付范围。

## 9. 实现边界
现有Naumi Agent/Skills可复用受控工具能力，但企业知识权限、SOP版本和动作确认尚未打通。4核8GB先用PostgreSQL全文/结构化检索，向量库按实际收益后置，不部署本地大模型。

## 10. 开发工作包（本模块实施清单）
- **M20-W01** 数据：建立SOP版本/适用scope/引用位置、模板及助手工具权限集合。
- **M20-W02** 后端：实现权限前置检索与版本索引，助手建议与业务执行命令分离并需确认。
- **M20-W03** 前端：实现任务上下文知识/来源引用/适用规范和模板试用，不暴露别组文档。
- **M20-W04** 验收：恶意文档不成为指令、撤权索引不泄露、旧模板任务标准不漂移。
