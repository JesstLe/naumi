# M23 绩效周期、员工查证、复核、申诉与归档

服务域：绩效｜阶段：P2｜上游：D01、D08、D13｜依赖：M21、M22

## 1. 使用场景与责任
员工先检查自己的交付证据，主管复核，HR/授权复核人处理争议，最终周期锁定。员工离职、转岗或迟到验收不让历史记录丢失或任意变化。

## 2. 功能与页面
- 周期建立、参评名单、资料齐备检查、个人明细、主管意见、员工确认/申诉、独立复核、版本归档。
- 明确确认是“已阅读”还是“认可结果”，不同动作分开记录。
- 跨团队支援按冻结贡献和组织规则归属，不在周期结束时临时争抢产出。
- 锁定后更正通过重开审批或下一周期调整，保留原版与差额，不覆盖历史。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| cycleId / period / timezone | 明确半开区间[start,end) | HR制度 |
| participantSnapshot / reviewerChain | 参评任职及复核角色冻结 | M01/M02 |
| ruleVersion / evidenceCutoff / factHash | 冻结口径和证据水位 | M21/M22 |
| calculationRevision / state | 核算版本和审核状态 | 周期流程 |
| appealId / evidenceRefs / resolution | 争议与补证、复核结论 | 员工/复核人 |
| lockedAt / approvedBy / adjustmentRefs | 最终核准与后续调整链 | 获批流程 |

## 4. 流程与状态
`准备 → 影子/草稿核算 → 员工查证 → 主管复核 → 申诉/独立复核 → 核准 → 锁定归档`。
截止后到达事实进入迟到队列，按制度决定重开或下期调整；不能自动改已锁分数。处于申诉期的结果不得伪装为最终已确定。

## 5. 跨模块联动
M21解释事实，M22重演公式，M19发复核/申诉待办，M24只展示授权且标注状态的数据，M29记录敏感查看/导出与变更，M25不在此模块直接发薪。

## 6. 权限与规则
本人看个人细项；主管仅授权参评范围；HR最小必要。申诉复核人不应为原争议单一决策人，无法分离时需公司指定更高层复核。导出默认脱敏/加水印并记录用途。

## 7. 接口与事件（拟定）
`POST /api/enterprise/v2/performance/cycles`；`POST .../{id}:freeze`；`POST .../appeals`；`POST .../{id}:lock`。
产生 `performance.cycle.locked.v1` / `performance.appeal.resolved.v1`；只向获批读模型发布，外部HR同步需另行授权。

## 8. 异常与验收
- 员工转岗/主管离职时复核链可经批准转交，不丢申诉期限。
- 迟到事实、规则修订和重开能区分原版/新版，旧导出可追溯。
- 计算人无法自行跳过全部审核锁定；读写/导出越权均测试。
- 员工能从个人结果定位到工单、交付版本、规则和排除理由。

## 9. 实现边界
公司当前绩效制度、周期、试用期/外包适用性待确认；本轮不宣称已建立正式考核制度。第一期交付事实看板，不自动影响薪酬。

## 10. 开发工作包（本模块实施清单）
- **M23-W01** 数据：建立周期/参评快照/证据cutoff/核算修订/复核链/申诉/锁定与调整。
- **M23-W02** 后端：实现freeze/review/appeal/resolve/lock权限及状态，独立复核和迟到事实处理。
- **M23-W03** 前端：实现个人查证、已阅读/认可分开、主管待办、申诉证据和版本差额。
- **M23-W04** 验收：锁后更正留旧版、主管离职可转交、员工范围隔离、不自动发薪。
