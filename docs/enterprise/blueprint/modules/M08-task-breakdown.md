# M08 任务拆解、交付规格、依赖与标准工作量

服务域：工作流｜阶段：P1｜上游：D07、D08｜依赖：M05、M07

## 1. 使用场景与责任
设计主管把“一个店铺活动需求”拆成主视觉设计、商品精修、详情页、美工适配等可验收任务。每个任务有清楚交付范围，避免接一个大单后无法追踪协作贡献。

## 2. 功能与页面
- 任务分解表、模板复制、依赖图、规格清单、工作量建议、主管校准和发布预览。
- 支持设计→美工依赖、多个SKU并行、共享主视觉被多个适配任务引用。
- 点数按任务类型和难度锚点估计，复杂度/版本须可解释；不是按出图张数直接计绩效。
- 一任务首期一个贡献人；多人共同执行拆子任务。共享贡献模型后续按M21启用。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| taskId / requirementId | 稳定UUID及所属工单 | 工作流 |
| taskType / skillTags | 设计、美工等类型及能力要求 | 模板+主管 |
| deliverableSpecs / acceptanceItems | 数量、尺寸、格式、源文件及验收项 | 冻结表单 |
| dependencyIds | 同权限范围DAG，不允许环或自依赖 | 主管配置 |
| points / benchmarkVersion / difficultyReason | 冻结工作量与锚点依据 | 标准工作量库 |
| teamId / dueAt / reviewerId | 承接团队、承诺期限、验收责任 | M07/M09 |

## 4. 流程与状态
`草稿计划 → 校准 → 排期确认 → 发布`。发布后任务规格、点数、期限不能直接改，走M12变更。
发布前校验规格完整、DAG、前置输出可用、任务负责人有效。v1要求前置任务验收后才能认领；如未来允许提前认领但禁止开工，需显式v2策略，不能文档与代码各一种规则。

## 5. 跨模块联动
M09以计划算容量，M10认领与派单，M15创建创作工作区，M16/M17按规格评审验收，M21按冻结点数记录贡献。任务拆分不生成重复业务需求。

## 6. 权限与规则
同一产出拆多任务时必须区分新增工作和复用工作；已经验收的主视觉不能每个店铺适配再全额计原始点数。主管不能在周期末单方面提高点数刷绩效；变更需理由和复核。

## 7. 接口与事件（拟定）
沿用v1 `plan-tasks` / `publish`，新增字段通过v2扩展；拟定 `POST /api/enterprise/v2/requirements/{id}/task-plan:validate`。
产生现有 `workflow.plan-tasks.v1`、`workflow.publish.v1`；M09/M10/M19消费，发布事务与事件同写。

## 8. 异常与验收
- 自依赖、环、跨企业依赖、缺规格和重复任务ID均拒绝。
- 批量规划原子成功或失败；多人编辑以expectedVersion冲突，不后写覆盖。
- 标准点数变更不改已发布任务；同一交付资产复用不等于新产出。
- 从一张活动表拆成设计+美工串并行任务，能逐一找到验收项和上游输入。

## 9. 实现边界
基础已有design/artwork、点数、截止、DAG与发布；任务规格、能力标签、点数锚点、团队字段和复杂度审批待扩展。单工单事务保留，不按子任务拆独立服务。

## 10. 开发工作包（本模块实施清单）
- **M08-W01** 数据：扩展任务规格/点数锚点/能力要求和计划版本，明确原始创作与适配点数。
- **M08-W02** 后端：实现DAG/规格/任务ID校验、计划原子发布、规格点数冻结及v1兼容。
- **M08-W03** 前端：实现拆单表和依赖图、模板套用预览、发布前逐任务错误定位。
- **M08-W04** 验收：环/自依赖/跨企业引用、批量半失败、并发规划和标准点数更新不影响旧单。
