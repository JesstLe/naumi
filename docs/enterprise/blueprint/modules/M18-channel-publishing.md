# M18 交付上架、渠道发布、回执与召回

服务域：分发集成｜阶段：P2人工回执、P3受控API｜上游：D03、D05、D09、D12｜依赖：M03、M14、M17、M26

## 1. 使用场景与责任
运营将已验收主图/详情/活动素材用于相应店铺或投放。系统跟踪“交付后有没有用、用了哪版”，不把验收按钮直接等同于商家平台已上架。

## 2. 功能与页面
- 发布计划、渠道规格预检、待发布包、人工执行回执、API状态查询、替换/下架/召回。
- 第一期可下载包后人工发布，填写外部商品/广告/页面ID和证明；未验证显示人工回执。
- API发布需要渠道明确支持且公司授权，逐批预览目标店铺和内容；高影响操作二次确认。
- 同一素材多店使用按发布实例区分，保留每个渠道状态和版本。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| publicationId / shopId / channel | 一次外部使用实例 | 运营计划 |
| externalObjectId / slot / locale | 商品/页面/广告及位置，不按名称猜 | D05或人工验证 |
| approvedRevisionIds / acceptanceId | 已批准交付版本 | M17 |
| externalRequestId / idempotencyKey | 外部调用关联；支持与否需实查 | 渠道适配器 |
| status / publishedAt / observedAt | 平台事实和观察时间分开 | D12 |
| recallReason / replacementPublicationId | 召回与替代链 | 运营/合规 |

## 4. 流程与状态
`draft → approved → scheduled → submitting → published/failed/unknown`；撤回独立 `recall_requested → recalled/unknown`。
对外写请求超时先按外部ID查询和人工核实；不因HTTP失败直接重发。部分店铺成功不回滚成“全失败”，逐发布实例记录。

## 5. 跨模块联动
M17提供批准包；M14授权到期触发受控召回；M27按发布实例关联效果；M24显示发布漏斗；M19通知失败/待核查；M29留外部写审计。

## 6. 权限与规则
平台令牌隔离到店铺/用途，凭据进入秘密库。未批准、过期授权或错店铺不得发布。聚水潭已确认不等于一定能修改所有平台内容；API不可用时人工回执路径继续可用。

## 7. 接口与事件（拟定）
`POST /api/enterprise/v2/publications:preview`；`POST .../{id}:approve`；`POST .../{id}:query-status`。
产生 `publication.state.changed.v1`，M27/M24/M19消费；事件带事实置信来源manual_verified/platform_readback，不混算。

## 8. 异常与验收
- 调用成功响应丢失不会二次发布；unknown进入核查队列。
- 多店批次可定位逐店结果；版本过期后新发布拒绝。
- 外部平台没有幂等能力时，适配器采用单实例租约+先查后核，不承诺绝对恰好一次。
- 召回执行后读回目标状态，操作员上传截图不冒充平台API验证。

## 9. 实现边界
本期先设计人工发布+可追踪回执，不编写自动上架连接器；不重建OMS/WMS，不改聚水潭订单/库存业务。

## 10. 开发工作包（本模块实施清单）
- **M18-W01** 数据：建立逐店/对象/位置的publication与请求指纹/回执来源，状态含unknown。
- **M18-W02** 后端：先人工回执接口，后实现逐渠道授权写入/查询/召回，保留外部接受ID。
- **M18-W03** 前端：实现发布预览/批准/部分成功/待核查及替代版本，不一键掩盖逐店状态。
- **M18-W04** 验收：响应丢失先查不重发、过期素材拒绝、多店部分失败和召回真实读回。
