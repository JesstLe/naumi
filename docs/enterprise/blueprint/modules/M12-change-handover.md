# M12 需求变更、延期、转派与离职交接

服务域：工作流｜阶段：P1受控转派、P2完整变更单｜上游：D01、D07、D08｜依赖：M01、M09、M10、M11

## 1. 使用场景与责任
运营中途换卖点、活动改期、设计师请假、员工离职或跨组支援，都不能靠直接修改原任务解决。发起人解释变更；主管及受影响业务负责人确认成本与期限。

## 2. 功能与页面
- 变更单、前后差异、影响任务/依赖、重新估点、延期期限、接收确认、交接资料清单。
- 变更类型：范围、规格、商品版本、截止、执行人、验收人、取消/暂停。
- 调整仅作用于批准后的新基线；原期限、原点数和原交付事实保留。
- 离职自动生成任务交接候选；接收人确认资料可用后才结束原责任区间。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| changeId / changeType / reasonCode | UUID+分类，拒绝无理由覆盖 | 发起人 |
| baselineVersion / proposedPatch | 指定原版本和受限可变字段 | 工作流快照 |
| impactTaskIds / deltaPoints / newDueAt | 影响范围及新增工作量 | 主管评估 |
| approvalIds / decisionAt | 业务/承接方批准链 | M31规则 |
| fromAssignee / toAssignee / effectiveAt | 交接边界，不能历史回溯替换人 | M10+接收确认 |
| handoverAssetRefs / contributionSegments | 资料版本及前后贡献区间 | M13/M21 |

## 4. 流程与状态
`申请 → 影响评估 → 待批准 → 已批准 → 待交接/执行 → 已完成`；拒绝/撤回保留。执行前复核原聚合版本，期间已验收的任务不得按旧提案覆盖。
紧急交接可走简化批准，但仍记录谁批准、接手时间和资料；不把离职人员过去贡献清零。

## 5. 跨模块联动
M06展示变更历史；M08版本化任务规格；M09重排容量；M13保留源文件；M17约束交付基线；M21按区间分摊贡献；M22判断外部变更导致的返工/延期；M19通知全部受影响人。

## 6. 权限与规则
提单人只能申请变更；直接改点数、取消已验收事实、代员工确认交接均受限。跨组转派须接收组范围授权；离职不扩大素材给全公司。

## 7. 接口与事件（拟定）
`POST /api/enterprise/v2/change-requests`；`POST .../{id}:assess`；`POST .../{id}:approve`；`POST .../{id}:apply`。
产生 `workflow.change.approved.v1` 和 `workflow.handover.completed.v1`。批准和应用分开，消费者按版本幂等更新。

## 8. 异常与验收
- 两个并行变更不互相覆盖；应用基线过期必须重新评估。
- 源文件缺失不显示“交接完成”；无人接收时主管有明确升级待办。
- 延期前后时间都可追溯，考核不只读取最后一次dueAt。
- 已验收后纠错通过冲销/新事实，不能删除绩效证据。

## 9. 实现边界
现有release仅适用于未开工任务；活跃工单文本/点数已冻结。此模块必须以新增变更契约实现，不能放开数据库字段编辑来绕过冻结。

## 10. 开发工作包（本模块实施清单）
- **M12-W01** 数据：建立变更申请/影响评估/批准/应用版本及责任交接区间，不覆盖原人和原期限。
- **M12-W02** 后端：实现受限patch、基线冲突检测、交接资料清单和接收确认，配合容量重排。
- **M12-W03** 前端：实现前后差异、受影响依赖、deltaPoints/期限和批准/交接待办。
- **M12-W04** 验收：并行变更、应用前已验收、源文件缺失、离职无人接收和迟到绩效调整。
