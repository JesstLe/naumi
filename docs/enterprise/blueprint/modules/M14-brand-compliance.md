# M14 品牌规范、商品卖点与内容合规

服务域：业务主数据+资产｜阶段：P1最小清单、P2规则库｜上游：D04、D05、D10｜依赖：M03、M13

## 1. 使用场景与责任
多品牌的颜色、字体、Logo、包装版本、宣传用语和平台要求不同。品牌负责人维护标准，商品/合规负责人审核声明，设计与运营按任务引用的版本执行。

## 2. 功能与页面
- 品牌规范包、卖点资料、证书/授权、限制词/适用场景、平台规格与版本生效日期。
- 上传规范后人工确认结构化字段；AI解析仅提供建议，不自动变成已审核事实。
- 对交付物进行尺寸/格式/必要文字等确定性检查；敏感宣称和版权判断保留人工复核。
- 过期字体/肖像/素材授权提示影响任务与已发布渠道，进入替换或召回流程。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| guidelineId / brandId / version | 品牌版本，发布后不可改 | 品牌负责人 |
| approvedClaims / restrictedClaims | 适用商品/场景及审核人 | 商品/合规资料 |
| logoAssetRevision / palette / typography | 固定素材版本和标准值 | M13 |
| rightsHolder / proofRef / validUntil | 授权主体、证明和有效期 | D10 |
| channelSpecVersion / checklist | 平台规格来源和采集时间 | D05 |
| exceptionApprovalId | 单次例外、范围和截止 | 授权审批 |

## 4. 流程与状态
`草稿 → 品牌/合规复核 → 已发布 → 到期/撤回`。任务冻结所用规范版本；新强制规则发生时列出影响单据，由负责人决定重审，不能静默改变历史通过结果。

## 5. 跨模块联动
M05在表单附标准；M08拆解验收清单；M15提供受控创作上下文；M16评审引用证据；M17验证授权；M18处理替换/下架；M20把已批准标准放入检索库。

## 6. 权限与规则
品牌内可读，商业秘密按范围进一步限制。运营上传的卖点未审核时显式标记；不能把ERP标题或供应商图片默认当可对外发布的授权内容。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/brands/{id}/guidelines`；`POST .../compliance/checks`；`POST .../guidelines/{id}:approve`。
产生 `brand.guideline.published.v1` / `compliance.rights.expired.v1`，M15/M16/M18/M19响应并留证据。

## 8. 异常与验收
- 无授权证明、过期/撤回资产不能作为新发布来源；历史在用列出影响范围。
- 自动检查失败/超时显示“待人工”，不能自动当通过。
- 同品牌不同渠道规范可并存；冲突时指明生效版本和复核人。
- 通过任务能导出当时的品牌规范、检查项和例外批准，而不是只能看最新规则。

## 9. 实现边界
这是内容治理和证据流，不承诺自动法律判定或替代专业审核。现有模板/品牌素材可作为输入，不将未审文档直接作为生效规范。

## 10. 开发工作包（本模块实施清单）
- **M14-W01** 数据：结构化品牌规范、批准卖点、素材权利、平台规格及生效区间，保留审核来源。
- **M14-W02** 后端：实现版本发布/撤回、到期影响查询和检查结果，自动检查未知不当通过。
- **M14-W03** 前端：实现品牌包/检查项/授权证明/例外审批，任务可查看冻结规范。
- **M14-W04** 验收：旧规范可复现、未批准卖点标记、权利过期阻新发布且列现有影响。
