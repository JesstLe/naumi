# M16 在线评审、逐项批注与返工责任

服务域：工作流｜阶段：P1基本评审、P2图上批注｜上游：D08、D09、D10｜依赖：M11、M13、M14

## 1. 使用场景与责任
设计主管看视觉质量，运营看卖点/业务需求，必要时品牌/合规参与。每条意见绑定具体稿件版本，避免钉钉聊天里“改这张”无法追溯。

## 2. 功能与页面
- 稿件对比、缩放预览、坐标批注、清单勾选、意见分类、评审轮次和返工确认。
- 意见分类：未达原标准、业务新增、资料错误、规范变化、偏好优化；责任需复核，不由系统猜。
- 单项意见可标“已处理/待确认/不采纳及理由”；所有必需意见处理后才可建议验收。
- 一个评审包可以多人评论，但必须配置最终决策角色，不能“谁最后点就谁说了算”。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| reviewRoundId / taskId / revisionIds | 固定稿件版本和轮次 | 提交交付 |
| reviewerId / reviewRole / deadline | 评审主体和责任 | M07/M31 |
| commentId / anchor / content | 版本内坐标或时间码，文本清洗 | 评审输入 |
| issueType / severity / responsibility | 分类、严重级别、已复核归因 | 主管确认 |
| resolution / resolvedRevisionId | 新版本解决依据 | 执行人+评审人 |
| decision / decisionVersion | 退回或建议通过的版本化结论 | 评审决策 |

## 4. 流程与状态
`待评审 → 评审中 → 待修改/建议通过 → 已关闭`。返工产生新轮次、保留旧批注；新增业务范围转M12变更，不强行记为质量返工。
评审通过是M17验收的必要条件之一，不等于已对外发布。评审人超时触发升级，不自动默认通过。

## 5. 跨模块联动
M11重新进入制作；M12处理范围变化；M14提供检查依据；M17冻结终审结论；M21/M22只使用已复核返工分类；M19向待处理人通知，不向全组广播敏感意见。

## 6. 权限与规则
执行人不能验收本人任务；多角色同人时需替代审核人。只读评论权限不包含下载源文件。批注删除使用撤回/更正状态，保留审计；不能在锁定周期后悄悄修改返工责任。

## 7. 接口与事件（拟定）
`POST /api/enterprise/v2/reviews`；`POST .../reviews/{id}/comments`；`POST .../reviews/{id}:decide`。
基础已有 `request-rework`；完整评审拟产生 `review.round.closed.v1`，M11/M17/M22消费。

## 8. 异常与验收
- 两人同时提交不同结论需版本冲突/汇总规则，不能覆盖。
- 新旧版本坐标不混用；视频时间码指向固定revision；无权资产不出预览。
- 评审超时、审核人离职、客户改需求能明确转交/变更，不自动通过。
- 多轮意见、归因和处理版本可完整导出；绩效返工数不直接等于评论条数。

## 9. 实现边界
v1有review/rework状态及次数，没有坐标批注、多角色评审或返工责任。第一期允许结构化清单+文字意见，保留未来批注版本模型。

## 10. 开发工作包（本模块实施清单）
- **M16-W01** 数据：建立评审轮次/固定revision/批注锚点/问题归因及决定版本。
- **M16-W02** 后端：实现评论/处理/决策的角色与版本校验，业务新增转变更单，本人终审拒绝。
- **M16-W03** 前端：实现版本对比、清单/文字意见，后续增加图上坐标/视频时间码批注。
- **M16-W04** 验收：多审核人竞争、旧稿批注不迁错图、超时不默认通过、返工归因可复核。
