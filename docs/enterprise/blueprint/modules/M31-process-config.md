# M31 流程配置、归属规则发布与版本治理

服务域：各领域配置｜阶段：P1必要规则、P2配置中心｜上游：D05、D07、D13｜依赖：M02

## 1. 使用场景与责任
不同品牌/店铺需求表、承接团队、审批链、SLA、验收清单不同。业务配置员维护草稿，授权负责人发布，开发团队维护可执行边界；不把所有规则写死在页面代码。

## 2. 功能与页面
- 表单模板、归属、审批角色、日历/SLA、任务类型、点数基准、通知模板和绩效规则的版本管理入口。
- 草稿差异、样本回放、影响范围、批准、指定生效时间、停用和紧急回退。
- 只开放受限条件/动作DSL，不支持任意SQL/脚本，也不支持绕过鉴权的“超级规则”。
- 配置按所属域保存，本入口提供统一体验，不做所有服务必经的单点同步调用。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| configType / configId / revision | 对象和不可变版本 | 业务草稿 |
| scope / conditions / actions | 类型化范围与受限动作 | 配置编辑 |
| effectiveAt / retiredAt | 生效区间，避免重叠歧义 | 发布审批 |
| testCases / expectedResults | 无命中、多命中等验证样例 | 业务/开发共建 |
| approvedBy / changeReason / checksum | 发布证据与内容完整性 | 审批流程 |
| rolloutCohort / rollbackRevision | 试点范围与兼容回退版本 | 发布计划 |

## 4. 流程与状态
`draft → validated → approved → scheduled → active → retired`。发布前校验引用人员/团队存在、范围合法、规则冲突和样本回放。
配置发布影响新单/新计算；在途任务按冻结版本执行。需要追溯调整时走专门变更/周期重开，不能一次发布重算所有历史。

## 5. 跨模块联动
M05表单、M07路由、M09日历、M08点数、M16审核、M19通知、M22绩效分别拥有领域配置；M29留审计；M32提供版本观测和回退。

## 6. 权限与规则
高影响发布与编辑分权；规则不能赋予操作者本来没有的企业范围。配置缓存带版本和有效期，失联时沿用明确可用的已批准静态规则，但账号授权不能以永久缓存兜底。
密码/令牌不属于普通配置版本内容，引用秘密ID即可。

## 7. 接口与事件（拟定）
`POST /api/enterprise/v2/config/{type}:validate`；`POST .../{id}:publish`；`POST .../{id}:rollback`。
产生 `config.revision.published.v1`；按configType分发，消费者校验checksum和兼容版本，回退产生新发布记录而非删除旧版。

## 8. 异常与验收
- 两人并发编辑用expectedRevision冲突，不能最后写入覆盖。
- 无引用团队、同优先级冲突、无法满足的审批链阻止发布。
- 回退规则后新单按回退版走，旧单仍能解释当时归属和批准。
- 测试环境规则不能连生产通知/付费工具；样本回放无外部副作用。

## 9. 实现边界
不是第一期就做完整BPMN/低代码平台。先版本化最必要规则，真实复杂度出现后再评估流程引擎，保持业务命令和数据归属不被引擎锁死。

## 10. 开发工作包（本模块实施清单）
- **M31-W01** 数据：建立领域配置revision/checksum/effectiveAt/批准人/样例和灰度范围。
- **M31-W02** 后端：实现validate/publish/rollback及冲突检测，限制DSL，秘密仅存ref。
- **M31-W03** 前端：实现差异/样例回放/影响范围/生效安排和发布分权。
- **M31-W04** 验收：并发编辑不覆盖、规则回退可复现旧单、测试回放无付费/通知副作用。
