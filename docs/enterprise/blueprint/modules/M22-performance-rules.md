# M22 绩效指标、规则版本与可解释计算

服务域：绩效｜阶段：P2影子核算、P3正式采用｜上游：D08、D13｜依赖：M21、M31

## 1. 使用场景与责任
公司按岗位看交付量、质量、按时性、协作与改进；不能简单把任务数、AI调用数或店铺GMV等同个人能力。绩效负责人/HR与业务主管共同批准口径，员工能看到公式和证据。

## 2. 功能与页面
- 岗位指标库、规则版本、权重/阈值配置、样本试算、新旧规则对比、缺失证据处理。
- 候选指标：有效工作量、经责任核对的按时率、初稿通过率、返工结构、协作响应；是否纳入总分由公司确认。
- 默认无最终分数；先影子核算至少一个完整周期，复核偏差和异常分布后才批准使用。
- 引擎只执行受限公式/表达式，无任意eval脚本；每次计算可复现。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| metricId / unit / direction | 指标单位和好坏方向 | HR/业务确认 |
| ruleId / ruleVersion / jobFamily | 规则修订及适用岗位 | 审批发布 |
| weights / caps / missingPolicy | 权重、封顶和缺失策略 | 公司制度 |
| evidenceCutoff / factRevisionIds | 计算使用的数据截点 | M21/M23 |
| numerator / denominator / exclusions | 可解释分子分母及剔除理由 | 计算明细 |
| scoreDraft / explanation / engineVersion | 草稿结果及重演依据 | 核算引擎 |

## 4. 流程与状态
规则 `草稿 → 试算 → 评审 → 发布 → 生效 → 停用`；不能追溯替换旧周期规则。
示例而非最终制度：有效工作量=Σ冻结点数×贡献比例×已批准质量系数；按时率=按时有效工作量/可评价应交工作量。质量系数、权重、剔除规则全部待确认。
零分母=暂无可评价数据；接口缺数据=待补证，不等于0分。主管晚验收不直接算员工晚交。

## 5. 跨模块联动
M21供事实；M09供工作日历快照；M12/M16供责任与变更；M23管理复核/申诉；M24展示获批口径；M27业务效果仅作团队研究，不直接入个人评分。

## 6. 权限与规则
规则创建、批准、核算和最终确认分权；禁止单一主管在核算后调整权重偏袒个人。自动结果只作复核草稿，不自动触发工资、奖金或人事处罚。

## 7. 接口与事件（拟定）
`POST /api/enterprise/v2/performance/rules:simulate`；`POST .../rules/{id}:publish`；`POST .../calculations`。
产生 `performance.calculation.completed.v1`；M23消费草稿，不能把计算完成当周期已核准。

## 8. 异常与验收
- 同事实/规则/引擎版本多次计算结果一致，舍入规则固定且明细可解释。
- 迟到事实、争议返工、请假与跨岗样本有明确缺失/剔除记录。
- 指标调参不能静默改锁定周期；无足够样本不给强排名。
- 算分失败不影响业务派单/验收；不同岗位先同类比较，不生造统一能力榜。

## 9. 实现边界
绩效规则和核算均待开发，当前事件只能提供部分事实。正式制度由公司审批，不把本文示例数字作为实施默认值。

## 10. 开发工作包（本模块实施清单）
- **M22-W01** 数据：定义metric/rule/engine版本、分子分母/排除项、单位和确定舍入规则。
- **M22-W02** 后端：实现受限公式引擎与样本试算，零分母N/A、缺字段待补证，规则发布分权。
- **M22-W03** 前端：实现公式解释、输入事实、试算差异和岗位可比范围，不默认出全员排名。
- **M22-W04** 验收：相同输入可重演、无任意eval、迟到规则不改旧周期、算分失败不阻工单。
