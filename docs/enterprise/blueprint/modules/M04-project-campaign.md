# M04 项目、活动与跨店需求组合

服务域：工作流｜阶段：P2｜上游：D03、D06、D07｜依赖：M03、M06

## 1. 使用场景与责任
大促、新品上架、品牌升级包含多个店铺和批次需求；活动负责人需要看总体里程碑，设计主管需要看真实任务负载，而不是另建重复任务。

## 2. 功能与页面
- 活动项目、里程碑、批次需求、责任地图、关键路径和风险列表。
- 支持同一活动多品牌/店铺，但不因同项目而扩大人员权限。
- 跨店共用主视觉采用一个原始任务+各渠道适配任务，不复制原始任务产出量。
- 从项目一键创建需求草稿，逐单确认后提交；模板批量生成有预览。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| projectId / campaignCode | UUID+公司内唯一业务号 | 活动负责人 |
| sponsorId / projectOwnerId | 发起与执行负责人 | 审批确认 |
| brandIds / shopIds | 授权对象集合 | D03 |
| milestoneId / targetAt | 里程碑；不直接覆盖子任务期限 | 运营排期D07 |
| requirementIds / batchId | 原需求引用，不复制状态 | M06 |
| baselineRevision / changeId | 活动基线及变更依据 | M12 |

## 4. 流程与状态
`策划 → 已立项 → 执行 → 待复盘 → 归档`。活动完成率按已验收工作量/已承诺工作量；草稿不计入。关键店铺未交付即使任务数完成99%也不能显示“全部就绪”。

## 5. 跨模块联动
M06产生需求；M08创建依赖；M09汇总里程碑资源；M12管理跨需求变更；M18回传各店铺发布状态；M24看活动层交付与业务结果，不能用总GMV反推某设计师贡献。

## 6. 权限与规则
项目负责人只能关联其可见单据；跨事业部合作由双方负责人明确授权。项目时间变动只产生变更建议，需逐个受影响责任人确认排期。

## 7. 接口与事件（拟定）
`POST /api/enterprise/v2/projects`；`POST .../projects/{id}/requirements:link`；`GET .../projects/{id}/milestones`。
产生 `project.milestone.changed.v1`，M09/M19更新风险与通知；M04消费需求验收和发布回执事件形成可重建汇总。

## 8. 异常与验收
- 同一需求重复关联不重复计产出；项目移除需求不删除原工单。
- 项目归档后迟到事件保留并标记，不能无审计重开项目。
- 关联越权需求拒绝；按授权只看汇总不展示隐藏店铺详情。
- 里程碑延期能够列出受影响任务、批准人和修订版本。

## 9. 实现边界
当前创作画布项目不是公司活动项目；本模块新建业务项目ID，使用引用关联，避免混用项目归属和画布共享权限。

## 10. 开发工作包（本模块实施清单）
- **M04-W01** 数据：建立活动/里程碑/需求引用及基线，不复制子任务状态为另一写源。
- **M04-W02** 后端：实现范围内关联/移除与里程碑汇总，按验收工作量而非文件数计算完成度。
- **M04-W03** 前端：项目总览分开需求/任务/发布实例，展示关键店铺和跨组依赖风险。
- **M04-W04** 验收：重复关联不多计、项目改期不直接改子任务、无权单据不可被关联读取。
