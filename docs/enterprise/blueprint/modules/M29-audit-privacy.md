# M29 审计、数据分级、留存、导出与删除

服务域：各域审计+报表｜阶段：P1底座｜上游：D01—D14｜依赖：M02

## 1. 使用场景与责任
发生错派、越权、文件外泄、点数争议或规则修改时，能够回答谁在什么授权下改了什么。数据负责人制定保存期限，IT管理审计设施，业务审计人按范围读取。

## 2. 功能与页面
- 单据时间线、权限/规则变更、敏感读取和导出、外部写操作、失败拒绝、审计查询与取证包。
- 数据分级：业务公开摘要、内部需求/素材、人员绩效、财务成本、秘密凭据；每类有访问与留存规则。
- 导出申请用途/范围、审批、异步生成、短时下载和可追溯标识。
- 删除/归档先做引用与保留期检查，保留法律/争议冻结记录。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| auditId / traceId / commandId | 跨服务关联，不含秘密原文 | 各域命令 |
| actorId / delegatedBy / authRevision | 真正操作主体与代理依据 | M02 |
| entityType / entityId / beforeAfterDigest | 目标和最小必要变更摘要 | 领域事务 |
| action / outcome / reason / occurredAt | 成功/拒绝及理由 | 服务端 |
| dataClass / retentionUntil / legalHold | 保存与冻结策略 | 公司制度 |
| exportJobId / approvalRef / downloadAudit | 导出过程证据 | 导出服务 |

## 4. 流程与状态
审计与关键业务命令在同事务留记录，再异步集中查询；不能因报表审计汇总服务故障让关键原始审计丢失。
删除 `申请 → 引用/期限核查 → 批准 → 逻辑封存/删除 → 存储清理验证`；备份删除周期和恢复后的再次删除策略需明确。

## 5. 跨模块联动
M01离职保留历史身份；M12追踪变更；M13管理资产引用；M23记录绩效复核；M26记录同步和回调；M32处理日志/备份资源与告警。

## 6. 权限与规则
审计只记录必要摘要，不把对话、供应商凭据、完整签名URL或买家资料全塞日志。只追加事件不等于防篡改证明；需要更强取证时用独立权限的归档存储/校验链并实测恢复。
审计管理员与数据库运维权限分开，运维访问需留授权记录。保存期限是公司制度待定，不由开发随意给永久。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/audit?entityId=&cursor=`；`POST .../exports`；`POST .../retention-requests`。
产生 `audit.export.completed.v1` / `privacy.retention.applied.v1`；敏感导出通知限批准范围。

## 8. 异常与验收
- 成功/失败命令、代提/代办、规则变更和导出均能定位操作者。
- 同一资产有验收引用/争议冻结不能误删；备份恢复演练后删除策略仍生效。
- 日志采样不丢必须审计项；轮转失败和磁盘将满提前告警。
- 无权用户搜索不到他人绩效审计全文，取证包不包含秘密。

## 9. 实现边界
当前企业audit与新工作流events可复用，但全链路读取审计、分级保留、取证和删除流程尚未打通；本轮仅提出实现要求。

## 10. 开发工作包（本模块实施清单）
- **M29-W01** 数据：定义敏感分级/保存策略、关键命令审计、读取/导出审计与legalHold。
- **M29-W02** 后端：实现事务审计、导出审批/鉴权、引用检查与受控删除，不记秘密原文。
- **M29-W03** 前端：实现范围内时间线、取证/导出申请、删除影响与保留理由。
- **M29-W04** 验收：取证可关联操作者/版本、备份恢复后删除策略延续、无权看不到敏感审计。
