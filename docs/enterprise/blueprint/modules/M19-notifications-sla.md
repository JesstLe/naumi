# M19 站内待办、钉钉通知、提醒与升级

服务域：集成worker｜阶段：P1｜上游：D01、D07、D08｜依赖：M02、M07、M10、M26

## 1. 使用场景与责任
钉钉继续作为员工触达渠道：运营提交后通知主管，指派通知员工，返工通知执行人，验收通知运营。真正的业务状态在本系统，消息只是入口。

## 2. 功能与页面
- 站内待办、钉钉卡片/工作通知适配、未读/待处理、通知偏好、免打扰和升级规则。
- 聚合相同任务短时间内的进度提醒；关键指派/返工/授权撤销不依赖普通订阅开关。
- 卡片链接跳回系统鉴权；若支持钉钉卡片动作，必须验证回调主体、签名和命令版本。
- 失败通道不会阻断工单事务，站内待办始终能查。

## 3. 数据获取与关键字段
| 字段 | 类型及规则 | 来源 |
| --- | --- | --- |
| notificationId / sourceEventId | 事件派生通知，唯一去重 | outbox |
| recipientId / externalRecipientKey | 系统人员到钉钉ID映射 | M01/M02 |
| templateVersion / payloadClass | 模板及可披露字段级别 | M31 |
| channel / state / providerMessageId | 站内/钉钉及发送回执 | 通道适配器 |
| dueAt / escalationLevel / ownerId | 业务SLA与升级责任 | M07/M09 |
| attempt / nextRetryAt / dedupeKey | 退避重试和幂等 | worker |

## 4. 流程与状态
`待发送 → 发送中 → 通道已接受/失败/未知 → 已读或业务已处理`。通道已接受不是员工已读，已读不是已认领。
超时提醒先确认业务状态仍未解决；审批完成但消息晚到不再发送催办。重试有上限和死信，人工可查询/补发，但不能重复执行业务命令。

## 5. 跨模块联动
消费M06提交、M10指派、M11阻塞、M16返工、M17验收、M23复核、M29风险等事件。组织变动时更新收件人；历史消息不得给新任人员泄露未授权资料。

## 6. 权限与规则
消息正文只含必要业务号、动作和链接，不带源文件下载签名、个人绩效明细或供应商秘密。通知接收范围和实际页面范围一致；离职人员停止发送。

## 7. 接口与事件（拟定）
`GET /api/enterprise/v2/inbox?cursor=`；`POST .../inbox/{id}:read`；钉钉回调由M26适配。
产生 `notification.delivery.updated.v1`；通知结果不回写工单完成状态。消息超时的可靠性目标需按钉钉权限和限流实测后确认。

## 8. 异常与验收
- 钉钉故障时业务仍可操作，站内待办不丢；恢复后不重复轰炸。
- 同一事件重复投递只生成同渠道同收件人一条有效提醒。
- 非工作时间按策略延后，紧急升级有授权例外和频率限制。
- 验证“已发送/已读/已处理”区分；撤权后旧消息链接不再打开资料。

## 9. 实现边界
钉钉软件已确认，但自建应用、机器人、工作通知和卡片能力待选；第一期可先站内通知+获批通道，不能假定机器人能读取全部组织或回写审批。

## 10. 开发工作包（本模块实施清单）
- **M19-W01** 数据：建立站内待办/渠道delivery/去重键/模板版本与收件人身份映射。
- **M19-W02** 后端：实现outbox消费者、钉钉限流退避/死信、过期待办抑制，链接仍需当前鉴权。
- **M19-W03** 前端：实现未读/待处理区分、失败重试状态和受限通知偏好。
- **M19-W04** 验收：钉钉故障不阻业务、重复事件不轰炸、已读不当认领、离职旧链接拒绝。
