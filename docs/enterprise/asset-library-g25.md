# G25 独立素材与交付页

## 目标与数据归属

原Demo素材页保留轻色卡片布局；正式工作区不再显示“正在接入”。本页不是不受任务约束的网盘，不创建独立文件副本、审核状态或绩效事实。任务内上传、不可变文件版本、扫描、提交、验收及来源参考继续复用同一服务端数据和权限。

页面分为“交付版本”和“来源参考”两个分区，严禁把Excel原附件或Naumi生成图片自动当成交付成果。

## 交付版本

- 仅列当前企业、团队canRead范围内需求的delivery_assets，来源团队/历史参与者的读取范围与任务详情一致。先授权再统计/分页。
- 默认全部可见，可切换“我的上传”；本人上传不绕过当前需求读取权限。按文件名、需求标题、任务标题搜索，24条稳定分页（上传时间倒序、ID倒序）。不把每个任务最后200项当全库。
- 业务状态由持久事件推导：候选=未见提交事件；当前提交=当前active任务处于review、当前assetIds包含该版本且有提交事件；历史提交=曾提交但不再处于当前提交；已有验收记录=不可变验收事件明确引用该版本。验收记录优先级最高，后续检查隔离不抹去验收事实。
- 各状态数量来自完整授权范围并包含当前搜索/本人条件，状态筛选只改变列表与匹配总数；同一快照内计算，不能前端筛选一页后冒充总数。
- 卡片显示文件名、任务内版本号、大小、上传主体/时间、所属需求/任务、业务状态及独立文件检查状态。完整SHA256、最近提交/验收主体/时间/版本可展开查看。取消/归档需求不抹去已有文件及历史，只显示真实需求状态。
- “已有验收记录”不是“当前可用”：隔离或待检查版本禁用字节预览和下载，仍可按权限查看检查历史与所属任务。

## 来源参考

- 只列正式需求snapshot.referenceAssets中明确勾选的文件，不遍历整个原表附件目录。
- 每个需求-文件关系单独展示，同一hash被两个需求引用时保留两个溯源关系，不错误地合并权限。
- “我提报的需求”使用requester稳定账号；不是“我的上传”。搜索文件名和需求标题，24条分页，完整总数不受分页影响。
- 重用ReferenceStore对当前批次启用、原行hash、选中附件归属、元数据及存储配置的校验；列表仅证明元数据关系，字节可用性仍在读取时重新校验。
- 来源变化/停用/未配置单列原因；不显示下载或预览入口。旧快照没有明确选择清单时保持为空，不自动补选。

## 字节访问与预览

交付文件增加受保护PNG/JPEG预览：上限8MiB、单边8192、总像素1600万，实际字节头判断类型和尺寸，后缀不作为可信判断。HTML/SVG/PDF/PSD等不内联执行；超过限制仍沿授权附件下载。仅点击时加载一张图片，不自动并发拉取整页原图。

预览沿用完整SHA256校验、同一文件描述符、校验后再次授权与检查门禁。审计仍是文件字节读取operation=download，并以detail.deliveryMode=preview明确区分预览，旧下载语义保持。响应限定image/png或image/jpeg、no-store/nosniff/CSP，BFF核对viewer但viewer不代替登录。

来源预览沿用现有受保护参考接口。所有下载、重新检查及检查历史使用已有接口，不下发密钥、物理路径或公开blob URL。上传必须回到当前任务，不增加“随便上传后挂到别人任务”的入口。

## UI行为

搜索、分区、状态与本人条件改变时重置分页；切号/企业/团队清空旧列表、预览及统计，迟到响应不覆盖新范围。读取失败显示错误与重试，不回退演示素材或把失败变成0文件。卡片可进入原需求/任务详情，检查历史复用既有弹窗，返回后刷新。
