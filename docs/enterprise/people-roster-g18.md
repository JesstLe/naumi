# G18 人员清单批量录入与确认

## 用户流程

原18482界面“成员与团队 → 人员映射”增加“批量录入资料”。用户下载空白TSV模板，或从Excel/钉钉表格复制粘贴8列：人员ID、版本、真名、花名、Naumi邮箱、来源实例、来源企业ID、启用。支持载入当前已有资料进行批量修改。每批1–100条。

新增人员的ID/版本留空，由浏览器生成稳定UUID、版本0；更新必须明确完整ID、版本及启用状态。姓名不作为查找、合并或绑定依据。同名可建不同人员。3个来源账号字段必须全部填写或全部为空；花名/邮箱不授予登录或任务权限。

## 检查与确认

1. 本地解析TSV，支持Excel的引号转义、引号内制表符/换行、UTF-8 BOM；拒绝错误表头、未闭合引号、列数错误、过量数据。空行跳过。
2. 服务端在当前企业目录管理员事务内校验ID/版本、重复ID/账号、已有账号占用、关联源行时禁止直接改绑账号、启用状态和输入字段。
3. 预览只读返回逐条原资料、新资料、变更字段、当前账号绑定状态及行级错误。任何错误整批不允许提交；同名仅提示核对，不自动合并。
4. 用户明确确认“仅更新人员资料，不自动建立登录权限或原表人员绑定”，携带previewHash、commandId提交。任何版本或预览变化整批拒绝；审计与写入同事务；同命令重放不增加记录。
5. 保存成功后刷新原人员列表，之后使用已有源行选择/绑定流程。此模块不按名字自动扩展690个源字段。

## 身份与数据边界

正式工作区复用Naumi会话、签名企业/团队身份、manage及独立person_directory_admins授权；本机准备模式仍明确local-owner。批量预览/保存均重新鉴权。账号“已建立绑定”只表示既有工作流绑定有效，源站实时登录授权继续单独校验。

切换账号/企业/团队、关闭弹窗或离开工作区后，旧清单和待返回请求不再渲染。输入改变必须重新预览。重试结果未知的提交使用同一命令，不自动换新命令重复创建。

只下载空白模板，不把真实姓名填成演示样例；表格字符串作为纯文本处理，界面转义。原Excel字段、已有任务、验收事实及账号/团队授权表不由此接口改写。数据库schema仍12。

## 验收

集中验证模板解析、同名分开、新增与修改混合、无变化条目、重复ID/账号、过期版本、改绑保护、预览无写入、事务故障回滚、重放、撤权、跨企业/团队、表格转义及原UI浏览器完整流程。真实公司未提供的关系保持空；真实库0人员资料/0映射不变。

## 状态

服务端、原UI及本机/正式接口已实现并完成集中验收；本模块不代替实际对应表、Naumi站点配置或正式公司上线。整体目标ACTIVE。

- POST /v1/people/roster-preview、/roster-apply；正式BFF action为people-roster-preview/people-roster-apply。本机准备接口支持同名动作，保留原CSRF和仅回环监听。
- 单人编辑与批量录入复用候选校验及资料写入方法；批量ID与账号企业UUID规范化后判重，大小写不会绕过同ID检查。预览无变化的条目不增加资料版本；批量审计使用profile-batch操作名。
