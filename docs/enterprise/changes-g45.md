# G45 活跃需求变更：合同与实施

## 目标与使用流程

运营在已批准/执行中的需求内提出变更；系统显示前后差异、受影响任务/依赖、计划与承诺冲突。需求方负责人和执行方负责人分别独立批准，执行方应用新版本。原18482需求/任务详情为入口，不另做管理后台。

## 输入与范围

受限patch允许需求title/brief/acceptance，以及已有任务title/points/dueAt。单次最多50任务，点数1–100、截止为明确时区时间，不接受任意字段、人员/企业/源关系/资产/验收状态覆盖。依赖结构、商品/规范换版、取消和跨组转派分别走对应合同，未以本模块冒充完整M12所有子功能。

需求文字变更影响全单，存在review/accepted任务时拒绝；只改指定任务则其他已验收任务保持原样。目标任务review/accepted或待交接拒绝；先完成明确返工/交接决策，再重新申请。应用时新截止须仍晚于当前时间。无变化、重复任务ID和不存在任务均拒绝。

## 状态与版本

proposed → approved（两侧齐全）→ applied；proposed/approved可rejected或由原申请人withdrawn。审批和应用分开，不隐式写任务。变更ID、命令ID稳定；同命令同输入重放，异输入冲突。变更记录存订单聚合，命令/聚合/事件/通知同事务。

申请保存原聚合版本、业务快照hash及完整结构化影响。业务快照排除变更审批本身及updatedAt/version；任意原业务内容变化（包括任务进度/计划/人员）令旧方案失效，需要重新申请。审批与应用都复核。并行申请可以存在，一份应用后另一份不得覆盖新版。

每单最多20条变更、同时最多10份待决提案。提交提案后聚合不超过768KiB，后续决策上限1MiB，为待决方案批准/撤回预留空间。达到上限走有关联的后续需求，不删除旧历史。已应用变更的approved需求也禁止用原plan-tasks重建任务，以免丢失承诺基线。

## 权限与独立性

需求方requester+request或manage可申请；执行方dispatch可申请。业务批准需需求方manager或requester+request；执行批准需执行方dispatch。批准人均不得是申请人或任何受影响任务的当前/历史贡献者，两侧不能是同一人。应用只允许执行方dispatch。

每次请求复核当前身份与原单可见范围。应用事务再次解析历史批准人的当前工作流成员/绑定及权限；已撤权批准不继续生效。源站外部权限仍遵守BFF每次请求检查和45秒来源令牌的既有边界，不声称跨库即时原子撤权。

## 原基线与绩效

第一次应用时保存原任务title/points/dueAt及首次变更ID；每次变更保存before/after、原因、双方批准和应用人/时间。原需求文字保存首次基线。已验收任务与旧贡献事件从不修改。

后续验收事件增加原始点数/原期限、当前有效期限和变更ID。现有绩效dueAt继续使用原始承诺，不因为延期自动消除迟到；points使用独立批准后的最终工作量，并保留originalPoints供核对。延期豁免/绩效纠错仍走现有受控纠错，不将申请原因自动当免责。前端显示原期限与现期限。

## 联动

不自动改排期、工时、执行人、附件或Naumi积分。影响报告列受影响下游依赖、点数变化、计划结束晚于新期限及后续任务期限早于前置的冲突；负责人明确审核后再安排排期。应用保留原执行状态/进度/来源链接。规范和商品快照不换版；复核既有品牌规范有效性。站内通知仅发送给当前仍可见原单的相关人员，外部钉钉沿用已配置连接器。

## 兼容与启用

schema33增加runtime changes_enabled，默认false。正式启用经changes-enable-plan/changes-enable与预览hash、明确全部读写进程升级确认，minimum_reader/writer均至少33。旧32就绪和请求门禁拒绝，不降低floor或回灌库回滚。新进程漏配同样拒绝，工作流服务未启用时动作503。实际schema8/原Excel与人员候选不迁移。

## 验收清单

独立批准/双侧分离/跨团队、旧版本/进度改变/并行应用、已验收与评审保护、延期原期限绩效、点数与历史、审批撤权、审计失败全回滚、命令重放、原API/BFF与原页面、运行门禁与旧程序拒绝。源码固定、原数据保留与实际副本回滚另附本轮VERIFICATION.txt。整体目标ACTIVE，正式员工与生产发布保持独立门禁。

## 实施与集中验证记录

- 工作流使用原command/detail接口，新增`POST /v1/change-preview`与原生BFF `action=change-preview`；服务端detail投影当前批准/应用按钮资格，换账号/团队和关闭/更换弹窗令旧请求失效。原需求与任务详情增加“需求变更”，支持字段表单、差异、两侧批准、拒绝/撤回、应用与记录。
- 网络响应丢失保留同一个commandId及已冻结输入，原请求重试只增加一份变更。方案内容变化不隐式沿用旧批准。移动端390px差异表无页面横向溢出；时间按上海时区显示，原始时间字符串仍存事件。
- 服务集中回归覆盖并发同命令只应用一次、不同任务已验收保持、变更影响依赖、事务内通知故障整体回滚及原dueAt迟到事实。原生BFF隔离fixture和真实Next均覆盖完整申请/双人批准/应用。
- 开发运行包51组，包括实际固定旧32在启用33前可用、启用后readyz与业务请求503；漏配changesEnabled的新版进程同样拒绝。真实Next36组和完整锁定依赖类型检查通过。最终固定版结果见VERIFICATION.txt。
- 浏览器19项通过，覆盖真实UI提交、响应丢失/重放、两独立账号批准、实际字段应用、原期限保留、换账号清屏、纯文本转义、桌面及390px。T3 snapshot连续两次15秒超时、evaluate同样超时，另一内置iab不存在；按工具约定改为独立headless Chromium新profile，通过Playwright管道控制，不用CDP、不接用户Chrome。安装了本机测试专用headless shell，未更改项目依赖。
- 首次运行包仍断言27模块（实际新增后28）、测试配置过早带changesEnabled，已按阶段正确修正。真实低权限Next检查发现runtime_installation上FOR SHARE需要写权限；改为持共享迁移advisory锁+只读SELECT，不扩大运行数据库权限。浏览器首次对个人账号错误等待企业工作区，改为验证其没有工作区及清空旧弹窗。失败日志保留，生产门禁未放宽。

本轮不调用47生产API、源目录/原Excel不修改，不开启真实工作流或改本机18482/18494进程。schema33仅在隔离库执行。M12仍待商品/规范/依赖结构换版、取消/暂停申请、离职候选与交接资料确认；全目标ACTIVE。
