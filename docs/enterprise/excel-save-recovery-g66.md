# G66 Excel轻编辑可靠保存、冲突留存与显式重试

日期：2026-10-20。任务分支：`codex/enterprise-workflow-foundation-20261016`。

## 目标和发现

承接G65，完成G62 Excel轻编辑自身的失败恢复。用户继续填写人员花名表，本模块不写身份绑定、不连接生产、不启动完整Office适配器、不迁移真实工作库。

原保存方法虽保留pendingSave，但保存失败后仍可修改工作簿；再次保存会随编辑签名改变而生成新命令，旧命令已提交与否并未核对。原方法调用sgCommand把写与刷新合在一个异常路径，已提交后读失败不够明确。并发修改仅提示关闭重开，没有在原窗口保留、核对无关变化和导出稀疏修改的完整路径。

## 产品规则

### 固定一次保存尝试

首次保存固定原文件引用、打开时整份附件引用、所有稀疏单元格修改、createdAt、清单上传字节、上传文件名、commandId、expectedVersion和完整命令。仅显式用户操作发起请求，无自动写重试。

1. **结果未知**：上传或关联命令网络失败、超时、408、5xx及幂等指纹异常，保留同一保存尝试。锁定修改、撤销、重做、切换编辑和公式栏输入；即使重新选中单元格也保持锁定。可导出修改清单，并按原字节/原命令核对。
2. **确定拒绝**：400/403等明确未执行，解除编辑锁，允许修正后使用新命令；不复用不同内容的旧commandId。
3. **已提交但读失败**：显示“Excel副本已保存，列表刷新未完成”。只重复GET，既不上传第二份清单也不提交第二次关联。
4. **成功刷新**：读取最新工作表用于列表展示，但编辑器的已打开文件版本仍对应刚保存的引用和提交版本，避免把尚未载入的新版本当作已合并的工作簿。

### 冲突核对与显式重试

版本冲突后只读读取最新工作表。只有以下条件全部满足才提供“基于最新版本重试”：目标行和附件字段仍可编辑，目标引用只存在一次，文件kind/id/name/excelRevision与打开时完全相同。

这说明变化发生在其他位置或其他附件上，不是同一工作簿的内容冲突。重试保留最新附件列表，只替换目标引用；用户确认后生成新命令ID和最新版本，再经服务器CAS提交。核对后再发生竞争，重新核对，不绕过CAS。

目标工作簿已有不同副本、被移除、字段/记录删除时不直接覆盖或复活引用。当前实际编辑仍留在窗口，可导出后核对同事版本。冲突后继续输入会立即作废旧核对结果，包括公式栏中尚未按回车的输入，防止旧结果提交盖掉新输入。

### 修改留存与离开

- XLSX/XLSM仍可导出实际编辑文件，沿用原样式/图片保留与原生重算标志。
- 新增“导出修改清单”：JSON包含原文件kind/id/name、parentRevision、Sheet/单元格/类型/值和时间。旧XLS同样可留存稀疏修改；不把JSON叫作已合并Excel文件。
- 结果未知的离开弹层明确说明失去本窗口核对信息；已提交但未刷新的关闭弹层明确“内容已保存”。放弃与保存后关闭沿用原独立确认。
- 无localStorage/sessionStorage草稿写入。窗口崩溃或关闭后的自动恢复、清单重新导入与逐单元格跨版本合并尚未实现。

## 实现结构

新增`excel-save-model.js`（引用核对和不可变manifest）及`excel-save-ui.js`（保存状态机/核对/导出）。删除旧exSaveRevision的实现，原函数仅委托新模块；不并行维护两套保存逻辑。

`excel-preview-ui.js`在打开时记录openRefs，在输入/撤销/重做边界检查锁状态并使旧比较失效；状态展示和恢复面板共享当前exSession。所有网络写入仍使用原sgRequest、原CSRF/会话与服务端权限/CAS/幂等。未改工作流后端或文件存储结构。
