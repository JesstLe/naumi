# G21 团队工作日历与周负载

## 需求与边界

原员工周排期把预计工时均分到所有自然日，休息日和调休无法表达。本模块保留原18482浅色界面及现有任务计划字段，增加团队标准工作日历。团队日历表示每位成员的标准可用时段总量，不表示整个团队的总产能，不代表实际出勤、加班或绩效。

每周周一至周日各配置0–1440分钟，按15分钟粒度；0为休息日。日期例外按上海公历日期覆盖该天标准，可用于全团队休假、调休上班、半天办公，附简短说明。最多366个例外日期，不从国家或公司名称推断法定日历。个人请假审批/个人产能覆写及拖拽改期另列后续，不伪称本轮完成。

## 默认与算法

没有发布日历时revision0/configured=false，保留旧的自然日均分及每天8小时参考，UI明确未配置。首次配置表单可提供周一至周五8小时的待确认值，但不自动保存。

已配置时，对任务整个计划区间（最多366天）逐日计算可用分钟数M[d]，任务预计工时H分配为H×M[d]/sum(M)。周查询只截取显示范围，分母仍使用完整任务区间，跨周不会重复分配全部H。若全区间sum(M)=0，该任务进入“计划内无工作日”提示，不将工时伪记为已排完0。0工时、不设计划、未分配任务与个人超载分别处理。

同一人多任务按日累加，与所在执行团队该日标准容量比较；未分配不称个人超载。跨团队可读任务沿用实际承接团队日历，按团队+执行人分组，不能套用提报团队的日历，也不合并两个团队的容量。只返回当前可读任务与相关容量/日历版本，不因此授予其他团队编辑日历权限。

修改日历只改变当前周负载展示，不改变任务起止、承诺日期、预计工时、执行状态、已验收事实或绩效。历史日历版本可查；历史周按当前版本查看时明确口径，不作为冻结考勤台账。

## UI与接线

原团队排期增加“工作日历”；成员只读，主管编辑每周分钟与日期例外，预览影响后确认保存。周视图显示日负载/当天容量、休息日、日历版本与无工作日任务提示。所有数据走原Naumi会话和企业/团队BFF；切号、切团队、关窗丢弃迟到响应；不写浏览器正式日历缓存。
