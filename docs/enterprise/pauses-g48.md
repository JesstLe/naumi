# G48 业务暂停、恢复与排期联动

## 业务规则

需求级暂停不同于个人任务阻塞，也不同于取消。只允许active→paused→active，不清空原任务状态/执行人/百分比/文件，不自动延长截止时间或抹去迟到事实。暂停申请期间仍正常执行，只有双方独立批准并应用后才暂停。恢复也需独立双侧批准，执行方manage明确确认当前排期、人员和外部业务。

短期暂停保留人员WIP承诺和计划工时预留，避免把原任务隐藏后制造虚假空闲。周排期显示暂停状态及保留预留，不占用新的第二份额度；恢复时重验当前WIP上限和执行人资格。需要释放人员并转交的情况走明确交接/取消流程，不默默释放。暂停期间可由dispatch通过原排期编辑/拖动影响预览修改计划，改动使旧恢复审批失效；原dueAt不自动改动，延期走独立需求变更。

## 状态与权限

WorkOrder.status新增paused；pauses保存20条以内暂停/恢复申请，pausePeriods保存应用暂停时间/申请ID及恢复或取消结束时间。request/approve/reject/withdraw/apply-pause带mode pause/resume，既有两侧权限与独立性规则沿用取消审批，申请人/本单贡献者不能批准，两侧不同人；应用重验历史批准人资格。一次只允许一个待决申请，不自动猜测人事身份。

## 联动与数据

影响预览复用订单锁内文件/上传/项目/渠道快照，不持久化隐藏关联详情；保存任务原计划/估时/截止时间。暂停后执行动作、交付登记/分片、新渠道发布、交付审核拒绝；历史文件下载和渠道实际回执保留。SLA暂停期间不产生新催办，恢复后仍按原截止时间计算。暂停/恢复不重放Naumi收费任务、不改变积分、不撤销外部发布。

暂停期间待交接保留但不能接收，恢复后继续原清单；可转明确取消，由G47收口待交接和变更。取消时关闭开放暂停区间、终止待决恢复申请。工时可补录确实参与的历史日期；整天处于暂停且非已验收任务的新增工时拒绝，暂停/恢复边界日保留人工申报与独立审核。已有工时/绩效事实不改写。

## 运行与界面

schema36 pauses_enabled默认false，显式plan/enable、reader/writer36，真实旧35与新版漏配均拒绝。原需求/任务抽屉加入暂停/恢复审批、影响、独立批准与历史；未知响应同命令重试，账号/团队切换清屏；浅色桌面和390px。需求列表/任务/周排期清晰显示暂停，不用任务原in_progress标签冒充订单仍可执行。
