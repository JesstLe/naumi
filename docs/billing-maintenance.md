# 计费后台维护

管理员登录后打开 `/admin/billing`。功能计费单位支持按图片、项目或整个任务；价格支持固定积分、质量加分辨率、分档和成本加成；复杂条件按优先级匹配第一条规则。用户组当前为 default，不能把未接入的分组当成已实现权限。

修改后先模拟报价和部分成功/失败结算，填发布说明、查看逐项旧值与新值，再发布。并行发布冲突时草稿保留；查看服务器版本后可以合并草稿，其他管理员的未冲突改动保留，同字段冲突会明确提示。恢复旧版本会创建一个新版本，历史记录不会覆盖。

新价格影响新任务。任务创建后冻结价格、成功计费范围、失败收费、自带接口比例、预占比例与扣款顺序。旧订单按原金额、积分与到期规则付款到账。配置读取失败时暂停新的收费请求，不套用旧缓存价格。供应商链路沿用原配置，本模块不启用 Router。

后台商品只开放原积分包；历史订阅与授权仍停售。购买还受服务器 `NAUMI_PUBLIC_COMMERCE` 总开关约束。注册赠送、新兑换码到账有效期、人工赠送有效期均可配置；码的领取期限与到账积分有效期是两件事，已发兑换码保持原到账规则。

供应商成本项支持 CNY、USD、积分，USD 成本加成须有人民币折算率。数值都是估计，不是供应商发票。具体成本键依次匹配 `provider:model:quality:resolution`、`provider:*:quality:resolution`、`*:model:quality:resolution`、功能标识、`*:*:quality:resolution`。成本加成使用表单选择的成本键；固定价下只改成本不会改变扣费。兑换码发行估计使用 `redeem:credit:estimate`，单位成本乘发行积分数；缺配置显示未记录。

公开接口不暴露成本。BI 按币种分开汇总估计成本，未知值不按零成本推算利润。历史积分估计不属于人民币成本。旧高质量累计付款门槛是保留兼容字段，当前系统没有启用它的准入限制；需要按付款金额区分价格时，使用条件规则的累计付款门槛。

结果未知时保留预占，后台人工核对须记录供应商结果/产物依据及说明。核对只处理账务，原任务恢复链路处理媒体；不得为凑齐结果重新请求供应商。网络中断后浏览器保留操作编号，已创建任务回放原提交响应；没有提交回执的请求保持待核查，可通过原任务列表查找结果。

回滚不得直接让旧程序接管已调价的新任务。发布前备份配置、数据库和媒体，保留固定旧镜像。回滚前暂停新收费提交、核对在途任务及已调价配置；保留所有新账务记录。只有已验证的兼容场景可以自动回滚。

性能验证输出在忽略目录 `output/billing-20261003/`。本地报价+预占+结算，50 次预热后各测 500 次：串行 p95 约 8.29ms，并发10 p95 约24.54ms，错误为0。每个新任务完整配置读取1次，结算0次；并发仍使用原5连接池。相同完整扣费回归从4.37秒/3558次SQL最终复测为7.87秒/4825次SQL，单次完整回归耗时约增加80%（此前测得4.98秒，完整回归受环境及初始化影响明显）；包含新增事务、幂等和成本审计，不是单条配置查询耗时。测试为本机fixture，无真实供应商，不能据此声称线上延迟不变。当前功能最多100条规则，匹配为O(R)，价格键查找为O(1)，成功结果处理为O(图片数)，不会扫描历史版本。
