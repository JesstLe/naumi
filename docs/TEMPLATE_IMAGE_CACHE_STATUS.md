# 提示词模板图片持久化缓存

更新时间：2026-09-14

## 已实现

- 模板图片字节不写入 PostgreSQL，而是复用现有持久化存储：本地模式写入 `MEDIA_DIR`，云端模式写入 R2。
- 以图片内容 SHA-256 命名为 `templates/cache/<sha256>.<ext>`，相同内容自动复用同一个对象。
- 数据库保存稳定图片地址，并保留原始来源、缓存时间、失败原因和最后尝试时间。
- `/api/templates` 与首页不再把第三方图片地址直接交给浏览器；远程图片统一走带模板 ID 的同源懒缓存入口。
- 懒缓存成功后回写 `app_templates.image`；使用“模板 ID + 当前图片值”条件更新，避免覆盖管理员同时进行的编辑。
- 管理后台增加“缓存模板图片”，每批 12 张、最多 4 路并发，可继续处理或重试失败项。
- “同步官方模板库”完成后自动进入图片缓存流程。
- 官方模板导出遇到 `/media/...` 相对地址时转换成官方站绝对 URL，避免自部署实例误请求自己的同路径文件。
- 管理员通过 JSON 设置远程图片 URL 时，先缓存成功再保存；上传文件仍直接进入持久化存储。

## 安全与容错

- 仅允许 HTTP(S) 公网图片，禁止凭据 URL、非标准端口、localhost、内网/文档保留 IP 和危险重定向；兼容本机代理常用的 `198.18.0.0/15` Fake-IP DNS。
- 每次重定向都重新校验目标域名与解析地址。
- 响应体最多 12MB，并同时校验响应类型和 PNG/JPG/WebP/GIF/AVIF 文件签名。
- 单图下载超时为 25 秒；失败只记录状态，数据库继续保留原图片地址。
- 同一源 URL 在单进程内合并并发请求；本地使用 URL 哈希索引避免数据库不可用时重复回源。
- 本地 `/media` 与 R2 对象均使用一年 `immutable` 浏览器缓存。

## 数据结构

`app_templates` 启动时自动补齐：

- `image_source`：原始第三方地址。
- `image_cached_at`：最近成功缓存时间。
- `image_cache_error`：最近失败原因，成功后清空。
- `image_cache_attempted_at`：最近缓存尝试时间。

## 验收项

- `npx tsc --noEmit`
- `npm run build`
- `git diff --check`
- 隔离实例验证模板 API 输出同源代理、首次请求落盘并回写数据库、后续请求跳转稳定 `/media/templates/cache/...`。

## 后续运维

- 首次上线后在“模板管理”点击“缓存模板图片”，将历史远程封面批量迁移。
- 也可在服务器运行 `node scripts/template-image-cache-prewarm.mjs http://127.0.0.1:3012`，无需管理员凭据即可按公共模板列表完成预热。
- 失败数量不为 0 时可再次点击重试；原图链接始终保留在 `image_source` 或当前 `image` 中。
