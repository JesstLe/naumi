# Bug 与性能排查记录（2026-09-28）

## 本轮目标

围绕最新的视频生成链路和高频页面做一轮“先运行、再定位、后修复”的审计，优先处理会导致功能不可用、积分错误或并发重复产物的问题；性能项先形成可量化基线，不在没有用户体验证据时做大范围拆包。

## 已确认并修复

1. **视频任务表缺失**
   - 现象：代码会读写 `app_video_tasks`，但 `ensureSchema()` 没有创建该表；当前运行库实查为 `missing`。
   - 影响：配置视频供应商后，创建上游任务成功也会在本地入库阶段失败，前端无法正常轮询。
   - 修复：补齐表、索引和并发/退款状态字段，保持首次访问自动迁移。

2. **视频成功后积分只预扣、不结算**
   - 现象：创建任务调用 `reserveCredits()`，成功分支没有扣减积分本金，也没有释放 `credits_used` 占位。
   - 影响：余额被长期占位，流水缺失，后续任务可能误报积分不足。
   - 修复：成功完成时在事务内锁定任务，使用稳定流水 ID 只结算一次，并清理生成预留记录。

3. **失败退款取当前环境价格，不取任务实际价格**
   - 现象：失败分支读取 `VIDEO_TASK_COST` 当前值；若任务创建后改价，会多退或少退。
   - 修复：任务行返回并锁定创建时 `cost`，失败事务按实际成本只退一次。

4. **并发轮询可能重复下载和重复落视频节点**
   - 现象：同一任务的多个 GET 都能看到 `processing` 并同时完成落盘。
   - 修复：数据库短租约领取轮询权；产物 ID 改为由任务 ID 稳定派生；成功结算和失败退款均采用行锁与幂等状态。

5. **异步任务缺少崩溃恢复预留记录**
   - 修复：创建时写入 `app_gen_reservations`，轮询时续期，成功/失败清理；进程在上游调用期间退出后可由现有清扫器释放占位。

6. **三个 Hook 依赖/错误解析问题**
   - Dashboard 登录弹窗 effect 改用真实依赖 `openAuth`。
   - Dashboard 数据源使用 `useMemo`，避免每次渲染制造新空数组并令下游筛选重复计算。
   - OAuth 错误参数不再二次 `decodeURIComponent`，避免带 `%` 的已解码参数触发异常；同时补齐 `t` 依赖。

## 性能基线

- 生产构建通过；`/canvas` First Load JS 约 **371 kB**，路由自身约 **128 kB**。
- 当前画布是主要前端性能候选，但包含 React Flow、模板、账户、支付与多种编辑弹窗。下一轮应先用浏览器 Performance/React Profiler 确认首开耗时和交互长任务，再按弹窗与低频面板做动态加载，避免只为包体数字进行高风险拆分。

## 文字节点 Dock 同步修复

- **现象**：文字节点卡片已有 `content`，点击节点打开底部 Dock 后输入框为空。
- **根因**：`canvas-client.tsx` 有两段切换文字节点的 effect。第一段先写入 `selectedText.content`，后面的旧 effect 又用 `node.prompt` 覆盖；已生成节点通常没有 `prompt`，因此最终显示为空。
- **修复**：合并为一个同步入口，优先使用 `content`，无内容时回退 `prompt`，删除会覆盖输入的旧 effect；同时增加回归断言，刷新后重新选中文字节点时 Dock 必须包含节点正文。
- **验证**：`scripts/canvas-text-node-smoke.mjs` 11 项通过，最后一项实际断言刷新后 Dock 值等于已生成文本；`npx tsc --noEmit` 和 `npm run lint` 通过。
- **仍存在的独立构建问题**：`npm run build` 在收集页面数据阶段报告 `/api/admin/brand-logo`、`/api/agent/verify-image`、`/api/aplus` 的 `.next` 页面模块缺失；这些路由源码存在，属于当前构建缓存/路由产物问题，不是本次 Dock 修复引入。

1. **文字节点参与多选拖动后刷新回位**
   - React Flow 从已选节点本体开始拖动时不会触发 `onSelectionDragStop`，旧实现只持久化图片集合，还会把 `text-*` 误发到作品坐标接口。

   - 原生媒体控件、时间轴、抽帧与预览区域此前会把交互继续交给 React Flow；视频又永久 `tabIndex=-1`，键盘播放入口不可达。
   - 媒体交互面统一使用 `nodrag nowheel nokey`，选中视频可聚焦，Space 在媒体层内完成播放/暂停并停止向画布传播。

## macOS 节点 Dock 提示词高度修复（2026-09-29）

- **现象**：macOS 端点击图片、占位或文字节点后，Dock 的提示词输入区在部分窗口位置或原生纵向缩放状态下会被 flex 布局压缩成约两行。
- **根因**：输入区虽有自适应脚本，但文字 Dock 的容器最小高度仅 142px，手动尺寸同步又允许输入区降到 54px；同时未展开状态的 `max-h-36` 会把脚本写入的高度再次限制为 144px。节点靠近窗口底部时，Dock 也会优先放在只有约 180px 的下方空间。
- **修复**：图片、占位和文字提示词统一采用 112px 最小高度；文字输入按内容增长至 240px 后内部滚动；Dock 最小高度提升为 218px，拖动缩放也不能退回两行；停靠算法优先选择可容纳完整编辑区的一侧。
- **交互结果**：短提示词默认约五行视野，长提示词自动增高且有上限，用户仍可纵向调整或切换窗口化编辑，不会遮满画布。
- **回归**：`scripts/canvas-text-node-smoke.mjs` 使用 macOS Chrome UA，覆盖默认高度、强制缩小保护、长文本自适应、手动放大和窗口化编辑。

## Windows / macOS 选中节点 Dock 响应式安全区（2026-09-29）

- **生产基线**：在现网复杂画布中，390×844 时选中节点 Dock 会覆盖顶部项目区，节点工具条被裁切；1093×614 时选中节点及 Dock 会向右越界。本轮不修改线上业务数据，只以截图作为修复前基线。
- **根因**：Dock 按完整画布宽高计算，只保留 8px 边距；低高度窗口在节点上下都放不下时会退化为 `top: 8px`。React Flow 又会在窗口缩放后保留旧 viewport，导致节点留在新视口之外，而 Dock 被单独夹到边缘。
- **修复**：为选中节点悬浮层统一加入顶部、左右和底部 safe area；顶部在桌面保留 64px，在窄屏保留 108px 以容纳第二行账户操作；底部为视图工具条保留空间。Dock 上置时额外为节点工具条预留空间，两侧都不足时退化为安全区内的底部 sheet；1093×614 这类“宽但矮”的窗口会在空间允许时把 Dock 向右避开左下工具条，获得完整纵向布局。窗口尺寸变化时只做最小 viewport 平移，保持当前缩放和选中节点可见，不改节点持久化坐标。
- **交互修复**：顶部节点工具条改用顶部 safe area；展开文字编辑器也遵守四边安全区。单选文字节点不再重复显示“批量操作栏”；真正多选时隐藏单节点 Dock/工具条，批量栏固定在视图工具条上方并保留居中动画。缩放菜单打开时临时提升视图工具条层级，避免菜单项被 Dock 拦截。
- **浏览器回归**：`scripts/canvas-responsive-dock-smoke.mjs` 使用 macOS / Windows Chrome UA，覆盖 1600×1000、1366×768、1093×614、1024×768、768×900、390×844 六档视口，断言 Dock 不越过顶部/左右/底部安全区、不覆盖项目 chrome、账户操作和节点工具条，并断言选中节点仍在横向视口内；另在 390×844 真正多选两个文字节点，断言批量栏不越界、不覆盖左下视图工具条，且单节点 Dock/工具条已退出。每个组合输出真实截图到 `output/canvas-responsive-dock-smoke/`。
- **剩余边界**：UA 自动化可以验证布局与键位分支，但不等同于实体 Mac 的 Safari/触控板验收；部署后还需在现网“产品.jpg”复杂画布复验 390×844、1093×614，以及 macOS Safari 的窗口缩放与触控板平移。
