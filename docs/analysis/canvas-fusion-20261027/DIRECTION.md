# 按 Naumi 原生逻辑决定参数与后续方向

依据：用户2026-10-27确认的[融合原则](../../CANVAS_CAPABILITY_ADAPTATION.md)，以及本轮固定main的[能力矩阵](CAPABILITIES.md)。以下是设计建议，非已完成代码或用户已批准的开发排期。

## 1. 参数不是全搬，也不是全删

| 参数/状态 | 分类 | 原生呈现方向 | 当前源码 |
|---|---|---|---|
| 视频描述、原文对白、负面要求 | 用户创作内容 | 主创作栏或对应文字/镜头节点；不重复维护副本 | `video/prompt.ts`、`script-assets.ts` |
| modelId、providerId、wire profile | 模型选择＋内部路由 | 用户选择模型；渠道/协议/凭据留后台，默认映射继续冻结 | `api/video/catalog`、`providers/wire.ts` |
| 文生/图生/首尾/混合/编辑/续写 | 业务意图＋能力模式 | 以用户想做的事和当前输入组织，内部映射合法mode；首尾角色不能靠猜 | `client-settings.ts`、`contract.ts` |
| 时长、画幅、分辨率、是否生成声音 | 真实结果参数 | 常用控制集中，由实际模型能力限制选项 | `parameter-panel.tsx`、`parameter-options.ts` |
| 精确宽高、水印、种子等 | 模型相关高级参数 | 仅真实支持时出现，按用户可理解的含义命名 | `settings-panel.tsx`、`contract.ts` |
| first_frame/last_frame/source_video等职责 | 真实引用语义 | 在连线/素材标签中表达，可修改与交换；不能为了少字段丢掉语义 | `reference-list.tsx`、`node-submission.ts` |
| orderedInputs.id/nodeId/value、分类序号 | 内部素材绑定 | 系统管理稳定ID；UI选择正式素材，避免用户编辑URL/内部ID | `references.ts`、`reference-materialization.ts` |
| `{{ref N}}`、图片N/视频N/音频N | 编译格式 | 原生@/素材标签表达；兼容旧保存内容，提交时编译供应商所需格式 | `compact-composer.tsx:34`、`prompt.ts` |
| 镜头名称、描述、秒数、角色状态 | 创作结构 | 可编辑镜头节点/段落；区分一段多镜头与多段制作链 | `shot-editor.tsx`、`canvas-video-tools.ts` |
| dependsOn、mediaBindings、runId | 内部执行图 | 连线/等待状态呈现；ID、绑定与恢复由调度层处理 | `canvas-workflow.ts`、`workflow.ts` |
| 相机、镜头、焦距、光圈、movement | 摄影意图 | 高级摄影控制；说明它实际编译提示词，和3D空间机位不是同一数据 | `camera.ts` |
| characterOrientation/character_orientation | 业务含义＋上游命名 | 统一“角色朝向/跟随图片或动作视频”，具体键由适配层处理 | `settings-panel.tsx:45-47` |
| providerOptions其他原始键 | 协议配置 | 优先提供已理解的业务标签；不因目录有key就照原名暴露 | `settings-panel.tsx:43-58` |
| operationId/idempotencyKey/revision | 幂等与并发状态 | 由应用负责，不作为普通创作参数；保存冲突给可操作反馈 | `video-node-schema.ts`、`node-submission.ts` |
| billingVersion/credits/冻结快照 | 系统计费与恢复 | 沿现有报价/授权边界，不引入一套上游确认流程 | `submission.ts`、`workflow-freeze.ts` |
| ComfyUI节点输入槽、工作流配方 | 专业配置 | 在自备工作流配置层维护；普通画布消费已配置的能力 | `byoc-settings.tsx`、`byoc.ts` |
| FFmpeg args、输出/辅助文件JSON | 专业表达与执行接口 | 常用裁剪/拼接/音量等转成原生操作；原生命令留专家/Agent路径 | `media-actions.tsx`、`media-engine.mjs` |
| 3D directorProject、上游message协议 | 上游工程与集成结构 | 先设计Naumi工程模型/引用/保存；不直接作为我们万能节点字段 | 原上游Director3D与旧设计第128行 |

**实现前验证**：每个设置先回答“影响什么结果、由谁维护、能否从现有节点关系派生、协议是否真需要”。不是字段越少越好，也不是字段越全越好。

## 2. 当前源码里已经能定位的交互整理点

### 2.1 引用双轨表达

紧凑创作栏插入 `{{ref N}}`，高级引用列表显示 `ref N · 类型N`，编译器再转换。底层表达能力完整，但用户要理解两套编号。后续可统一为Naumi原生素材标签/`@`；必须保持顺序、角色、旧内容兼容与真实媒体映射，不直接替换字符串后宣称无影响。

### 2.2 高级模型字段直出

`settings-panel.tsx` 对朝向做中文映射，其余模型参数标签直接使用key。这是具体可改的交互点，不需要重写契约或协议适配。先盘点当前实际发布目录，再给常用字段业务标签和合适控件。

### 2.3 媒体处理暴露JSON

`MediaActionsDialog` 把预设动作和FFmpeg/FFprobe原生JSON放在同一个处理方式选择中。底层能力可以保留，普通创作流程应以剪哪里、保留哪段声音、按什么顺序拼接等任务表达；专业入口按真实用户需要保留，不一刀切删除表达力。

### 2.4 工作台、节点高级设置与紧凑创作栏

它们已经复用较多设置逻辑，但操作入口和参数密度不同。先以画布日常创作为主线，确认共同业务状态与必要的差异；不要为了“统一”另建万能设置框架。

## 3. 建议的后续切片（供定方向）

| 候选切片 | 目标闭环 | 直接复用 | 真正要新增/重做 | 验收重点 |
|---|---|---|---|---|
| A. 现有视频体验原生化 | 选素材→描述/必要参数→生成→结果继续创作 | V01—V11、任务与媒体链 | 统一引用与@、模式/参数呈现、复杂情况反馈 | 同输入请求语义保持；首尾/排序/切模型/刷新/旧任务兼容 |
| B. 角色与场景资产 | 建身份/场景→绑定素材与状态→多镜头复用 | 图片/文字节点、elements、正式素材与剧本规则 | 角色/场景的最小资产模型、复用及状态变体交互 | 真正按身份引用；修改不误覆盖旧结果；无重复配置 |
| C. 原生3D导演台 | 引用角色/场景→摆位/机位→预览→图/视频回画布 | 上游成熟操作流程；适合的渲染/媒体基础 | Naumi工程保存、场景编辑与输出接线；明确可复用模块 | 关闭重开保持；多视角/结果关联；原画布可继续生成 |
| D. 原生音频节点 | 添加/导入音频→播放/编辑/引用→结果复用 | V19/V21/V22、媒体job、正式资产 | 独立节点交互；若需要配音/生成再接真实能力 | 不把“有播放器”当创作完成；保存/连线/裁剪/权限 |
| E. 可操作的视频制作链 | 剧本/镜头→依赖→执行/暂停→恢复→成片素材 | V12—V18、27个Agent工具、DAG | 用户可看懂的阶段和依赖操作；最少必要新UI | 按真实产物推进；单片段与多任务分开；未知任务不重复 |
| F. 多轨编辑器 | 放素材到轨道→裁剪/混音/转场→导出→回画布 | 媒体处理引擎、任务、素材与播放器 | 轨道工程/片段时间/混音/转场语义及原生编辑UI | 工程可保存恢复；预览与导出一致；长处理可取消 |

建议先完成A，或按用户指定优先做C；B/C/D/E的实际顺序由创作场景决定。**本轮不强行规定先开发全部角色/场景才能做导演台**，也不因为准备未来功能先造通用平台。

## 4. 每个切片交付前的集中验收

- 正向：输入→操作→真实任务/输出→回到原画布继续使用。
- 编辑：保存、刷新、复制/撤销、切项目与切账号，历史结果和用户后续编辑保持。
- 边界：缺素材、未知能力、加载失败、取消、待核查、过期引用、并发修改。
- 交互：桌面/窄屏、键盘、选中/连线、无冗余标签、必要错误反馈。
- 实际生成：适用时验证供应商受理、参数、结果媒体、存储和账务，不把HTTP200或固定素材测试等同于内容质量。
- 保护：原有生图、视频在途任务、作品/权限和冻结上下文不因新节点被覆盖。

不是每一处文案改动都跑全量构建；完成一个完整切片后集中验收，并更新实现记录。
