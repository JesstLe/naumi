# APIMart image2.5 系列：模型、参数与价格核查

核查日期：2026-10-08（Asia/Shanghai）。范围：公开模型页、价格页、API 文档。未发起收费调用，未修改应用配置或生产服务。

## 1. 模型 ID：3 个 model，4 种选择

|渠道|请求 model|version|官网描述|计费|
|---|---|---|---|---|
|原生 Flare|`gpt-image-2.5-flare`|不传|快速生成、批量创作|实际 token|

**重要：EXT 模型页明确提示「ext 渠道灰度升级中：目前仅部分账号已切换至 2.5，等待官方完成全部账号升级。」** 因而公开 ID、版本或价格存在，不代表本项目供应商账号已经执行 2.5。此项需要账号侧确认。速度、质量定位是供应商描述，不是本次实测结论。

## 2. 原生价格：输入和输出分开计费

两种原生模型单价相同。单位：USD / 1,000,000 tokens。

|项目|黄金|铂金|钻石|网站“官方价”|
|---|---:|---:|---:|---:|
|非缓存文本输入|4|3.8|3.6|5|
|缓存文本输入|1|0.95|0.9|1.25|
|非缓存图片输入|6.4|6.08|5.76|8|
|缓存图片输入|1.6|1.52|1.44|2|
|图片输出|24|22.8|21.6|30|

价格页同时展示供应商 Credits，数值为上表 USD 数值 × 10。例如黄金图片输出 240 Credits/M ≈ $24/M。**供应商 Credits 不等于 NAUMI 用户积分。** 当前公开页的“黄金价 当前价格”不能证明本项目账号会员等级。账号分组倍率、折扣可能影响实扣。

本次页面未列出 image2.5 独立的文本输出单价；不要套用其他系列的文本输出单价。

原生估算公式（仅在有真实且可区分的 usage 时使用）：

```text
USD = (非缓存文本tokens × 文本价
     + 缓存文本tokens × 缓存文本价
     + 非缓存图片tokens × 图片价
     + 缓存图片tokens × 缓存图片价
     + 图片输出tokens × 输出价) / 1,000,000
```

若输入总量已经包含缓存命中量，先拆分，不能再次叠加。单纯 `input_tokens/output_tokens/total_tokens` 未必足以区分文本、图片及缓存，因此不能据此假装精确还原输入费用。供应商单任务总费用存在时优先采用，不再额外加 token 费用。

## 4. 请求参数逐项对照

两渠道均使用 `POST https://api.apimart.ai/v1/images/generations`，JSON 请求体、Bearer API Key。以下枚举大小写按各自文档保留。

|字段|原生 Flare / Sunburst|EXT Flare / Sunburst|费用影响及注意|

|`version`|未列出|`flare/sunburst`，默认 flare|EXT 两版本同价|

### 精确像素与编辑约束

- 原生自定义宽高均为16倍数，单边≤3840，长短边比≤3:1，总像素655,360–8,294,400；高于2560×1440标为实验性。
- 原生编辑建议不传 size，按输入比例与 resolution 推导；若要求明确规格，应选择对应已声明参数并验收实际像素。
- 原生参考图需公开直链，本地图可先用 `POST /v1/uploads/images`，使用返回顶层 `url`。不能将本机/NAS私网路径直接传给公网供应商。
- 原生蒙版需 Alpha PNG，与第一张原图宽高完全一致；Alpha=0表示修改；一次一张。边界外像素不保证完全不变。
- 文档蒙版大小说明同时出现50MB及4MB，本期按更严格4MB准备，实际上限待确认；远程下载默认20MB/60秒，具体部署可能覆盖。
- 原生没有流式部分图支持。EXT 的蒙版、精确像素、透明背景、压缩及输出格式均未在本次文档声明。
- `quality=auto` 不是固定 medium：原生按当前尺寸 max 预留，完成后按真实用量退差；对可控报价应显式指定质量。

## 5. 任务费用与 NAUMI 加价规则的关系

- 原生当前提交示例读取 `data[0].task_id`；EXT 推荐 `X-APIMart-Response-Version: 2026-07-27` 和 `Idempotency-Key`，202 示例读取 `data.id`，顶层还有 `request_id`。EXT 页面另有 code=200 的说明，适配应覆盖文档里的兼容结构，不假定一种形状。
- `GET /v1/tasks/{task_id}` 的结果读取 `data.cost`、`data.credits_cost`，有 usage 时保存真实 usage。任务文档称前者任务扣费金额，后者扣费积分；结合价格页的美元与 Credits 配对保留 USD / 供应商 Credits 两种口径，接入时再核验真实账号响应及账单。
- 任务响应示例里的 `0.01325`、`0.2`、`0.15` 只是结构样例，绝不是实际固定单价。
- 原生文档称失败退预扣；业务上仍应保存费用/退款确认状态，不单凭 failed 把供应商成本写成0。
- 原币实际总成本优先；缺失时有充分分项 usage 才估算，否则待确认。不能用账户余额差额归属并发请求。
- 人民币成本=USD成本×锁定的有凭据换算因子；用户售价=人民币完整API成本×锁定倍率1.5。尚未核验本项目实际会员、充值成本、汇率、积分兑换，故本报告不列确定人民币售价。
- 1.5倍率表示加价50%，售价减API成本的毛利率约33.33%，不是扣全部费用后的净利率。输入输出总成本0.50元→售价0.75元只是算术示例。
- 用户已有 medium 上限要求：原生 low→low，medium及更高档→medium后，上游调用/报价/结算按有效参数；EXT未声明quality，可保留前端请求质量并在上游过滤，但不能虚称EXT执行了原生medium质量。
- 本报告没有确认生产当前默认模型，不能凭公共目录自动替换或启用生产预设。
