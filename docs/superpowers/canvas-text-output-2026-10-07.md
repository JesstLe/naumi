# 画布文字输出契约修复（2026-10-07）

## 已核验原因

用户的文字节点包含商品摄影画面描述和参考图。生产的两笔调用有输出 token，但 `message.content` 为空。使用同一账户已保存的文字要求及托管参考图，经过同一个冻结的 `vision.reference` 配置复现：上游 `finish_reason=stop`、正文为空、`message.images` 返回图片。该问题不是 token 上限耗尽，也不是漏发请求。

单独添加 `modalities: ["text"]` 后仍返回图片；不能仅依赖供应商支持这个参数。补充文字编辑系统约束及用户输入语义包装后，同一视觉用途返回 434 字正文，耗时约 12 秒，不再包含图片。探针仅记录字段类型、长度及 token 数，不保存响应正文、图片或推理。探针直接调用供应商，会产生供应商用量，但未操作用户钱包或文字节点。

## 实现

- 通用生成、竞品反推、智能帮写保持原系统任务，增加纯文字输出约束。画面描述是待编辑文本，不是执行生图命令；参考图仍发送给原冻结视觉模型。
- 画布图片助手同样限定文字输出，不移除图像输入或改模型配置。
- 两个接口设置 `modalities: ["text"]`，保持原 `max_tokens=1800`；不添加付费重试或备用模型，legacy SDK 也禁用隐式重试。
- 共用正文解析器只读取显式文字块，忽略推理、图片、工具调用；识别图片、审核拒绝、空正文和无正文的长度截断。错误日志只含路由及枚举代码。
- 返回图片的任务不成功落字或正常结算，保留现行未知结果 hold 及同 ID 禁止重复提交，历史 hold 不改动。

## 验收与发布

- 基线使用真实 route 和本机模拟供应商复现图片输出，HTTP 502；修复版本输出正文，单次调用，结构化文字、纯推理、图片、拒绝、空正文、长度截断均覆盖。
- 数据库回归覆盖三种文字模式带参考图，以及助手 SSE 图片输出、收费、冻结报价和重放。
- 独立副本回滚恢复原 route 字节及 HTTP 502 行为，不回滚实际工作区。
