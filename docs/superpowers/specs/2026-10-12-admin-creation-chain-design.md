# 管理后台创作全链路详情设计

日期：2026-10-12

状态：完整范围已获用户确认；书面设计待审阅，尚未进入产品实现或发布。

任务分支：`codex/admin-creation-chain-20261012`

代码调查基线：`b1d10c21bcfc36ecbbfcc0bda6200b890b4a2a2f`。

## 1. 目标与验收口径

用户要求：“管理后台需要可以看到用户上传的是什么，要求是什么，结果是什么，全链路”。用户已确认覆盖所有创作入口，采用以下统一详情：

**上传原图、参考图、蒙版等输入 → 用户原始要求和参数 → 模型与工具执行步骤 → 图片、文字、视频等结果 → 失败原因和积分结算。**

管理员从用户、业务任务、作品或对话记录进入同一条创作链，能够核对实际收到的素材、原话、实际执行及实际交付。成功、失败、取消、部分成功、待核对和零积分操作均能查看；历史资料不足时逐项说明“未记录”，不能靠名称、时间接近或当前配置推断。

“上传”指服务器已收到并接受的文件或素材引用。仅在浏览器选中文件、尚未提交的内容无法留存。非创作操作如登录、充值、导航、移动画布节点不新增创作任务；现有安全访问日志继续承担其审计。

本设计不增加后台重跑、重新生成、替用户发起工具调用、批量导出用户素材等功能。查详情和播放媒体均为只读，不触发模型消费或补结算。视频记录和播放器纳入功能，不以启用此前延期的视频供应商为前提。

## 2. 现状与选择

| 现有能力 | 可复用部分 | 当前缺口 |
| --- | --- | --- |
| BI 业务任务 | 图片异步任务、画布图片任务、视频任务及状态、积分 | 同步工具、零积分文字和其他创作入口不完整 |
| BI 图片与来源 | 作品、准确的任务来源、同账号关联 | 缺少统一输入、要求、步骤、结果详情 |
| BI 对话 | Agent、创作聊天的用户和助手文字 | 参考素材、工具步骤、产物及按轮次关联未展示 |
| 图片异步任务 | 冻结 payload/snapshot、持久化的输入 Buffer 引用 | Buffer 可能已经过转换，不能统一声称是原始上传文件 |
| 同步工具计费包装 | 幂等请求摘要、结算、部分结果 JSON/流式结果 | 请求摘要不能恢复原图、蒙版、原始要求；无统一证据记录 |
| 视频与工作流 | 视频参考角色、任务参数；工作流执行/导入记录和产物 | 媒体预览与归一化详情尚未接入后台 |

比较三种方案：

1. **统一证据记录加旧数据读取适配（采用）**：新操作保留必要资料，后台以一种详情契约展示，旧记录读取现有真实证据。能补齐同步工具缺口，且不重写现有调度和计费。
2. 仅扩展 BI 查询：改动较小，但原本未保存的上传和要求仍无法恢复，不满足新任务全链路目标。
3. 全部业务迁入新任务引擎：关联最集中，但会重构成熟的队列、恢复和计费路径，扩大本次范围和上线风险。

采用方案 1。新模块负责证据存储、关系和后台读取；原业务模块仍负责执行与真实状态，计费模块仍负责报价、预占、结算和释放。

## 3. 管理员使用流程

### 3.1 列表与入口

扩展现有“业务任务”，保留原分页、用户范围、时间和状态筛选，加入入口/类型和“资料完整度”筛选。列表展示用户、入口、用户要求摘要、接受时间、业务状态、结果数、实际积分及完整度；要求为空与未记录分别显示。

从用户详情查看该用户全部创作；从作品进入对应输出所在的链；从 Agent/创作聊天进入具体轮次。详情链接携带任务来源和稳定 ID，刷新或返回列表保留筛选。同一操作在任务、作品、调用和积分多个入口出现时，均指向同一详情，不产生多个业务任务计数。

列表的一行对应一次服务器接受的顶层创作操作。Agent 一轮对话为顶层，调用的图片/工具任务在详情内展开；这些子任务仍可直接检索，标明所属主任务。现有运营统计口径不自动扩大：同步工具/上传等统计扩展另行标注，不能将新列表行数直接替换原统计指标。

### 3.2 统一详情

详情头部显示用户、入口、任务 ID、接受和完成时间、当前状态、资料完整度。正文按以下顺序排列：

| 区域 | 展示内容 |
| --- | --- |
| 输入素材 | 原图、参考图、蒙版、首尾帧、视频、音频、文件等，按用户提交的角色与顺序排列；显示文件名、类型、大小、来源和可用性 |
| 用户要求 | 用户原话、补充要求、负向要求；长文字展开/复制；聊天轮次保留上下文引用 |
| 参数 | 用户选择及接受时生效的公开业务参数分别展示，例如模型名称、尺寸、分辨率、质量、数量、时长、选区和裁剪；保留显式 false、0 和不发送参数 |
| 执行过程 | 接受、排队、工具/模型开始与结束、公开进度摘要、主备通道尝试、输出保存、交付、失败/取消确认、结算等实际事件 |
| 结果 | 所有实际产物：图片预览、完整文字、视频/音频播放、可下载文件信息；标明对应步骤、成功/部分结果及交付状态 |
| 积分与异常 | 报价、预占、实际结算、释放及对应账本；可公开的失败原因、错误码、待核对事项 |

图片支持缩略图和放大对照，输入与结果可同时查看。视频/音频按需加载播放器，支持拖动；不自动播放。文件仅对已支持、安全的媒体类型内联展示，其他文件显示元信息，通过管理员受控下载取得。图片中的文字、用户文本按普通文本或已有安全渲染器展示，不执行 HTML/SVG/脚本。

390px 页面改为纵向卡片，参数和长文本折叠，时间线可展开；桌面与手机保留同样的字段和完整度提示。时间线、对话和结果各自分页，打开详情不下载整段视频或全量原图。

### 3.3 缺失与状态

字段区分：已记录且为空、未记录、原素材不可用、不适用。页面不能把四者统一渲染为空白。历史只有转换后的模型输入时标明“已记录处理后输入，原始上传未记录”。已删除的结果保留任务和元信息，预览显示不可用。

业务完成、证据完整、媒体可读是三个独立判断。任务真实完成但部分证据缺失时仍显示完成，同时提示缺项。取消申请不是取消成功；供应商响应未知或既有流程需要核对时显示待核对，保留已取得的部分产物和真实费用。

## 4. 数据与模块边界

### 4.1 统一证据模型

采用独立的兼容新增表，不向 BI 扁平 `BiRow` 填入整个业务 payload。命名为 `app_creation_records`、`app_creation_assets`、`app_creation_events`、`app_creation_links`，各自职责如下：

| 单元 | 主要字段与职责 |
| --- | --- |
| record | 稳定 creation ID、schema version、服务器确认的账号、来源类型/来源 ID、入口、feature、project/session/turn 引用、接受时间、用户原话、用户参数、生效公开参数、模型名称快照、配置/价格版本、字段记录状态 |
| asset | 所属记录、方向 input/output、角色、顺序、文件元信息、SHA256、受管存储引用、同账号作品引用、原始/处理后标记、保存时间；文本结果作为受限分页内容或受管文件，不无限堆入列表 JSON |
| event | 所属记录、业务阶段稳定事件键、序号、观察/业务时间、公开步骤类型与摘要、实际通道/模型标识、异常与结果引用；原始请求响应不写入该表 |
| link | 同账号的 parent/child、业务任务、会话轮次、作品、模型调用、计费 operation、账本引用及关联证据类型 |

对 `(owner, source_kind, source_id)` 建唯一约束；事件键、素材角色和序号等使用稳定键去重。账号取服务端认证结果，不能信任 body.email。账号、时间和来源建立索引；JSON 内容仅按白名单持久化。任意子链、素材、作品和账本关联都校验同账号。

接受时的用户要求、输入清单、模型显示名和业务参数为不可变快照；新增执行事件、结果和关联为追加写入，可用性由读取时实际检查或明确状态事件表达。不得用当前供应商资料、改名后的 label 或当前价格覆盖旧快照。旧记录缺少当时显示名时，显示“当时名称未记录”，可另标注当前名称；原模型 ID 作为管理员可核查的独立字段。

列表业务状态和费用从既有业务/计费记录读取；证据事件不成为第二个调度状态机或财务事实来源。已有费用未知则显示未知，不能通过结果张数乘现价补算。公共父任务展示子任务费用汇总时按计费 operation ID 去重，避免把同一结算在父、子任务计两次。

### 4.2 关联规则

新业务将 creation ID 通过服务端执行上下文传入任务、工具、模型调用和作品创建环节；嵌套异步任务在持久化快照保留父引用，不依赖进程内上下文恢复关系。Agent 使用 session ID + turn ID 确认轮次，侧栏与小球复用的同一轮仅记录一次，工作台会话继续隔离。

历史读取只使用已有明确的 job/task/operation/turn/provenance 引用，并验证账号。画布父节点、相同标题、prompt 相似、时间临近都不能证明执行因果。用户复制作品应显示“复制来源”，不能把旧作品的生成任务伪装成本次生成。导入、补素材和模板实例与真正模型执行分别标识。

### 4.3 新模块划分

- 证据契约与采集：定义白名单、入口适配器和接受/追加接口，不依赖后台 UI。
- 仓储与关系：事务、去重、分页、账号约束及旧来源读取适配，不调用供应商。
- 管理员服务：统一详情、时间线和媒体授权，复用 BI 鉴权/访问日志，不复用面向客户的公开素材授权。
- 详情 UI：拆出素材、要求/参数、时间线、结果和积分组件，现有 dashboard 只负责列表及打开详情，不继续扩大单文件职责。

## 5. 采集时序与失败处理

### 5.1 接受请求

完成认证、账号状态及参数/文件合法性检查后，服务器建立稳定业务身份，再保存输入与最小证据记录；必需输入及记录持久化成功后才发起外部付费执行。复用原有请求幂等键和 fingerprint，不改变其语义或重新分配收费 ID。同键重放只读取原记录与原结果；不重复保存文件、追加执行或扣费。

各路由解析已校验的业务数据构建证据，不通用复制 HTTP body、headers 或供应商 JSON。Multipart 文件在实际读取时留存原字节并记录文件元信息；若服务器收到的是前端已转换的图，只称“服务器收到的上传图”。归一化、裁剪、蒙版生成等后续步骤另外保留实际处理输入或操作参数，不能把处理后的 PNG 冒充原文件。

已有持久输入（图片 job Buffer 引用、受管作品、视频参考）优先建立引用，不再复制相同字节。引用型输入必须验证同账号作品/任务或请求自身合法的受管素材；外链按现有输入安全策略取得并落到受管存储后作为本次输入，后台查看不重新向任意外链抓取。无需保存未经使用、未通过验证的全部剪贴板或工作流配置。

必需证据保存失败：在付费执行前拒绝接受并通过原流程释放已有预占，给出正常失败提示；不开展缺少必需输入证据的新执行。已开始的旧任务和已经发生的外部执行不因后续审计写入异常重复调用供应商。

### 5.2 执行与产物

在实际业务边界追加事件，引用原阶段/尝试 ID。记录公开工具名称、用户可见摘要和实际参数；Agent 内部思考、系统提示词、完整上下文、密钥、请求头、含签名的供应商 URL 等不进入后台证据契约。

模型输出经现有校验并持久化后登记结果。多图、套图和 A+ 等逐项记录；坏图、空输出、媒体拉取失败不能标成已交付。已有业务支持的主备尝试分别呈现，后台不会新增重试策略。文本流记录最终用户可见文本及中断时已交付的片段，不保存每个 token 为一个事件。

业务记录提交与证据链接能够共用本地事务时一起提交；外部响应之后无法共用事务的证据追加失败时，记录可核对的缺口。补齐只从已有业务快照、输出、账本和公开步骤恢复，执行读写去重，绝不重放供应商调用。不能仅因“后台资料保存失败”将已交付的工具响应改成可自动重试的失败。即使缺口事件也无法写入，读取时根据必需阶段和源记录差异显示不完整，不能默认完整。

拒绝鉴权和无效文件等未接受请求沿用现有安全/错误日志，不留存未经授权的素材。通过认证和校验后发生的余额不足、队列失败、供应商失败等，可用稳定 operation ID 记录接受前拒绝/执行失败的公开原因；不把这些事件计作成功创作。

## 7. 历史兼容与完整度

旧图片/画布/视频任务直接读取现有记录；同步工具从 billing operation、结果响应与可靠作品 provenance 读取；Agent/创作聊天从明确轮次、公开 steps、artifacts 读取；上传/工作流从已保存记录读取。适配器不修改历史 payload、钱包、作品来源或已发布配置。

旧资料可以满足部分字段，但每项记录其证据来源。没有原始上传、原话、当时模型名称或完整结果时分别显示未记录；当前作品图不是输入的替代。历史不保证全量恢复，不后台扫描外部链接、不调用模型补写“用户要求”。

完整度是分区状态集合：输入、要求/参数、过程、结果、费用，各分区可为已记录/部分记录/未记录/不适用；总览据此显示完整、部分或历史资料不足。媒体不可读另行标识。运行中任务显示截至当前的资料状态，不因尚未产生结果误判历史缺失。

列表在数据库分页后按本页批量读取关联；统一来源采用稳定的 `(accepted_at, source_kind, source_id)` 顺序，同一 source 在新表和旧适配器中去重，不先在内存加载全部旧数据。详情输入/结果每页 20 项，时间线每页 50 项，文本每段不超过 20,000 字符并可继续读取，最终必须能查看全部已保存内容。

## 8. 管理员 API、媒体与留存

增加统一只读详情与分页资源，沿用 `/api/admin/bi/` 命名空间：creation、creation-events、creation-assets 及受控媒体读取。详情通过 source kind + ID 查询并返回稳定 creation ref；后续资源使用 creation ref + asset/event ID，服务端重新校验所属记录。客户端不能提供任意 URL、磁盘路径或另一个账号的素材引用要求代理读取。

每个 API 独立复用 `biAuthorize`、管理中心访问门控和 rate limit；匿名/非管理员按原行为拒绝，查询失败不能绕过账号验证。响应沿用 private/no-store、Vary、noindex、nosniff。访问详情、读取文本内容、放大或下载输入/结果媒体写现有管理员访问审计，日志只记 actor、任务/素材引用、动作及结果，不记用户完整内容和密钥。

受管图片复用安全读取、像素上限和缩略图处理；不通过整个 durable payload 解码展示图片。预览失败只影响该素材，仍可查任务。视频/音频用受控 Range 读取，拒绝无效范围；文件下载使用安全 Content-Disposition 和类型白名单。业务原有文件/请求限制保留，媒体读取不引入任意外网抓取或内网 SSRF 能力。旧记录仅剩供应商临时链接且无法安全读取时显示不可用。

原图与证据素材属于业务媒体，按现有任务/作品的数据保留和显式删除规则管理，不加入定期缓存清理。数据库记录引用保存中的业务文件，避免普通结果清理误删输入。删除、存储迁移或损坏后保留可用性说明，不承诺永久保存，也不新增未经用户要求的自动清除周期。未来删除文件必须检查全部业务/证据引用，不能仅看作品表；本轮不做全库删除或空间回收。

客户积分与供应商成本分开展示，真实成本未知保持未知；人工配置优先和供应商元数据修订规则保持。API 只返回公开业务参数、供应商显示名/标识及安全错误摘要，不返回凭据、完整 HTTP、支付秘密、冻结执行包或内部推理。冻结包仅供服务端执行，不成为管理员下载资源。

## 9. 验收设计

所有验收围绕真实数据和关联语义，采用隔离数据库、受管测试媒体和模拟供应商；不为后台只读功能重复大量真实付费请求。

| 验收场景 | 必须证明 |
| --- | --- |
| 单图、蒙版、双参考、首尾帧、音频/视频文件 | 原字节/已处理标记准确，角色与顺序正确，输入和结果不混淆 |
| 同步工具、异步任务、套图/A+、文字、Agent、工作流、上传 | 每个入口有稳定记录，包含实际要求和所有产物，零积分同样可查 |
| 幂等重放、进程重启、Agent 嵌套子任务 | 同一操作记录/文件不重复，无额外模型调用与收费；父子引用恢复准确 |
| 部分结果、供应失败、超时、取消申请/确认、待核对 | 状态来自业务事实，保留已交付内容，不将未知当成功或退款 |
| 证据持久化失败 | 付费前失败不执行；执行后追加失败不重放、不造成重复扣费；缺口明确可见 |
| 历史缺少输入、标签已改、原作品已删除 | 不猜原图/原话/价格，不重写历史，不因缺项隐藏任务 |
| 同账号/跨账号关系、管理员门控 | 每级关联和媒体均校验，未授权无法读取素材；接口不能读任意 URL/路径 |
| 可疑 SVG/文本、超大图、Range、秘密字段 | 安全处理和既有边界有效，后台契约及访问日志不泄露秘密 |
| 财务 | 原 operation、报价、预占/结算/释放及账本语义保持，汇总去重 |
| 桌面与 390px | 原图/要求/结果可完整查阅，长文本和多结果可分页，缺项/异常提示清楚 |

线上验收先核实镜像与版本、管理员/匿名权限、使用已有记录核对输入/要求/结果及账本，确认该后台读取没有产生供应商请求。视频播放器使用安全的隔离测试素材证明；未启用的真实视频通道仍按原约定延期，不写成供应商验收通过。

## 10. 实施与发布边界

后续计划分四个依赖阶段：证据契约与兼容存储 → 所有入口采集/关联 → 后台查询与统一详情 → 集中验收及发布。按入口适配实现，最终按完整范围验收；不把只有异步生图可查看的中间状态交付成全链路完成。

迁移仅新增表、索引及兼容的可选业务引用；旧镜像忽略新证据可继续运行。新镜像读取旧记录正常，回滚只切固定镜像，保留新增表/记录/媒体，不回灌数据库、不删除证据。发布前确认新索引和事务不会长时间锁定现有任务表，并验证在途任务兼容。

本聊天后续实施默认先在 120.27.162.85 构建/验收，保留 HTTPS 与本机独立服务。香港维持独立配置、数据库及媒体，是否发布遵循后续明确任务目标；不自动同步数据。不连接/回传旧 101，不恢复迁移 heartbeat，不接 OSS/NAS，不启用延期的视频配置。

真正上线前重新刷新 main 和已完成的同事分支，核对当前运行基线，持 deployment lock 完成最新完整可读备份、固定候选构建、回滚检查、切换前基线复核和最终验收。空间维护与发布次数使用当时最新交接记录，不把本设计文档提交计作迭代或成功发布。

## 11. 书面设计自检及交接

- 目标覆盖上传、原始要求、过程、结果、异常和费用，入口清单包含所有现存创作类别。
- 新任务证据留存与旧任务缺项展示分别明确，不许诺恢复从未保存的文件。
- 调度、计费事实和证据职责分开；幂等、取消未知、失败后恢复和原字节语义没有相互冲突。
- 素材和关系验证覆盖每一层，管理员查询只读，完整执行包和秘密不成为证据内容。
- 页面、契约、存储、采集、兼容、验收和部署边界已明确，无占位待定需求。
