## 4. 共用结构与请求契约

采用 `src/lib/imagegen/`：`catalog` 管用例/来源，`schema` 管请求与结果类型，`capabilities` 解析实际支持情况，`prompt` 管规范化，`dispatch` 调用既有执行器，`postprocess` 管确定性像素处理。模块名称是拟新增接口，当前不存在的功能不标为已实现。

```text
Agent工具 / 画布操作 / 工作台
  → 同一请求校验、素材权限与能力解析
  → 明确报价/确认、冻结执行配置
  → 既有生成或编辑任务 / 本地像素处理
  → 同一阶段与任务结果
  → 作品库、关联画布节点、私有媒体及缩略图
```

请求包括：版本、入口、operationId、Skill ID/修订及用例、generate/edit/batch/postprocess模式、用户原始要求与规范化说明、逐字文本/不变量、按顺序排列的素材和角色、用户蒙版、模型显示ID、质量/分辨率/比例或像素尺寸、透明要求、输出控制、批次子项和来源节点。素材引用采用站内资源ID/受鉴权URL，不接受宿主文件路径或任意命令。

**提示词自动触发：** 在服务端报价、路由和配置冻结之前，统一解析用户本次原始提示词中的明确能力要求。画布节点、工作台与Agent共用此解析结果；按钮是可选入口，不是执行能力的前提。例如“生成一只透明底鹈鹕”形成强制透明输出要求；“去掉这张图的背景”结合当前编辑目标选择抠图路径。记录要求来自提示词、当前显式控件还是Skill，保留用户原文。

否定、引号中的印字内容、提问或比较不能当作执行指令：“不要透明，白底”“在图片上写‘透明底图’”“透明底是什么意思”不触发透明处理。本次明确要求覆盖上次继承的选项；本次明确控件与提示词互相矛盾或意图不清时，提交前提示具体冲突，不擅自收费执行。必要素材缺失时说明所需目标或蒙版，不要求用户先点对应能力按钮。

透明要求使用所选模型家族的已核实原生透明通道，或者预先展示并合计报价的“生成→抠图”步骤；满足正常报价/大额确认后随普通提交执行。没有合格路径时收费前明确阻止；不能静默换生成模型、忽略要求或将不透明底图报告为透明成功。其他明确用例沿共用目录和工具执行，不能只把要求追加进提示词后就宣称能力已触发。

素材角色为 `edit-target`、`reference`、`insert`、`style`、`mask`。编辑必须有明确目标；只给风格参考不自动视为编辑。蒙版对应首个编辑目标，明确透明区域为重绘区；核验解码尺寸、alpha、静态格式和资源归属。大小与像素安全门槛沿用本站限制，不将来源API的50MB或16图无条件变成本站默认。

结果包括 operationId、真实任务ID/子项ID、状态、执行模型和通道、请求/实际参数及差异原因、真实积分状态、作品ID、媒体引用、实际尺寸/格式、alpha检查结果和各子项错误。显示名称与实际模型ID分别保存。最终配置快照写入已有执行证据，不受后续元数据刷新影响。

旧接口缺少新增字段时保持既有行为；新共用适配层调用既有生成、编辑、抠图和本地编辑执行器，避免HTTP内转发后发生二次预留积分。分类不改变文字模型入口或文字节点的类型。

## 5. 能力、参数与来源包执行选项

能力以管理员显式配置为优先，上游有来源资料兜底。false、0、明确禁用和“不发送”均为有效配置。用三态 supported/unsupported/unknown 表示真实支持程度，并携带证据来源/日期。资料中的模型名称、价格层级和包内GPT参数不能证明其他供应商支持；资料刷新不能改变已发布映射。

每个路由候选分别校验编辑、蒙版、参考数量、比例/尺寸、质量、input_fidelity、透明输出、输出格式/压缩和可配置上游策略。筛除无法满足强制要求的候选；保持原优先级、负载和失败回退策略。所有候选不支持时提交前提示，不扣生成积分。未知的高级参数默认不作为保证可用的选项，管理员补充显式配置并验证后开放；已发布旧请求继续用原冻结规则。

| 来源控制 | Naumi适配 |
|---|---|
| generate、edit、generate-batch | 同一执行层的生成/编辑/批次模式 |
| n vs 多条prompt | 同一提示词多变体 vs 每个独立素材/分镜单独子任务 |
| model、size、quality、background、input_fidelity | 后台模型/通道映射；原生尺寸和后处理尺寸分别标识 |

| output_format、output_compression | 支持PNG/JPEG/WebP；区分上游原生输出与本地转码；JPEG不能承诺透明 |
| moderation | 仅服务器白名单及供应商明确支持的取值，不能放宽本站现有审核策略 |
| prompt-file、JSONL | 受限纯文本/结构化批次导入，预览后执行；不接受脚本路径 |
| augment/no-augment、结构化提示字段 | 明确用户控制补充程度；详细要求默认仅整理 |

## 6. 透明图和确定性后处理

保留已有AI抠图与局部蒙版工具。来源 `remove_chroma_key.py` 的能力通过受控像素处理提供：指定key色、容差、角点/边框自动取色、soft matte、透明/不透明阈值、边缘收缩/羽化、溢色清理。Naumi实现可用现有Sharp移植核心逻辑；原脚本及许可作为来源材料保留，不执行用户上传Python。

去底色与AI抠图分开命名：去底色针对纯色背景，复杂场景可以由用户选择AI抠图。参数先校验范围和阈值关系；默认保留前景像素、已有alpha和原始版本。结果检查alpha及透明像素占比，不将棋盘格或不透明白底记为真实透明。全部透明、边缘严重污染等异常标出，提供恢复原版本。

格式转码/缩小只处理已有字节，不重复调用模型；与供应商生图费用区分。初版确定性本地后处理为0积分，保留鉴权、幂等、资源上限和操作记录，不作供应商调用。透明格式为PNG/WebP；JPEG需明确背景色并确认扁平化。缩小不能冒充原生高分辨率或AI高清放大。

## 7. Agent、画布与工作台交互

**Agent：** 用共用目录查询能力和参数。当前画布引用按角色传入，执行前显示计划和必要报价；展示“整理需求→生成/编辑→处理输出→保存”中的真实活动阶段，不伪造计时进度。产物落入当前画布及作品库，失败不凭空生成图片URL；自然语言与图片创作结果类型分离。

**画布直接入口：** 新建图片/空白画布的“创作 Skills”入口不要求开启Agent。选中图片后提供“创作与编辑”，多选时提供角色分配/融合/批量。默认面板显示用途、提示词、模型、比例、分辨率、质量；高级区展开蒙版、透明、输出格式等适用项。只展示当前模型与工具已开放的选项；未知/不支持的信息放在说明中，避免一排灰色无效档位。去底色先显示局部预览，确认后保存新版本。

选择Skill只填写流程，不自动扣费执行。生成与编辑有清晰动作标题，参考图序号/角色可修改；蒙版沿用画笔和选区入口。结果保留输入关联和当前位置安排，不抢用户正在编辑节点的焦点。旧12个Skill和个人Skills仍可使用、导出、另存。

节点提示词提交时自动解析能力，面板可显示“已识别：透明背景；执行：生成→抠图”等实际计划，用户无需额外点击透明/抠图按钮。旧生成接口同样经过解析，避免只有新面板有效；界面上的计划属于说明，不虚构供应商支持。

**批次与工作台：** 同批次每个子项有语义名称、原要求、参数、状态、产物与积分结果。并发受后台和现有队列上限控制；取消停止领取未提交子项，已提交任务保留可追踪状态。刷新后从任务读取进度；fail-fast不删除已成功结果。对已成功子项不自动重做，收费重试必须先确认原任务状态。

## 8. 计费、可靠性、媒体与兼容

同一operationId的重复请求返回原任务/作品；相同ID不同内容拒绝。多次点击、刷新、Agent和画布同时提交不重复扣费。报价包含当前模型、数量、尺寸与质量；现有大额确认、冻结配置、预留/结算/退款规则保持。

上游已受理但超时的任务标记待查询，不能因浏览器断开直接另发任务或重复退款。只有可确认未受理/终态失败的情形按现有安全调度回退；进度和费用以服务端任务状态为准。原图已生成但R2写入失败时先保存本地可读镜像，后台重存相同字节，不重新调用模型。

原图、PNG/WebP透明图、转换副本、缩略图和预览分别存储，保留实际MIME、尺寸及来源关系。继续私有媒体权限和签名下载；跨账号、私有mask、参考图和ZIP均受鉴权。模型输入优先完整原始产物，画布展示按需加载变体。

优先复用已有任务快照和操作记录，只新增必要的可兼容字段/辅助表；所有新增字段有旧客户端默认值。历史任务缺少信息标“未记录”，不回填虚构参数或重放历史任务。保留R2新配置和各站独立数据；不全量同步媒体/数据库，不改DNS或恢复用户自带接口。

## 9. 验收与完成标准

集中验收一次，发现问题后仅复测受影响项；沿用同事已通过的无关模块，不对每张Skill卡重复收费生图。

1. 19个用例均有可追溯目录和流程映射；逐项说明复用工具、实际支持与缺失原因。Agent和画布均能完成代表性的生成、编辑、蒙版、多图、批次与本地后处理，不能仅测菜单可见。
2. 隔离测试验证三态能力、管理员优先/false/0/省略、输入角色顺序、数量/尺寸限制、映射冻结、跨账号拒绝、幂等与账本、明确失败回退和已受理超时不重放。未知高级参数不会静默发出。
3. 用合成图验证去底色硬/软alpha、自动key色、羽化/收缩/溢色清理、透明格式和JPEG扁平化；验证输入/蒙版尺寸及alpha错误，格式压缩和缩小后的真实像素/文件MIME。
