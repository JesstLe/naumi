# BI 模型、供应商与混合路由配置

状态：用户已批准 PostgreSQL 配置中心、BI 表单管理及版本发布的架构；正在编写实施计划，尚未修改产品代码或发布。日期：2026-10-04（北京时间）。

## 目标与现状

用户希望在现有私有 BI 管理面板中管理供应商、上游真实模型、对外模型及混合路由。采用项目现有 PostgreSQL 作为配置中心，以表单操作结构化数据；发布时生成不可变版本，由执行代码引用。常规模型增删、别名映射与路由调整无需改代码或重新部署。JSONB 仅用于内部快照和受限规则字段，不要求操作者手写 JSON，也不引入额外配置中心中间件。

已查看另一现场“评估 AI Gateway 架构”：正在实施统一计费配置，已提交报价、任务快照、工具、画布、视频及到账链路，正在完善后台和用户价格展示。该现场负责价格与账务，本方案负责模型配置与执行路由，接口通过稳定标识衔接。

Naumi 已有可编辑的主生图通道设置，但文字别名、Flow 模型和视频供应商仍部分来自环境变量；`isImageGatewayModel` 使用固定正则。Router 已用 JSON 描述候选路线，但启动时加载，供应商注册和四个对外模型仍受代码限制。当前私有 BI Router 代理只允许读取操作记录，没有配置写入接口。

## 选定结构

采用 PostgreSQL 内的结构化模型注册表、不可变发布快照、已支持协议适配器与 Router 私有配置接口。供应商、模型、候选、用途映射有稳定 ID 与引用约束；草稿改动、版本发布、实际应用状态分别管理。

仅在原设置页增加输入框不能覆盖路由；仅编辑服务器 JSON 仍需重启，也不能提供统一审计与旧任务恢复。因此 BI 保存和发布模型配置，Naumi 与 Router 按明确版本读取它。

配置覆盖已有生图、文字/视觉、视频能力。生图混合路由延续现有 Router，文字和视频复用各自已实现的协议和任务恢复逻辑。不声称已有图片 Router 能直接处理文字或视频；不在本次额外建立跨模态自动混合调度器。

代码保留协议适配、鉴权、输入校验、幂等、任务恢复和账务执行逻辑。数据库配置管理数据与规则；新增已支持协议的供应商、模型或候选组合无需部署，新增尚未支持的供应商协议仍需实现适配器。配置不能执行任意脚本。

## BI 页面

在 `/admin/bi` 增加「模型与路由配置」，仅管理员能访问其页面及 API，公开页面无入口。

1. **供应商**：稳定 ID、名称、协议、接口地址、凭据状态、启用状态、超时、并发上限。凭据单独加密管理，不能混入配置导出。
2. **上游模型**：供应商、真实模型 ID、显示名称、模态、生成/编辑/视觉能力、支持的质量与原生分辨率、参考图上限、参数映射及计费成本引用。
3. **对外模型**：用户可见 ID、名称、是否展示、适用入口、默认用途；选择直连某个上游模型或绑定生图混合路由。明确显示这个对外模型包含哪些真实模型。
4. **路由规则**：候选列表、任务类型、质量/尺寸、编辑、主体一致性、文字准确性等条件；先筛能力，再按明确策略排序。优先级、可比成本、延迟等策略有明确定义，禁用项不能参与新任务。
5. **预览与版本**：草稿校验、规则模拟、发布差异、实际应用状态、操作者与原因、历史版本、恢复旧配置。全部通过表单操作，共用服务端数据校验，不增加高级 JSON 编辑器。

模型目录、供应商状态、每个候选的排除原因、实际命中、降级及配置版本可在 BI 查到。人工启用状态与运行时健康状态分开，管理员不能把手填“健康”当作真实探测结果。

## 内部版本快照合同

以下是结构示例，ID、URL 与候选均为示例，不作为生产初始化内容：

```json
{
  "schemaVersion": 1,
  "providers": [
    {

      "name": "供应商 A",
      "protocol": "openai-images",

      "credentialRef": "credential-a-v1",
      "enabled": true,
      "timeoutMs": 120000,
      "maxConcurrent": 4
    }
  ],
  "upstreamModels": [
    {
      "id": "supplier-a-image",
      "providerId": "supplier-a",
      "model": "image-model-a",
      "modality": "image",
      "enabled": true,
      "capabilities": {
        "generate": true,
        "edit": true,
        "preserveIdentity": true,
        "textAccuracy": true,
        "qualityRank": 3,
        "qualities": ["medium", "high"],
        "nativeResolutions": ["1K", "2K"],
        "maxReferenceImages": 4,
        "expectedLatencyMs": 30000
      },
      "parameterMap": {"quality": {"medium": "medium", "high": "high"}},
      "costRef": "supplier-a-image-estimate"
    }
  ],
  "publicModels": [
    {
      "id": "naumi-image-standard",
      "label": "标准生图",
      "modality": "image",
      "enabled": true,
      "visible": true,
      "target": {"type": "pool", "id": "product-standard"}
    }
  ],
  "pools": [
    {
      "id": "product-standard",
      "modality": "image",
      "strategy": "priority",
      "candidates": ["supplier-a-image"],
      "rules": [
        {
          "id": "product-image",
          "priority": 100,
          "when": {"task": ["product"], "resolution": ["1K", "2K"]},
          "require": {"preserveIdentity": true, "minQualityRank": 3}
        }
      ]
    }
  ],
  "bindings": {"image.generate": "naumi-image-standard"}
}
```

配置版本、摘要、应用状态、操作者和原因是服务端元数据，不能信任客户端自行填写的版本。类型使用严格 JSON schema，未知字段、重复 ID、缺失引用、循环引用、模态错配、非法金额单位、无有效默认模型或不满足能力的默认路由均拒绝发布。

`bindings` 映射功能用途到对外模型，例如普通生图、编辑、抠图兜底、Agent 文字、视觉审核、OCR 兜底及视频用途；适用入口来自代码中的稳定功能注册表，不能由 JSON 增加任意执行入口。

`parameterMap` 限定为已支持适配器的参数和值映射，不能任意改写鉴权头、任务标识、租约、账务金额或请求地址。透明底、原生分辨率与服务端放大分别表示；当前 5K 后处理不能被标为供应商原生 5K。

现有 BYOK 保持账户私有作用域与独立信任边界，不能因用户填入 Router 别名就获得平台持久任务恢复权限。

## 凭据与内部接口

供应商密钥沿用浏览器 RSA 加密传输、服务端 AES-GCM 落库；API 仅返回已配置状态，不回显明文、密文、凭据指纹或密钥片段。配置 JSON 只记录不可变 `credentialRef`。更换密钥创建新引用，不覆盖旧任务使用的引用。

接口地址禁止含用户名、密码或查询凭据；私有 URL 不进入公开模型目录。地址校验限制协议、跳转及云元数据地址。已有受信任内网服务通过服务端明确允许列表管理，不能让浏览器自行添加免校验目标。

Router 增加专用的配置读取、校验/模拟、准备、应用状态与激活接口。使用独立管理凭据，普通生成 token 不能修改配置；管理监听与 Nginx 白名单只对现有 Naumi 私网开放，不把当前仅 GET 的 BI 代理整体改成任意写入代理。

发布失败与结果未知需要明确返回状态及相同操作编号重试方式；不得在管理接口错误消息或日志中输出完整请求体、上游密钥或供应商响应中的凭据。

## 发布、生效与旧任务

1. 保存草稿，校验引用、协议、能力及凭据就绪；模拟只计算候选，不发付费生成请求。
2. 创建不可变配置版本，向 Router 准备该版本并核对摘要。未准备成功不对新任务开放。
3. Naumi 新任务始终携带明确模型配置版本。Router 激活经过核验的版本后，更新 Naumi 当前版本指针；应用状态有待应用、应用中、已应用、失败或结果未知。只有摘要与状态核对成功才显示“已生效”。
4. 两个服务不能假装拥有跨服务原子事务。激活/指针更新中断时，通过持久发布记录和同一操作编号核对恢复；Naumi 仍按已记录版本执行，不能靠重新生成图片修复配置同步。
5. 在途任务冻结模型配置版本、对外 ID、解析后的目标/候选及凭据引用。已有 Router 接受记录继续使用原供应商任务 ID 查询，不因后台改路由再发生成请求。旧任务结果未知时保留预占并核查，不能自由转发另一个供应商。
6. 禁用供应商或删除映射停止接收新任务；有在途引用的历史版本和凭据不能物理删除。紧急停用涉及旧任务时明确进入暂停/人工处理，不伪装成确定失败。
7. 恢复历史配置创建新的发布记录；不改写旧日志。所有版本共享按实际供应商账户划分的并发限额，不能为每个版本另开限额导致总量翻倍。

应用默认读取现有运行配置并保持当前目录、通道、质量退档及尺寸后处理。迁移有无法可靠识别的上游能力时标为待确认，不能虚构为已支持。自定义对外模型不再依赖固定四种别名的正则白名单。

## 与计费现场的衔接

- 同事模块继续唯一负责用户售价、预占、结算、赠送、商品、有效期与上游成本配置。
- 模型配置中的 `costRef` 引用计费模块的成本项；不再提供第二份可编辑供应商金额表。成本排序使用明确计费版本中的成本估计，未知成本不能当零，缺乏可比较货币成本时禁止该候选池选择最低成本策略。
- 账务快照同时记录计费版本与模型配置版本。BI 区分用户选择的模型、真实执行模型、供应商、路由、质量降级和成本来源；不能把积分差额当人民币利润。
- 混合路由变更不重算旧任务售价；结算依同事冻结的账务政策执行。上游实际费用若没有回执，只显示估计或未记录。
- 当前同事正在修改价格展示和 BI 成本字段。实施时先同步已提交分支，模型配置页用独立组件；共享 BI 导航、类型、账务审计与发布流程集中集成，不能包含同事尚未提交的改动。

4. 接入 `text-models.ts`、Agent/视觉调用、视频供应商配置及视频任务快照；对每种模态分别验证能力和恢复路径。
5. 增加 BI 配置组件，整合现有导航、悬停详情、发布审计和成本引用；前端展示配置概要及应用状态。
6. 对同事最终账务版本做集成验收，按现有固定版本发布流程协调 Naumi 与 Router 部署，不并发切换同一服务器。

## 验收标准

- 在后台新增同协议供应商/模型、修改默认模型、增删生图候选后，新请求目录与模拟/实际模拟供应商命中一致，无需重新部署。
- 匿名、普通用户、伪造或过期会话不可读写配置；跨站发布拒绝；公开目录只含可见模型概要，不泄露真实上游、地址、成本、凭据与配置规则。
- 重复发布不会重复创建版本；同版本并发发布产生明确冲突；无效 JSON、悬空引用、循环路由、缺密钥、能力不符均不能使现行配置失效。
- 候选筛选、优先级/成本/延迟排序、质量映射、禁用、健康状态及主体/文字/编辑要求有确定性的测试。
- 发布过程中和发布后恢复旧任务、轮换凭据、服务重启和失败恢复均不会重发已接受的付费请求；版本间并发限制合并正确。
- 文字、视觉、视频及画布实际执行与其后台绑定一致；重复、超时、部分成功和结果未知沿用已冻结模型与账务版本。
- 价格不因只修改显示名称或模型配置而擅自改动；供应商模拟和后台模拟不产生真实付费请求。
- 桌面与窄屏完成供应商表单、候选展开、字段校验、差异确认、历史恢复和失败状态的界面验收。
- 上线前备份数据库、配置、媒体及 Router 状态，准备协调回滚；上线后验证真实版本、配置摘要、私有权限、目录与模拟链路及只读账务核对。

## 审阅结论

方案将“后台能改”明确为“目录、解析和实际执行按配置版本一致生效”，没有以 JSON 编辑器替代执行接入。价格只保留一个配置源，旧任务和旧凭据有保留规则，Router 管理接口与生成接口分离。尚未修改产品代码、调用生产配置写接口或发布新版本。
