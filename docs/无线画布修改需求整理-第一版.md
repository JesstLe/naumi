# 无线画布修改需求整理 第一版

更新日期：2026-09-17

## 1 文档目的

本文将《无线画布修改建议-第一版.doc》中的反馈整理为可评审、可排期、可验收的产品需求。原文共提出首页优化及五项画布功能优化。

本次工作只整理需求，不代表相关功能已经实现或通过验收。附件截图用于说明信息结构和交互意图，不作为深色主题、字体、颜色等视觉样式的照搬依据；后续实现仍遵循项目统一的浅色界面规范。

## 2 需求总览

| 编号 | 模块 | 优先级建议 | 原始反馈 | 整理后的需求目标 |
| --- | --- | --- | --- | --- |
| CANVAS-001 | 画布首页 | P2 | 首页页面优化 | 重组首页信息结构，突出创建入口、常用工作流和个人项目，降低查找历史项目的成本。 |
| CANVAS-002 | 批量导入与分组 | P1 | 批量导入图片成组 | 多张图片导入后可作为一个组统一选择和操作，并提供明确的成组与解组能力。 |
| CANVAS-003 | 节点类型 | P1 | 没有文字生成节点，参考稿定设计 | 新增文字生成节点，使用户可在画布内生成、保存并继续使用文本结果。 |
| CANVAS-004 | 节点创建交互 | P1 | 添加节点按钮大一点 | 放大节点连接处的新增按钮及点击热区，保证不同缩放级别下容易发现和点击。 |
| CANVAS-005 | 模型与 API | P0 | 模型还没连接 API，没有选项 | 接通实际模型 API，并在生成面板中提供真实可用的模型选项、默认项和异常状态。 |
| CANVAS-006 | 节点尺寸与视口 | P0 | 导入图片后，新建节点很小，没法自适应大小 | 从大尺寸图片继续创建节点时，新节点和编辑控件在当前视口中仍保持可读、可点、可编辑。 |

优先级说明：P0 为阻断核心生成流程或导致功能不可用的问题；P1 为核心效率和编辑能力；P2 为入口与信息架构优化。

## 3 详细需求

### CANVAS-001 画布首页信息结构优化

#### 用户问题

当前首页缺少清晰的内容分区。常用工作流、个人项目和新建入口之间的层级不够明确，用户难以快速开始常见任务或找到历史项目。

#### 需求说明

1. 首页保留明显的新建项目入口。
2. 增加常用工作流或通用模板区域，展示可直接复用的高频工作流。
3. 个人项目独立成区，并支持按月份归类或筛选。
4. 项目卡片至少展示封面、项目名称和更新时间；卡片操作入口保持统一。
5. 无项目、无模板和加载失败时分别展示可执行的状态，不使用无意义宣传文案填充页面。

#### 验收要点

- 用户进入首页后，可以在首屏找到新建项目和常用工作流入口。
- 用户可以按月份查看个人项目。
- 点击工作流可进入新项目创建或复用流程，点击个人项目可回到对应画布。
- 在常用桌面宽度和窄屏下，卡片不重叠、不横向溢出。

#### 待确认

- 常用工作流由运营预置、管理员配置，还是根据用户使用频率自动生成。
- 个人项目按创建时间还是最后更新时间归入月份。

### CANVAS-002 批量导入图片成组

#### 用户问题

多张图片导入画布后是彼此独立的节点，后续整理、移动和批量操作成本较高。

#### 需求说明

1. 一次批量导入产生的多个图片节点支持成组。
2. 用户也可以多选任意图片节点后执行“成组”。
3. 组被选中时，支持整体移动，并保持组内节点相对位置。
4. 提供“解组”，解组后节点恢复独立编辑。
5. 成组、移动和解组结果在刷新画布后仍可恢复，并进入撤销与重做记录。
6. 成组只改变编辑组织关系，不应自动制造图片之间的生成血缘或连接线。

#### 验收要点

- 选择两张及以上图片后可以成组，单张图片不显示或禁用成组操作。
- 拖动组时所有成员同步移动，成员之间的相对位置不变。
- 解组不删除图片、不改变图片尺寸、不改变已有连接关系。
- 刷新页面后组关系和位置不丢失。
- 成组、组移动和解组均可撤销、重做。

#### 待确认

- 批量导入完成后应自动成组，还是只提供一次明显的“将本批图片成组”操作。附件文字可支持两种解释，实施前需要确定。
- 组是否允许嵌套；第一版建议不支持嵌套组。

### CANVAS-003 文字生成节点

#### 用户问题

新增节点菜单只有图片生成和视频生成，缺少文字生成节点，用户不能在同一画布中完成文案生成与后续视觉生成衔接。

#### 需求说明

1. 在新增节点菜单中加入“文字生成”。
2. 文字生成节点包含提示词输入、模型选择、生成操作、生成状态和失败重试。
3. 文本结果可查看、复制和继续编辑，并随项目保存。
4. 文字节点可接收上游图片或文本作为上下文。
5. 文字结果可连接到下游图片或视频生成节点，作为提示词或上下文输入。
6. 生成中、成功、失败和未配置模型四种状态需要有明确反馈。

#### 验收要点

- 用户可以从空白画布或已有节点旁创建文字生成节点。
- 提交提示词后调用真实 API 返回文本，而不是固定演示内容。
- 刷新页面后节点、提示词、结果和连线仍存在。
- 下游节点能够读取文字节点的最新有效结果。
- API 失败不会清空用户已输入的提示词，用户可以重试。

#### 待确认

- 第一版需要支持的文字模型和供应商。
- 文本结果采用单结果覆盖、保留版本，还是每次生成新增子节点；建议与现有画布的版本和血缘规则保持一致。

### CANVAS-004 放大添加节点按钮

#### 用户问题

节点侧边的新增按钮尺寸较小，在复杂画布或缩放后不容易识别和点击。

#### 需求说明

1. 放大按钮的可见尺寸和点击热区，按钮图标仍使用现有矢量图标体系。
2. 按钮在节点选中、悬停和不同缩放级别下均保持足够对比度。
3. 按钮不遮挡节点内容、缩放手柄、连线端口或相邻节点。
4. 点击后继续打开新增节点菜单，不改变现有连接起点语义。

#### 验收要点

- 在常用缩放区间内可以稳定点击按钮，不需要精确瞄准一个很小的点。
- 按钮的悬停、按下和键盘聚焦状态清晰。
- 放大后不引入误触连线、误拖动节点或遮挡内容的问题。

### CANVAS-005 接通模型 API 并提供模型选项

#### 用户问题

生成面板虽然存在模型相关控件，但没有实际可选择的模型，用户无法确认生成请求会调用哪个模型，也无法完成真实生成。

#### 需求说明

1. 前端从服务端获取当前账号和当前环境真实可用的模型列表，不在前端硬编码虚假选项。
2. 至少提供一个可用默认模型；存在多个模型时允许用户切换。
3. 模型项应展示用户可理解的名称；必要时补充能力、积分消耗或限制信息。
4. 服务端校验提交的模型是否可用，不能信任前端任意传入的模型标识。
5. 未配置 API、鉴权失败、额度不足、模型不可用和上游超时需要分别反馈。
6. 文字、图片和视频节点只展示与自身能力匹配的模型。

#### 验收要点

- 打开生成面板后能看到至少一个来自服务端的真实可用模型。
- 切换模型后，请求实际使用所选模型，生成记录能够追溯模型标识。
- 无可用模型时生成按钮不可提交，并明确说明缺少的配置或能力。
- 使用真实账号完成一次端到端生成，结果、积分结算、失败退款和画布回流符合现有业务规则。

#### 待确认

- 第一版接入的供应商、模型清单、默认模型和不同模型的积分价格。
- 模型选择是全局偏好、项目级设置，还是每个生成节点独立保存；建议节点级保存并允许项目默认值。

### CANVAS-006 新建节点尺寸和视口自适应

#### 用户问题

导入大尺寸图片后，画布为了容纳图片可能处于较小缩放比例。此时从图片继续创建的新节点在屏幕上显示得过小，输入区和操作按钮难以使用。

#### 需求说明

1. 新节点应根据节点类型和内容使用合理的默认画布尺寸，不能沿用过小的固定尺寸。
2. 从已有节点创建子节点后，视口应将新节点带入可编辑区域；必要时仅聚焦新节点及其父节点，而不是重新缩放到整个画布。
3. 编辑态控件需要保持可读和可点击。若画布缩放过小，可采用临时聚焦、编辑浮层或屏幕空间最小尺寸等方案。
4. 图片节点仍按真实宽高或既定比例展示，不通过拉伸图片来解决控件过小问题。
5. 新节点应避让父节点和附近节点，避免生成后重叠。

#### 验收要点

- 在包含多张大图或长图的画布中，从任一图片创建新节点后，用户无需手动多次放大即可输入内容并提交。
- 新节点不会显示成截图中的微小控件，也不会生成在视口之外。
- 自动聚焦不改变其他节点的尺寸和坐标，不造成明显视口跳动。
- 刷新后节点的实际尺寸、位置和连接关系保持一致。

#### 待确认

- 优先采用“新节点自动聚焦”还是“编辑控件保持屏幕空间最小尺寸”。建议先做自动聚焦与合理默认尺寸，再评估是否需要屏幕空间浮层。

## 5 建议实施顺序

1. 先核对 CANVAS-005 和 CANVAS-006。前者决定生成能力是否可用，后者直接影响主流程能否操作。
2. 再实现 CANVAS-002 和 CANVAS-003，补齐批量素材组织与文字到视觉的工作流。
3. 同步处理 CANVAS-004，作为节点创建交互的小范围改进并并入画布模块验收。
4. 最后完成 CANVAS-001 首页信息架构，待常用工作流来源和月份规则确定后一次性落地。

## 6 模块级验收建议

为减少高频测试占用，建议按以下三个大模块集中验收：

1. 画布编辑模块：CANVAS-002、CANVAS-004、CANVAS-006。
2. AI 生成模块：CANVAS-003、CANVAS-005。
3. 首页与项目管理模块：CANVAS-001。

每个模块完成后再集中执行 TypeScript、Lint、构建、接口回归和真实浏览器验收；涉及模型的模块额外执行一次真实 API、积分和结果回流验证。

第一版确定采用以下规则：

1. 一次批量导入两张及以上图片后自动成组，同时保留手动成组与解组。
2. 组不允许嵌套；分组只表达编辑关系，不改变项目归属或生成血缘。
3. 个人项目按最后更新时间归入月份分区。
4. 第一版优先采用新节点自动聚焦与合理默认尺寸，不引入屏幕空间浮层。
5. 图片模型从服务端真实模型目录读取；文字模型从独立 Agent 配置读取。

完整实现记录和回归命令见 `docs/CANVAS_STATUS.md`。当前状态为本地发布候选已通过，生产上线结果以发布验证记录为准。
