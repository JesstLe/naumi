## 1. 用户需求与产品目标

用户要求 Naumi 最终面向 Agent，方便 Agent 使用全部功能，完成出图、自动剪辑、分镜脚本和一键生成大片；并要求拆解目标、采用 PRD 制定分阶段完成规划。

产品目标：用户或外部 Agent 提供创作意图、素材和预算，Naumi 将其转为可编辑、可恢复、可交付的创作项目。人和 Agent 操作同一份项目，网页、CLI、MCP 使用同一套业务规则。

“一键成片”定义为：在输入及授权充分时，从需求到最终可播放视频自动推进，无需用户逐个镜头提交；遇到真实缺失条件时停在可续接的阶段。它不是只生成若干视频链接，也不是承诺任意模型、预算和素材都达到电影级效果。

### 1.1 产品目标编号

| 目标 | 预期结果 | 完成证据 |
| --- | --- | --- |
| G1 全面可操作 | 已纳入能力清单的用户业务操作均可由授权 Agent 发现和执行 | 功能分母、公开工具映射、成功/失败/权限验收，无未解释遗漏 |
| G2 完整图片创作 | 需求、参考、生成/编辑、检查、交付和局部修改闭环 | 实际图片、原始文件、可编辑项目、费用与回执 |
| G3 剧本到分镜 | 从简述或完整原稿形成可编辑剧本、角色、场景与镜头计划 | 内容覆盖、镜头时长、连续性和来源可追溯 |
| G4 自动剪辑 | Agent 可编辑正式时间线、声音、字幕并导出 | 工程可人工接手，导出符合时间线，原素材保留 |
| G5 一键成片 | 自动完成创意规划、素材生成、剪辑、检查和交付 | 真实 Agent 完整运行；局部返工仅重算受影响部分 |
| G6 可持续交付 | 长任务可恢复，成本可控，状态真实，跨入口一致 | 重启/断网/并发/取消与账务验收、实际部署证据 |

### 1.2 全部功能的范围

范围包括个人与企业身份下获授权的创作、素材、项目、画布节点、角色/场景/导演预演、工作流、作品、分享/导出、账户用量，以及按职责授权的企业管理与平台管理业务操作。不能只用现有 65 个工具作为“全部功能”的分母。

P1 建立逐项清单；P6 对当时完整在用功能及新增功能收口。涉及管理员配置发布、成员权限、删除等操作，保留对应业务权限和真实影响说明，不让普通创作令牌越权。外发分享与发布必须来自明确的任务意图或已有授权。

登录挑战、首次创建凭证、恢复账户等必须由账户本人完成的动作记录为身份建立边界，不把密码、供应商密钥、服务器维护命令包装成创作工具。当前令牌不能管理令牌的规则继续保留。所有例外必须在清单中列出原因；不能以“后续再说”将普通业务功能永久排除。

本轮不扩展为新建通用 Agent 平台、替换现有计费/任务系统、任意代码执行平台或重写画布。维持模块化单体和独立 Worker；10万活跃目标继续由现有容量台账度量。

## 2. 用户与关键场景

1. **外部 Agent 使用者**：接入一次后，通过自然语言要求 Agent 完成创作；无需了解内部节点表、供应商参数映射或手工下载再上传中间结果。
2. **站内创作者**：可完全自动执行，也可先看方案再制作；随时进入原生画布修改脚本、镜头、素材或时间线。
3. **团队创作者与管理员**：在明确的企业空间内合作，权限、作品、预算与审计归属准确；个人素材不会因作为团队输入而被改写归属。

### 2.1 必须交付的场景

- **图片**：“用这张产品图做主图和四张详情图，保持产品与文字准确；只修改第二张背景。”
- **已有素材剪辑**：“把这些视频剪成30秒竖屏，保留关键对白，加字幕和背景音乐。”不能要求用户先把视频放进网页才能使用 CLI。
- **剧本分镜**：“将这段原稿拆成镜头，保留全部对白，生成角色/场景参考，先只给方案。”不能擅自开始收费生成。
- **一键成片**：“用这些图片做30秒产品短片，中文旁白、字幕，预算内自动完成。”交付 MP4、字幕和可编辑工程。
- **局部返工**：“第三镜改成夜景，其他保持。”只使实际依赖失效，重做相关镜头并重新合成，保留此前版本。
- **断线接续**：Agent 或浏览器退出后，已受理任务继续；新会话通过项目/任务 ID 恢复，不要求用户重新描述全部需求。

## 4. 目标体验与交互

### 4.1 从需求到结果

接收简报与素材 → 读取真实能力/项目 → 形成方案与预算 → 保存正式脚本、角色、场景、镜头 → 准备参考与声音 → 生成/选用镜头 → 编排时间线与字幕 → 渲染 → 检查 → 下载或继续修改。

入口允许选择：

- **自动完成**：在已授权范围和预算内连续执行，正常步骤不重复确认。
- **先看方案**：停在可编辑方案；用户选择制作后再推进。

缺失时长、比例等信息且可以从任务推定时，记录合理默认值继续；对改变主体身份、核心剧情、用途或预算的歧义才集中提问。展示内容只保留方案、关键选择、真实阶段、费用、产物和需要用户处理的问题。

“一键”不要求所有创作功能被压缩成一个巨型工具。外部 Agent 可以使用细粒度工具完成复杂任务，也可以提交完整制作计划；站内 Agent 通过同样的业务接口执行。

### 4.2 人与 Agent 接力

- 所有生成物与中间资产落入已有项目和作品体系；返回稳定 ID、可访问产物、网页定位入口和必要版本。
- 人工修改后 Agent 必须读取当前 revision，冲突返回可操作差异；不得用旧全量快照覆盖新编辑。
- 方案、正在执行的冻结快照、最终作品分开。改草稿不改变已受理任务的执行语义。
- 结果迟到时挂回来源版本；用户选择是否采用，不覆盖已编辑的时间线或镜头。
- 终态结果可下载并继续引用；临时签名地址到期后能由同一资产身份重新获取。

### 5.1 字幕、声音与剪辑的完成定义

- V1完整闭环至少覆盖中文和英文、正式旁白音轨、用户已有音乐/音效、音量与淡入淡出、SRT导出与字幕烧录。独立音乐生成作为能力清单项评估，不假定已有；没有生成能力时仍可使用合法已有素材。
- 独立配音需有真实可用的生成通道；“视频本身有声音”不能替代此项。工具列出可用音色与语言，冻结实际配置并记录成本。没有通道时相关需求保持未完成。
- 自动剪辑必须理解任务选取片段，能在时间线调整出入点与顺序；仅concat不得标为自动剪辑完成。
- 输出规格从真实渲染与模型能力提供；支持16:9/9:16/1:1的剪辑导出，首轮成片验收采用30秒1080p。素材分辨率不足时不将放大标成原生高分辨率。
- 先交付15–60秒短片的完整能力，再在P6验证3–5分钟多段项目。该范围是验证样本，不新增用户时长禁令；长片上限来自真实能力与资源，并可通过分段制作扩展。

## 6. Agent 契约设计原则

以下为目标契约，不代表当前CLI命令或API已存在。实际名称在P1按现有接口确定并回写，避免同时建立近义接口。

### 6.1 三类操作

1. 发现与读取：查询能力、项目、素材、方案、任务、成本和结果。
2. 业务编辑：保存脚本、分镜、引用、时间线及修订；返回实际资产ID与revision。
3. 执行与交付：提交生成、制作、渲染、检查，查询/恢复/取消以及下载结果。

全链计划引用现有实体，不将任意shell、数据库SQL、供应商URL或密钥作为模型输入。工具由同一注册表/契约生成CLI与MCP视图；不为了协议功能数量增加无用的resources/prompts服务。先保证现有stdio和HTTP可用；远程MCP传输仅在真实客户端需求成立时评估。

### 6.2 状态与错误

- 调用受理、镜头生成完成、成片完成分别可辨。外部调用返回成功可能只代表拿到taskId；必须能继续读取最终产物。
- 高层项目至少表达待输入、方案就绪、运行中、部分完成、待处理、失败、取消中、已取消、已完成，并映射已有底层状态；不整体改写旧任务枚举。
- 返回稳定错误码、影响阶段、是否已提交、是否可重试、应查询的原ID与修复建议；unknown不可被包装为failed并重新收费提交。
- 支持进度订阅或查询；断开不取消任务。公开阶段进度以真实事件为依据，不生成虚构百分比。
- MCP工具返回与CLI JSON包含结构化资产/任务身份；输出长度有界，大结果分页或资产化，不截断剧本后冒称完整。

### 6.3 预算与修改

用户的一次制作预算涵盖生成、配音、转写、媒体处理与允许的自动返工；后台复用冻结报价与实际账务。token日额度继续独立生效，项目预算是用户选择的成本意图，不新增默认强制限额。

并发阶段通过现有事务规则预占可用额度，不能分别看到同一余额后同时超额。阶段报价变化或预算不足时保留成果并给出继续/缩减方案；不逐步重复确认，不静默换成较差方案。退还、预占释放、复用不收费和取消中已发生费用以真实账务为准。

既有产品审核步骤（如A+母图）继续遵循该模块规则；自动完成模式不默认为用户伪造审核。需要改变业务规则时作为单独需求说明。

| Agent规划与制作应用层 | 简报、计划修订、阶段意图、质检决策、依赖失效范围 | 基于已有Agent与video workflow扩展；仅持久化现有实体未承载的意图/引用 |

| imagegen / video / audio适配 | 对应生成请求、模型执行上下文、持久任务与回执 | 复用已有执行通道；确无音频生成能力再补专门适配 |
| timeline / media jobs | 时间线语义、媒体处理、渲染、结果采用 | Agent调用正式服务；Worker复用现有队列、租约和恢复 |
| billing / saas / feature-access | 报价/结算、账户/企业归属、业务权限 | 不因拆模块拆事务，写入仍由所属模块完成 |
| release-runtime / observability | 受理任务归属、发布排空、阶段耗时与结果证据 | 已有监测扩展业务关联，不新建全局事件总线 |

依赖方向：网页/HTTP/CLI/MCP入口 → 应用用例 → 领域与既有适配。模型输出须经业务校验；前端仅负责展示与交互。长流程离开对话仍由持久任务推进，不能依赖Agent进程一直在线。

迁移方式：先扩展公共服务与兼容适配，再逐个接通工具和原生UI，最后移除已无调用者的兼容入口。记录迁移调用方与退出条件；不建立第二套项目、任务或媒体库。

## 8. 质量与验收目标

以下是拟定验收门槛，不是当前成绩。P1登记样本和测量方法，P7按固定版本执行；如需调整必须记录原因，不能看完结果后删失败样本。

### 8.1 功能与可靠性

- 纳入的创作业务操作工具覆盖率达到100%；分母来自P1功能清单，并在P6按当时主线复核。角色受限与身份建立例外分别统计，不计为已实现。
- AC01–AC12场景全部完成，所有受影响账务/权限/幂等关键断言通过；尚未验收的能力不得对外宣称全面支持。
- 不重复扣款、不越权读取、原素材不被覆盖、已确认编辑不被迟到结果覆盖为硬不变量；有限测试通过不作为数学证明。
- 非生成控制面受理p95≤1秒、p99≤2秒沿用现有目标；上传、规划LLM、生成和渲染耗时单独测量。环境/负载未固定时不宣称达标。
- 初次真实全链样本至少20次，覆盖图片、已有素材剪辑、从零成片、局部修改与恢复，记录首次完成率及恢复后完成率。首轮目标自动交付≥18/20；供应商失败计入端到端分母并单列原因。该样本只支持首轮验收，不外推线上SLO。
- 完整质量验收先使用冻结素材/任务集做本地确定性验证，再用真实Agent与供应商验收。测试实际费用、账号授权和样本规模在执行前登记，不用无限重试换通过率。

### 8.2 成片质量

每部成片附输入、计划、素材来源、镜头/版本、实际费用、质检结论。自动检查与人工观看分别记录：

1. 文件可完整解码、尺寸/时长/帧率/音轨与约定一致，无意外黑帧、截断和静音。
2. 剧情、关键卖点、人物/商品身份与必须保留的文字没有明显错误。
3. 镜头顺序和节奏符合用途；字幕可读、不越安全区，对白与字幕时间对齐。
4. 音量无明显削波，旁白清晰，音乐不淹没对白，切点声音合理。
5. 风格统一、连续性可接受；任何未通过项标出时间码、镜头和修复建议。

验收采用技术有效性、需求遵循、主体连续性、剪辑节奏、声音字幕五维，各1–5分；最终样片每维至少4分且无关键事实错误。评分由具名验收者基于固定rubric观看确认，模型自评仅作辅助。自动返工次数与成本由任务授权约束；耗尽后交付已有成果和待修项，不能静默无限重做。

## 9. 阶段与完成定义

依赖主线：P0规划 → P1基础 → P2图片 → P3剧本分镜 → P4剪辑声音 → P5一键成片 → P6全覆盖 → P7真实验收。

- **P0 规划基线**：本PRD、执行台账、源码证据和验收定义落库。仅表示规划完成。
- **P1 Agent接入与项目基础**：从空白账号空间建立项目，上传三类素材，通过CLI/MCP找到并继续操作。
- **P2 图片创作闭环**：从参考图完成批次、检查、定向修改和原图交付。
- **P3 剧本分镜与镜头生产**：内容、角色/场景、镜头计划、生成/复用、恢复构成可用制作链。
- **P4 自动剪辑与声音字幕**：正式时间线、独立配音、字幕、混音和渲染贯通，已有素材可直接成片。
- **P5 一键成片与局部返工**：一句需求贯通全部阶段，人可中途接手，返工范围和费用准确。
- **P6 全业务覆盖与使用体验**：补齐剩余业务域、导演预演和按角色授权操作；覆盖清单无遗漏，CLI/MCP使用文档完整。
- **P7 真实Agent/供应商与发布验收**：完成真实费用和作品验证，再按授权站点蓝绿发布及线上验收；待发布不标已上线。

每阶段交付包含代码、模块文档、实际产物、集中测试及未完成项。详情、拆分工作包和AC见[执行台账](2026-11-10-agent-creation-platform-execution.md)。

## 10. 决策、依赖与发布边界

- 默认由外部Agent负责创意推理，Naumi负责可执行的资产、工具、任务、账务和结果；站内Agent复用同样用例。高层制作必须保存足够计划，使恢复不依赖原聊天上下文。
- 用户给出的全部功能需求持续保留；P5是首个完整短片里程碑，不冒充P6/P7结束。
- 独立配音/转写服务、无界面导演渲染、真实模型效果属于需验证依赖。先盘点现有配置，必要时比较适配方案，不能在PRD中虚构供应商可用性或成本。

- 具体日历排期取决于P1复核、实际执行人、已有任务整合及供应能力，不承诺未经估算的日期。以阶段验收驱动推进。
- 规划及代码合并不解除47暂停发布决定；默认站点和更具体授权按AGENTS.md执行。纯文档不发布，不增加功能迭代/发布计数。
- 容量、发布与公开说明仍使用现有[产品台账](../PRODUCT_READINESS_100K.md)、[发布手册](../RELEASE_RUNBOOK.md)、[生命周期](../RELEASE_LIFECYCLE.md)、[公开说明](../PUBLIC_RELEASE_NOTES.md)，不建冲突的第二套标准。
