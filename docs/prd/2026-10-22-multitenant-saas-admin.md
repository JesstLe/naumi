## 1 目标与交付边界

将现有 Naumi 后台重构为平台管理与企业管理两层，完成平台总览、租户管理与详情、企业后台，以及贯穿两层的创作全链路。管理员从企业或用户出发，可以核对素材、原始要求、执行、结果和实际费用。企业管理者只操作获授权的本企业范围。

### 1.1 三张确定的视觉目标

以下三张均已选定，各自对应正式页面，不是互斥方案：

1. [平台总览](../design/saas-admin-20261022/platform-overview.png)：平台侧导航、指标、趋势、待处理事项、租户列表。
2. [租户内创作详情](../design/saas-admin-20261022/tenant-creation-detail.png)：企业身份与标签、左侧记录列表、右侧素材到结算的主从详情。
3. [企业概览](../design/saas-admin-20261022/enterprise-overview.png)：企业上下文、成员与用量、近期创作、企业授权和待处理事项。

图中的企业、人数、金额、日期、套餐、图片是示例数据，禁止写入真实业务默认值。真实数据没有的功能不得用假数字填充。图中执行步骤按真实事件展示，不能将所有业务固定画成四个成功节点。

### 1.2 完成标准

- G01：三个页面均为真实产品页面，接入受鉴权的数据；不是静态截图、独立演示站或另一套客户代码分叉。
- G02：平台后台只有一套主导航；旧 URL 可兼容访问，不再嵌套完整旧后台。
- G03：从租户列表到某笔创作详情最多两次主要操作；详情和筛选能通过 URL 恢复。
- G04：新创作保留服务器接受的输入、原话、公开参数、执行关系、结果和账务证据；历史缺项明确“未记录”。
- G05：平台角色、企业成员身份、创作归属和扣费归属分别建模；UI 隐藏菜单不能替代服务端校验。
- G06：各完整模块集中测试，最终检查跨企业、媒体、异步任务、账务不变量和同尺寸视觉；每一项结果可追溯。
- G07：代码完成、功能验收、整合、实际发布分别记录。蓝绿发布未收尾时不报告上线完成。

### 1.3 本轮范围与非目标

本轮包括现有功能迁移、租户管理入口、企业组织权限界面、稳定查询上下文、统一创作证据、数据范围与成员操作边界、配置/计费入口归并、必要的兼容数据层。

不新增支付渠道、自动续费或自动订阅扣款；不自定客户售价；不将个人余额转入新企业钱包；不自动归属历史私人资产；不替换创作引擎、供应商适配或既有计费状态机；不重做已有企业协作产品的需求/排期/绩效工作台。企业统一资金池、SSO、跨机租户迁移和独享数据库自动开通不作为本轮默认功能。

“额度与用量”在本轮首先展示真实授权、席位规则和实际消耗。若未有独立企业钱包，只能显示“成员账户用量”，不得冠以“企业余额”。企业套餐采用管理员维护的权益记录，不自动产生订单或扣款。所有展示出来的主要操作必须可执行；未实现操作不伪装成可用按钮。

## 3 角色及权限

### 3.1 身份模型

- 平台管理员：经现有服务端管理员认证。可管理全部租户，查看平台创作证据和账务；平台敏感配置沿用原门禁。
- 企业所有者：在某租户内拥有组织、岗位、可见记录和企业设置权限；不能修改平台身份或增发积分。
- 企业管理岗位：岗位能力与上下级范围共同决定权限；等级不构成跨企业授权。
- 企业成员：保留原创作工作台；只有获授权的企业管理能力才可进入相关管理视图。
- 无企业身份用户：仍可使用原个人功能；不能因为企业功能上线将私人历史自动暴露给任一企业。

### 3.2 权限矩阵

| 动作 | 平台管理员 | 企业所有者 | 企业管理岗位 | 普通成员 |
| --- | --- | --- | --- | --- |
| 查看全部租户 | 是 | 否 | 否 | 否 |
| 新建/暂停/恢复租户 | 是 | 否 | 否 | 否 |
| 修改套餐、席位、平台授予的功能 | 是 | 否 | 否 | 否 |
| 查看本企业概览 | 是 | 是 | 按授权和范围 | 仅已有授权允许时 |
| 管理本企业成员 | 是 | 是 | manage_members 且仅下级 | 否 |
| 管理企业岗位与组织 | 是 | 是 | 沿现有授权，不因新 UI 自动扩大 | 否 |
| 停用企业成员身份 | 是 | 是 | manage_members 且仅下级 | 否 |
| 全站封禁账号 | 是 | 否 | 否 | 否 |
| 重置全局登录密码 | 沿现有安全流程 | 不作为普通企业成员操作 | 否 | 本人原账号流程 |
| 查看企业创作 | 是 | 本企业范围 | view_records 且可见范围 | 本人原工作台权限 |
| 查看平台供应商/采购成本/真实路由 | 是 | 否 | 否 | 否 |
| 企业设置 | 是 | 可配置业务资料 | 明确能力授权才可 | 否 |
| 平台模型和价格发布 | 沿既有版本门禁 | 否 | 否 | 否 |

字段权限在 API 序列化层裁剪。企业端不会收到供应商凭据、原始 upstream 响应、内部模型 ID、采购成本或平台全量审计，再靠 CSS 隐藏。

既有企业端对对话正文和调用审计的限制保留。企业“创作要求”展示明确归属的创作原话，不等于开放整段历史私人对话。平台可以在授权审计范围查看完整关联。

### 3.3 权限计算和撤销

- 有效能力取平台账号状态、租户状态、授权有效期、企业功能权益、成员状态、岗位能力与数据范围的交集。
- 显式 false、0、空允许列表与禁用均有效，不得被默认值覆盖。
- 企业停用仅阻断该企业的新管理/创作请求；已有付费执行按原幂等恢复与收尾，不触发自动重放或任意退款。
- 成员离职撤销后续企业访问，不删账号、不转移资产、不擦除审计。
- 每个服务端请求重新校验范围；前端切企业、切账号、撤权时取消旧请求、清理数据与媒体 URL。
- 全站封禁、密码修改与企业身份停用在界面和 API 命令中区分，禁止复用含糊的 `status` 命令导致全局副作用。

## 4 导航及路由

### 4.1 平台后台

| 一级入口 | 主内容与二级入口 | 建议正式路由 |
| --- | --- | --- |
| 总览 | 指标、趋势、异常、租户摘要 | `/admin/center` |
| 租户管理 | 租户列表、新建、租户详情 | `/admin/tenants`、`/admin/tenants/[tenantId]` |
| 用户管理 | 全站用户、个人档案、平台功能权限 | `/admin/center?section=users`，保留稳定用户参数 |
| 创作记录 | 统一创作列表；图片/对话/调用作为视图和证据 | `/admin/creations`、`/admin/creations/[creationId]` |
| 套餐与账务 | 企业权益、充值订单、积分流水、实际对账 | `/admin/billing` 及明确 section |
| 模型与供应商 | 前端模型、通道、能力、成本资料、版本、健康 | 复用 `/admin/model-management`，高级配置为子页 |
| 系统与审计 | 站点、登录支付集成、内容管理、访问/管理日志、部署 | 复用旧功能的专用子路由 |

主导航不罗列全部技术表。当前页所属模块有唯一激活项；模型新旧两入口不同时突出。只授权实例运维的 deploymentsOnly 入口和范围保留。

### 4.2 企业后台

沿用 `/enterprise`。URL 包含已验证的 tenantId、view、日期、成员、状态、页码、选中 creationId。

主导航：企业概览、组织与成员、岗位与权限、创作记录、额度与用量、企业设置。企业切换器仅列出服务端可访问企业。只有一个企业也明确显示当前企业；无企业权限显示已有返回工作台入口和具体原因。

企业协作工作台保持独立业务入口，导航底部“返回创作工作台”使用现有有效工作台路由，不制造死链接。

### 4.3 旧入口兼容

- `/admin` 登录入口保留；认证后的默认页进入平台总览。
- `/admin?view=settings` 默认进入真实设置，不再打开用户管理；旧 tab 映射到新位置。
- `/admin/center?section=operations|artworks|conversations|calls` 保留深链和视图入口，优先指向对应创作证据视图。
- `/admin/teams`、`/admin/team-access` 的现有授权/组织能力被租户详情收敛；迁移期可保留明确子页链接，禁止第二套完整导航。
- `/admin/billing?section=wallet` 直接打开钱包/充值配置，不显示业务收费首屏。
- 所有旧入口不得因重定向丢失用户、日期、页码或已选记录；不支持的旧字段给予明确提示而非静默扩大查询。

## 5 平台总览详细要求

### 5.1 页面骨架

左侧平台导航；顶部面包屑、当前平台身份和必要的搜索；内容区标题、日期范围与“新建租户”。全局搜索只有在用户/租户/创作均具备真实查询时显示；否则使用当前页面搜索，不能做装饰输入框。

| 编号 | 区域 | 数据和交互 |
| --- | --- | --- |
| P01 | 日期筛选 | 默认最近 7 个自然日，Asia/Shanghai；包含今天；服务端用半开区间换算 UTC |
| P02 | 企业总数 | 查询范围内正式租户总数；停用仍计入总数，另分状态；不等于用户总数 |
| P03 | 活跃企业 | 区间内有已接受顶层创作的不同租户数；无可信归属不计入已确认租户活跃 |
| P04 | 创作数量 | 顶层业务创作数；Agent 子调用不重复计数；指标旁可查看口径 |
| P05 | 待处理异常 | 待核查、明确失败、授权临近到期分别计数；同任务不重复叠入总异常 |
| P06 | 趋势 | 按日展示已接受创作；缺少数据标明不可用，不渲染虚假零线；键盘可获得数值 |
| P07 | 待处理列表 | 按类别进入带条件列表；有状态来源与最后更新时间；无异常显示“暂无待处理事项” |
| P08 | 租户摘要 | 企业、权益名称、有效成员数、期间创作、状态、最近活动、管理入口；默认 10 行 |
| P09 | 查询 | 名称/负责人搜索、状态筛选、排序与分页；URL 可恢复；请求取消与过期响应保护 |
| P10 | 空/错/加载 | 骨架保持布局；局部失败不清除其他独立已成功区域；展示重试和更新时间 |

同比/环比只在比较窗口与分母可靠时显示；无上一期不写 `+0%`。示例截图的增长百分比不作为必做 KPI。

## 6 租户列表和生命周期

### 6.1 字段

| 字段 | 规则 |
| --- | --- |
| tenantId | 不可变 UUID；V1 兼容既有 team UUID；支持复制 |
| name | 2–80 个可见字符，trim，禁止纯空白；作为名称而非唯一权限标识 |
| owner | 已存在且有效的登录账号；显示姓名和必要身份；不输出凭据 |
| status | active、suspended、expired；待开通可用 draft/pending，只有完成后可访问 |
| entitlementName | 来自真实配置；无配置显示“未配置”，不能按人数猜套餐 |
| validUntil | ISO 时间或永久；与成员期限、积分有效期分别展示 |
| seatLimit | 正整数或明确不限；未知为 null；使用人数指有效成员身份数 |
| featurePolicy | 明确的允许/拒绝/继承，不能用空对象掩盖全开 |
| version | 乐观锁版本；写入必须提交 expectedVersion |
| createdAt/updatedAt | 真实服务器时间 |

### 6.2 新建租户

平台管理员点击“新建租户”→输入名称、选择已有负责人、授权期限、席位上限和功能权益→预览→创建。未配置套餐目录时提供实际权益表单，不展示假套餐价格。

提交带幂等 commandId；一次事务创建或引用企业锚点、企业设置、初始所有者关系、授权与审计。冲突或中途失败不留半成品租户。负责人已拥有既有团队时显示可复用的准确对象，不隐式合并另一企业或覆盖成员。

新建用户继续通过已有账号流程独立完成，不在租户弹窗里收集明文密码。重复点击/超时查询同一 commandId；结果未知显示“正在核对创建结果”，不能再生成新 commandId 盲重试。

### 6.3 状态与权益编辑

编辑名称、授权期、席位和功能先显示变更摘要；保存失败保留草稿。409 提示数据已变化并允许重新读取，不覆盖他人修改。暂停需原因并说明影响该企业；恢复重新验证授权。

席位调低至已使用以下不能自动踢人；拒绝该变更并列出当前有效人数。权益收缩不重写已接受任务的冻结执行与价格，只影响后续接受。租户不提供永久删除按钮，归档/暂停保留资产和账务。

## 7 租户详情

头部固定呈现企业名称、状态、权益名称、成员数、授权期和平台身份；平台“查看租户范围”不是模拟登录。切换标签不丢租户范围。

| 标签 | 内容 | 主要操作 |
| --- | --- | --- |
| 概览 | 企业基本资料、期间用量、异常、最近活动 | 编辑资料、查看异常 |
| 成员与权限 | 成员、岗位、上级、身份状态、席位、可见范围 | 管理成员、查看权限来源 |
| 套餐与额度 | 实际权益、席位上限、授权期、功能范围 | 平台维护权益；明确谁可编辑 |
| 创作记录 | 任务列表与全链路详情 | 筛选、打开记录、查看关联证据 |
| 账务 | 已确认归属的消费、退款、预占与释放；原账户账务单独标注 | 查看账本；沿已有审核操作，不造新扣费 |
| 操作记录 | 操作者、动作、目标、时间、原因、变更前后、结果 | 筛选、查看变更 |

当尚无租户独立资金池，账务展示真实记录与来源，不显示图中不存在的“可用企业余额”。权益编辑与财务事实不能混在同一个保存动作。

### 7.1 创作列表

列表筛选：日期、成员、入口、状态、资料完整度；默认最近 7 天和 20 条。标题优先用户要求的安全摘要，其次业务类型；数据库 ID、媒体路径不充当标题。长标题最多两行，完整内容在详情。

一行至少有业务名称、操作者、创建时间、状态、结果摘要、实扣积分、资料完整度。未知实扣显示“待结算/未记录”，已知零积分显示 `0 积分`。原 `imagegen` 技术记录按可靠关系作为子步骤，不能凭时间合并。

桌面采用已选图的左列表右详情；较窄桌面改为列表到详情路由；移动端全宽详情并提供返回列表。详情 ID 和所有筛选进入 URL。后台刷新不夺取用户滚动位置或切换选中记录。

### 7.2 全链路详情字段

| 分区 | 必须展示 | 读取/交互规则 |
| --- | --- | --- |
| 摘要 | 业务、用户、租户、来源、接受/完成时间、业务状态、证据完整度 | 状态、完整度和媒体可用性分别表示 |
| 输入素材 | 原图、参考图、蒙版、首尾帧、视频、音频、文件；角色和顺序 | 受控缩略图；按需原图；明确原始或处理后输入 |
| 原始要求 | 用户原话、补充/负向要求、明确关联的轮次 | 文本可展开和复制；不从输出或标题反推原话 |
| 公开参数 | 用户选择与接受时生效参数，显示名快照、分辨率/比例/质量/数量等 | false、0、omit 保真；当前名称与历史快照分开 |
| 执行过程 | 接受、排队、工具/模型尝试、保存、交付、异常、结算等真实事件 | 时间线按稳定事件顺序；父子关系可展开；无事件则未记录 |
| 结果 | 所有图片、文字、视频、音频、文件及交付状态 | 支持多个产物与部分成功；安全 Markdown；视频不自动播放 |
| 费用 | 冻结报价、预占、实扣、释放、退款、结算状态、账本引用 | 各项独立，按 billing operation 去重；不以当前单价估算实扣 |
| 技术与来源 | 原始来源引用、配置版本、证据来源、内部执行细节 | 平台权限限定；企业端服务器裁剪 |

详情只读，不能通过“重新查询”触发生成、补扣、退款或重放历史请求。截图中的“导出记录”仅在受权限控制的文本证据导出实现后显示；不默认批量打包用户媒体。

### 7.3 状态与缺项

业务状态至少区分：queued、running、succeeded、partial、failed、cancel_requested、cancelled、needs_review。适配源状态时保留原值供审计，未知源状态不能映射为成功。供应商 HTTP 成功/流建立不等于业务完成。

字段状态：recorded（含已知空值）、not_recorded、unavailable、not_applicable、restricted。完整度由必要字段及真实事件确定，不伪造百分比分数。素材删除显示“素材不可用”，不会删除任务和账务证据。

## 8 企业后台详细要求

### 8.1 企业概览

对应第三张视觉图。默认最近 7 天，所有区域使用同一经服务端验证的企业及岗位范围。

| 编号 | 区域 | 规则 |
| --- | --- | --- |
| E01 | 企业切换器 | 服务端可访问列表；切换清除旧数据、详情、草稿与播放器；若有未保存编辑先提示 |
| E02 | 当前范围 | 企业名、本人岗位、全部企业成员/我的下级等准确范围；不声称全企业统计而实际只查下级 |
| E03 | 成员/活跃/创作/实扣 | 真实可见范围内统计；不包含平台其他租户；实扣仅消费事实 |
| E04 | 最近创作 | 缩略图、业务、成员、状态、已结算积分、时间、查看；保留失败和处理中 |
| E05 | 成员用量 | 按实际消费归集，按同一范围排序；退款另外呈现，不用估计作实扣 |
| E06 | 企业授权 | 真实权益名称、席位使用、授权期限；未维护项明确未配置 |
| E07 | 待处理 | 可管理范围内失败、待核查、即将到期等真实事项；链接能恢复筛选 |
| E08 | 管理动态 | 本企业允许查看的成员/岗位操作摘要；不得暴露密码或平台内部操作秘密 |

全局管理入口、供应商路由、采购成本、平台收入和其他企业名单不进入企业端响应。企业版名称、50 席位和到期日期来自配置，不采用图片中的样例。

### 8.2 组织与成员

列表：姓名/账号、岗位、直属上级、用工类型、成员状态、企业身份期限、最近活动、管理操作。全站账号状态可作为不可编辑提示，不能与企业身份混同。

- 所有者调整岗位/上级先验证无循环、不可越级、不能管理自身权限来提权。
- 永久成员期限为明确 null；实习生可有独立到期时间。租户到期、成员到期、账号到期、积分到期分别展示。
- 企业管理员暂停/恢复的是 membership，不直接写 `app_users.banned`；旧全局操作从企业 UI 移走并在 API 防误用。
- 成员加入与移除操作使用事务、权限校验、版本与审计；离职不删除创作归属或账务。
- V1 不默默开放一人多企业：若代码约束未完成迁移，准确提示冲突；完成显式 membership 模型及全局账号解耦后再开放，不以 UI 企业切换器作为已支持证明。
- 选择既有账号加入时只搜索允许管理的账号范围；不能让普通企业管理员枚举全站用户资料。无安全邀请/验证机制时，企业自行加入流程不伪造，平台代管理入口应真实可用并清楚说明。

### 8.3 岗位与权限

沿用可用岗位能力并显示每项影响范围；将能力、等级、数据范围分别展示。角色修改需预览受影响成员数、版本校验和原因。拒绝循环上级链、自我提权、跨租户角色 ID、管理同级或上级。最后一名有效所有者不能通过普通成员操作被移除或停用。

### 8.4 企业创作与用量

复用创作详情组件和公共契约，企业投影只含允许字段，不调用平台 admin API。新记录按冻结 tenantId 查询；历史无法确认归属时不自动归为企业资产。

保留已授权的旧成员内容查看时必须独立标注“成员历史记录，企业归属未确认”，保持原可见范围，不能扩展到私人对话、供应商信息或其他企业资料；该视图不计入已确认企业资产/财务指标。新增数据不得继续依赖这种兼容方式。

额度与用量页展示真实席位/功能限制和区间实际消耗。客户价格、钱包和成员限额仅在已有服务端规则支持时开放对应操作；无独立资金池不提供“分配企业余额”。

## 9 数据契约和查询原则

### 9.1 通用返回

列表包含 items、分页、appliedFilters、generatedAt、scope（platform/tenant/member）、availability。分页与总数使用一致过滤；查询最多 100 条/页、默认 20；日期跨度设置合理上限，导出走单独受控路径。

错误：未登录 401、明确无功能权限 403、对象不在可见范围 404、版本冲突 409、参数无效 400、可重试服务不可用 503。只返回稳定错误码和必要中文解释，不回传 SQL、凭据、堆栈或完整上游响应。

所有管理数据使用 `private, no-store`，缓存键如存在必须包含认证作用域、租户和版本。没有认证的预取不能造成跨用户缓存。

### 9.2 推荐 API 边界

| 契约 | 职责 | 权限 |
| --- | --- | --- |
| `GET /api/admin/tenants` | 平台租户列表、筛选及摘要 | 平台管理员 |
| `GET /api/admin/tenants/[id]` | 租户概况、权益及已确认用量 | 平台管理员 |
| `POST /api/admin/tenants` | 创建租户 command | 平台管理员、同源、幂等 |
| `PATCH /api/admin/tenants/[id]` | 修改资料/权益/状态 command | 平台管理员、版本/原因 |
| `GET /api/admin/saas-overview` | 平台总览，复用底层统计 | 平台管理员 |
| `GET /api/admin/creations` | 全链路列表，支持 tenantId/user/source/status | 平台管理员 |
| `GET /api/admin/creations/[id]` | 摘要、输入/结果、参数、费用 | 平台管理员 |
| `GET .../[id]/events` | 时间线/子任务分页 | 与主记录相同 |
| `GET .../[id]/assets/[assetId]` | 逐次鉴权的受控媒体代理，含视频 Range | 主记录+素材双重校验 |
| `/api/enterprise` | 现有企业列表/快照/成员命令 | 原企业鉴权和范围 |
| `/api/enterprise/creations` | 企业列表、详情、事件、媒体的客户投影 | 经企业鉴权；绝不转发完整 admin 返回 |

可复用原 API 而非机械新建全部端点，但须保持职责、权限、分页与错误语义，记录最终路由映射。GET 不触发供应商调用或业务写动作；审计访问日志除外。

### 9.3 冻结归属与证据存储

采用既有全链路设计的 record、asset、event、link 独立证据层；执行与账务仍由原模块负责。

| 对象 | 核心字段与约束 |
| --- | --- |
| creation record | creationId、schemaVersion、actorUserId/email、scopeKind、tenantId、payerAccountId/账务来源、sourceKind/sourceId、parentId、acceptedAt、要求与参数快照、模型显示名及配置版本、记录状态 |
| asset | creationId、方向、角色、顺序、原始/处理后、受管存储引用、hash、MIME、大小、可用状态；不存可直接绕过权限的永久 URL |
| event | creationId、稳定 eventKey、序号、业务时间/观察时间、类型、真实状态、公开摘要、输出引用；追加去重 |
| link | creationId、目标类型/稳定 ID、关系和证据来源；双端同账号与租户范围校验 |
| membership | 稳定企业与账号关系、岗位、状态、授权期、版本、加入/离开时间；全局账号为独立对象 |
| tenant entitlement | 企业、真实权益/席位/期限、显式功能配置、版本、操作者及审计；不生成财务事实 |

scopeKind 区分 personal、tenant、legacy_unconfirmed；tenant 类型必须有可信 tenantId。服务器解析身份与活跃工作空间，不能信任 body 中的 email/tenantId/role。普通创作请求没有明确企业上下文时不得按“当前任职关系”自动给旧资产补归属。

### 9.4 工作空间、付款账户及离职历史的确定规则

- 创作工作台提供“个人空间/企业名称”的明确上下文；入口从企业后台进入时预选并核验对应企业，但企业选择本身不授予能力。选择仅影响后续新项目/会话，当前项目/会话创建时的归属固定，不能通过切换下拉框搬家。
- 项目、画布、会话及有父任务的调用优先使用持久化父对象的 scope。请求传入 scope 与父对象冲突时拒绝；Worker 继承同一冻结 scope，不接受新的客户端覆盖。
- 无父对象的新请求必须由服务端解析 personal 或当前有效 tenant context。兼容旧客户端没有上下文时只按原个人能力处理并记录 personal/legacy-client 来源，不能获得企业权益。明确传入企业但未授权/过期/停用时拒绝，绝不静默退回个人执行。个人入口仍可使用原个人能力，但不会借用暂停企业的模型、席位或额度授权。
- 企业创作素材必须属于同一企业，或由本次上传取得。复用本人个人素材时通过明确选择进入企业上下文，界面说明企业授权管理员可查看本次输入，并保存本次受控输入引用；不得自动扫描/转移个人媒体。其他企业素材即使同一账号也不能按对象 ID 直接引用，跨企业分享另行设计。
- V1 不改变实际付款规则：接受时由既有计费层解析并冻结真实付款账户，记录 payerAccountId 或等价稳定账户引用及 billing operation。通常为现有请求账号；既有明确代付规则必须有实际配置/账本依据。不得因 tenantId 或企业所有者身份而自动改扣老板账户，也不把成员个人消费转为企业债务。
- 租户内按项目归属展示的消费须附“扣款账户/来源”；企业归属与付款账户是不同维度。未知付款方标未记录，禁止按当前成员关系补全。企业套餐与授权本身不产生财务记账。
- 企业所有者可查看本企业所有已确认归属的创作，包括已离职成员历史；普通岗位管理者默认仅查看当前有效下级的记录，离职归档归所有者/平台查看。页面明确“当前下级”范围；未来归档授权必须单独定义，不能靠 tenantId 放开全部。
- 历史归属未确认的成员资料继续使用原兼容范围；成员离职即撤销该兼容读取，不能因过去任职而保留私人历史访问。已确认企业资产则不随离职删除或转为个人。

新任务接受时冻结归属并传至 Worker、工具子任务、模型调用、媒体、结果和计费 operation；后台恢复使用持久化快照，不重新查当前成员关系。成员离职或换企业不改变旧 owner。旧记录只通过确切来源引用适配，不按时间、标题、相似 prompt 或当前成员列表推断。

一条顶层创作与子任务各有稳定标识，统计按明确 parent 关系去重；财务按唯一 billing operation 去重。未知归属与未知费用允许为空并附状态，不能用 0 表达未知。

## 10 创作入口采集范围

| 入口 | 接受时捕获 | 执行与结果关联 | 必须覆盖的例外 |
| --- | --- | --- | --- |
| 图片异步生成/编辑 | 原话、输入角色、冻结公开参数、tenant/actor | job、实际尝试、作品、结算 | 超时未知、Worker恢复、输入已转换 |
| 画布生成/改字/选区工具 | 节点/任务引用、实际提交素材与选区 | 画布 task、image job、结果节点 | 节点移动不是新创作；复制不冒充重新生成 |
| 商品套图、A+、竞品等同步工具 | 真实用户输入、素材、operation | 工具调用、批量输出、账本 | 部分成功、零积分、同步失败 |
| Agent/聊天 | session+turn、原话、明确提交素材 | 工具子任务、所有产物、成本去重 | 单轮多工具、工具失败、文本结果、同轮恢复 |
| 视频 | 首尾帧/图/视频/音频角色、参数 | video task、查询、交付、结算 | 处理中、取消申请、供应商状态未知 |
| ComfyUI/工作流/导入 | 来源、工作流和受控素材引用 | 实际执行或导入结果 | 导入不等于模型执行；不可恢复原材料标缺项 |

实现必须形成具体源文件和入口清单；某路径未经查证不能以“统一包装应该覆盖”结案。证据采集不得保存密钥、完整 HTTP 头或无边界 payload。输入体积与角色白名单采用现有受管媒体限制。

采集失败采用持久记录/事务或可恢复 outbox，不能静默产生无归属的新增企业任务。供应商已接受后，证据写失败不得重发收费请求；记入可恢复待核查状态并由原恢复流程处理。证据系统不是第二个调度引擎。

## 11 视觉、交互与可访问性

### 11.1 视觉基线

- 桌面参考为 1440×1024 设计比例；实际 PNG 比例按文件读取，QA 对齐同尺寸截图，不拉伸图片。
- 色板：导航深海军蓝 `#18324F`；页面 `#F7F9FC`；主体白 `#FFFFFF`；主要文字 `#13243A`；操作蓝 `#1762DC`；分隔 `#E3E9F1`。状态色按现有可访问规范调整。
- 继承项目中文系统字体；正文 14–16px，页面标题 26px，分区 18px；不引入外部字体网络依赖。数字可用 tabular-nums。
- 侧栏约 208–216px；顶部 60–64px；内容边距 24–28px；控件 36–40px；圆角 8px 左右；表格行 48–64px，带缩略图行可 72px。
- 主要对象为表格、列表和详情；使用间距和细分隔组织，避免多层嵌套卡片、无意义渐变和大量阴影。
- 沿用项目图标库中与预览最接近的线性图标；真实用户素材由授权媒体读取。示例产品图仅用于隔离 fixture，不进入生产数据。

### 11.2 响应式与状态

1440/1280 桌面保留侧栏；1024 附近减少非核心列，详情独立展开；768 以下折叠菜单；390 下纵向内容、全宽详情、可见返回和筛选。页面整体不横向溢出；确需横向表格有局部滚动和固定关键列。

菜单、标签、筛选、列表项、弹窗、保存与错误全部具备 hover、focus、selected、loading、empty、error、disabled、success 状态。弹窗焦点可达、Esc关闭、返回原焦点；有未保存修改时提示。状态不能只靠颜色。

图片加载失败保留文件角色和错误重试。管理后台媒体采用逐次鉴权代理，不返回可绕过后续撤权的共享签名 URL；撤权后停止新读取并取消正在进行的前端请求、清除 object URL 和当前展示。已传给用户的字节无法召回，不声称可以远程删除已下载内容。过期请求不能把旧企业数据覆盖到新企业。长要求和媒体路径不会突破列宽。无用宣传文案不进入 UI；保留权限、未知事实和财务口径这些必要解释。

## 12 性能、安全和迁移

- 列表不拉取全量媒体/对话/事件；缩略图懒加载、结果与事件分页；详情视频不自动下载整段。
- 数据查询按 tenant/owner/time/source 建合适索引，避免按每行进行 N+1 全量统计；慢查询记录证据后优化，不凭空承诺 SLA。
- 管理写入同源校验、身份校验、事务、幂等命令、版本和审计全部保留。模糊检索参数化，排序白名单。
- 用户内容用安全文本/现有安全 Markdown 渲染，媒体不执行 HTML/SVG/脚本；媒体 ID 与其记录、租户及操作者一并校验，防路径遍历与外链 SSRF。
- 迁移只扩展兼容结构，先字段/表与双读适配，再新写入与明确证据回填；本轮不删除旧表/旧字段，不回灌线上数据库。
- 旧会员唯一约束、全局封禁逻辑调整前先列所有调用方，集中验证。不得为了支持下拉框就直接去掉唯一索引。
- 回填有 dry-run、数量、来源依据、审计、批次幂等和可停止恢复；不明确的历史归属不回填。
- 回滚只回兼容代码和入口；保持新增可读数据、媒体和账务，不重放已接受/未知收费任务。回滚镜像必须理解新 membership 状态、冻结归属与媒体权限，并通过 A08、D06、A03/A10 回归；不能公开切回会忽略新权限语义的旧版本。发布前准备合格兼容回滚候选，否则阻断发布或走受控维护恢复，不能以“镜像能启动”冒充可回滚。

## 13 发布和交付

先完成本地隔离 fixture/API/浏览器/类型和构建证据，再整合最新 main 和已完成同事提交。纯内部后台改造不写公开更新说明；企业用户可见更新按项目公开文案规则单独审核且不泄露内部细节。

用户已授权的发布沿项目约定执行，但必须先读取 `docs/RELEASE_RUNBOOK.md`、`docs/RELEASE_LIFECYCLE.md` 和最新 47 交付状态；一个完整 Web 与同固定镜像 Worker；三锁；容量以 MemAvailable 和峰值核实；只有一个临时候选。
