# 画布图片贴合与原子删除修复（2026-09-29）

## 问题

1. 图片标题已经绝对定位到节点上方，但 React Flow 节点高度仍额外增加 `NODE_LABEL_H`，导致图片卡比图片高 36px；移除白色背景只能隐藏白边，不能让边框真正贴合图片。
2. 比例自愈读取数据库中的历史宽高，而不是浏览器实际解码得到的 `naturalWidth/naturalHeight`；旧元数据错误时无法修复。
3. 自动比例修复复用手动缩放回调，会写入坐标并增加撤销记录，导致自动布局被冻结、撤销栈被系统动作污染。
4. 图片与文字混合删除顺序调用两个接口，第二步失败时可能出现服务端只删除一半、前端仍显示旧状态且没有撤销记录。

## 实现

- 图片节点边界高度改为纯图片高度；标题继续显示在节点边界上方，布局间距仍单独计算标题空间。
- 图片加载后始终读取自然尺寸；自然尺寸和历史元数据不一致时回填真实尺寸，再按自然宽高比修复显示高度。
- 新增静默尺寸修复路径：只更新 `canvas_width/canvas_height`，不写 `canvas_x/canvas_y`，不写撤销栈。
- 新增 `/api/canvas/nodes/delete`，通过 PostgreSQL 单事务同时软删除图片节点、删除文字节点；任一 SQL 失败时整体回滚。
- 单独删除图片或文字节点也统一使用原子删除接口，避免行为分叉。

## 验证矩阵

- TypeScript：`npm exec tsc -- --noEmit`。
- 静态契约：节点样式高度不再包含 `NODE_LABEL_H`，比例修复使用自然尺寸及 `sizeOnly` 路径。
- 数据库事务：注入文字节点删除失败触发器，确认图片软删除同步回滚，两个节点均保留。
- 浏览器回归：图片/文字混合移动、单删、混合删、撤销、重做、刷新恢复、视频和音频节点复制。
- 发布前：生产构建、部署健康检查、画布页面检查及回滚演练。

## 回滚

- 代码回滚以本次独立提交的父提交为准。
- 数据库没有新增列或迁移；新接口和函数移除后不会遗留结构变更。
- 已经静默修复的 `canvas_width/canvas_height` 是有效显示尺寸，不需要数据回滚。
