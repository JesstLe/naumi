# 模型批量配置

## 目标与实现（2026-10-07）

后台 `/admin/billing` 默认进入「模型批量配置」。同一个配置中心完成选实际上游、创建/复用公开模型、设置展示名称、基础售价、选择兼容功能、预览、加入草稿、统一发布。供应商目录/能力登记有同页分区入口，不建立第二套价格或路由配置。

1. 在供应商/上游分区登记连接和模型，核验实际能力；自动目录只证明模型存在，不自动证明生成/编辑能力。
2. 选择新增或复用公开模型。新增 ID 与真实供应商 ID 独立；复用不允许悄悄换共享模型的上游。
3. 设置人民币基础价、成功单位、积分兑换率/舍入方式；文字可选实际用量价。
4. 全选兼容功能或只选未配置功能。停用、未核验、独立处理器和不兼容功能显示原因并禁止选择。
5. 默认设为所选功能默认模型，保留已有此模型特殊价格、路由、参数、后处理和其他模型选项。明确勾选才覆盖目标模型价格/关闭其路由。公开模型展示名称是共享字段，预览列出影响范围。
6. 预览默认模型、售价和路由变化，确认加入草稿。随后使用统一「校验并预览发布差异 → 填写原因 → 确认发布」。加入草稿不改变在线配置。
7. 单功能分区维护例外，再一起发布完整版本。

## 数据、权限和生效

批量计划写入现有 `ModelConfig.publicModels` 和 `business[feature].options/defaultModelId`，不改变共享 `bindings`，避免误改未选功能。无需新增数据库迁移，复用现有 `PUT /api/admin/bi/model-config/draft`、`POST .../validate`、`POST /api/admin/bi/model-config` 和版本回滚接口。后端继续执行管理员、同站、草稿修订、能力、计费单位与完整配置校验。Router 按现有 prepare/activate/receipt 生效确认，在途任务保持原版本。

在生产后台发布才更新生产配置。本地草稿没有跨数据库自动同步。基础价是批量写入初始值，不是今后覆盖所有功能的隐式继承；例外价格可独立编辑。工具/画布实际模型列表和报价继续从既有有效配置读取。

## 验收与回滚

`scripts/verify-model-batch.ts` 检查兼容性、原对象不变、整批拒绝、公开名称、默认列表、已有价格/路由/参数/后处理保护、明确覆盖、重复应用、停用保护。
浏览器验收通过隔离 PostgreSQL 和既有真实 Go Router 控制协议完成发布、刷新、模型列表、报价、非管理员、移动布局；供应商生成端点禁止请求。
代码回滚使用固定版本发布脚本生成的 `ROLLBACK.sh`；业务配置回滚在「发布记录」恢复原版本。保留数据库、媒体及供应商成本记录，不重新生成图片。
