## 已确认问题与实现

1. **BI 关键词/账户类型查询逐事件重复查询账户和企业。** 原 `accountFilter` 在流水、作品、任务、调用等每行上执行相关子查询，企业归属还重复扫描团队/成员。现在单条 SQL 内先聚合企业目录和匹配账号，以集合成员条件过滤事件；用户列表和概览复用目录联接。原姓名/邮箱/企业串联搜索、人工资料兜底、暂停企业与成员的目录归属、历史孤立邮箱、跨账号限制不变。没有跨请求缓存。
2. **新版用量查询同类相关子查询放大。** `usage-repository` 同样改为单查询目录/匹配集合，保留该模块既有当前归属优先级、历史事件计数、授权账号集合和未知值语义。
3. **状态索引过时、任务关联调用缺少索引。** 当前状态取 `result.status` 优先，旧索引只取顶层状态。新增有效状态复合索引及 `(operation_id,email)` 索引，保留旧索引供兼容回滚。统一创作状态筛选改为常量别名集合，避免逐行 CASE 计算。索引通过显式运维脚本并发创建，不在请求或启动中创建；生产尚未应用。
4. **BI 路由同步重复请求。** 本地筛选提交与 URL 回写分别创建等价 filter 对象，触发两次读取。请求 effect 改用序列化的真实查询参数；中止旧请求、禁止旧响应回填的保护保留。
5. **租户/创作文字搜索逐字路由跳转。** 新增局部输入组件，输入立即反馈，停顿 250ms 后提交 URL 条件，旧路由确认不会覆盖后续输入；日期和状态切换保持直接提交。
6. **供应商资料库旧读取继续执行。** 列表/详情读取现在支持 AbortSignal；更换条件、关闭详情和卸载都会取消相应读取，列表也按参数去重。资料库本身已有显式搜索提交，未将其误改为逐字请求；写操作和幂等规则不变。
7. **旧用量页全部用户渲染、全站用户资料预载及逐行 find。** 增加可选服务端分页，每页 30 人，汇总仍覆盖全体；成员资料仅批量读取当前页，Map 替代逐行全表扫描。旧 API 不传分页仍保留完整契约；成员资料的 opt-in 视图保留管理员鉴权，空集合返回空集合，最多 100 个账号。
8. **创作详情屏幕外媒体立即下载。** 素材接近可视区后才请求；原图仍可放大，视频/音频仍用受保护播放地址。已取消读取完成后不再创建遗失的 blob URL；图片使用异步解码。
9. **结果缩略图读取无关原图任务。** 读取结果图只取作品邮箱与结果地址，输入图继续保留完整来源查询和校验。私有响应、鉴权、完整图片访问审计保持。
10. **轮询重叠/旧响应覆盖。** 部署管理改为一次读完再等下一轮，隐藏页暂停轮询，主动刷新会取消旧读；模型健康读取取消旧请求，静默轮询不与手动读取重叠，卸载后不更新页面。

## 模块交接

- **模块与职责：** BI 负责只读运营统计；accounts 负责原生后台账号/用量读模型；各前端 hook 管理自身请求生命周期；artworks/创作媒体保持原归属模块。
- **公共接口、依赖方向、数据/状态/事务归属：** HTTP 路由继续先鉴权后调用读模型；BI 原 REPEATABLE READ READ ONLY 快照不变；企业范围由服务端传入，未引入额外写入、缓存授权或跨模块事务。旧用量 API 增加可选 page/size，旧用户 API 增加 view=members + 重复 member 参数，均向后兼容。
- **实现与迁移状态：** 不新增业务表，不改变写入/扣费/执行语义；两项增量索引在 `scripts/migrations/20261110-admin-query-indexes.sql` 和现有 `scripts/ops/admin-query-indexes.ts` 中登记。线上应用必须另按目标站蓝绿发布及部署锁流程执行。
