# 47 高峰期 TCP 内存耗尽与 NAS 读取释放

## 基线与现场

任务基线 `b6b5af3b1b2cc3d7f9519e0035623f01cb5342b4`。独立工作树，保留共享目录 20 项原修改；不合重构线。实查线上 Web/Worker 已为 `7e664c7a`，此前性能候选由其他发布任务于 18:29 完成上线。

10 月 27 日与 28 日 17 点多，历史内核均明确报 `TCP: out of memory -- consider tuning tcp_mem`；同窗口主机仍有可用 RAM、无 Swap 换页。今天 17:33 Worker HTTP 503/UNKNOWN，NAS 双探测超时与 SSH 异常同窗口出现，17:49 重启。它不同于普通进程 OOM、用户模拟进度或 Redis 排队缺失。

19:10 重启后 TCP 再次占用 111271 页（约 434.7 MiB）；NAS socat/SSH 转发层存在大量积压，Web 内同一 NAS 端口的接收队列数 MiB 且几十分钟无应用数据进展。约每分钟一次原生工作台读图 500，与新增连接时间对应。精确关联的已生成原图为 22767394 bytes（约 21.7 MiB），超过错误沿用的 12 MiB 输入限额。原始任务/请求/连接身份只在 ignored 证据。

代码断点：`readManagedObject` 在 Content-Length 超限时尚未取得 reader，直接 throw，跳过唯一的 reader.cancel。远端非成功响应转本地镜像也未释放 body。存储 fetch 未显式 no-store，Next 缓存分支会干扰响应取消。工作台查看既有生成图错误沿用 12 MiB 输入限制，并重复读取原图。

后台失败单独分类：最近 24h 父任务 587 succeeded / 90 failed；父子不相加。新版后的四个失败父任务，其原供应回执显示 HTTP 402 / quota，属于上游额度拒绝，不属于 TCP 故障。今日旧版本还有交付 RangeError 与连接池等待失败；它们的既有修复是否有效按运行版本区分。

## 模块与职责

- 对象存储模块拥有网络响应的消费/释放，所有签名请求明确 `cache:no-store`；拒绝 Content-Length、超限流、HTTP 错误、镜像回退均释放同一响应。
- 工作台 `imageBytes` 保持账号/作品归属，原输入素材限制不变；查看已生成图片使用既有 64 MiB 输出读取契约，只读一次，不再把输入准入限制应用到展示。
- 媒体 Route 在放弃远端错误响应时先释放 body，再走既有本地镜像语义。
- 无业务表迁移，不改变生成、计费、UNKNOWN、租约、供应商重投和并发参数。
