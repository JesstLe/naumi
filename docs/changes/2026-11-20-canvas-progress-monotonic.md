# 画布节点进度：任务身份与阶段计时分离

用户目标：同一次节点生成的显示进度不倒退，尤其是排队转执行的前 20%；新任务正常重置。
用户随后追加：前中段加快，超过90%才慢下来。本切片一并调整生成展示曲线。

## 根因与复现

`image-runs` 的派生/替换、空白节点入口在收到执行阶段时重置 `startedAt`，避免把排队耗时算入生成曲线。
`GenerationPlaceholder` 同时把该时间作为任务身份，时间变化会清空已显示的最大值。
实际 React + Edge、受控时钟复现：准备 14% → 排队 14% → 开始生成 **8%**，断言 exit 1。
阶段重计时本身正确；问题是显示身份错误复用了阶段时钟。

旧 `verify-canvas-generation-progress.cjs` 仍要求排队 0%，在未改生产源码的基线返回 `21 !== 0`。
本轮保留现行排队低进度和生成曲线，仅更新过时断言及浏览器测试，不削弱准入或权限。

## 公共接口、依赖方向及状态归属

- `GenerationPlaceholder.taskId?: string`：展示尝试身份。同 ID 的阶段/时钟变化沿用显示最大值；换 ID 才重置。旧调用未传 ID 时仍按 `startedAt` 重置。
- `scene-types` / `scene-projection`：派生、多图槽、原位重生成使用既有 `CanvasGenerationTask.id`；空白节点透传 `generationTaskId`。
- `image-runs`：空白节点在尝试开始时生成局部展示 ID；排队、执行和保存不更换它。不是供应商任务编号，不写业务表，不替代 operation/idempotency identity。
- `ArtNode` / `PendNode`：把展示 ID 传给原进度组件，不改节点几何或交互。
- `generation-progress`：生成前中段从旧18–32秒到99%改为6–10秒到90%；随后45–75秒缓慢到99%。每任务保持稳定的时长/缓动差异，去掉生成曲线叠加的正弦摆动，纯曲线自身也不倒退。排队低进度与真实阶段不改，结果可以提前结束展示。
- 依赖仍是原任务编排 → 场景投影 → 节点组件 → 展示进度；无新任务引擎、全局缓存或跨账号状态。

保留：阶段重计时、不将排队耗时算作生成耗时、99% 等待、原保存阶段上限、完成计数、失败/UNKNOWN 与原任务查询、节点位置/连线、任务提交/恢复、计费和供应商协议。
没有改 API、Worker、模型配置或生产配置。纯展示状态仍受组件生命周期约束；不新增跨刷新或浏览器重启的进度持久化。
