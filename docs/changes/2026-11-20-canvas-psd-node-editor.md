# 拆层子节点与图层编辑

拆层成功后，原图通过画布已有的父子连线关联一个分层节点。双击节点的图片进入编辑器，可以选择、移动和显隐像素图层，上下调整顺序，用可调半径的笔刷擦除或恢复蒙版。编辑器支持撤销、重做和放弃未保存修改。保存会更新节点预览，PSD 下载绑定到服务器实际保存的版本。

## 数据与协作

- 由本任务在 `codex/canvas-psd-editor` 实现。初始基线 `b5b6d09b`，集中验收前同步 `6c682412`。改动集中在画布拆层入口、结果关联、编辑器和图层文档存取。
- 拆层供应商、原图和原始 PSD 保持各自的归属。已有历史试用回执可从原图的智能拆层入口恢复。对缺少原图编号的旧回执，服务端核对原始请求指纹、账号和项目。一次操作对应一个稳定子节点；恢复和编辑读取已有图层。
- `/api/canvas/layered-psd/document` 负责关联、加载、保存和导出。沿用现有画布作用域、作品、事务与私有媒体接口。文档保存图层顺序、位置、显隐和图层局部坐标中的蒙版笔画。一次保存事务同步更新文档版本、节点图片和媒体归属。冲突写入返回 409，重复提交相同内容返回已保存的版本。
- 编辑范围为 Naumi 拆层生成的像素图层。海报中的标题保留像素字形。导出的 PSD 保留独立图层和可编辑灰度蒙版。数据库变更仅新增文档表；回退应用代码时，保留文档、媒体和作品。

## 实际验收

本机独立 PostgreSQL、私有媒体目录与真实 Next 画布。使用已经生成的 784 × 1440 海报，在隔离环境重建历史拆层回执。供应商传输使用已有 11 层像素，未发起真实生成。浏览器实际经过原图菜单、子节点、编辑器及下载，无需生产账号或生产回写。

1. Chrome 打开原图的智能拆层入口，得到一个有连线的子节点。双击后显示全部 11 层。移动主产品瓶身并下移两层，蒙版擦除、撤销、重做、部分恢复分别对比实际像素。
2. 保存后刷新，重新双击，顺序和编辑画面一致。读取画布上实际显示的子节点图片、数据库引用的私有 PNG、浏览器下载的 PSD 合成预览，三者与编辑器逐像素相同。
3. 独立使用 Python psd-tools 打开下载的 PSD。11 个图层的原始像素各自与输入一致，瓶身位置和层序已变，蒙版包含 0、255 和中间灰度。跳过 PSD 内嵌预览重新合成图层，每个 RGBA 通道的最大差值为 1/255。
4. 原任务重复关联只产生一个子节点；旧版本覆盖返回 409；原保存请求重试返回同一版本；匿名读取返回 401。浏览器没有提交新的拆层生成请求。
5. 原拆层 PostgreSQL 验收覆盖扣费、未知受理、失败退款、原操作幂等及私有归属。初次浏览器夹具缺少独立 Worker 密钥和站点初始化，分别修正夹具后完成上述路径。隔离环境的媒体缓存服务不可用，浏览器通过已有私有媒体原图回源，已检查实际显示的像素。

复现入口为 `scripts/verify-canvas-psd-document.ts <本地原始PSD>`（开启专用 loopback fixture 数据库和 `NAUMI_VERIFY_ISOLATED_DB=1`，使用 Node 的 `--conditions=react-server --no-experimental-strip-types --import tsx`）；随后执行 `uv run --no-project --with "psd-tools[composite]" --with Pillow python scripts/verify-canvas-psd-roundtrip.py <同一原始PSD> output/psd-document-e2e`。媒体素材和下载结果仅留本机的忽略目录。此记录对应隔离端到端验收，47 尚未发布此编辑器。

整合主线后，端到端、独立重合成、原拆层回归和 TypeScript 类型检查最终退出码均为 0。类型检查曾与 Next 启动同时读取正在更新的生成类型目录，待测试宿主结束后顺序复跑通过。

## 单独导出选中图层

双击分层节点，选择图层列表中的名称，再在列表下方选择 PNG 或 PSD。有未保存编辑时，入口显示“保存并导出选中图层”，下载读取实际保存的版本。文件按该层的原始像素尺寸输出，包括移到海报边界外的部分。隐藏层也可单独导出，海报中的显隐设置保留。

PNG 使用修边后的透明通道；PSD 内只有选中的命名像素层，使用该层自身坐标，保留原像素和绘制的灰度蒙版。文件名前缀取自原始图层序号，同名图层可区分。整张海报仍通过编辑器底部的“导出 PSD”下载。

在原文档 GET 导出入口上增加成对的 `layer` 和 `format` 参数，分别指定原始图层编号和编码。相同的账号、项目和文档版本校验适用于单层和整图。使用原合成器处理图层及其蒙版，导出时读取既有私有素材。

任务分支 `codex/canvas-layer-export` 从 `531a0bb2` 开始，整合主线 `218c4a12`。开发范围为图层编辑器、文档导出入口和对应验收。复用上一节两条验收命令。在隔离的 Chrome、Next 和 PostgreSQL 中，使用同一张真实 11 层海报，先从含未保存蒙版的瓶身直接导出，再刷新并依次下载所有图层的两种格式。独立打开全部 22 份文件，逐层检查图层数量、名称、尺寸、源像素、透明通道与蒙版。额外覆盖隐藏层、移动及重排、首次下载与重开后一致、黑白底重新合成、版本冲突和匿名请求。整图回归、浏览器验收、独立文件解析和 TypeScript 检查退出码均为 0。

首次本机测试因跨盘依赖链接无法解析字体，改用工作树内的同版本依赖后通过。浏览器下载的产物和截图留在忽略目录 `output/canvas-single-layer-export-20261120/`（本机主工作区），测试浏览器、Web 和数据库宿主已关闭。本次为隔离端到端验收，尚未发布到 47。
