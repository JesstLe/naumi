# 画布模型报价与积分显示修复

## 任务与基线

- 用户反馈：GPT-Image-2.5 在带原图操作时出现应用内的“所选模型不支持当前操作”，同时质量选择器显示“— 积分/张”。用户要求修复，且不新增确认、业务限额或重复拦截。
- 分支：`codex/canvas-model-pricing-fix-20261024`；基线：`905c8c635e41ff3f4443d43db9776d1db3aab469`。独立于已完成的服务器性能分支，不混入该分支补丁。本轮不发布。
- 原始字节及 SHA256 保存于 `output/canvas-model-pricing-fix-20261024/before/` 和 `BASELINE.json`。

## 已核实的问题

1. 多供应通道模型的目录/生成计划按可用候选判断，`managedBillingModel` 却仍用主目标的启用状态和能力重复否决；执行器已对供应通道采用不同处理。
2. 通用价格目录先解析默认生图模型，默认模型不可执行会使整个目录失败。
3. `ImageQualityControl` 忽略 billing 的错误/加载状态，缺值统一显示横杠；`modelId` 只参与能力选择，没有用于价格查询。
4. 仅凭截图没有取得当次请求及线上配置；源码可达缺陷与该次线上根因分开记录。

## 本轮实施

- 报价侧不再按供应通道模型的单个主目标重复否决，保留公开模型选择、权限、冻结上下文与原定价身份。
- 通用价格目录只依赖经过鉴权的用户计费事实，不再要求默认生成模型可执行；缺失规格返回 `null`，不拖垮其他规格。具体模型价格继续由独立 quote 接口提供。
- 质量控件接入现有 quote，按模型、质量、分辨率、比例获取单价；多张总价独立报价，避免数量阶梯价误乘。加载、失败及重试采用紧凑浅色状态，不增加生成禁用条件。
- 图片节点和空白节点的现有控件接入比例与实际张数；不改生成执行、原报价回执、余额、扣款和任务恢复链。
