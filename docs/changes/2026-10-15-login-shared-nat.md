# 企业共享出口IP登录限频修复

## 问题与任务顺序
用户报告公司同事首次登录即频繁，并提供47访问日志统计。源码确认为进程内`login:<IP>`、20次/10分钟，成功和失败全部计入，公司共享NAT出口相互挤占。该记录优先处理登录阻断，GeekNow备用生图已由同事独立上线，当前47模型配置v113；本任务不覆盖渠道和同事配置。工作台模型家族去重在独立分支处理。

用户提供的日志数字作为线索，不直接当本轮已采集事实。旧Cookie修复在7fae36c独立上线，主业务f4b3df1版本不变是保留原业务镜像的结果；兼容map里的17847旧路径兜底应继续存在，单看版本/该兜底存在不能证明修复未上线。部署前核完整map当前SHA及新同源页面优先行。

## 实现
- 原生登录移除共享20次桶。独立PostgreSQL命名空间app_auth_login_attempts保存限频状态，蓝绿新旧槽共享，不依赖重启清零。
- 账号+网络10次失败/10分钟、账号跨网络30次失败/10分钟；成功不占失败额度，不清除已有失败以免并发成功抹掉其他失败。共享网络仅保留600请求/分钟高容量突发保护，195同事集中成功不相互封锁。
- 验证前原子预约，按账号和网络顺序加事务锁，防并发多槽超限。pending最多30秒计入失败预算，异常计ignored；响应429包含Retry-After。DB异常503不绕过保护。
- 账号和网络只以站点HMAC摘要落库，不存明文花名/IP/密码。过期记录20分钟保留、批次1000清理和SKIP LOCKED，有限SQL/锁超时。
- 相同规范化花名/邮箱统一账号键；优先使用Nginx覆盖的x-real-ip，proxy不接受伪造CF头。未知账号走真实scrypt计算，错误账号不直接跳过密码计算。保留封禁/到期、密码重置原有会话失效、HttpOnly/SameSite和HTTPS Secure。
- 独立auth-login-server复用真实Next登录POST，不复制另一份密码实现；仅/login和私有ready路径，没有Agent/生图/注册/Worker入口。NAUMI_AUTH_LOGIN_ONLY仅只读验证现有业务结构，新表单独加法初始化；登录响应只读活钱包/发票，不跑全main业务迁移或改余额镜像。正常全站模式保持原余额刷新逻辑。

## 验收与发布门槛
- 两个独立连接池共享隔离PostgreSQL：同IP195成功、单账号失败隔离、25并发最多10预约、跨IP账号失败保护、过期/中断、HMAC隐私。原生登录route另验195有效会话/余额、错误401后429、同事200、封禁403、非法请求400、CF伪造不轮换网络、HTTPS cookie、用户行完全不变。
- 47蓝绿仅替换原生登录精确入口：旧业务容器持续服务→固定代码旁路登录服务/私有就绪→受控真实账号验收→Nginx语法/CAS/平滑切流→保留原后端完成在途。旧工作台登录仍按原legacy map走17847；不抢占旧工作台或更改生图/SSE/媒体/现有JS。
- 旁路使用当前已运行镜像的Node依赖及固定源码bundle，绝不把同事未完成main整站切入；依赖/源码SHA、最小env、非root只读fs/回环端口、资源上限、关闭Worker。不宣称因此主业务已更新到main。
- 两部署锁与旧工作台锁、可读数据库备份、原网关/容器/账号积分摘要、切换期间健康采样、guarded回退仅网关，不恢复业务DB或清用户会话。发布实际结果另记，不以文档/单次200代替线上验收。
