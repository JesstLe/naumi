## 实际结果

| 供应通道 | 本轮证据 | 处理 |
| --- | --- | --- |
| 原默认 TDH / gpt-image-1 | POST /images/edits 返回 503 / model_not_found，default 分组无可用通道 | 不把未知能力改成支持；从抠图默认用途中替换出去，原模型与历史版本保留 |
| TDH / gpt-image-2 | 隔离探测收到 HTTP 200 头，但 120 秒内正文未完成，受理/费用结果未知 | 保留未知探测记录，不重发该请求，不作为本轮开放依据；线上该供应商原超时配置为 280 秒，本次探测不足以断言其永久不可用 |
| Geeknow / gpt-image-2 | 通过线上已配置代理调用，返回图片链接；下载原结果并解码为真实透明 PNG，随后网站实际抠图成功 | 开放独立的抠图用途；不修改现有普通生图通道的参数、顺序或权重 |

初始 Geeknow 原生 fetch 直连发生连接重置，没有使用线上专用代理，因此不作为该通道能力否定证据。代理验证使用新的合成输入和独立探测编号，未重放任何历史用户请求。一次验证脚本因独立 Node 进程缺少打包依赖在 main 前退出、没有发起供应商请求，补齐仅测试进程依赖后才执行；没有修改应用镜像/运行环境。取回已返回的图片曾遇到一次 TLS 重置，重试只读下载成功，没有重新生图。

供应商 JSON 自报 background=opaque，实际 PNG 却包含透明像素。因此透明结论依据完整解码和目视结果，不能仅以 HTTP 200、文件扩展名或供应商文字字段判定。
