# 11 月 17 日后台负载排查

范围：平台后台 26 个页面入口、企业后台 1 个页面入口及各标签、相应的 66 个平台和 39 个企业 API 路由目录。按导航核对首屏、默认折叠项、切标签和轮询触发链，再下钻到共享数据库连接池、事务、SQL 和供应商请求。以上数字是入口盘点，不表示逐个接口的线上压测。线上仅只读取证。

## 已确认的问题与改动

| 区域 | 已核实的风险 | 本轮处理 |
| --- | --- | --- |
| 企业成员快照、创作历史、历史兼容入口、运行健康 | 与额度报表同样，在 `FOR SHARE` 锁定账户权限相关行后继续做历史、健康或余额统计；统计慢时会延长账户锁，拖住需要更新同一账户的计费与余额请求。 | 改用只读快照取数，再用短事务复核授权；单媒体读取保持原有专用鉴权，写入、结算和数据归属不变。 |
| 企业工作区全局刷新 | 企业列表和成员快照各自每 30 秒刷新；页面隐藏后仍跑，聚焦与定时重叠时可能重复请求。 | 隐藏时停止轮询，同一刷新入口只允许一个在途请求；返回页面补查，权限边界继续由服务端执行。 |
| 平台套餐账务 · 待核查 | 侧栏角标每轮并发 4 个取数查询；完整视图每轮并发 8 个取数查询。角标和页面各有定时请求，慢查询容易占满小连接池。 | 角标合为一条只读 SQL；列表和汇总合为两条依次执行的 SQL；进入待核查时暂停侧栏轮询，全量视图只在进入或手动刷新时取数。完整 GET 的遗留账务状态推进入口及 Worker 兜底本轮保留。 |
| 平台模型供应商 · 通道容量/运行监控 | 隐藏页面继续定时取数，慢请求可以与下一轮叠加。 | 页面可见且无同一入口在途请求时刷新。供应商余额沿用缓存和同凭据请求合并；缓存失效仍可能向上游查询。 |

涉及模块与边界：企业模块的 `enterpriseReportRead` 持有企业授权和只读投影规则；成员快照走同一内部机制，但保留只拥有成员管理权限的主管可查看成员的原规则。创作和健康模块通过这一入口提供自己的查询；授权变更时丢弃旧结果，权限丢失报原有鉴权错误，层级等取数范围变化报 409。账务模块拥有待核查查询、来源优先级和排序；前端轮询只决定何时取数，不参与权限或账务状态判断。无数据库迁移。

## 其余入口和剩余风险

| 入口 | 本轮观察与下一步 |
| --- | --- |
| 企业概览、成员、岗位、设置 | 成员和岗位共用上表已修复的快照。企业选择列表仍逐企业计算权限并短时取锁，租户多时应优先量化、合并查询。概览的「处理中」会并发查排队、运行、申请取消三种状态，每次都经过带汇总的概览查询；应改成一次筛选的轻量列表。 |
| 企业创作记录、额度与用量、运行健康 | 移除了已定位的长报表账户锁；历史列表翻页仍可能重复计总量，密集预览仍会产生授权媒体的请求，建议根据真实查询计划和视口加载量优化。额度折叠区按需加载的修复见[上一轮事故记录](2026-11-17-enterprise-usage-load.md)。 |
| 平台运营概览、用户用量、租户管理及详情 | 核对了聚合、趋势查询和标签触发；在本轮查过的读链路未发现同样的账户锁包住长统计。仍需以真实数据量复核聚合窗口、索引和列表翻页。 |
| 平台用户管理、创作记录及追踪 | 旧用户接口进页可并发查 4 组数据，用户详情同时取多项历史；追踪详情和用户媒体按操作或列表渲染触发。先确认线上调用量，再分拆默认请求；未证实它们引发过此次故障。 |
| 平台套餐、账务、采购成本、模型供应商 | 除已修待核查和供应商轮询，采购成本仍并发查流水、汇总和账户概览；没有发现这一路径在页面后台定时触发，建议先量化正常窗口，再决定拆分或按需加载。 |
| 平台运行健康、系统审计、部署管理、配置 | 已检查状态刷新、入口权限和读写触发区分。既有 Fleet / 模型健康刷新已有可见性和在途保护；配置发布的短间隔观察仅在发布状态下运行。本轮没有逐一触发部署、配置写入等操作。 |

## 生产证据与验收

47 的 Nginx 日志样本覆盖 11:23:49–16:22:10（含服务中断与恢复）。企业入口 404 次请求、39 次 5xx、最长 12.153 秒；所选企业的成员快照 375 次、2 次 5xx、最长 12.013 秒；企业用量 21 次、1 次 5xx、9 次客户端主动断开（499）、最长 12.010 秒。PostgreSQL 慢日志记录企业创作列表 9 条超过 500 毫秒（最长 1.602 秒）、健康任务计数一条 2.569 秒。这证明同一时间段有跨接口受影响，也证实部分后台读接口偏重；日志没有足够证据把其它页面认定为历史宕机的触发源，平台待核查没有可用的生产请求样本。

已验证：独立 PostgreSQL 16 执行 `verify-enterprise-analytics.ts`（报表不阻塞账单账户行、撤权 403、可见集合不变但层级变化 409）、`verify-enterprise-artworks.ts` 和 `verify-saas-creations.ts`（历史范围、素材权限、跨租户、账务关联与撤权）、`verify-billing-pending-view.ts`（计数、明细顺序、诊断及账务状态边界）。`node --test scripts/verify-admin-visible-refresh.mjs` 通过隐藏、回到页面、在途请求去重和释放监听验证。附带试跑的综合企业集成脚本受未初始化的独立站点 `site_policy` 阻塞在工作流入口，未作为整套通过。

47 保持原运行版本，本轮未部署。后续现场验收先测企业「处理中」、租户列表和待核查，再看共享连接池等待、跨接口 503 和慢 SQL；目前不能用隔离测试替代线上高峰验证。
