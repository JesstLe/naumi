# 画布原图与缩放渲染修复

基线：`862592fcfc1c99883e5e311bb4647f950cf6ef7a`；分支 `codex/canvas-raster-quality-20261107`。

模块与职责：画布图片表示选择与节点平面的浏览器栅格化提示。

公共接口、依赖方向、数据/状态/事务归属：CanvasImage 继续调用 canvasMediaVariant；该接口所有缩放均返回 original。媒体授权、原始文件、字节队列、已解码帧保留和后台任务不变。CSS 仅取消整个节点平面的 will-change:transform，连线保留已有层级/悬停门禁，不改变节点位置或连线交互。

调研与证据：
- 用户在 r7 版本 23.48% 缩放截图中继续看到明显模糊，r7 的发布/API 验收不足以证明视觉问题解决。
- 已在当前真实“产品.jpg”项目读取图片自然尺寸，预览可达 1600px，但画布仍使用有损预览；先前“4 倍采样与原图无差别”的表述没有充分证据。
- 整个节点平面使用长期合成提示，缩放后有复用栅格层的风险。关闭该提示是质量优先的取舍，不宣称已在用户 GPU 上单独复现根因。
- T3 浏览器截图包括工具栏在内均模糊，且输入/点击超时，不能用该截图判定修复成功。切换到本机 Edge 的真实素材静态渲染对照，图片可正常清晰缩小；静态对照不冒充生产全链路或用户 GPU 验收。

本次实现与迁移状态：画布节点始终请求原图，去掉小尺寸有损预览选择及“无差别”假设；取消图片/文字节点整平面的强制合成。列表封面、小图标等独立展示策略不在本次修改范围。

集中验证：
- media-loading、node-drafts 75 项、hover-plane、render-layer-order 通过。
- 真实 React/ReactFlow/Edge + 模拟媒体服务的 image-stability 13 组通过：低缩放原图，23.48%/50%/110% 不换低清帧、不重复下载、不白屏；缓存回访与授权隔离仍通过。此测试不调用真实供应商、不写生产项目。
- TypeScript 与固定镜像构建/发布结果随后追加。

未完成项与下一步：固定 main 镜像发布、在线原图加载规则核验；用户设备相同缩放视觉验收尚未完成。允许原图带宽及重绘成本增加，以质量为先。
