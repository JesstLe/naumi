# 画布批量运行：全量提交与真实排队展示

## 模块与职责

开工基线 `fd2497b08711301d77a0ad03a0c3d7a6499a3ce9`。任务分支 `codex/canvas-batch-placeholders-20261114`；共享管理 UI checkout 和未提交改动保持。本轮是新的画布交互任务，不实施先前生图失败调查中的后端修复。

用户要求批量多少个就显示多少个占位，排队时显示“排队中”，开始后显示原有百分比；后续明确去掉前端两路限制。

## 设计与实现

- 批量运行不再等两项整次生成结束后才启动下一项。选中且可运行的节点通过现有单节点 owner 各自开始，图片占位在第一次异步等待前建立，后端继续拥有受理、任务排队和供应商容量；没有新增前端队列、批次后端接口或统一任务平台。
- `runSelectionBatch` 默认不限制数量，专门调用方才显式提供并发数。反推/帮写使用的独立文字派生入口显式保留原来的 2 路策略，避免连带更改无关入口；选中文字/图文混选的“批量运行”没有这道前端上限。
- 图片任务收到持久化 job ID 后进入排队展示；轮询原 job 的 `operationStatus=queued` / `status=queued` / `stage=planning` 显示排队，其余旧版非终态回执沿用执行中语义。现有后端父/子任务投影已经提供排队信息，本次不修改服务端准入、租约、报价和账务。
- `GenerationPlaceholder` 排队时只显示“排队中”（英文 Queued），不展示百分比、进度条、步骤和虚构排队名次；执行后仍使用既有百分比曲线。该百分比是已有展示进度，不声称为供应商精确完成比例。
- 图片派生与空白节点在从排队转为执行时重设展示时钟，后续执行轮询不反复重设；排队时间不消耗百分比曲线。占位 ID、拖动位置和结果附着逻辑保持，不在阶段切换时新建节点。
- 去重、批次重复点击保护、锁定/忙碌节点跳过、账号/项目/工作空间切换停止新动作、单项失败继续、原任务查询/恢复及防重复提交保持。没有把轮询失败转换为新生图 POST。

## 公共接口与归属

`selection-run.ts` 仅拥有集合编排，`selection-run-controller.ts` 拥有当前文档的批次摘要；`image-task-controller.ts` 拥有原单任务提交/轮询/附着；`image-runs.ts` 和现有 presentation 拥有占位阶段与位置；React 组件只渲染阶段。任务和计费仍归既有后端模块，无数据库、配置、请求参数或供应商适配变更。
