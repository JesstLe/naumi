# 画布抠图可用性与真实透明输出

## 用户目标与允许变化

选中已载入、可编辑、未锁定且空闲的图片时，Dock 与节点快捷入口都能调用已配置的抠图图片模型。隐藏的后台默认处理器不需要出现在用户模型列表中。输出必须含实际完全透明背景和可见主体，灰白格仅可作为界面预览底纹，不写入资产。

## 基线与根因

- 独立分支 `codex/canvas-cutout-transparent-20261117`，基线 `d86a5c97daa632ce00407164d2c47d929571f188`；共享 checkout 的全部既有修改保持。
- 默认处理器已启用但 visible=false 时，公开目录将可执行性等同于可选模型数量，返回 available=false；两个画布入口因此误置灰。
- Dock/runCutout 额外把 supported=false 当作不可执行，和已有独立处理器 available=true 的协议矛盾，节点入口与 Dock 判断不一致。
- 抠图检查只要求 alpha<255，整张 alpha=254 的灰白格也被持久化成成功结果。
- 旧分割器 mask 合成在同一 Sharp 延迟管线 removeAlpha().joinChannel()，可能丢掉新 alpha；处理失败后又静默返回原输出，掩盖透明度丢失。

## 架构与实现决策

- 目录 owner 单独判断已配置 cutout 默认处理器的实际启用、工具范围、透明能力、供应通道与凭据；不公开隐藏模型 ID，不恢复全局 admin-only，不影响用户手动选择。
- 画布沿用公共 featureExecutionBlock，Dock、节点与提交前判断共用同一就绪事实。只读、锁定、加载、生成中、权限和素材归属继续生效。
- 继续走原 `/api/cutout`、模型执行、冻结报价、任务身份、结果保存与恢复链路，不新增生图接口或绕过计费。
- 抠图输出在任何上传、作品写入和成功回执前检查完全透明像素与可见主体；不以存在 alpha 通道冒充去背景。失败返回明确的局部错误，不把不合格图片落为新作品，不自动再调用付费模型。
- 生成提示明确禁止画出棋盘格/白底板。旧灰度 mask 只在确为灰度、不含伪透明时处理；先物化原图 RGB，再拼接单通道 alpha，保留原图像素。真实透明 PNG 保持原始字节，不对色彩做猜测式抠除。
- 此像素校验是必要条件，不冒充语义分割质量或原像素保真认证；没有自动修改用户历史图片。供应商已受理但输出不合格的账务/UNKNOWN 沿用原 owner，不能擅自重放或宣称未发生上游调用。

## 影响模块与保护行为

公开模型目录 → feature catalog → Canvas Dock/节点；cutout provider → executeCutout → 存储/作品/原同步账务。生成式抠图仍可能重绘主体，不新增分割服务，不改变管理员映射和收费。不修改通用 imagegen 透明判定，不影响其他图像/视频/文字生成。
