连续生成的新增用例又发现：计费层可能以已保存的计费 intent 编号替换请求中的 idempotencyKey，而画布回执仍存原 UUID。之后查不到原任务，完成后再次生成被拦。现在画布向计费层提供原回执编号，并通过可选 onIdentity 回调，在发送前保存计费层最终选择的编号；既有计费缓存的优先级和其他调用者行为保持。已有成功回执带 taskId 时按本人任务 ID 查询，兼容此前成功回执的编号差异。自备工作流继续使用原域编号，不经托管计费。
