# 用户用量与产出看板

## 模块与职责

- 本轮固定基线 `cb1d2f4932e402a75511485173027ed049ed342e`，在 `codex/admin-operations-20261029` 实现。
- `UserUsage` 只负责筛选、真实响应展示、按用户下钻与 CSV 导出，业务统计归属 `bi/usage-repository`，通过 `usage-contracts` 交互。
- 独立平台入口 `/admin/usage` 复用 `requireAdminPage` 和 `AdminCenterShell`；企业控制台使用 `<UserUsage embedded enterpriseId={id}/>`，不叠加第二层 Shell。
- 企业请求只走 `/api/enterprise/usage?enterpriseId=…`，服务端核验当前成员可见范围；前端不通过硬编码角色或本地资料扩大权限。

## 本次实现

- 浅色用量看板：日期、企业、花名/账号筛选；近 7/30/90 天；原全部后台导航和子页保留。
- 概览显示活跃用户/天数、业务任务、生成作品、实际消费、每活跃人日产出及活跃用户人均产出。
- 按用户最新要求，不显示失败率、失败次数、等待耗时或系统延迟。
- 每日趋势提供产出/积分/活跃三个切换；同一真实日数据可以展开表格查看，SVG 无随机样本和伪造趋势。
- 用量构成区分消费、退回、净消耗、上传、导入/复制、未归因及已删除作品；不把上传、复制当作生成产出。
- 管理员扣减独立展示，不混入用户实际消费或净消耗；首条记录只标为所选期间首条，不冒充全历史起点。
- Token 缺失显示“未记录”，已记录的真实 0 保持 0；同时显示完整 Token 样本覆盖数。
- 用户表支持后端排序、分页、点击用户过滤，再下钻原任务/作品/流水；企业版仅提供当前可用的任务/作品入口。
- 日期/用户筛选保留在 URL。企业嵌入态使用 `usageFrom/usageTo/usageEmail/usageQ/usageSort/usagePage`，不覆盖控制台原筛选。
- CSV 按筛选逐页请求真实数据，包含全部匹配用户而非只导出当前页；数值缺失保持“未记录”，字符串做表格公式转义。超过 10,000 账号提示缩小筛选，遇到总数/排序变化停止而不交付缺页文件。
- 读取具备 loading/empty/error/retry；筛选变化或卸载取消旧请求和导出，不把旧作用域的响应显示到新页面。

## 指标边界

- “活跃人日”是逐用户自然日去重后求和，不是在线工作时长。
- 每活跃人日产出是已保存生成作品除活跃人日，不是作品质量、采纳率、员工绩效或节省工时。
- 积分/作品是期间整体使用强度，不是单张作品核算成本或人民币成本。
- 企业筛选依据当前可见成员集合，历史任务原冻结企业归属不被重写；口径在页面折叠区显式列出。
- 历史来源不可用时展示缺口，不把未接入说成没有业务发生。
