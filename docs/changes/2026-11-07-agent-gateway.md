## 调研结论（实施前）

- **没有给机器用的凭证**：登录只签发浏览器 Cookie（`nv_user`，30 天）。代码里还留有 Supabase Bearer 旧路径，但站点走原生账号，这条路径不可用。
- **没有对外通道**：没有 CLI，也没有稳定的对外接口约定。`scripts/mcp-tool-host.mjs` 是站内 Codex 桥接用的，只回调本机端口，外部连不上。
- **可复用的基础已经齐全**：
  - 站内 Agent 的工具注册表（`createNaumiTools`），覆盖创作中心 26 个入口和视频等，共 65 个工具；
  - 执行边界（`AgentHarness`）；
  - 计费预检与冻结（`agentBillingPrecheck`）；
  - 功能权限（`assertAgentToolAccess`）；
  - 生图的操作编号、报价和回执幂等。
- **调研中发现的风险**（实现时已处理）：
  - 非私有媒体模式下，`managedAgentReference` 不校验媒体归属，所以网关自己用 `canReadMedia` 校验。
  - 服务端签发的会话凭证不会因密码重置失效，所以令牌鉴权自己检查 `auth_revoked_before` 是否晚于令牌创建时间。
  - `/api/agent/*` 会被功能闸门按 Cookie 拦截，所以网关单独放在 `/api/agent-gateway/v1`。

## 实现

详见 [AGENT_GATEWAY.md](../AGENT_GATEWAY.md)。

- **令牌**：
  - 格式为 `nmk_` 加 43 位随机串，只存 SHA-256。
  - 权限分为只读和收费（`read` / `write`），可设每日积分上限和有效期（30 天、90 天、1 年、长期），可吊销，每个账号最多 20 个。
  - 令牌只能由浏览器会话管理，且校验同源和跨站请求。
- **执行**：网关就是一个没有模型的 Agent 会话，外部 agent 替代模型发出工具调用。
  - 每次调用依次经过：权限 → 严格参数 → 服务端报价与冻结 → 排空登记 → 预算占用（令牌行锁，同时限制 4 个并发）→ 执行 → 创作记录 → 落账。
  - 遇到拒绝时直接返回 JSON 状态码，此时一定没有提交。受理后以 NDJSON 流返回进度和结果，客户端断开不影响执行。
  - `operationId` 保证幂等：同编号同参数返回原结果，同编号不同参数返回 409。
- **媒体**：
  - 上传走画布原图通道，同时在作品库生成一条"Agent 上传"记录。
  - 图片参数中的本站地址必须属于本人。
  - 下载经 `serveMedia` 进行，支持私有媒体和 Range 请求。
- **发布运行时**：新增 `release-runtime/account-work.ts` 和 `store.beginAccountWork`，按账号登记 accepted-work。
  - 没有会话归属，因此同一令牌可以并发。
  - 完成的记录 7 天后由现有逻辑清理。
  - 蓝绿排空会等调用完成；排空中的槽位在提交前就拒绝新调用。
  - 最初用的是 agent-run 会话登记。开启运行时后发现：同一令牌的并发调用会被会话唯一性拒绝，而且每次调用都会留下一行会话归属，所以改成了现在的方式。
- **CLI 与 MCP**：
  - `public/agent/naumi.mjs`，零依赖，Node 18 以上，站点直接提供下载（`/agent/naumi.mjs`）。
  - JSON 输出，退出码有明确含义；支持 `key=@本机文件` 自动上传。
  - `naumi mcp` 提供 MCP stdio 服务。
- **界面**：账号中心新增「Agent 接入」入口和 `/account/agent` 页面，用于创建、列出和吊销令牌，令牌只显示一次，页面附接入命令。
- **给 agent 的说明**：`skills/naumi-cli/SKILL.md`。
