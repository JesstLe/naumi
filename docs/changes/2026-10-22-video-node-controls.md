## 实现方案

1. 使用现有 canvas UI token 和视口自适应弹层：模式独立；比例图块、分辨率、离散合法时长滑条、声音及数量集中展示。时长与分辨率由后台能力组合联动，管理员未开放的选项不显示。
2. 批量选择 1/2/4。单条沿用原节点生成；多条在同一项目创建独立结果节点，复用持久视频工作流、冻结参数、逐条计费及恢复机制。批次编号持久化，重复提交不能重复创建节点/收费；未知结果只能查询原批次。
3. 提示词优化复用现有文字模型调用，增加视频专用约束；保留完整长提示词、对白与引用占位符。先预览，再显式应用，不自动生成视频。

## 实现完成

- 模式菜单先于参数摘要，参考模式按当前能力显示“全能参考”或“图片参考”。比例/清晰度/离散时长/音频/1、2、4数量采用现有 canvas token，弹层沿用视口收敛与滚动。
- 数量以 `config.batchCount` 随原节点配置保存；单次提交、制作链、工作台发送前剥离该 UI 字段，不误传给供应商。清晰度与时长联动，声音关闭保留 false，未知能力不伪造可选项。
- 新增受 canvas+video 权限限制的 batch 接口，原节点加 1/3 个兄弟结果节点。整批参数与价格先冻结和检查，总价是逐条报价之和；复制节点与加密批次回执同事务提交。任务仍走现有工作流、队列、独立计费/结果/取消。失败节点可单独在原节点/历史处理，不自动重放整批。
- 客户端持久操作编号；丢响应先查原批次，未派发的 pending 批次保留回执。改成单条或修改参数不能绕过未核实批次。不同账号、不同内容复用编号拒绝。
- 优化沿用现有文字模型路径，视频输入上限 16384，不再截为 600；长输出截断及引用标记改变拒绝。保留默认文字调用配置及限流；无可用配置不拼接电商套话。优化结果预览，显式应用，取消/卸载中止等待，原文发生变化不能直接覆盖。
