## 模块一：图片交付字节复用

`imagegen/delivery-bytes.ts` 只拥有一次交付尝试的内存字节，不拥有任务、账务或存储事务。Route 显式传入现有解码器；尺寸读取、透明检查、后处理与落盘读取同一份已校验字节。变换生成的字节直接登记，URL 改变后原字节退出；输出批次变化时 retain，落盘后 release，尝试结束 finally clear。没有进程级缓存，不取消严格格式校验，不改变存储失败保留 inline 原图及原结果续交语义。

## 模块二：视频退避与取消

`claimVideoTaskPoll` 在原子 UPDATE 中增加持久 due 条件，保留原状态、归属、租约与单赢家规则。首次取消将原任务唤醒但不抢正在执行的 poll lease；重复取消不重置退避。取消在当前轮询开始后到达时，schedule 不覆盖新唤醒，下一次领取更新 last_polled_at 后继续原退避。未新增任务、供应商重投、结算或额度规则。

## 模块三：协调连接故障

`coordination-pool.ts` 只把实际 slot 已满或锁未取得作为普通 busy。连接获取失败释放 slot，并抛出保留 cause 与精确 coordination key 的专用错误。`coordination-activity.ts` 在视频应用边界只识别本入口最初锁的 checkout 错误：结束本次观察后仍向调用方报错并记录有界错误码。不同子任务的同类错误不得关闭已执行工作的父观察；真实锁确认丢失、供应商/业务异常及 finish 失败沿用 release runtime UNKNOWN，不更改全局背景活动语义。

## 模块四：缺坐标布局

`canvas/placement-space.ts` 拥有单次布局的占用索引和原最近边候选规则。按空间桶筛选碰撞、去重重复候选、距离只计算一次；连续同尺寸兄弟节点复用一个有界候选最小堆，距离并列严格沿原插入顺序，不为所有 anchor 保存多份缓存。空位置不建立索引，大跨度矩形使用精确线性路径，不增加用户限制。已有坐标和 session 缓存保持；稳定布局循环复用索引，新增占位等旧调用继续通过原接口，不维护第二套摆放规则。
