# 浏览器缓存故障恢复

## 问题与证据边界

用户反馈大量节点图片加载失败、刷新异常，清缓存后恢复。截图本身未给出浏览器存储错误/HTTP状态，不能直接归因缓存总量。线上未读取/改动。

主线基线 b3a04f35f7ef612010617ddf835f41f5f2cf2485。已确认三个代码窗口：
1. 图片缓存IDB读/写事务只有事件完成，没有期限。外部网络AbortController不终结IDB等待，pending可一直保留。
2. 作品元数据loadAccountSnapshot同样先等缓存读，并在网络成功后等缓存写，能卡刷新。
3. 非SHA版本的坏图片缓存通过元数据验证后解码失败，组件没有单条跳缓存重取，刷新仍命中同坏记录。

截图“正在读取工作流”来自工作流导入POST/NDJSON，不是图片缓存状态；本模块不将它宣称已修复。

## 模块与职责

- BrowserCacheStorage只管理可丢弃缓存的连接和事务生命周期；每次打开/事务1500ms期限，异常时结束全部等待者并将该缓存DB在当前页面会话旁路，保留正常认证回源。
- browser-image-cache负责已授权图片字节、版本/owner/epoch校验、容量淘汰、去重。图片下载完成后不等待落盘。
- browser-data-cache保留作品数据revision/账号隔离和去重；网络结果不等缓存持久化。
- CachedImage仅在实际decode失败后单次bypassCache重取，仍走授权，非托管图片不扩大重试，第二次失败结束。
- 不清全部站点数据、不清草稿/登录、不改生成、计费、供应商、业务任务。
