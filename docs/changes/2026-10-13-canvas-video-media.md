## 本批实现

- 增加持久媒体任务及账号隔离 API，操作 UUID 与请求摘要防止重放改变参数；任务使用原账号已完成作品、视频节点结果或可读私有媒体身份解析输入，真实读取并验证 SHA，实际 FFprobe 数据按存储 key/SHA 缓存。
- 增加首/当前/尾帧、音轨提取、音视频分离、精确重新编码裁剪、拼接、原生 FFmpeg/FFprobe 参数数组和多输出处理框架。原生参数使用 `asset:N` / `output:N`，保留滤镜、编码器查询及多输入/输出表达力；显式路径、嵌入路径及协议受控，参数不经过 shell。没有音轨或越界时间在任务创建前拒绝。
- 增加独立媒体 Worker 与共享临时副本协议：Worker 不读取应用 DB、供应商密钥、R2 密钥、正式媒体或 Docker socket。生产子进程使用 C launcher：逐任务 chroot、独立 UID/GID、清理环境、no-new-privileges、禁止网络/提权相关系统调用、CPU/文件/地址空间/进程数限制；只提供只读执行库与本任务授权输入。最多两个 FFmpeg 执行任务，设置超时及取消进程组，终态由应用确认后清理副本。
- 固定源码 Docker 镜像增加编译好的 launcher、FFmpeg/FFprobe 运行库；标准 Compose 和新机 Compose 增加独立内部媒体服务、临时挂载、只读根文件系统和资源限额。尚未验证 Linux 构建/容器执行，也尚未修改实际服务器 Compose/env。
- 媒体结果显式登记账号归属，实际输出探测、字节数和 SHA 校验后上传。作品写入与媒体任务完成状态同事务提交；应用重启后由现有独立任务 Worker 扫描恢复。多文件分片输出开始验证内部引用，完整 HLS/DASH 输出及复用仍待集中验证/修正。
- 通用 `addArtworksTx` 保持原 `addArtworks` 调用契约，同时允许现有视频任务在完成/计费同一事务中创建作品。主视频结果已接入独立真实 FFprobe，写入实际尺寸并在私有上传时显式指定 owner；供应商的全部多类型输出仍待接线。
- 结果读取器按实际流长累积限额，不以未受信任的 Content-Length 预分配；声明偏小、超限和断流不越界写入，异常取消读取并释放 reader。
- 隔离测试 harness 增加真实独立媒体 Worker 和原创无音轨视频，Worker 不继承数据库/供应商/对象存储凭据。`verify-video-fusion-media.ts` 已编写，使用真实 App/DB/Worker/私有媒体，并另行启动实际 FFprobe 核对输出；当前尚未运行。
