# 稿定画布工作流跨站粘贴

## 范围与真实样本

用户授权实现稿定框选复制 → Naumi 画布直接粘贴。使用用户提供的真实 `editor-next` HTML 剪贴板格式 `10.0.0`，不是截图识别。样本顶层 18 项，递归 38 元素（16 文本、11 图片、5 组、3 SVG、3 path），19 条范围内工作流关系。实际素材和文案仅留在忽略的本地 output，不提交仓库。

## 模块实现

- `workflow-clipboard.ts` 纯解析器：只接收用户 paste 事件中的 HTML；有标记才接管，其他图片/本站节点粘贴保持原路径。限长、限层、节点去重、白名单字段、公共素材域、循环检查；绝不执行剪贴板脚本。
- 坐标统一缩放并保持相对布局。分组递归展开为可编辑本站图片/文本节点；5 个分组保留独立框、点击标题全选成员；SVG/path 安全栅格化为装饰节点，不冒充可编辑矢量。装饰像普通素材一样持久化和移动/撤销，不作为分组生成的默认参考图片。
- `workflow-import` 使用真实账号、检查目标项目所有权；图片在 DNS 固定/重定向逐跳校验和大小限制下下载，转成 PNG 写入本站存储，不保留热链。最多 4 个并发同步，实际素材数进度通过 NDJSON 输出；无伪造百分比。素材准备完成后在单事务内创建节点/关系/样式与来源记录，硬失败回滚 DB 并清理本次媒体。
- 用户随后明确选择“原始链接失败，则根据元数据生成占位框”。HTTP 错误/连接失败/地址缺失保留原坐标、尺寸、标题、提示词和所有连线，显示简短的“待补图片 / 补充图片”；元数据记录缺失原因，不把占位图宣称为原素材。危险地址、超限素材、恶意 SVG 仍直接失败。正常分组生成默认参考图排除装饰与占位图。
- 补图使用 `/api/canvas/workflow-import/asset`，同账号锁、所有权/节点锁定检查、12MB 静态像素校验与幂等；直接补入原节点，不另建下游节点、不搬动位置或重接线。两份像素快照均保留，现有 history 通过服务端版本编号支持补图撤销/重做。来源清单记录最初的缺图状态，当前是否待补以节点实时 source 为准。
- 来源 UUID 重映射。图片→图片用已有 parent/parent_ids；图片→文字及文字→文字用 source_ids；文字→图片用 target_ids。保留提示词、文字及模型/公开参数来源快照，但不改变本站模型选择、已发布映射或账单，不自动执行。
- `useWorkflowPaste` 不主动读系统剪贴板，不存储用户剪贴板内容；按项目/账号 epoch 隔离，切换/离开取消，重试沿用操作编号。整组新增共用现有 history，一步撤销/重做。修复现有批量历史逐条删除因旧 state 覆盖而漏删节点的问题；首批导入撤销后保持空白编辑态，重做仍可达。导入图文不触发原来的自动比例修复/自动文字高度收缩，保留明确尺寸；用户可编辑/缩放。文字→文字连线补充循环检查。
- 新表 `app_canvas_workflow_imports` 和 `app_canvas_workflow_asset_ops` 分别增加来源/分组/导入幂等结果与原位补图像素版本；不迁移原数据。导入快照用于来源核验，晚到重试读取实时节点、文字与样式，不把已补图/移动/编辑倒退为旧快照。人工模型配置/供应商元数据完全不修改。

## 功能边界

入口是稿定 `editor-next` 的完整 HTML 复制数据；普通截图或不带该结构的复制保持原图片/文字粘贴行为。只迁移复制范围内的图文、分组、来源提示词和连线，不迁移竞品账号/计费/任务 ID，不自动执行竞品工作流；模型选择和实际生成以本站管理员配置为准。SVG/path 栅格化为本站装饰素材，不提供矢量编辑。分组标题全选成员并使用已有多选整体移动，嵌套边框会恢复；不是把竞品分组数据变成本站可执行自动任务。

本轮只在 `codex/canvas-workflow-paste` 开发并推送，交给统一合并者；不发布新机，不连接或回传旧机。
