## 发现

1. 原 `tool_start` 仅含调用 ID/工具名，参数、目标、时间和结果归属未进入展示模型。
2. 运行时事件已有服务端 `at`，Canvas SSE 只发送 data，持久化只保存 type/data；内存重建曾把历史时间改成当前时间。
3. 同名工具可以有多个调用，结果不能用工具名或“最近一步”猜归属。
4. 没有 `tool_end` 的历史调用不能当成已失败、已取消或仍在供应商执行。

## 实现

- 新增 `CanvasAgentToolCard`：浅色紧凑卡片、展开/收起、原生按钮键盘交互、`aria-expanded`/`aria-controls`；展开时将卡片滚入可见区域。
- 状态区分执行中、已完成、失败、等待确认、未执行、连接结束后的待核对。报价及门禁原因常显，不藏在折叠区，也不被后续泛化摘要覆盖。
- `publicToolDetails` 只输出白名单标量：颜色/强度/比例/分辨率/质量/数量/宽高/时长/帧率/格式/背景。原始 args、提示词、URL、签名、鉴权信息不进入公开参数卡。
- Canvas 换色/精修/复刻使用真实服务端参考集与画布尺寸设置，不用模型填入的其他 URL 伪装目标。目标只存已解析的当前图 ID，图片与标题由当前上下文解析；历史目标缺失时不猜图片。
- 服务端时间同时进入 SSE 与持久历史；冷恢复保留原时间，旧记录无时间则保持未知。耗时为本次调用从 start 到 end 的总用时（含校验和结果挂载），不是独立供应商耗时。运行中按时钟更新；无结束事件且客户端结束时隐藏不确定耗时。
- 进度更新保留首次 start，不重置计时；终态后迟到 start 不回退。
- 成品通过 `toolCallId` 关联授权入库的 artifacts；卡片用结果 ID 解析现有对话中的图片，点击只预览已有结果，不再次提交。
- 实时和历史共用 reducer；恢复不再截去当前轮前面的工具步骤。旧事件无字段继续兼容，不伪造参数、耗时或结果归属。
