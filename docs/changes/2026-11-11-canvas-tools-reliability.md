## 模块与职责

1. 选择与菜单：保留现有 selection owner，接入 React Flow 的选择框 contextmenu，不新建选择状态。
2. 保存恢复：现有文本/视频/历史 owner 分别拥有草稿、原请求和 ACK；UI 保存入口只编排这些窄接口，不改幂等、CAS 和账号空间边界。
3. 工具：模型目录、报价、执行使用同一 feature 和用户选择；模型输出保存、账务回执沿用原模块。
4. PNG：只读核验，无修改。

## 已实现

- ReactFlow 的选择框右键复用既有批量菜单；没有修改鼠标选择语义或新增选择状态。
- Ctrl/Cmd+S（包括正文输入时）和底部保存按钮共享 `save-command`；同时恢复文字、视频和提示词，单一 owner 失败不饿死其他保存。历史只重试原命令；不同账号/空间/视图的异步结果不串写。
- 读取服务器已保存且完全匹配的文字时清理原 pendingWrites；不清除不同内容。错误节点/项目的 ACK 不算成功。真实冲突继续保留草稿和原冲突解决入口，不靠隐藏提示消除未保存状态。
- 抠图开放公开、已配置透明能力的用户模型；报价和执行不再抹掉选择。旧调用缺 quality 时仅从冻结的抠图执行读取质量，不改透明像素算法。
- 超分移除固定 Replicate 客户端，采用统一托管模型调用，展示模型、质量、分辨率和增强方向；没有 CPU 插值兜底。
- 印刷图先由同一模型调用提升细节，再保留确定性的尺寸排版/DPI 写入/PNG 编码。这些格式操作不是 AI 增强替代品。新增模型账务 UNKNOWN 保持核对，不能沿用旧“本地处理必然无供应商费用”的判断。
- 所有已公开图片模型继续由后台能力、工具范围、映射和冻结报价控制；不改人工价格、供应商配置或历史任务。
