## 目标与当前事实

用户要求全部生成图片入口统一使用本地浏览器缓存，重点解决103重复打开图片的流量。目标已建立，103 UI及图片缓存读取接口已上线，真实浏览器验收通过；固定版本及边界见文末。

- 开工 origin/main：520ba89ae57a4f98b76a555c125193a907732fba，独立 codex/browser-image-cache-20261013；共享目录不切分支。
- 现有browser-data-cache仅保存作品元数据，不保存图片字节。私有R2媒体307签名地址会更新，local只缓存300秒，无内容条件请求；刷新仍可能请求图片。
- 103既有HTTP入口不具备Service Worker/CacheStorage的安全上下文条件，采用HTTP也支持的IndexedDB Blob，而非以安装Service Worker为前提。

## 实现方案与验收门槛

1. 统一CachedImage/CachedNextImage和下载读取；图片缓存键为当前已验证账号、稳定媒体key、变体、内容版本，签名URL不入缓存键。
2. 每次展示先批量检查当前媒体权限与内容版本，仅传少量元数据；缓存命中不传图片字节。原图/预览/缩略独立缓存，不拿缩略图替代下载。
3. 服务端真实会话及媒体所有权校验；数据库和媒体仍保存原URL。失败响应、HTML、opaque、视频和超大文件不持久化；存储不可用走原展示链路。
4. 账号切换/退出、跨标签退出清理私有Blob及objectURL；在途旧账号请求不能重新写入。普通业务刷新只失效授权/版本元数据，不清空所有图片。
5. 总容量128MiB、单图128MiB、400项、7日；LRU和配额失败回退；按需加载、并发去重、离屏取消、不预下载整幅画布。
6. 集中验证冷加载/重开/刷新/浏览器重启，图片字节请求1→0；原图下载复用、更新失效、越权拒绝、退出/多标签及quota退化。画布/作品/26工具/Agent/Skills/套图/A+使用源码覆盖清单。
