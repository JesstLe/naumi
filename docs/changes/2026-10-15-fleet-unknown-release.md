# 夜间发布未知状态防重复

## 问题
已租出的发布未回执/进程中断时会标blocked，但原队列查询仅选planned/preparing，第二天另一个计划可能继续签发。在根执行器需人工核实时，中央不能把下一晚当作另一个可直接执行的发布。

## 修复
- 同实例存在preparing或带lease_id的blocked计划时，20:00规划跳过，避免产生另一份重复发布。
- 即便遗留了第二天planned计划，下发前逐实例事务锁内再检查任何带租约blocked状态，保持原计划待准备、不签发新任务。
- 恢复只有原lease真实最终failed/accepted回执可解除未知状态，保留幂等审计和实际业务数据；不重发已未知的root部署，不用改DB/积分回滚它。
- 未租出的基线不匹配blocked不会伪装成已执行；之后仍按真实基线重新门槛，不误把所有历史blocked一概锁死。

## 验证与生产边界
真实隔离Postgres/HTTP回归：过期租约unknown、第二天既存planned保持、第三晚不新建、原真实lease回执后解除、丢poll/ack及单次审计保留。类型/受影响lint集中验证；源码独立回滚与原hash、字面输出另有制品。
生产103仍仅私有portal，未发布新镜像、未切公网或启动调度；47/NAS未改变。当前管理员与NAS连接资料缺口仍待用户补齐；该修复是代码层防止上线后的重复切流，不称整个目标完成。
