# 浏览器参考图适配与原图保留

用户要求优化上传限制，原则是浏览器承担缩放/编码，不裁切拉伸，原图查看下载不被参考图替代。独立codex/browser-reference-upload-20261020从0530ad8b开始；fetch main038b840b。只本地实现/验收/提交推送，不部署。

## 范围
1. 浏览器预检64MiB/64MP，图生图参考自适应有界尺寸/体积，PNG透明保留与清理内存；当前参考接口12MiB/总64MiB和80MP仍保护。
2. 画布上传保留原始File，客户端生成512/1600缩略预览，服务端只校验并保存，不再重新解码原图生成缩略。原图上限64MiB/64MP，不是任意放开。
3. 自动画幅采用适配前原图尺寸，生成用像素可等比例缩小但不改变原始画幅意图；保留原有编辑/多参考角色规则。

## 协作边界
canvas-client只上传上限/prepare调用/选择文件限额，不覆盖PDF线程uploadRoot的布局/mergeWorks/显式边/抠图/原图/Dock等增量；改client-image-upload、imagegen client/canvas-client和上传保存链路。费用/生成/Worker不改。

实现与验证结果随模块更新。

## 实现完成

- 新image-upload-policy把原图64MiB/64MP和参考传输12MiB分开。按本次参考数量共享64MiB/80MP总预算、最长4096、最多8MP/张；浏览器PNG/JPEG/WebP头部预检在解码前执行，支持EXIF方向和静态图校验。
- browser-reference-image仅制作生成用副本，先保尺寸/高质量编码、必要时等比例缩小；透明PNG保alpha，不裁切、不拉伸。浏览器释放bitmap、canvas、blob URL。没有createImageBitmap时使用DOM图像解码。
- submitCanvasImagegen用适配前的原图尺寸和既有reference/edit-target角色规则解析auto画幅；参数明确时不改，重复提交仍追踪原ID。浏览器处理后再次检查账号/项目，切换后不继续上传。
- 画布导入保留原始File字节；客户端顺序生成512/1600预览，服务端仅解码这些有界小图验证，不重新resize整张原图。归档原图完整保留供查看/下载；生成参考另存且无画廊缩略，不持久保存额外完整原图。
- 本地multipart与私有S3/R2直传申请/完成对齐64MiB；完成支持浏览器预览。旧12MiB数据库约束做扩展兼容升级，新程序不缩回旧约束；上传对象仍不可变正式key、账号隔离、重复complete幂等。单账号未完成直传软额度256MiB/20项。
- 档案入站仅支持64MP以内静态PNG/JPEG/WebP，伪MIME按实际头部识别；无预览的旧小图客户端沿用原fallback，大图无预览明确422不把服务器当压缩站。替换/工作流补图等既有12MiB像素编辑路径未擅自放开；competitor原有prepareImageUpload默认行为保留。
- canvas-client改动仅MAX_UPLOAD、根导入preserveOriginal/错误分项和上传并发4→2，保留PDF线程布局/显式边等独立增量；不改费用、生成适配、Worker、模型后台策略。
