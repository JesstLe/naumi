# 画布可选模型与 MVP 排序

用户确认范围保存已生效，但画布只展示一个模型，并要求在 MVP 后台管理前端顺序。

画布生图、扩图、改字、标注返回该工具已开放的完整可用目录。生图 Dock 使用共享的按工具选择状态，刷新保留有效选择；后三个工具补充模型选择入口，质量档位跟随各自选择的模型。默认模型只负责没有有效选择时的回退。报价和新请求采用相同的选中模型，范围外请求仍拒绝，已接受任务保留冻结配置。没有模型选择入口的画布文字、助手、OCR 继续使用管理员默认。

MVP 增加“调整排序”弹窗，上移、下移后统一保存。服务端要求完整且不重复的模型家族列表，并沿用版本冲突保护、同一操作重试、Router 发布和专用草稿。排序移动 publicModels 中的可见家族及其比例分支，同步各工具 business.options.sort；不修改工具范围、默认绑定、路由、质量映射或价格。没有新增字段或数据库迁移，原镜像可读取排序后的配置。

验证：TypeScript 检查；隔离 PostgreSQL 原生范围与排序发布、非法/重复排序、并发冲突与幂等重试、家族顺序、业务目录排序与价格保留；七项画布原生解析/报价检查（四项图片允许选择、三项文字保留默认）、范围外请求/报价拒绝、历史冻结执行和旧版本拒绝；真实浏览器选择画布组、选择并刷新模型、排序保存/刷新、范围修改保留顺序、移除后的回退、请求报价一致和手机宽度。供应商真实调用 0。
