# 画布生图显示与应用范围一致

用户发现取消模型的四个画布范围后，画布生图Dock仍可看到该模型。线上只读核对模型配置v33：Gemini四项均未选，四个canvas目录都只返回gpt-image-2.5；Dock却取全局自由生图目录，并沿用本地模型缓存。节点与空白生图请求也走 `/api/generate-image` 的自由生图策略和售价。后台范围已经生效，画布普通生图入口未与其对齐。

画布Dock现在读取 `canvas.image` 目录，只展示管理员统一的当前模型，质量、比例与分辨率取该模型参数。托管模式不读取旧 `naumi:canvas-image-model`，加载或失败时不回退展示自由生图目录。仍遵守此前七项画布操作由管理员统一配置的政策，不新增用户模型选择。扩图、改字和标注继续独立读取自己的范围与默认；移除默认时既有范围服务保护最后一个模型并回退。

共享生图端点根据 `origin=canvas` 采用 `canvas.image` 解析与计价，客户端报价与实际提交一致；请求里的旧模型/body/header无法覆盖管理员默认。新任务保存已接受的模型与对应客户价格，目录校验使用同一冻结画布配置。普通自由生图入口继续 `image.generate`，供应商与采购成本保持原配置。已接受任务按原执行bundle/quote恢复，不重新选新默认。无需数据库迁移。

功能目录在页面获得焦点或重新可见时刷新；版本变化使报价缓存失效，管理员功能保持默认选择，不被其他功能的选择事件清空。后台与画布分开标签页时，返回画布即可更新当前模型。

提交阶段仅在画布请求或既有专用预设中使用已接受的管理员模型。普通生图保留原选择与用户自带接口，不能把BYOK替换为平台模型。`scripts/verify-canvas-scope-byok.ts` 调用真实生图handler与本地两个模拟通道，确认普通生图发送用户自己的模型并豁免积分，画布忽略同一自定义模型请求、发送管理员模型；实际收费调用0。
