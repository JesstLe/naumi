# 空节点左右分支（2026-11-16）

## 模块与职责
- `src/components/canvas/nodes/pending-node.tsx`：空占位节点渲染。补右侧 `id="out"`（source）端口，与左侧 in 端口对称常显。
- `src/lib/canvas/detail-run.ts`：`attached` 回调补带结果作品 id（`result.ids[0]`），供血缘改写。
- `src/components/canvas/canvas-client.tsx`：新增 `rewirePendingBranchSources(consumedId, artworkId)`；三处空节点消费点（上传落地 / 空节点生成 / 细节生成）接线。

## 公共接口、依赖方向
- 端口语义与真图片节点一致：右 out = 拉线开分支，左 in = 接输入；投影边 `sourceHandle:"out"` 此后在空节点上也能正确锚定（顺带修复既有空→空连线的锚点缺失）。
- 血缘改写复用既有 `pending-link` 本地历史动作（可撤销、无服务端往返），不新增动作类型。

## 本次实现与迁移状态
- 用户决策：空节点允许直接开左右分支（先搭骨架、后上传的画法）。
- 编译器已支持：`compileCanvasLink` target=pending 分支对来源无类型限制（空→空合法）；空→作品引用仍按既有规则拒绝（无图可引用），落地为静默 noop 或"无法引用"提示，不新增放行。
- 关键补齐——血缘延续：空节点上传/生成后会换成新的作品 id，原先下游分支 `inputs` 里的空节点 id 会悬空、连线静默消失。现于三处消费点先改写引用（pending-link 历史动作）再 `consumePending`；个别分支正在生成/上传时改写跳过，不阻断结果落地。
- 已知边界：分支节点自身正在生成/上传时改写失败则保持悬空，后续生成会有"连线已变更"校验提示，与现状一致。
