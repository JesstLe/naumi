## 已复现的四类问题

### 1. 详情模式仍使用旧比例契约（优先级高）

入口 `generateChild` / `generatePend` 的 detail 分支调用 `generateDetailSequence`。后者仅接受 1:1、4:3、16:9、9:16，其余传入 `aplus-web`；A+ 后端 `sizeFor` 又只映射三档尺寸。

- 选择 3:4：实际捕获 FormData `format=aplus-web`，后端尺寸选择 `1536x1024`，竖版变成横版请求。
- 选择 2:3：同上。
- 选择 9:16：format 保留，但后端尺寸选择 `1024x1536`，实际尺寸契约为 2:3。
- 对照 1:1：`1024x1024` 正常。

此为真实前端函数与真实后端尺寸函数的隔离复现；没有提交真实任务或声称已测供应商最终成图。普通生成的精确比例修复没有覆盖此独立 A+ 路径。

### 2. 详情模式失败仍删除占位（优先级高）

真实 `generateDetailSequence` 在参考图读取失败时已经创建 1 个占位，但 finally 无条件删除它；结束时剩余 0，未保留 failure 状态。错误仍可能显示于 Dock 或提示中，不能称完全无报错。

对照相同参考读取失败的 `runGen`：保留 1 个 `not-started` 失败占位。前轮普通生成反馈修复没有覆盖详情生成。

### 3. 刷新恢复结果未落地就清除回执（优先级高）

执行实际恢复 effect，并调用实际 `mergeWorks` / `refetchWorks`。模拟任务查询 succeeded 且返回结果 ID，但作品补取返回空集合：画布没有该结果，恢复回执仍被删除，后续轮询不再安排。

对照作品补取返回结果：清回执正常。此缺陷是丢失当前自动恢复入口，不表示服务端作品文件被删除；之后整表加载仍可能找回。

### 4. 保留失败卡使批量运行跳过可重试源节点（优先级中）

使用真实 `runGen` 产生 `not-started` 失败状态；操作锁已释放。真实 `currentSelectionRunTargets` 把所有 generationTasks 都当作忙碌状态，返回 0 个目标。只移除失败任务后，相同节点返回 1 个目标。

此为批量运行遗漏，不能泛化为普通单图重试永远失败。应与 `selectedGenerating` 一样区别终态失败和仍需核对的未知状态，不能直接放开状态未知的付费任务。
