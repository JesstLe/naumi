## 修复实现

### 1. 历史一致性

`getAgentSession` 返回精确数据库 revision。idle 会话每次取用都对照持久版本，版本不同则重建运行时，先等本进程已有写入，不先把旧缓存写回。

`saveAgentSession` 对 runtime 执行 CAS：新建仅允许首次插入，已有 revision 仅允许条件 UPDATE，不允许已删除记录被迟到 writer 重新 INSERT。revision 更新单调至少一微秒。兼容未传 revision 的历史调用，但本版所有产品写入调用均显式传 revision/null。混合旧程序存续期的无条件写入仍要靠蓝绿归属与排空收尾，不宣称新代码能约束旧二进制。

客户端 autosave 不再强制 flush 进程旧快照；读取、改名、删除不会因旧持久化 promise 冲突而一直报错。SSE 首次保存冲突返回 409 和 `AGENT_SESSION_CONFLICT`，释放 running 状态，不留下永远“处理中”的会话。不自动重放已接受工具。

### 2. 执行事实与流式

每个实际 tool_end 保存 callId、turnId、工具、成败、摘要、真实媒体、验收状态/分数/图片。工具结果中的 OCR/普通文字不作为媒体回执；读图和作品列表也不冒充新生成产物。

回复中的未核验媒体路径不进入可渲染图片；`/media/` 和 Markdown 图片跨 chunk 时保留完整边界，普通文字继续流式。明确验收分数声明须匹配本轮真实 review 与对应图片，旧轮同分数不能冒用。证据不一致时保留已存在的真实产物，状态 `needs_review`，不触发收费重做。

这是媒体路径和明确分数的事实核对，**不是用户意图关键词拦截**，也不是任意自然语言谎称完成的全语义识别器。部分普通分数字符串可能先流出，最终 reply 会纠正；不宣称每个短暂 token 均经过语义验真。

独立创作记录持久化工具事件，避免再只依赖可被覆盖的会话快照。事件写入失败不使成功收费操作重做；标记待核查并保留最终文字/产物。running 维持到结果证据收尾。采用本轮 receipts，而不是易被事件列表裁剪影响的数组下标，提取最终结果。

### 3. 原始要求、读图、验收与模型能力

- 新 `inspect_images` 读取/OCR/比较最多六图；沿用鉴权、媒体归属、取消和独立 100 秒工具时限，模型请求 80 秒、重试零次。复用 `vision.review` 绑定，不新增生成计费。
- `verify_image_output` 自动提交服务器保存的用户要求，以及产品/构图参考图，不只提交成品和模型自填 goal。对照图优先于模型自行补充的列表。
- 返回逐项 checks；缺检查项、截断、无效返回保持未验收；任一明确要求 met=false，即使高分也不通过，不自动再收费生成。
- 生成/编辑参数在六千字内保留原始要求，声明最新修改优先，执行细化与原文冲突时忽略。四个旧 multipart 入口原先只留 400/600 字，已统一到 6000，避免刚加回的要求又被截掉。
- `list_image_models` 读取公开模型目录；目录补充启用通道声明的最大参考图数量与是否验证，禁用/无凭据通道不贡献上限。最终仍由实际计划校验，不改变全局默认模型/价格/参考限制。
- 输入角色说明区分 edit-target、insert、style；预检失败保存具体错误码和 `not_submitted`，不把未提交说成供应商失败。

模型对提示词的遵从仍需真实结果验收，不把原文透传等同于所有画面语义百分之百满足。

### 4. 后台

独立作品为“生成结果”，仅最后一个 assistant 回复进入“最终答复”；不再把进度拼成第二个结果。Markdown 排版保留，答复中的任意图片/链接不直接请求网络，真实图片通过原有鉴权作品接口展示。

工具时间线读得出工具名与失败原因。步骤无账务时显示“该失败步骤未记录账务，本轮结算单独列出”，本轮实扣仍来自原账务，不改收费规则。失败事件读取保持本人/根记录限定，并按根取最新一条，避免长链挤掉其他记录。
