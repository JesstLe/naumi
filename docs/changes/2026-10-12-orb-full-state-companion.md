# 小球全表情陪伴反馈（2026-10-12）

## 目标与调研结论

- 沿用 tycoding/grok-ball 的 MIT SVG vendor。实际提供32种，不是42种：00–07、10–21、30–41，ID空号不代表缺失资源。vendor保持原字节。
- 采用用户所希望的 Muse / Dot 式反馈体验原则：明确任务反馈、轻量即时回应、自然休息和唤醒；不是对两款产品全部行为的复刻或验收声明。
- 原实现仅公开8种、实际任务映射6种；停止使用待机表情。现在manifest、画布真实事件、交互、生命周期统一接32种。
- 本轮仅本地开发、提交任务分支；不上线，发布交给另一个Agent。无新增模型调用、自动重试、工具调度器、费用入口。

## 架构与优先级

`orb-model`全状态目录 → `orb-companion`纯事件状态机 → 每画布实例`useOrbCompanion` → 原`CanvasAgentOrb`/SVG引擎。

1. 停止、受限、等待确认优先，不被hover、输出delta、工具结束或成功结束覆盖；真实失败先显示34至少2.5秒。
2. 任务内接收/阶段反馈和短情绪，不误报工具成功；文字pill始终描述任务而不是装饰情绪。
3. 闲置休息仅在非执行、非受限、非失败/停止状态发生。长任务60秒短暂疲惫2.4秒后自动回任务，不装睡。
4. 短回应1.6秒、交互冷却2.4秒；提交接收650ms，唤醒900ms。按下一个状态截止时间调度，不用React逐帧/逐秒轮询。
5. 隐藏页面取消截止计时，返回按当前实际时间同步；reduced-motion仍显示静态眼形，沿用引擎暂停、销毁及IntersectionObserver。
6. 控制器范围=`email + projectKey`，切项目/账号丢弃旧scope事件；新会话/删除当前会话重置。工作台没有接入此实例，不共享messages/busy/AbortController。小球仍只是当前画布侧栏的同一个Agent。

## 后台结构化状态

- `agentBillingPrecheck`只新增可选attention元数据，原block/terminate/报价/授权判断与冻结版本保持。
- `runtime`发出并持久化`attention {kind: waiting|restricted|resolved}`；计费门禁可附原有公开报价reason，不包含工具参数或密钥。
- 画布真实流、历史当前轮、幂等回放均保留attention；终态`waiting/restricted`区别于`completed`。前端done.ok表示本次回复流完成，存在attention时不显示任务完成。
- 工具确认被terminate后若模型没有最终文本，沿用实际门禁公开报价作为回复，避免把合法等待状态报成空回复错误。收费判断和用户下一轮确认规则不变。
- 反馈按钮仅本地呈现，不上传用户反馈、不注入模型、不自动继续任务。复制异步结果有epoch/session校验。
