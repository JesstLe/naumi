# Canvas 图片离屏驻留回收

## 范围与基线

用户要求持续推进稳定性优化并避免新回归。产品基线为 `be466fc5`，此前读取期限/失败保留草稿继续保留。`8503ebce` 只修旧缓存验收等待器，不改产品。

本模块不合main、不部署47/103、无供应商调用，不改图片文件、生成输入、收费、任务ID或ReactFlow全局虚拟化阈值。

## 实际切口

旧CanvasImage一旦显示过图片，`hasFrame`就使离屏节点继续持有高清显示引用。即使磁盘和热Blob缓存有容量上限，已显示图片自身的lease仍可能累积。

保留以下清晰度合同：100%及以上可见图显示原图；同图缩小后不把已有高清质量偏好降低；缺尺寸和预览失败的原图兜底保持。`forceOriginal`不是永不回收的固定标记。

## 职责与接口

- `src/lib/canvas/image-residency.ts`：只管理同一ReactFlow根下的显示消费者驻留。`registerCanvasImageResidency(element, evict)`返回可见性、实际帧尺寸、帧清除和dispose接口。它不读写数据库、字节缓存或业务任务。
- 池按Canvas根隔离、弱引用存放。可见及现有180px预加载边缘内的帧不因本离屏预算被回收。
- 离屏帧最多16个、实际自然尺寸估算RGBA合计最多128MiB；超额优先释放较早离屏者。没有压力时保留最多15秒，避免快速来回平移撤帧。浏览器调度暂停时回收时点受事件循环影响，不承诺物理内存即时返还。
- `CanvasImage`区分记住的质量偏好与当前真正驻留的帧，source/retry拥有独立身份；回收让src变为undefined，经现有CachedImage释放本消费者lease，不删除节点、连线或缓存数据。
- 重新进入视口沿原质量选择和授权/cache路径恢复。清理取消计时和监听；账号/工作区会话失效保持原清图链路。
- 其他参考图组件借用同图时继续持有自己的引用；本模块不全局revoke对象URL，最后消费者释放才真正撤销它。

## 验收与证据边界

- 模块级真实React/ReactFlow provider、CanvasImage/CachedImage、浏览器PNG解码和IndexedDB，HTTP/auth/locale与可见性事件为显式fixture。
- 独立实际ReactFlow整合使用原生IntersectionObserver/ResizeObserver和真实视口移动，验证预加载边缘、短返、15秒离屏回收、重新授权/复用字节、参考图借用及账号清除。
- 验证对象是DOM src、ObjectURL生命周期、自然尺寸、计时器清理和媒体请求次数；估算RGBA不是RSS/GPU实测，不宣称全浏览器内存有硬上限。

### 独立审查修正

初版在共享IO同批先报B离屏、再报最旧A入屏时同步trim，可能在中间态误回收A。React合批后URL不变却丢失resident/settled记账，造成假加载超时。

修正为先合并整批可见性变化，再在微任务中选择离屏候选；不是只延后回调。新增同批Bfalse/Atrue边界验证A原URL不变、不revoke、不产生假错误。dispose同步移除entry，后继微任务不会回调已卸载消费者。独立审查在其检查范围内未再确认其他新增P1/P2，不把局部审查等同全项目无回归。
