# Naumi 品牌清理

## 范围与实现

- 当前仓库统一默认 Naumi 名称和现有 `/logo.png`。删除四张旧品牌资源与品牌特判；导航、画布、方形图标及 favicon 回退到同一资源，显式白标配置仍生效。
- 套图、试穿和作品 ZIP 文件名使用共享 `BRAND`，微信回复使用运行时品牌。清理后台示例、错误提示、设计稿注释、CDN 和下载注释。
- 中英文隐私政策和服务条款使用已有的中性运营方文案，不再声明第三方公司及其备案信息；没有虚构新的公司或备案号。
- 手机号与微信新实例的内部身份域名使用 Naumi 默认值。既有实例必须保留原身份域名配置；手机号服务端 `PHONE_EMAIL_DOMAIN` 和构建期 `NEXT_PUBLIC_PHONE_EMAIL_DOMAIN` 需一致。没有重命名或迁移用户账号、历史任务和媒体。
- 授权签发、更新服务和云端开通不再硬编码第三方地址。签发资格保持管理员检查与显式 `LICENSE_ISSUER`/`LICENSE_SERVER_URL` 判断，未配置默认拒绝；云端开通未配置则禁用链接，更新地址未配置返回空值。
- Docker 构建参数新增手机号身份域名和云端入口配置；示例 env 记录配置要求，不写入凭据或实际服务地址。

## 验收与恢复

- 模块验收：`node scripts/verify-brand-config.mjs` 覆盖默认资源、显式白标配置、下载命名、现有身份域名覆盖、微信品牌、签发门控及更新配置。
- 当前受版本管理的源码、文档和资源扫描通过：原始副本有 62 行旧标识和 4 张旧 Logo，修改后文本及文件名残留均为 0。
- `BRAND_CONFIG=PASS checks=46`；TypeScript 与 Next.js 优化构建通过。构建先排除了共享依赖 junction 引发的字体路径问题，并修复本轮英文 JSX 的转义，最终使用独立依赖成功构建。
- 实际本地 Next.js 浏览器验收通过：中英文隐私政策、服务条款、导航和页脚均显示 Naumi，`/logo.png` 两处正常加载；英文页面无旧运营方及备案信息，客户端错误 0。
- 另一份修改副本执行回滚后恢复 37 个原始文件，37 个 SHA256 均一致；新增测试及文档在回滚副本中移除，正式工作副本仍保留修改。
- 原始文件及 SHA256 保存在本任务忽略的 `output/brand-cleanup-20261010/original`；回滚脚本仅恢复明确文件并校验哈希，在另一份副本上演练，不覆盖共享 checkout。
- 本轮只处理仓库品牌清理，小球原型暂停；未修改数据库、账号或服务器运行配置，也没有回传旧机。
