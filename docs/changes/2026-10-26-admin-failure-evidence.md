# 管理后台直接展示任务失败原因

## 范围与基线

用户要求失败原因直接显示在后台，避免只看到“失败”后再人工查库。本轮仅本地开发与集中验证，不部署、不合重构、不恢复 Worker、不改 UNKNOWN、不重提任务。任务分支 `codex/admin-anomaly-triage-20261026`，原始 HEAD `ef057ea39433f65d0b62ee73e98920c7df6b2b4b`；开工刷新 `origin/main=368c93e2343c57a330a0db6831ccbef01283ed6d`，已经包含于本分支。

原案例的直接错误是供应调用 `transport-unknown / ECONNRESET`，客户账务 released/charged0，供应结果及费用 unknown/pending。这不是供应商明确拒绝或“确认没有扣费”，也没有证明重置发生于供应端。

## 实现

- 平台管理后台的新创作与历史生成列表显示中文原因和已记录错误码；详情在素材前直接显示失败阶段、证据来源和时间、供应通道/模型、供应结果与费用状态、对应子任务实际扣费及剩余预占。
- 增加只读诊断投影 `CreationSummary.failure`，只在平台管理接口返回；企业接口保持原有投影，不泄露供应通道与底层错误。
- 按当前页精确原任务/owner读取，parent→child只跟随同owner；新创作还保持同tenant约束。每个任务只使用最新供应调用回执，不拿全站最后一条错误或旧尝试给当前任务归因。
- 复用现有任务、供应回执与账务表，不新建业务表、不迁移、不写历史任务。只读取白名单错误类别/传输码/HTTP状态和供应身份，不返回原始供应消息、请求体、URL、凭据或图片字节。
- 没有证据时显示“失败原因未记录”；旧供应表不存在时不猜测。读取有深度/条数边界，达到边界显示证据不完整。查询仅追加在已选出的失败/部分成功/待核查记录上，不改变列表总数、父子计数、状态筛选或账务结果。
- 分类区分连接错误、超时、明确额度、鉴权、模型权限、审核、限流、供应服务异常，以及“供应响应已有输出但尚未完成本地交付”。单凭403不标成额度不足，客户释放预占不标成供应商未扣费。
