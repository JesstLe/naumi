# 图片背景意图与抠图通道修复

## 范围与基线

- 用户反馈图片节点出现“抠图通道尚未核实透明输出能力”和“提示词同时要求透明和不透明背景”。
- 独立分支 `codex/image-background-intent-20261022`，刷新远端后从 `origin/main 7b1e970c` 开始；视频节点工作 `24e6a8f3` 单独保留，不混入修复。
- 本轮不重放用户任务、不修改已发布供应商配置/冻结任务、不执行付费供应商请求。先提交修复；生产发布另按目标站生命周期进行。

## 排查与实现

- 旧意图规则把所有“不透明/白底”字样作为背景要求，无法区分主体材质、待移除的白底、来源描述和输出背景；同句的明确冲突反而可能漏判。
- 背景意图改为匹配背景定向短语；先识别背景移除并消耗原背景字样，再判断输出背景。保留否定、引号内文案、能力询问及真正的背景冲突检查。原始提示词不修改。
- 旧抠图模拟主动跳过透明能力筛选，之后只要一个候选未核实就拒绝整个计划。改为逐通道同时筛选编辑和透明能力，与执行时同一规则；未知和显式不支持通道不进入冻结候选，已核实通道继续工作。
- 抠图默认模型与实际执行统一使用工具默认优先级，避免工具已指定新模型但预览仍读取旧 binding。
- 不删除透明结果 alpha 校验；全无合格通道时在调用/扣费前明确失败，不假定未知供应商支持。
