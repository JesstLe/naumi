## 公共接口、依赖方向、数据与事务归属

- `canvas/text-output-policy.ts`：纯输出预算及终态部分正文解析。默认8192 tokens；人工配置优先，可设 `parameterMap.textOutput={maxTokens,maxSupportedTokens,tokenParameter}`。参数格式仅接受 `max_tokens` / `max_completion_tokens`，不从模型名推断，供应商已知上限可收窄。无配置时8192是应用默认预算，不是该模型已验证支持8192的证据。
- 单文字节点保持既有12000字符边界；超出节点容量也返回明确未完成结果，不暗中截短为成功。`finishReason=node_limit` 与供应商 `length` 分开。
- `text-output-server.ts`：连接冻结执行上下文与输出策略。两个文字入口共用策略，成功、截断、图片、拒绝、空正文分别处理。完整收到但不可用的文字回复按确定的领域失败处理；网络中断仍是UNKNOWN。
- Billing模块拥有失败回执、预占和最终结算。部分正文使用既有 `synchronous-failure-v1` 白名单扩展字段，回执与财务结算在原事务内提交。收费继续遵循冻结报价与既有失败结算规则，不改全站价格/模型映射。没有因错误码或零积分独自释放未知任务。
- `text-continuation.ts`：只读原账号/工作空间的已终结回执，并核对原项目。`continuationOf` 是原operationId；新续写为显式新意图，携带原已保存正文，只让模型写后续，再由路由拼接。未核验回执、外账号、外项目、外工作空间都不调用供应商。
- BillingProvider选定实际编号后，经原retained submission的identity回调在POST之前持久化原请求；不预先随机换号。原任务 owner 保留已生成结果，按账号/工作空间/项目/节点缓存恢复提示；缓存不是授权或账务证据。跨刷新查询只恢复原请求，不把缓存文档写回；用户后来保存的正文、标题、位置、连线保持。
- `bi/text-response-evidence.ts`：仅记录请求/回报型号、完成原因、请求额度和输入/输出/推理token计数；不含正文、提示词、推理内容、URL、密钥。型号名不同标为 `different-label-unverified`，不猜底层模型、不自动换模。

## 用户可见行为

1. 正常回复保存原正文工作流和撤销记录；单纯输入、保存和正文Ctrl/⌘+Enter不调用模型。
2. 截断回复单独预览，不覆盖原正文。用户可“使用这段文字”（零模型请求）、“继续写作”（显式新意图）、或“放弃本次回复”（保留原正文，无模型调用）。
3. “重试保存”只保存已知正文；“查询原任务”沿原身份查询未知结果；已确认拒绝可明确重新生成。
4. 续写中断/刷新后沿该续写自己的编号恢复；续写明确失败仍保留先前已生成部分。未知结果不换号、不自动重试、不自动清缓存。
5. 旧版助手SSE遇length不发送成功done；返回已落库的终态失败/部分正文。BillingProvider只在匹配原编号的终态失败上清意图，未知错误不清。
6. 未完成回复在现有创作栏的正文区域展示，保留模型选择与主操作；正文/AI写作标签、手写编辑、原文字生图路径保持。
