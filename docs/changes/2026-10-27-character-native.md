## 已选业务语义

1. 角色节点ID是身份，外观ID是该身份下的明确选项；修改名称不改变引用身份。不同镜头可以选同一角色的不同外观，不依赖全局“当前外观”。
2. 连线和@共用已有`OrderedInput`：角色是具备明确来源的文字上下文 `character:<id>#<appearanceId>`，不是用户填写URL或节点ID的输入框。
3. 提交前由服务端读取角色设定及正式自有图片，展开为普通文字/图片有序引用；按输入ID重映射后续引用编号，避免增加角色图片后误指向其他素材。
4. 展开后，角色设定冻结为`inline:character:<id>#<appearanceId>@<revision>`及完整文字，参考图片冻结为现有媒体身份/哈希；继续使用既有任务快照、预扣和Worker。角色文字明确列出其对应图片编号，避免多个角色参考混淆。
5. 已受理任务的幂等查询先于角色读取。角色后续修改、删除或参考图移除，不触发旧任务重提，也不改写旧任务快照。新生成使用当次可见的角色版本，缺少素材则在提交前报错。
6. 保存使用`expectedRevision`与`operationId`；图片归属先核验，再在保存事务内共享锁复核。重放先于当前依赖检查，原操作已成功后删除参考图不会把原重放误当作新保存。
7. 新模块持有自己的工程/事务；已有视频、导演和后续节点共享项目归属入口，保留历史表名和兼容导出，不新建第二套画布项目。
