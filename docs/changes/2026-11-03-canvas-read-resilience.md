# 画布读取有界恢复：第一批

## 基线与交付边界

- 用户要求持续优化缓存相关打不开/刷新等待，并避免新增回归。
- 在 `codex/model-mapping-103-20261029` 单向接收主线，固定基线 `af877f1507061d5c92702f67785c29438c5f8bbe`。本轮不合 main、不部署 47/103、不调用供应商；此前固定候选的条件整合授权不自动覆盖后续实验提交。
- 本批只改浏览器读取、显示和失败恢复；没有改生成受理、计费、供应商、任务恢复协议、原图质量/显示档位或离屏驻留政策。
- 不能把本地故障注入等同于用户当次线上事故根因，也不称所有启动链路已经有界。

## 已复现问题

1. `/api/account` 的网络/授权头/正文一直 pending 时，共享 promise 一直存在；IDB 自身已有期限不能终结这类网络等待。
2. Canvas 初始化同时等待作品、项目名、文字节点，辅助读取也没有完整期限。旧 catch 把失败当空作品并置 `textNodesReady=true`，后续真实文字持久化 effect 会把本地旧草稿覆盖成空数组。
3. 图片授权、共享下载的旧 AbortController 不保证等待的授权函数或非合作 Promise 实际完成；fallback 和解码也存在无界等待、槽位长期占用。

## 模块、接口与状态归属

### `browser-read-deadline`

公开函数 `withBrowserReadDeadline(work, {timeoutMs, signal?})` 只负责浏览器**读取**期限与调用方取消。给工作函数独立 signal，同时显式结束外层等待，即使底层不响应 abort 也不会卡住调用方。成功释放 timer/listener；迟到工作在开始后续 I/O 或发布状态前必须检查 signal。

不是写入重试/任务受理判断器。TimeoutError 不代表供应商未受理，不触发生成 POST 或退款。

### 作品元数据与 Canvas 初始化

- `loadAccountSnapshot` 保留 owner/epoch/revision、缓存、并发共享和敏感字段过滤；网络读取30秒覆盖 auth/fetch/JSON，迟到结果不得写缓存。
- 明确 `persisted:false` 是原生无数据库模式合法响应；其他缺失 artworks 的服务端响应失败，不伪装空文档。
- Canvas 每次挂载拥有35秒初始化等待，项目/文字读取各30秒且覆盖正文。失败保持作品未知、文字未就绪；不启用保存、不覆盖草稿，显示简洁重试入口。
- 取消挂载取消自己的读取，只停止本挂载的账号等待，不取消其他消费者共享的账号读取。
- 仍采用完整初始化提交：本批没有拆成局部节点边读边编辑，以避免迟到结果覆盖已编辑内容。显式无数据库文字响应仍恢复原local草稿。
- Works/Workbench 若本次已显示同账号旧快照，只在 TimeoutError 时保留；权限失败、其他错误及账号切换保持原行为。不把旧快照包装成 Canvas 的权威成功。

### 图片读取与解码

- descriptor 批次15秒；正常共享读取60秒；内容共享下载60秒；异常回源60秒；decode20秒。它们是分阶段期限，不是整个图片链路60秒总上限。
- 超时/最后消费者取消回收网络票据，迟到auth不新增请求、迟到正文不发布ObjectURL；共享传输的其他消费者继续保有其身份。
- decode超时不当作坏缓存再次下载。真正坏图仍只单次重新授权绕缓存读取。
- 仅同identity/owner/revision的已显示画面在超时升级时保留。权限拒绝/账号切换/授权失效依旧清除。
- 不改`readBrowserImage`编辑/下载接口、原图数据和素材权限。

1. account严格形状校验误拒绝原生`persisted:false`；增加精确兼容而非泛化所有坏响应。
2. 公共读取新增超时会使Works/Workbench在已显示stale数据后清空；只在本次同账号快照已显示且TimeoutError时保留，并补权限/换号正控。

测试脚手架原失败保留：瞬时HTTP未建立真实重叠导致去重断言误判，改为明确hold首请求；UI成功后原文字高度自适应会保存同ID/同内容，禁止的是失败期间写文档或空内容覆盖，不是所有合法保存。
