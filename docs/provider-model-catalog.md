# 供应商模型目录自动显示（2026-10-07）

入口：管理中心 → 系统设置 → 模型配置中心 → 供应商。

已配置供应商沿用现有注册表（首次初始化从现有服务端配置导入），不从互联网臆造供应商名称。进入供应商页先读数据库目录缓存，过期/首次读取时自动使用原加密凭据执行只读GET模型目录；手动刷新使用同一通路。供应商独立显示名称、真实模型ID、目录更新时间和错误状态。地址/协议/凭据改动先保存草稿再刷新，不能让浏览器提供任意待查询地址。

标准兼容通道采用连接baseUrl下的`/models`；APIMart兼容目录读取根路径`/v1/models`，以实际响应是否提供data/models列表判定是否接通。不声称接口发现就是生成成功或能力核验。没有标准目录适配的协议明确显示未声明接口，并显示已配置模型，不猜测供应商全量模型。没有上游名称时显示真实ID。接口包含分页标记/结果超过600个时提示只展示部分。

`GET /api/admin/bi/model-config/catalog`：管理员个人已保存草稿的供应商、持久目录和已配置模型，不访问上游。

`POST`相同路径：`{providerId,draftId,expectedRevision}`，管理员权限、同站校验、草稿归属/修订检查，服务端读取原凭据执行只读发现。成功缓存5分钟，失败缓存1分钟并保留上次成功结果。来源为已保存供应商连接的标准目录接口；不是公开客户模型列表。

缓存表`app_model_provider_catalog`，按供应商ID+地址+协议+不可变凭据引用摘要隔离，重启后保留。数据库advisory lock避免同连接并发拉取；目录不保存token或原始响应。响应2MiB有界读取，超过大小、无效schema、HTTP错误均显示失败，不记空目录成功。

不会自动新增可收费模型，不改变采购价/售价/路由/已生效版本/在途任务。能力与公开别名继续由已有模型配置流程核验、保存和发布。

新增迁移：`scripts/migrations/20261007-provider-model-catalog.sql`，运行时幂等创建同表。回滚代码保留缓存表，不需要回滚数据或删除媒体。

验收：`npm run verify:provider-catalog`覆盖去重、名称、明确未适配、缺凭据、跨请求数据库缓存、并发、失败保留旧目录、连接/凭据隔离、管理员边界、跨站、草稿修订及生效版本不变；仅fixture，不发起收费生成请求。后续生产检查/发布结果单独记录。
