# 模型配置中心维护说明

模型配置中心位于 `/admin/bi/models`，通过管理中心的「系统设置 → 模型配置中心」进入。服务端页面与每个管理 API 单独校验管理员权限，普通用户、企业用户和匿名请求不能读取配置、凭据引用、成本、模拟详情或发布历史。内部报价与成本继续由 `/admin/billing` 维护。前台只取得已开放的模型别名、质量和尺寸能力，不取得供应商地址、真实模型名、路由组成或成本。

## 配置与发布

依次建立供应商、上游模型、对外模型和默认用途。供应商选择现有协议，填写地址、超时、并发和密钥；浏览器加密传输密钥，服务端加密保存，每次更新生成新凭据引用。编辑器不会回显密钥，也不把密钥写入浏览器存储。上游模型填写供应商实际模型名和已核验能力；支持高质量、原生尺寸或编辑能力应以已验证的接口行为为依据。原生 2K/4K 的 OpenAI 兼容通道还需填写尺寸参数映射。5K 保留现有基础出图后处理，仍按选择的尺寸计费。

上游成本通过选择计费中心已有成本项引用。模型中心没有第二套金额编辑器。最低成本路由只能使用完整且可比较的货币成本，未记录、仅积分成本或不能统一币种的候选会被拒绝。固定积分价格不会因路由选择了另一个上游而重新计算；成本加成价格仍按原计费功能的显式成本项和授权上限计算。配置成本及没有上游回执的调用成本都是估计值，不能当作实际供应商账单。

一个对外图片模型可以直接映射一个上游，也可以映射图片混合池。混合池选择真实候选、顺序和优先级／最低成本／延迟策略，按任务、质量、尺寸、编辑、参考图及保真等条件筛选。相同显示名称的对外模型仍保留不同标识。文字、视觉及视频使用其现有协议适配器直接映射；新增协议需要实现适配器、能力验证和测试，不能通过填一个任意字符串启用。

默认用途分别控制生图、编辑、生成式抠图、Agent 文字和视觉、文字生成、标题、竞品、参考分析、审图、OCR 视觉兜底和视频。隐藏模型也能作为默认用途；前台只取得该用途的质量和尺寸摘要，不取得其内部标识。Replicate 商品分割、固定放大、Paddle OCR 主引擎、本地排版及媒体后处理保留现有专用设置；它们的生成式或视觉兜底使用注册表。已迁移实例的旧通用模型和供应商写接口拒绝修改并引导到模型中心，Replicate 专用设置仍可维护。

编辑先保存个人草稿，在线版本保持不变。「路由模拟」只读草稿与当前计费成本，展示候选及排除原因，**不会发起供应商生图或扣积分**。发布前校验并查看差异，填写原因后提交。发布确认依次检查 Router 准备摘要、激活状态和数据库指针；只有确认成功才显示已生效。界面显示模型版本、计费版本、草稿修订、供应商有效并发和发布记录。

发生 409 时保留本地输入，对比远端草稿后选择保留本地或载入远端；不要直接覆盖另一位管理员的修改。发布结果未知时保留同一个操作编号，通过「核查／恢复」重试原操作。等待核查期间不能启动另一笔发布。历史恢复先生成新草稿，再作为一个新版本发布，原历史与凭据仍保留。

## 已接受任务与账务

每个新任务冻结模型版本和计费版本，并保存对外模型、目标、不可变凭据引用及必要的 Router 摘要。排队的画布任务、套图／A+ 审核流程、视频创建与轮询，以及 Agent 子操作继续使用接受时的版本。用户自带密钥任务保存加密且绑定用户的连接快照，后续改变用户设置不会改变原任务；平台兜底也使用原版本。供应商实际执行模型与用户选中的别名分别进入 BI。

模型配置过期的客户端收到 409，刷新列表并保留输入，不能自动重发生成。确认的质量参数拒绝可以按原规则退档；超时、连接中断、创建结果未知及旧任务缺少安全快照时进入核查，不能自动重复付费 POST。视频注意／处理中任务不能通过「重试」再创建另一笔上游任务。

积分仍只有原计费服务负责预留、结算、释放和流水。现有质量基础价与尺寸差价、成功数量、失败、用户自带密钥、套餐／企业折扣及授权上限不由模型中心重新定义。BI 的「实际提交模型」表示 Naumi 直接提交的模型；混合池此字段是提交给 Router 的别名，具体供应商命中应查看 Router 执行链路记录。

## 并发、凭据与服务连接

直连供应商使用 PostgreSQL 原子租约，覆盖多个应用实例和保留版本。同一地址来源与凭据的重复供应商配置会归并账号；供应商稳定标识保留密钥轮换前后的共享额度。归并同时移动有效租约，保留最低历史限制。Router 的混合候选也共享账号额度。提升草稿上限可能暂时不会提升有效额度：历史版本尚不能安全退休，界面会显示保守限制。不能用复制供应商绕过额度，也不能删除旧凭据或状态文件。

Naumi 应用需要六项私有连接设置：`NAUMI_ROUTER_MANAGEMENT_URL`、`NAUMI_ROUTER_MANAGEMENT_TOKEN`、`NAUMI_ROUTER_GENERATION_URL`、`NAUMI_ROUTER_GENERATION_TOKEN`、`MODEL_CONFIG_ENVELOPE_SECRET`、`MODEL_CONFIG_TRUSTED_ORIGINS`。地址只能由服务器配置，表单不能指定控制面地址。管理令牌、生成令牌及封装密钥应独立；封装密钥和管理令牌至少 32 字符。保持原 `SETTINGS_SECRET` 和 `VIDEO_WORKER_SECRET`，不能通过改密钥让历史数据失去解密能力。

Router 管理监听使用 `NAUMI_ROUTER_MANAGEMENT_ADDR`，持久配置目录使用 `NAUMI_CONFIG_STATE_DIR`，与原 `NAUMI_STATE_DIR` 一起备份。管理接口仅绑定回环，容器通过私有桥接代理访问精确路径；公开站点不代理 `/internal/config/`。供应商地址要求 HTTPS；确需访问服务器内网服务时，由服务器配置精确 origin 允许列表，元数据地址仍不能放行。不同 origin 的重定向不允许携带密钥。

## 发布与恢复

使用两个仓库的固定提交、已验证镜像和 Router 二进制摘要。发布前暂停入口与 worker，确认没有正在提交的付费任务，备份 PostgreSQL、生产配置、媒体清单和增量、Router 执行／配置状态及 New API 数据。校验备份可读且对应暂停后的数据；保留生产配置、数据库与媒体卷。先部署兼容旧请求的 Router，再使用 `scripts/deploy-release.sh` 协调发布 Naumi，确认版本、权限、公开脱敏、模拟零生成、用户／账务指纹和媒体不变后恢复入口。

回滚旧 Naumi 前暂停 worker 和生成入口。旧版本不能处理的新格式任务留待兼容 worker 完成或人工核查，不能改写快照重新发起。回滚旧 Router 时保留新版 Router 的对应摘要恢复服务与状态备份；旧 Router 只接旧格式请求。不要恢复旧数据库覆盖新账务，不要删除媒体或配置状态。`ROLLBACK.sh --check` 仅证明回滚文件与固定镜像存在，不能代替这项兼容性核查。

验证命令包括 `verify:model-config`、`verify:model-publication`、`verify:model-admin`、`verify:model-execution`、`verify:model-tools`、`verify:model-router-contract`，以及全部原计费、生图、视频、BI 回归和 Router race/vet。测试必须使用隔离本地数据库与假供应商，不以真实用户或付费请求做权限、密钥、扣费和恢复验收。
