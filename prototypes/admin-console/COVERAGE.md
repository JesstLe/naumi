## 详情与操作

- 创作：素材、输入/处理后输入、冻结参数、执行时间线、关联子任务、账务、技术来源。
- 历史任务：独立任务 ID、来源、提交日期和原任务证据。
- 图片：独立图片网格与搜索，进入对应原任务详情。
- 对话：用户/助手消息、条目数量、Token、来源及关联创作入口。
- 调用审计：前端模型、请求 Wire ID、上游确认模型、供应商、模型/计费版本与原账务。
- 租户：成员/岗位、共享额度、授权期限、创作与账务；保持租户 ID 随 URL。
- 用户：功能授权模式与逐项勾选。
- 账务：订单付款状态、原币成本未知/已确认、采购对账差额、版本差异；模拟计算只在本地运行。
- 模型：原配置抽屉保留，补供应通道、分辨率、高级参数区块；元数据库具有独立详情/编辑。
- 系统：结构化表单、提示词编辑、模板、兑换码及管理日志前后值。
- 部署：实例身份、用户与权限入口、指令、运维授权与版本策略；不执行服务动作。
- 通用列表：搜索、状态筛选、分页、按筛选导出、详情；可编辑记录保存为本次预览草稿。

保存、启停、巡检与配置动作仅修改演示内存；真实服务、业务数据、密钥、模型调用与费用均不接入。

## 兼容与深链接

- 每个子页面有本地 hash 路径，例如 `#tasks/calls`、`#billing/wallet/products`、`#models/config/pools`。
- 原一级 `#tasks`、`#models` 等自动指向对应默认子页面。
- 页面刷新、浏览器前进后退、一级导航往返保留筛选/页码；租户详情保留 tenant。
- `/admin/bi`、`/admin/mvp`、`/admin/mvp/library`、创作 `[id]`、创作 `resolve` 及设置旧 query 入口有明确映射，不增加重复侧边菜单。
- 24 个源码页面路径逐个对应视图或兼容映射；原型不架设这些真实 HTTP 路由。

## 构建与验证

编辑 `subpages.js` / `subpages.css` 后运行：

```powershell
node prototypes/admin-console/build-preview.cjs
node prototypes/admin-console/verify-subpages.cjs --root <ABS/prototypes/admin-console> --output <ABS/evidence> --deps-root E:/Workspace/naumi
```

构建器以命名区域内嵌到原 `index.html`，最终文件仍独立离线可打开。没有引入服务器、包依赖、生产 API 或全新前端框架。

回归分层：
1. 原版浏览器实跑，证明原任务列表/抽屉可用，但五个截图二级入口未覆盖。
2. 修改版逐个点击 25 个二级入口；遍历 88 个声明路由状态（含默认入口别名），不是 88 个独立生产功能。
3. 检查桌面/手机溢出，真实筛选、前进后退、详情、表单保存、模拟计算、零 HTTP/零页面异常。
4. 初版 24 项交互继续验证；只调整导航定位与输出图选择器，不放宽原行为断言。
5. 独立副本恢复初版真实字节，再用同一 subpage runner 复现缺失状态。

首轮发现状态点击与 URL 同步的事件时序问题、团队入口详情资料不足；原失败记录保留。初版回归另外发现导出/刷新按钮随旧页头剥离而遗漏，已重新放入模块页头。
